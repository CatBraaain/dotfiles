# MS-IME `StyleList\Custom` バイナリ解析

## 対象と目的

- 対象: `undotfiles/ime/key-settings.reg`
- 対象レジストリ: `HKCU\Software\Microsoft\IME\15.0\IMEJP\StyleList\Custom`
- 目的: キー設定スナップショットの内部形式を復元し、アクションコードを逆解析するための前提を記録する

この文書は、保存済みスナップショットから確認できる事実と、今後の実験で検証する事項を分けて記録する。スナップショットの更新手順やレジストリへの適用手順は `undotfiles/ime/SPEC.md` の対象である。

## 結論

`key-settings.reg` は暗号化・圧縮された未知のバイナリではない。次の層を順に復元すると、キー設定レコードを人間が読める形までデコードできる。

1. `.reg` ファイル全体を UTF-16LE として読む
2. `hex:` のカンマ区切り値をバイト列へ戻す
3. `REG_BINARY` のバイト列を CP932 として読む
4. NUL区切りのレコードへ分割する
5. 各レコードを最初の `=` でキー名と6個の状態別アクションへ分ける

通常のレコード形式は次のとおりである。

```text
割り当てキー=状態1 状態2 状態3 状態4 状態5 状態6\0
```

右側の6項目は状態別のアクションコードである。各項目は実際のバイナリ1バイトではなく、2桁の16進数を表すASCII文字列である。一部の旧プロファイルには`F3=80`や`L2F1=B0`のような1項目だけのレコードもある。

## エンコードの各層

### `.reg` 全体

ファイル先頭は UTF-16LE BOM (`FF FE`) 付きで、`Windows Registry Editor Version 5.00` から始まる。`file` コマンドでも Windows Registry little-endian text と判定される。

`hex:` 値の行末にある `\` は、`.reg` の論理行が次の物理行へ続くことを示す。

### `hex:` 値の復元

`key` 値の先頭は次のバイト列である。

```text
53,50,41,43,45,3d,38,31,20,30,36,20,32,44,20,33,30,20,30,37,20,30,36,00
```

カンマ区切りをバイト列へ戻すと、CP932/ASCII上では次のレコードになる。

```text
SPACE=81 06 2D 30 07 06\0
```

外側の`3d`はASCIIの`=`、`32,44`はASCII文字列の`2D`に対応する。

### CP932

日本語の割り当てキーは CP932 で格納されている。

| バイト列の例 | 復元文字列 |
|---|---|
| `94 bc 8a 70 2f 91 53 8a 70` | `半角/全角` |
| `83 4a 83 5e 83 4a 83 69` | `カタカナ` |
| `82 d0 82 e7 82 aa 82 c8` | `ひらがな` |

英数字、`+`、空白、`=`、アクションコードはASCIIである。

### NUL区切り

各レコードはNUL (`00`) で終わる。値の末尾にはレコード終端に加えて最終NULがあり、バイト列上はNULが2つ続く。

キー名に空白や`+`が含まれるため、空白では分割しない。最初に現れる`=`だけを区切りとして使う。

## 6状態のアクション配列

右側の6項目は、次の順序で状態に対応する。

| 位置 | IME状態 |
|---:|---|
| 1 | 入力変換済み文字なし |
| 2 | 入力文字のみ |
| 3 | 変換済み |
| 4 | 候補一覧表示中 |
| 5 | 文節長変更中 |
| 6 | 変換済み文節内入力文字 |

したがって、次のレコードは半角/全角キーに対して全状態で同じアクションを割り当てる。

```text
半角/全角=CD CD CD CD CD CD
```

次のレコードは状態ごとに異なるアクションを割り当てる。

```text
Ctrl+BackSpace=84 55 1F 1F 00 15
```

左側が割り当てキー、右側が6状態それぞれのアクションである。`80`、`FF`、`FE`、`00`などのアクションコード自体の意味は、別途検証が必要である。

## ライブレジストリのデフォルトプロファイル

Windows上のライブレジストリを、次の基底パスから読み取った。

```text
HKCU\Software\Microsoft\IME\15.0\IMEJP\StyleList
```

`Custom`以外には、次の5プロファイルが存在した。括弧内は各REG_BINARY値のレコード数である。`Color`配下の表示色バイナリはキー設定レコードに含めていない。

| プロファイル | キー設定フィールド |
|---|---|
| `ATOK` | `key`(88), `S1key`(1), `S3key`(1), `S4key`(3), `S6key`(14), `S7key`(11), `S8key`(1), `S9key`(5), `SDkey`(9) |
| `MS-IME2000` | `key`(62), `S1key`(1), `S3key`(1), `S4key`(6), `S5key`(7), `S7key`(12), `S8key`(1), `S9key`(3), `SDkey`(9) |
| `NATURAL` | `key`(65), `S1key`(1), `S3key`(1), `S4key`(6), `S5key`(7), `S7key`(12), `S8key`(10), `S9key`(3), `SAkey`(2), `SBkey`(1), `SCkey`(1), `SDkey`(9), `SEkey`(2) |
| `VJE` | `key`(85), `S1key`(1), `S3key`(2), `S4key`(2), `S7key`(12), `S8key`(1), `S9key`(3), `SDkey`(8) |

プロファイルごとの補助値は次のとおりである。

- `ATOK`, `VJE`, `WX`: `defRoma=MS-IME`, `DisableFunctions=3`
- `MS-IME2000`: `DisplayName=IME Standard`, `defRoma=MS-IME`, `DisableFunctions=2`

- `Custom`: `DisableFunctions=0`, `Color\RoamVal=1`

現在の `HKCU\Software\Microsoft\IME\15.0\IMEJP\MSIME` は `keystyle=Custom`、`style=NATURAL` である。`key-settings.reg` はライブの`StyleList\Custom`をexportした内容とバイト単位で一致する。

## 未解明のキーフィールド名

### レジストリ値名

`key`と`S*key`は、6状態の位置番号そのものではない。各値のレコード自身が6状態すべてのアクションを持つためである。ライブレジストリで確認できた値名とプロファイルは次のとおりである。

| 値名 | 存在するプロファイル |
|---|---|
| `key` | 全プロファイル |
| `S1key`, `S3key`, `S4key`, `S7key`, `S8key`, `S9key`, `SDkey` | 全プロファイル |
| `S5key` | `Custom`, `MS-IME2000`, `NATURAL` |
| `S6key` | `ATOK`, `Custom` |
| `SAkey`, `SBkey`, `SCkey`, `SEkey` | `Custom`, `NATURAL` |
| `S2key` | 存在を確認できず |

`imjpcus.dll`にも`S1key`〜`SEkey`という文字列は含まれるが、各フィールドの画面名や適用条件を示す公開文字列は見つからない。`S`と16進文字の命名規則は未解明である。

### レコード左側のキー名

通常のキー名のほかに、次のような未解明または複合的なキー名がある。

- 末尾に空白を持つ`← `、`→ `。`主に`SAkey`、`SCkey`に現れる
- `← Ctrl+K`、`← Ctrl+S`、`→ Ctrl+D`、`↑ Ctrl+E`、`↓ Ctrl+X`など、矢印キーと別キーを連結した名前
- `PageDown  Ctrl+X`のように空白数が異なる名前
- `Ctrl+Shift+Home Shift+Home`のように、修飾キー列を含む名前
- `L2F1`〜`L2F15`。`WX\key`にのみ現れ、`L2F1=B0`のように6状態形式ではない1トークンレコードを持つ
- `F3=80`、`F4=80`。`MS-IME2000\key`と`NATURAL\key`に現れる旧形式とみられる1トークンレコード

これらは空白で分割せず、レコードの最初の`=`までをキー名全体として扱う必要がある。

## 現時点で確定していること

- `.reg` 全体は UTF-16LE である
- `hex:` の値を戻すと、CP932のNUL区切りテキストになる
- レコードは `割り当てキー=状態別アクション` 形式である
- 左側は割り当てキー、右側は6状態のアクション配列である
- 日本語キー名はCP932で復元できる
- `key-settings.reg`のCustomレコードは6個の2桁16進値によるアクション配列で構成される
- 旧プロファイルには1項目だけのレガシーレコードも存在する
- `key` はCustomで通常キーを82件持つ
- `key` と`S*key`のレコードは、左側のキー名と右側の状態別アクション配列で構成される
- `key-settings.reg` はライブの`StyleList\Custom`とバイト単位で一致する
- ライブレジストリには`ATOK`、`MS-IME2000`、`NATURAL`、`VJE`、`WX`、`Custom`の6プロファイルがある
- `Custom`以外のプロファイルにも同じアクションコード体系が使われている
- 一部の旧プロファイルには6状態形式ではない1項目レコードがある
- `DisableFunctions` と `Color\RoamVal` は通常のDWORDである

## 未解明のこと

- 観測された各アクションコードと実際のIMEコマンドの対応
- `80`、`FF`、`FE`、`00`などの特殊値が「無効」「継承」「何もしない」のどれに当たるか
- `key` と`S1key`〜`SEkey`の適用順序と、各`S*key`の意味
- `S2key`が存在しない理由
- `← `や`→ `の末尾空白、複合キー名、`L2F1`〜`L2F15`の命名規則
- 旧形式の1項目レコードが表す状態と、6状態配列との関係

## 既存実装との関係

`undotfiles/ime/key-settings.ts` には、今回の外側の形式を扱う処理がすでにある。

- `:14-70`: UTF-16LE `.reg` のセクション、継続行、`hex:`、`dword:`を解析
- `:97-113`: CP932でデコードし、NUL区切りと最初の`=`でレコードを分解
- `:118-136`: レコード単位の追加・削除・変更を比較

現在の実装はCustomの6項目を意味のある状態として解釈せず、17文字のペイロード文字列として比較する。

## 次の逆解析手順

デフォルトプロファイルとの比較で候補を絞り、Windows上の変更前後exportで意味を検証する。

1. `ATOK`、`MS-IME2000`、`NATURAL`、`VJE`、`WX`、`Custom`の同じキー名を状態位置ごとに比較する
2. 既知の操作名から、`BackSpace`、`Delete`、矢印、`Enter`などのアクションコードを暫定対応付けする
3. 現在の`StyleList\Custom`をbaselineとしてexportする
4. MS-IMEのキー設定GUIで、1キーの割り当てだけ変更する
5. 同じキーを再度exportし、変更されたプロファイル値・レコード・状態位置を比較する
6. 入力中、変換中、候補一覧中など状態を変えて同じ実験を繰り返す
7. 複合キー名と1項目レコードは、GUI上の設定項目またはDLLの文字列参照と照合する

まず各状態の対応を固定し、その後にアクションコードとIMEコマンドの対応を確定する。単一の変更で複数状態のコードが変わる場合は、GUIが複数状態へ同時に割り当てた可能性を含めて記録する。
