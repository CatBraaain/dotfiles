# handoff-session plugin Spec

このpluginは、作業phaseを終えたagentが次のagentへの自然言語プロンプトを用意し、オーナーの確認後に完全な新セッションへ移るための `handoff_session` ツールを提供する。対象読者は、phase境界でコンテキストを切り替えるオーナーとagentである。

## 入力

`handoff_session` は次の入力を受け取る。

| 入力      | 条件                             | 意味                                      |
| --------- | -------------------------------- | ----------------------------------------- |
| `reason`  | 前後の空白を除いて空でない文字列 | 現セッションを終える理由                  |
| `handoff` | 前後の空白を除いて空でない文字列 | 次のagentへ自動送信する自然言語プロンプト |

`handoff` は続行目的、承認済みspecのパス、決定事項、作業・検証状態、未決事項、完了条件を含められる。ファイルパスを含める場合、次のagentはそのファイルを読んで続行する。

## 収束ループ

`handoff_session` はmain agentだけが使う。main agentは収束ループの開始時、ならびにseniorによるレビューまたは実装の完了時に呼び出す。オーナーが承認すると、新しいmain agentが次のphaseを別のseniorへ委譲する。

収束条件を満たしたmain agentは、`handoff_session` を呼び出さずオーナーへ結果を報告する。

## セッション移行

| 開始時の状態                        | 操作                                                        | 結果                                                                                          |
| ----------------------------------- | ----------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| 有効な `reason` と `handoff` がある | agentが `handoff_session` を呼ぶ                            | 現在のagent turn内で、ブラウザの質問UIが開き、`reason` と `handoff` が提示される              |
| 確認UIが表示される                  | `Yes, handoff` または `No, stay (reason next)` を選択する   | 選択肢は2つで、単一選択である                                                                |
| 承認する                            | セッション移行                                              | 完全な新セッション（セッションID接頭辞 `handoff-`）が開始され、`handoff` が内容を変えずに初回のユーザープロンプトとして送信される |
| 新セッションの開始後                | —                                                           | 新セッションはセッション一覧に現れる。表示は自動的に切り替わらず、オーナーが一覧から開く       |
| 新セッションの開始後                | —                                                           | 旧セッションはセッション一覧に履歴として残り、idle状態になる                                   |

新セッションが引き継ぐのは、旧セッションの作業ディレクトリ、agent preset、モデルルート（provider / model）だけである。旧セッションの会話履歴、要約、ファイル参照はLLMコンテキストへ渡らない。新セッションは自動送信された `handoff` だけを前段の作業入力として扱う。

## 移行しない条件

| 条件                                             | 結果                                       |
| ------------------------------------------------ | ------------------------------------------ |
| `reason` が欠落している、文字列でない、または空  | エラーを返し、現在のセッションを維持する   |
| `handoff` が欠落している、文字列でない、または空 | エラーを返し、現在のセッションを維持する   |
| `No, stay (reason next)` を選択する              | 任意の拒否理由の入力欄を表示する           |
| 拒否理由を入力する（または空欄のまま進める）     | 現在のagentへ次ターンのユーザーメッセージとして `no(<理由>)` を送信し、現在のセッションを維持する。空欄の場合は `no()` を送信する |
| 確認UIの回答前にturnが中断される                 | エラーを返し、現在のセッションを維持する   |
| 対話UIを利用できない（回答UIが不在、または子agentからの呼び出し） | エラーを返し、現在のセッションを維持する   |
| 新セッションの作成が失敗する                     | エラーを返し、現在のセッションを維持する   |

エラーはtool呼び出しの失敗としてagentへ返る。移行が拒否・中断・失敗したとき、旧セッションへ自動で戻す処理は発生しない（旧セッションで処理が継続する）。

## 既存の新セッション操作

dshが備えるNew Session（新規セッション作成）のUI操作は変更しない。これらはオーナーが任意に空の新セッションを開始する操作として維持する。
