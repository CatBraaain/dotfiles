# agentツールSpec

`agent` ツールで、独立したmainセッションの作成と、稼働中セッションへのメッセージ送信を行う。作成では、ユーザーが対話を引き継ぐ独立した標準mainセッションを会話ごとのtmux sessionとして作成し、初期依頼を即実行する。作成先は標準設定・標準権限のmainであり、呼び出し元セッションとの会話継続・結果待ち・成果回収は行わない。送信では、稼働している対象セッションへ短いメッセージを1件届け、必要なら相手が消費するまで待つ。対象読者は、利用者と実装・テストの担当者である。

## ツールの入力

| パラメータ | 必須 | 内容 |
| --- | --- | --- |
| `message` | 必須 | 相手セッションへ届けるテキスト。`session-id` 省略時は新規セッションが即実行する初期依頼になる。前後の空白を除いて空であってはならない |
| `session-id` | 省略可 | 送信先のセッションID。省略時は新規の独立mainセッションを作成する |
| `wait` | 省略可 | 相手がメッセージを消費するまで待つ秒数。`session-id` 指定時のみ有効で、正の整数であること |
| `cwd` | 省略可 | 新規セッションの作業ディレクトリ。作成時のみ指定できる。省略時は呼び出し元の作業ディレクトリを使い、相対パスは同ディレクトリを基準に絶対パスへ解決する |

空白のみの `message`・`session-id`、NUL文字を含む `message`・`session-id`・`cwd`、`session-id` のない `wait`、正の整数でない `wait`、送信時の `cwd` 指定は、いずれもツールエラーになる。

初期依頼と送信テキストの位置引数の規則は [pi-mux の仕様](../../../../.local/cli.exact/pi-mux/SPEC.md#new) の `new` と [send](../../../../.local/cli.exact/pi-mux/SPEC.md#send) に従う。送信テキストの上限（2800 code points）などCLIが検証する入力制約は本ツールでは再検証せず、CLIの失敗をエラー結果として返す。

## 呼び出し元の制限

`agent` はmain agentだけが呼び出せる。次の2段階で制限する。

| 層 | 動作 |
| --- | --- |
| `~/.agents/config/agents.yaml` | main 以外の全agentの `tools` から `!agent` で除外する |
| 拡張の実行時ゲート | 環境変数 `PI_AGENT_NAME` が `main` でない呼び出し（未設定を含む）をツールエラーにする |

実行時ゲートは `PI_AGENT_NAME` を agents拡張が設定することを前提とする。agents拡張の負う名前の正本は [agent管理の仕様](agent-management.spec.md#概要)が定める。

## 動作分岐

`session-id` の有無で動作が分かれ、どちらも呼び出し時点で登録されているbashツールを1回だけ使う。

| 条件 | 実行するコマンド | 成功時の status |
| --- | --- | --- |
| `session-id` 省略 | `pi-mux new --detached <message>` | `created` |
| `session-id` 指定 | `pi-mux send [--wait <seconds>] <session-id> <message>` | `delivered` |

- 作成では、sessionとwindowの命名はCLIに任せる。成功時はCLIの出力を本文に含め、会話IDとその会話への接続コマンドを示す。CLIがヘルプだけを表示する場合など、会話IDを返さなければ `error` とする。作成はdetachedで行い、呼び出し元や他の端末への自動attach・画面表示は行わない。
- 送信では、`--wait` は `wait` 指定時のみ `send` の直後に1回付ける。`message` は空白・引用符・改行・先頭の `-` を保持した1つの引数として渡す（CLIが複数引数を単一スペースで連結するため）。`wait` 省略時は相手の消費を待たず、書き込み確認後に完了する。
- 送信先はCLIが完全一致で解決する。稼働実体がないID・同じIDの実体が複数のときは、CLIがoptionを書かずエラーにする。稼働していない会話へは、`open` で復元してから送信する。
- bashが拒否・失敗したとき、コマンドが非0で終了したとき（送信では未消費タイムアウト・対象paneの消滅を含む）は `error` とエラー内容を返す。

構造化結果は `status`（`created`・`delivered`・`denied`・`error`）と、拒否・失敗時の `error` を持つ。作成したwindow名は返さない。

成功結果の意味は作成と送信で異なる。作成は全拡張の初期化完了や初期依頼の完了を待たない作成受付であり、送信は相手のpi実体がメッセージを消費したこと（`wait` 指定時）または書き込みを確認したこと（`wait` 省略時）を示す。

## 承認

`agent` の実行は、1回のユーザー確認を必要とする。選択肢は次の4つである。

| 選択肢 | 効果 |
| --- | --- |
| `Allow once` | その呼び出しだけを許可する。次の呼び出しは再度確認する |
| `Allow in this turn` | 次のユーザーメッセージを受け付けるまでの間、確認を省略する |
| `Allow in this session` | このセッションの残りの間、確認を省略する |
| `No, deny (reason next)` | 実行しない。続けて任意の理由を入力できる |

- turn・session承認は承認した動作だけに適用する。同じ動作では、承認が有効な間は入力が変わっても再確認しない。
- 承認の有効期間の意味は guardrail拡張の選択ダイアログに合わせる。本拡張の承認は、guardrailのコマンド承認・パス許可とは独立に保持・失効する。
- 選択ダイアログのキャンセルは拒否として扱う。拒否時の理由入力は任意で、空欄・キャンセルは理由なしとして扱う。拒否はエラーとして呼び出し元に返し、以降の呼び出しには影響しない。
- 選択ダイアログを提供できないUIでは確認ダイアログ（`confirm`）に置き換え、承認は `Allow once` 相当として扱う。理由入力はテキスト入力ダイアログを提供できる場合のみ行う。
- UIを持たない環境では承認できず、ツールエラーとして失敗する（fail-closed）。
- ダイアログの表示中にturn承認が失効した場合、その回答は失効済みとして拒否する。

問いかけと本文は動作種別で切り替える。専用・標準の選択ダイアログでは、問いかけの直後に継続承認の範囲を示す。作成では `Turn and session approvals apply to session creation only.`、送信では `Turn and session approvals apply to message sending only.` と表示する。

| 動作 | 問いかけ | 本文のフィールド |
| --- | --- | --- |
| 新規作成 | `Allow creating a new main-agent session?` | `message`、`cwd`（指定時のみ） |
| 送信 | `Allow sending a message to another session?` | `message`、`session-id`、`wait`（指定時のみ） |

本文には表の順に、`message` は改行を保持した全文、`cwd` は解決後の絶対パス、`wait` は秒数で示す。

### TUIの専用ダイアログ

通常表示・全画面表示のどちらでも、承認中は背景の会話を隠す全画面ダイアログを表示する。外枠を付け、上部の問いかけ、中央の本文、下部の4選択肢を横罫線で区切る。本文の各フィールドは、左右位置・幅を揃えた独立した枠に表示し、枠の間に空行を1行置く。各フィールド名は枠の上辺に `┌─ message ───┐` のように埋め込み、枠内は値だけを表示する。狭幅では上辺のフィールド名を表示幅内で切り詰める。問いかけと選択肢は固定し、表示領域を超える本文だけをセルの境界も含めてスクロールして末尾まで参照できる。端末サイズが変わると本文を折り返し直し、表示領域を合わせる。

本文内のLF以外のC0・C1制御文字とDELは、端末制御として解釈されない `\xHH` 形式の可視文字列で示す。LFによる改行・空行を保持し、実行に渡す `message` は原文を保持する。

| キー | 動作 |
| --- | --- |
| `↑` / `↓` | 選択肢を前 / 次へ移動する |
| `Tab` / `Shift+Tab` | 選択肢を次 / 前へ移動する |
| マウスホイール | 本文を3表示行ずつスクロールする。SGR mouse に対応した端末でのみ機能し、非対応の端末では `PageUp` / `PageDown` を使う |
| `PageUp` / `PageDown` | 本文を1ページずつスクロールする |
| `Enter` | 選択中の回答を確定する |
| `Esc` | ダイアログを閉じ、拒否として扱う |

通常表示では、ダイアログの表示中だけ SGR mouse tracking を有効化し、確定・拒否・中断で解除する。全画面表示では、表示中のUIが mouse reporting を管理するため、本ダイアログは有効化・解除しない。

### TUI以外のUI

RPC等では標準の選択ダイアログを使い、問いかけに続けて本文の各フィールドを `名前: 値` の形式で渡す。確認ダイアログへ置き換える場合も本文の全文を渡す。表示領域を超える内容は、そのUIの標準ダイアログの表示に従う。

## turn承認の失効

turnは、次のユーザーメッセージを受け付けるまでの期間である。

| イベント | turn承認の扱い |
| --- | --- |
| `input`（対話入力・RPC・拡張からの入力） | 失効する |
| ユーザーの `message_start` | 失効する |
| assistant・toolResultの `message_start`、turn・ツールの往復 | 維持する |
| セッションの置換（`/new`・`/resume` 等）・reload | 拡張ランタイムの再生成に伴って失効する |

session承認も同じ置換・reloadで失効する。履歴からはどちらの承認も復元しない。

## コマンドの実行構成

登録済みbashツールの権限確認・sandbox・中断・出力上限はそのまま適用される。承認の拒否・キャンセル・中断では、コマンドを実行しない。

通常の対話起動と同じ専用サーバーを利用する。専用管理先・設定の契約は [pi-mux の仕様](../../../../.local/cli.exact/pi-mux/SPEC.md) に従う。作成時は必要に応じて専用サーバーを起動する。送信時は稼働中の専用サーバーを使う。どちらも通常の tmux のソケット・設定・稼働状態には作用しない。`TMUX`・`TMUX_TMPDIR` によって解決先を変更しない。

両動作とも、登録済みbashからlogin shell（`bash -lc`）でPATHを読み込み、専用管理先のruntimeディレクトリを `XDG_RUNTIME_DIR` に明示して共通CLIを実行する。各引数はquoteして渡し、`message`・`session-id` の空白・引用符・改行を保持する。

作成では、親pi の会話情報（`PI_SESSION_ID` 等）を unset してから、入力で定まる作業ディレクトリで共通CLIの独立新規起動を実行する。初期依頼は1つの位置引数として渡す。新しいpi はPATH上で解決され、標準の設定探索（`~/.pi/agent/`・プロジェクト設定）で起動する。親pi の会話情報と固定ID指定を除き、新しいPTYの `TERM`・`TMUX`・`TMUX_PANE` を保持する。専用管理先のruntimeディレクトリを使い、paneの起動PIDとpi のPIDを一致させる。

送信では、親の会話情報を unset せずそのまま保持する。送信側の識別はCLIが `PI_SESSION_ID` 環境変数から埋めるためであり、未設定のときはCLIが `external` と識別する。cwdの変更は行わない。

新しいmainセッションは、呼び出し元の履歴・許可・承認を引き継がず、親の保存会話を再開・forkしない。初期依頼は新しいmainで1回だけ開始する。ウィンドウはtmuxサーバーの配下で動き、呼び出し元のpiプロセスやsandboxの寿命と無関係に存続する。接続クライアントの切断後も同じpiプロセス・pane・PTYで処理を継続する。

## guardrail との二重確認

`agent` のbash実行は guardrail のコマンド判定も受ける。標準の `guardrails.yaml` では共通CLIのコマンドはデフォルトルール（`.*` allow）で許可されるため、通常は本拡張の確認だけが表示される。ユーザーが `guardrails.yaml` のコマンドルールを変更し、共通CLIのコマンドが確認対象になった場合は、本拡張の承認に加えてguardrailの確認ダイアログが表示される。この二重確認は緩和・迂回せず、そのまま残す。
