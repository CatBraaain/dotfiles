# newagentツールSpec

`newagent` ツールで、ユーザーが対話を引き継ぐ独立した標準mainセッションを会話ごとのtmux sessionとして作成し、初期依頼を即実行する。作成先は標準設定・標準権限のmainであり、呼び出し元セッションとの会話継続・結果待ち・成果回収は行わない。対象読者は、この拡張を保守・変更する人である。

## ツールの入力

| パラメータ | 必須 | 内容 |
| --- | --- | --- |
| `prompt` | 必須 | 新セッションで即実行する初期依頼。前後の空白を除いて空であってはならない |
| `cwd` | 省略可 | 新セッションの作業ディレクトリ。省略時は呼び出し時の `ctx.cwd`。相対パスは呼び出し時の `ctx.cwd` 基準で絶対パスへ解決する |

`prompt`・`cwd` のいずれかにNUL文字を含む呼び出し、空白のみの `prompt` はツールエラーになる。初期依頼の位置引数の規則は [pi-mux の仕様](../../../../.local/cli.exact/pi-mux/SPEC.md#new) に従う。

## 呼び出し元の制限

`newagent` はmain agentだけが呼び出せる。次の2段階で制限する。

| 層 | 動作 |
| --- | --- |
| `~/.agents/config/agents.yaml` | main 以外の全agentの `tools` から `!newagent` で除外する |
| 拡張の実行時ゲート | 環境変数 `PI_AGENT_NAME` が `main` でない呼び出し（未設定を含む）をツールエラーにする |

実行時ゲートは `PI_AGENT_NAME` を agents拡張が設定することを前提とする。agents拡張の負う名前の正本は [agent管理の仕様](agent-management.spec.md#概要)が定める。

## 承認

`newagent` の実行は、1回のユーザー確認を必要とする。選択肢は次の4つである。

| 選択肢 | 効果 |
| --- | --- |
| `Allow once` | その呼び出しだけを許可する。次の呼び出しは再度確認する |
| `Allow in this turn` | 次のユーザーメッセージを受け付けるまでの間、確認を省略する |
| `Allow in this session` | このセッションの残りの間、確認を省略する |
| `No, deny (reason next)` | 実行しない。続けて任意の理由を入力できる |

- 承認の単位はツール全体であり、`prompt`・`cwd` の内容によらない。有効なsession・turn承認がある間は、入力が変わっても再確認しない。
- 選択肢の文言と有効期間の意味は guardrail拡張の選択ダイアログに合わせる。承認のstateは本拡張の中だけで管理し、guardrailのコマンド承認・パス許可とは独立に保持・失効する。
- 選択ダイアログのキャンセルは拒否として扱う。拒否時の理由入力は任意で、空欄・キャンセルは理由なしとして扱う。拒否はエラーとして呼び出し元に返し、以降の呼び出しには影響しない。
- 選択ダイアログを提供できないUIでは確認ダイアログ（`confirm`）に置き換え、承認は `Allow once` 相当として扱う。理由入力はテキスト入力ダイアログを提供できる場合のみ行う。
- UIを持たない環境では承認できず、ツールエラーとして失敗する（fail-closed）。
- ダイアログの表示中にturn承認が失効した場合、その回答は失効済みとして拒否する。

問いかけは `Allow creating a new main-agent session?` とする。本文に初期依頼を改行を保持した全文で示し、`cwd` が指定されていれば作業ディレクトリも示す。

### TUIの専用ダイアログ

通常表示・全画面表示のどちらでも、承認中は背景の会話を隠す全画面ダイアログを表示する。外枠を付け、上部の問いかけ、中央の本文、下部の4選択肢を横罫線で区切る。本文の `prompt` と `cwd` は、左右位置・幅を揃えた独立した枠に表示し、枠の間に空行を1行置く。各フィールド名は枠の上辺に `┌─ prompt ───┐`・`┌─ cwd ───┐` のように埋め込み、枠内は値だけを表示する。狭幅では上辺のフィールド名を表示幅内で切り詰める。`cwd` 省略時は `prompt` の枠だけを表示する。問いかけと選択肢は固定し、表示領域を超える本文だけをセルの境界も含めてスクロールして末尾まで参照できる。端末サイズが変わると本文を折り返し直し、表示領域を合わせる。

本文内のLF以外のC0・C1制御文字とDELは、端末制御として解釈されない `\xHH` 形式の可視文字列で示す。LFによる改行・空行を保持し、実行に渡す初期依頼は原文を保持する。

| キー | 動作 |
| --- | --- |
| `↑` / `↓` | 選択肢を前 / 次へ移動する |
| `Tab` / `Shift+Tab` | 選択肢を次 / 前へ移動する |
| マウスホイール | 本文を3表示行ずつスクロールする。SGR mouse に対応した端末でのみ機能し、非対応の端末では `PageUp` / `PageDown` を使う |
| `PageUp` / `PageDown` | 本文を1ページずつスクロールする |
| `Enter` | 選択中の回答を確定する |
| `Esc` | ダイアログを閉じ、拒否として扱う |

通常表示では、ダイアログの表示中だけ SGR mouse tracking を有効化し、確定・拒否・中断で解除する。全画面表示では、表示中のUIが mouse reporting を管理するため、本ダイアログは有効化・解除しない。

### TUI以外のUI

RPC等では標準の選択ダイアログを使い、問いかけに続けて `prompt: <初期依頼>` を全文で渡し、`cwd` 指定時は `cwd: <作業ディレクトリ>` の行を付ける。確認ダイアログへ置き換える場合も本文の全文を渡す。表示領域を超える内容は、そのUIの標準ダイアログの表示に従う。

## turn承認の失効

turnは、次のユーザーメッセージを受け付けるまでの期間である。

| イベント | turn承認の扱い |
| --- | --- |
| `input`（対話入力・RPC・拡張からの入力） | 失効する |
| ユーザーの `message_start` | 失効する |
| assistant・toolResultの `message_start`、turn・ツールの往復 | 維持する |
| セッションの置換（`/new`・`/resume` 等）・reload | 拡張ランタイムの再生成に伴って失効する |

session承認も同じ置換・reloadで失効する。履歴からはどちらの承認も復元しない。

## tmuxの構成

`newagent` は、承認後に呼び出し時点で登録されているbashツールを1回だけ呼ぶ。bashツールの権限確認・sandbox・中断・出力上限をそのまま適用する。承認の拒否・キャンセル・中断では、作成コマンドを実行しない。

通常の対話起動と同じ専用サーバーを利用する。専用管理先・設定の契約は [pi-mux の仕様](../../../../.local/cli.exact/pi-mux/SPEC.md) に従う。サーバーが未起動でも必要時に自動起動し、通常tmux のソケット・設定・稼働状態へ作用しない。`TMUX`・`TMUX_TMPDIR` によって作成先を変更しない。

| 条件 | 作成結果 |
| --- | --- |
| 作成する | `pi-mux new --detached <initial-request>` を呼ぶ。sessionとwindowの命名はCLIに任せる |
| 作成が成功 | `created` を返し、CLIの出力を本文に含めて会話IDとその会話への接続コマンドを示す |
| bashが拒否・失敗、またはtmuxコマンドが非0で終了 | `error` とエラー内容を返す |

構造化結果は `status`（`created`・`denied`・`error`）と、拒否・失敗時の `error` を持つ。作成先のwindow名は返さない。

作成はdetachedで行う。呼び出し元や他の端末への自動attach・画面表示は行わない。成功結果は会話ID・piプロセス・paneを確認した作成受付を示し、全拡張の初期化完了や初期依頼の完了は待たない。初期依頼のCLI入力処理は [pi-mux の仕様](../../../../.local/cli.exact/pi-mux/SPEC.md) に従う。

## ウィンドウで実行するコマンド

登録済みbashからlogin shellでPATHを読み込み、指定cwdで共通CLIの独立新規起動を実行する。初期依頼は1つの位置引数として渡し、cwd・初期依頼の空白・引用符・改行を保持する。

新しいpi はPATH上で解決され、標準の設定探索（`~/.pi/agent/`・プロジェクト設定）で起動する。親pi の会話情報と固定ID指定を除き、新しいPTYの `TERM`・`TMUX`・`TMUX_PANE` を保持する。専用管理先のruntimeディレクトリを使い、paneの起動PIDとpi のPIDを一致させる。

新しいmainセッションは、呼び出し元の履歴・許可・承認を引き継がず、親の保存会話を再開・forkしない。初期依頼は新しいmainで1回だけ開始する。ウィンドウはtmuxサーバーの配下で動き、呼び出し元のpiプロセスやsandboxの寿命と無関係に存続する。接続クライアントの切断後も同じpiプロセス・pane・PTYで処理を継続する。

## guardrail との二重確認

`newagent` のbash実行は guardrail のコマンド判定も受ける。標準の `guardrails.yaml` では共通CLIのコマンドはデフォルトルール（`.*` allow）で許可されるため、通常は本拡張の確認だけが表示される。ユーザーが `guardrails.yaml` のコマンドルールを変更し、共通CLIのコマンドが確認対象になった場合は、本拡張の承認に加えてguardrailの確認ダイアログが表示される。この二重確認は緩和・迂回せず、そのまま残す。
