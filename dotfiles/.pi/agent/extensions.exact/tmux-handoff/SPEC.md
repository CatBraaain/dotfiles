# tmux-handoff の振る舞い

この文書は、グローバルpi拡張 `tmux-handoff` と pi専用tmuxサーバーの観測可能な契約を定める。読者は、起動・再接続・外部連携を利用する人と、実装・保守を行う開発者・agent である。課題・目的・重要な制約の正本は [REQUIREMENTS.md](REQUIREMENTS.md) とする。

起動元は、利用者の端末で開始した対話pi を指す。backend は、専用tmux の pane 内で動作する対話pi を指す。接続クライアントは backend の PTY を表示・操作するtmuxクライアントを指す。

## 起動の適用条件

| 起動条件 | 結果 |
| --- | --- |
| 公式CLI、TUIモード、標準入力と標準出力が実TTY、startup、専用管理外 | 専用tmux へ引き渡し、起動元端末を接続クライアントにする |
| 公式CLI、TUIモード、実TTY、専用管理下 | 現在の pane で対話を継続し、接続recordを公開する |
| print・RPC・JSON・標準入出力のリダイレクト・SDK | 元の起動を維持する |
| 管理外での `/reload`・会話の置換 | そのプロセスを維持する |

拡張が無効な起動には、pi標準の起動動作を適用する。対象環境は、このグローバル設定が配置される Linux とする。

## 引き渡しと失敗

| 状態・入力 | 操作 | 結果 |
| --- | --- | --- |
| 管理外の適用対象 | 起動 | 初期依頼の実行前に、解決済みの会話と起動条件を backend へ渡す。起動元のエージェントループは開始しない |
| 専用サーバーが未起動 | 引き渡し | 専用ソケット・専用設定で自動起動する |
| backend の起動が成立 | 接続 | 接続先を示し、同じ端末で backend の入力・表示・resize を利用できる |
| 接続クライアントが切断、または起動元端末が終了 | 処理中 | 同じ backend プロセス・pane・PTY で処理を継続する |
| backend が稼働中 | 再接続 | 保存会話を再実行せず、その backend の PTY へ戻る |
| 管理マーカーと実管理先が不一致 | 起動 | 端末のrawモード・画面制御を復元して非0で終了する |
| 専用先の準備・backend起動が失敗、または60秒以内に成立しない | 引き渡し | 作成途中の起動の終了・清掃を試み、端末を復元して非0で終了する。backend の終了を確認できない場合は、診断を出して仮保存の会話ファイルを保持する |
| backend成立後にクライアントへの置換・接続が失敗 | 接続 | 起動元で初期依頼を代替実行せず、非0で終了する。成立した backend と接続recordは保持する |

失敗時にも、起動元のエージェントループへ戻る動作はない。端末の復元には canonical入力・echo・alternate screen・bracketed paste の解除を含む。backend の通常終了後は、その接続recordを削除する。

## 引き継ぐ条件と入力

| 対象 | 引き継ぎ後の状態 |
| --- | --- |
| 実行環境 | 同じNode実行ファイル、Node起動オプション、pi実行ファイル、プロセスcwd、pi が解決した会話cwdを使用する |
| CLI条件 | 会話選択用引数を解決済み会話の指定へ置き換え、それ以外のオプション・値・順序・`--` 境界を保持する |
| 環境変数 | 起動元の環境を保持する。`TERM`・`TMUX`・`TMUX_PANE` は新しい実行PTYの値にする |
| 親piの会話情報 | 継承した `PI_SESSION_ID`・`PI_SESSION_FILE`・`PI_PROVIDER`・`PI_MODEL`・`PI_REASONING_LEVEL` を除く。shellツールには backend の現会話情報が提供される |
| 初期依頼 | backend で1回だけ実行する。複数のCLI初期メッセージは元と同じ順序・回数で処理する |
| `@file`・画像指定 | 元と同じcwd・指定で backend の初期入力として処理する |
| 編集中の文字入力 | backend のエディタに復元する。復元だけでは送信しない |

引き渡し中に用いる環境を含むデータは、所有者だけがアクセスできるディレクトリ・ファイルに保持し、backend が受け取った時点で削除する。通常ログ・接続recordには環境変数や初期依頼を含めない。

## 会話の選択と保存

| 起動元で解決された会話 | backend の状態 |
| --- | --- |
| 既存の保存会話、`--continue`、`--resume`、既存ID指定 | 同じ会話ID・保存ファイル・保存先・名前を使う。選択画面や他ディレクトリからの選択確認を繰り返さない |
| `--fork` | 起動元で作成済みのfork結果を開く。再forkせず、fork後の会話ID・親情報・名前を保持する |
| 新規会話・新規ID指定 | 起動元の会話ID・保存先・名前を保持する。入力前には会話ファイルを作らない。ファイル名の時刻部分は backend の起動時刻になり得る |
| 存在しないファイルを明示した `--session` | 指定ファイル・会話IDを保持するため、引き渡し時にヘッダーと初期設定を仮保存する。会話入力のないまま正常終了、または成立前の失敗で backend の終了を確認できた場合は、その仮保存を削除する |
| `--no-session` | 起動元の会話ID・名前を保持したメモリ内会話とする |

## 専用管理先

| 項目 | 契約 |
| --- | --- |
| 管理ディレクトリ | `${XDG_RUNTIME_DIR:-/run/user/<uid>}/pi-tmux`。所有者専用の `0700` |
| ソケット | 管理ディレクトリ内の `server.sock`。全操作で絶対パスの `-S` を使用する |
| 設定 | `~/.pi/agent/extensions/tmux-handoff/tmux.conf`。通常tmux の設定ファイルとは独立する |
| サーバーの寿命 | クライアントやpiセッションがなくても存続する |
| 対話起動の接続単位 | 起動ごとに独立したtmuxセッションを作る |
| 独立起動の共通入口 | 同じ `-S`・`-f` でtmuxの直接コマンドを実行できる。`new-session -d`・`new-window -d` は表示クライアントを作らない |
| 管理下の判定 | 実ソケット、サーバーPID、pane ID、pane のPTY、pane の起動PIDと現在のpi PIDが一致することを確認する |

`TMUX` の有無やマーカーだけでは管理下としない。任意の通常tmux内で開始した対象pi も、専用先へ引き渡す。backend の子プロセスとして開始した別pi は、親pane のPIDと一致しないため、独立した起動として扱う。

専用サーバーの起動・停止・接続は、通常tmux のソケット・設定・稼働状態へ作用しない。独立起動側は、新しいpi を pane の起動PIDとして実行し、親pi の会話情報と引き渡しマーカーを持ち込まない。

## 接続record

外部の読み手は、管理ディレクトリ内の `instances/<instanceId>.json` を列挙し、`sessionId` で現在の接続先を探せる。同じ会話を複数プロセスで開いた場合は、instanceごとに別recordを保持する。会話の置換・reloadでは、古い対応を削除して現在の対応を公開する。切断だけでは削除しない。

| フィールド | 型・内容 |
| --- | --- |
| `version` | `1` |
| `instanceId` | 実行instanceのUUID |
| `sessionId` | pi の会話ID |
| `sessionFile` | 会話ファイルの絶対パス。メモリ内会話は `null` |
| `socketPath` | 専用ソケットの絶対パス |
| `serverPid` | tmuxサーバーPID |
| `tmuxSessionId` | `$` で始まるtmuxセッションID |
| `sessionName` | tmuxセッション名 |
| `windowId` | `@` で始まるtmuxウィンドウID |
| `paneId` | `%` で始まるtmux pane ID |
| `tty` | 実行PTYの絶対パス |
| `pid` | backend のPID |
| `pidStartTime` | Linux `/proc/<pid>/stat` の起動時刻ticks。PID再利用の識別用 |

recordの公開はファイル単位で原子的に行い、権限を `0600` とする。強制killやクラッシュで残るrecordはあり得るため、読み手は記載されたPID・起動時刻・ソケット・pane・PTYを照合してから接続する。接続には `tmux -S <socketPath> attach-session -t <tmuxSessionId>` を使う。

## tmux-serverユーザーサービス

`tmux-server.service` は同じ専用先を起動する。`Type=oneshot`・`RemainAfterExit=yes` とし、`start-server` は既に存在する専用サーバーも受け入れる。サービスの稼働表示は、各piセッションの存否を表さない。

サービスの停止は専用サーバーとその配下のpiを終了する。runtimeディレクトリはサービス停止で削除しない。通常起動の自動引き渡しは、サービスが事前に開始されていない場合も成立する。
