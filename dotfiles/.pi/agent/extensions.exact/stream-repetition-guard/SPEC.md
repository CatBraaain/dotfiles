# stream-repetition-guard

pi のモデル出力に含まれる連続反復を検知し、現在の agent 実行を中断する拡張。利用者と実装担当者が、検知条件・停止結果・適用境界をこの文書で確認する。

## 適用範囲と入力

拡張を読み込んだ main と subagent の各セッションで、assistant の生成中の出力を監視する。本文、thinking、ツール引数を対象とし、1つの応答内の各 content block（本文区間・thinking 区間・個別ツール呼び出し）を独立して扱う。

| 入力 | 監視する文字列 |
| --- | --- |
| 本文 | 生成中に受信した本文の文字列 |
| thinking | 生成中に受信した thinking の文字列。表示を隠していても対象 |
| ツール引数 | 生成中に受信した、シリアライズ済み引数の文字列。JSON の復号前の表記を対象とする |

ユーザー入力、ツールの実行結果、過去の履歴は検査入力に含めない。プロバイダーから文字列として公開されない reasoning や署名データも含めない。

## 文字と連続反復

文字数は Unicode コードポイント数とする。空白・改行・大文字小文字を含め、受信した表記の完全一致を比較する。Unicode 正規化や空白除去は行わない。例えば、ツール引数内の文字列 `\u3042` は、復号後の「あ」ではなく、受信表記の6文字として数える。

同じ block の出力は受信片の境界を越えて連続する。サロゲートペアが受信片の境界で分かれても1文字として数える。block 終端まで対にならなかったサロゲートは1文字として扱う。別の block・応答・セッションの文字列は連結しない。

「周期」は繰り返される文字列1つ分の長さ、「回数」はその文字列が途切れずに並んだ完全なコピー数、「反復文字数」は周期と回数の積を指す。通常の文章の後など、block 内の任意の位置から始まる反復を対象にする。

## 検知条件

以下の条件をすべて満たす連続反復を検知する。値は固定とする。

| 項目 | 条件 |
| --- | --- |
| 周期 | 1〜500文字（両端を含む） |
| 回数 | 10回以上 |
| 反復文字数 | 1,000文字以上 |

受信順で最初に条件が成立した文字位置で検知する。同じ位置で複数の周期が条件を満たしたときは、そのうち最も短い周期を検知理由に記録する。判定は表の範囲の完全一致に限る。より長い周期や言い換えを含む出力でも、その一部分がこの条件を満たせば検知する。

| 周期の例 | 最初に成立する回数 | 反復文字数 |
| --- | --- | --- |
| 1文字 | 1,000回 | 1,000文字 |
| 16文字 | 63回 | 1,008文字 |
| 20文字 | 50回 | 1,000文字 |
| 100文字 | 10回 | 1,000文字 |
| 500文字 | 10回 | 5,000文字 |

各例の文字列は、表の周期より短い周期を持たないものとする。

## 受信と停止

| 状態・入力 | 処理 | 観測可能な結果 |
| --- | --- | --- |
| 条件を満たさない出力 | 監視を続ける | 通常の生成を継続する。経過時間・総出力量だけでは停止しない |
| 同じ block の出力が複数の受信片に分かれる | 連続した文字列として判定する | 受信片の分け方によらず検知の有無・成立位置・周期・回数が一致する |
| 1つの受信片の途中で条件が成立し、その後に別の文字が続く | 成立した反復を検知する | 受信片の末尾が反復でなくても停止対象になる |
| 本文・thinking・ツール引数のいずれかで条件が成立する | pi の中断機構で現在の agent 実行を中断する | 停止状態は `aborted`。停止理由を記録し、その実行の未開始のツール呼び出しを実行しない |
| 検知済みの実行へ遅れて出力・終了通知が届く | 中断状態を維持する | 中断要求と検知記録はその実行について1回だけ。自動再試行・自動継続を起動しない |
| 利用者または呼び出し元が新しい実行を開始する | 新しい出力として監視を始める | 前回の文字列・中断状態を持ち越さない |

中断前に受信・表示した内容は保持する。検知した受信片のうち成立位置より後の文字や、中断要求前に送信済みの内容が表示される場合がある。実行済みのツールの副作用は巻き戻さない。

## 停止理由

検知したセッションの履歴に、識別名 `stream-repetition-guard` と、次の情報を記録する。

- 対象 block の種別（`text` / `thinking` / `toolcall`）と、その応答内の block 番号（0始まり）
- 周期の文字数、完全な反復回数、反復文字数
- block 内の成立位置（先頭から受信した文字数、1始まり）
- 反復検知により中断したことを示す理由

記録は履歴上で対象の assistant 応答と対応を追えるものとする。検知記録に本文・thinking・ツール引数の生の内容を複製しない。

中断された assistant 応答のエラー説明にも、識別名・block 種別・周期・回数・反復文字数を含む理由を付ける。対話画面で理由を確認でき、subagent の場合は呼び出し元の結果からも理由を確認できる。理由の付与によって停止状態を `error` へ変更しない。

## 運用上の境界

この拡張は反復条件だけで停止を判断する。既存の無通信タイムアウトや利用者の手動中断は、それぞれ従来の条件で動作する。

正常なテストデータや引用でも検知条件を満たせば中断する。条件に例外を設けず、利用者が必要性を判断して次の実行を開始する。
