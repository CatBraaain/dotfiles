# session-gc 拡張機能 Spec

pi 起動時に、古いセッションファイルを各プロジェクトの `archive/` へ退避し、`pi -r` / `/resume` のセッション一覧ロードを軽く保つ。

## 背景

セッション一覧は、一覧対象の各 JSONL を先頭から最後までパースして全文検索用テキストを組み立てる。そのため一覧対象のファイル数と合計サイズがロード時間にほぼ比例して効く。古いセッションを一覧の走査対象から外すことで起動時のロードを速くする。

## 実行条件

`session_start` イベントの `reason` によって、GC を実行するかどうかが決まる。

| `session_start.reason` | GC を実行するか |
| ---------------------- | --------------- |
| `startup`              | する            |
| `reload`               | しない          |
| `new`                  | しない          |
| `resume`               | しない          |
| `fork`                 | しない          |

`reload` / `new` / `resume` / `fork` では何もせず、実行時刻も記録しない。

## 頻度制限（throttle）

最後に GC を実行してから 24 時間が経過していないときは、GC を実行しない。実行時刻は `~/.pi/agent/.session-gc-timestamp` に Unix ミリ秒で記録する。

## 退避ルール

| 項目 | 内容 |
| --- | --- |
| 対象 | `~/.pi/agent/sessions/` 直下の各プロジェクトディレクトリ（全プロジェクト） |
| 対象ファイル | 各プロジェクトディレクトリ直下の `.jsonl` のみ。`subagents/`・`archive/` などサブディレクトリ内は対象外 |
| 残すもの | mtime 降順で直近 200 件（`KEEP_COUNT`） |
| 退避先 | 同プロジェクトディレクトリ内の `archive/` へ mv（`archive/` は無ければ作成） |
| 保護ルール | なし。実行中セッションは mtime が新しいため、mtime 降順の上位 200 件に必然的に含まれる |
| named セッション | 保護しない（判定しない） |

退避したセッションは `pi -r` の一覧と `pi --session <部分ID>` / `--fork <部分ID>` の検索から外れる。開くには `pi --session <フルパス>` を使う。deja-vu など再帰検索ツールからは引き続き見える。

## 実行方法

GC は起動の初期化をブロックしない。`session_start` ハンドラは即座に返り、`setTimeout` で切り離して実行する。

| 項目 | 内容 |
| --- | --- |
| 対象収集 | `readdir` + `stat`（mtime 比較） |
| 退避 | 同一ファイルシステム内の `rename` |
| 個別失敗 | 対象 1 件の mv 失敗は握りつぶし、残りを続行する（失敗しても元ファイルは残る） |
| 実行時刻の記録 | GC 実行のたびに書き込む（退避 0 件でも記録する） |

## 通知

退避件数が 1 以上で、UI があるとき（`ctx.hasUI`）に `session-gc: archived N old sessions to archive/` を info で通知する。0 件のときは通知しない。

## スコープ外（やらないこと）

- `archive/` の削除・圧縮はしない。
- keep 件数（200）の設定化はしない。
- named セッションの保護はしない。
