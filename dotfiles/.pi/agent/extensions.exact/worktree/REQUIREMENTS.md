# Session worktreeメタデータの要件

本書は、pi セッションが作業に使う Git worktree の関連を記録し、外部ツールへ供給する拡張の課題・目的・重要な制約を定める。読者は拡張の保守者と、連携するエージェント管理ツールの開発者である。

## 課題と目的

同じリポジトリを複数のセッションで扱うとき、既存の worktree を共有すると、別セッションの作業内容を変更したり、レビュー対象を取り違えたりする。エージェントは Git でセッションごとに専用の作業先を作り、外部ツールはどの作業先が選択セッションの担当かを識別できるようにする。別セッションの作業を引き継ぐ場合は、新しい作業先へファイルをコピーし、元の worktree は編集しない。

## 期待する成果

- 登録済み Bash ツールでの Git worktree の作成を自動で記録する。Windows ネイティブの pi では、有効な PowerShell ツールから場所と対象を直接指定した操作も記録する。1セッションで複数の worktree を担当でき、新しい作業先の追加で既存の担当を失わない。担当 worktree の移動・削除にも追従する。
- 外部ツールはセッションの JSONL から、そのセッションが担当する worktree を特定できる。同じセッションを再開すると担当を維持し、fork した新しいセッションには元の担当を引き継がない。
- SCM では、選択セッションが属するリポジトリの main worktree と、そのセッションが担当する現存 worktree だけを表示する。

## 重要な制約

- pi 本体を変更せず、拡張として実現する。
- 更新する関連は操作を実行したセッションのものに限る。メタデータは担当を示すものであり、作業先への書き込み権限は別の設定で管理する。
- pi のメモリ上とセッションファイル上で関連データを整合させる。保存には標準の custom エントリ追記 API を使い、既存のセッションヘッダーと履歴を保持する。旧書式の記録は移行せず、担当の根拠にも使わない。
