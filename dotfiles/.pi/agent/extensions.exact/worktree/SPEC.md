# Session worktreeメタデータ仕様

本書は、pi セッションが作業に使う Git worktree の関連を記録する `worktree` 拡張の入出力・状態・エラーを定める。読者は拡張の保守者と、セッションファイルを読む外部ツールの開発者である。目的と重要制約は [REQUIREMENTS.md](./REQUIREMENTS.md) に従う。保存形式は pi の標準 [CustomEntry](https://github.com/earendil-works/pi/blob/v1.5.0/packages/coding-agent/docs/session-format.md#customentry) を使う。

## 記録形式と保存

Bash 操作への自動追従で得た担当 worktree の一覧を、`type: "custom"`、`customType: "session-worktree-metadata"` のエントリに保存する。`data` は `{ sessionId: string, workspaces: string[] }` とし、`sessionId` には操作を実行した pi セッションの ID を記録する。記録時点の `workspaces` の各要素は、現存する Git worktree ルートを実体パスへ正規化した絶対パスとする。重複は持たず、登録順を保つ。同一 Bash 呼び出しで複数の `add` が残った場合、新規登録分は操作後に観測した Git worktree 一覧の順に追加する。担当がなくなった場合の `[]` も有効なスナップショットとする。

```json
{
  "type": "custom",
  "customType": "session-worktree-metadata",
  "id": "entry-id",
  "parentId": "previous-entry-id",
  "timestamp": "2026-11-09T00:00:00.000Z",
  "data": {
    "sessionId": "session-id",
    "workspaces": ["/worktrees/app/feature"]
  }
}
```

外部ツールと拡張は、上記の型と `customType` を持ち、`data.sessionId` がセッションヘッダーの `id` と一致するエントリのうち、追記順で最後の1件を採用する。末尾の行、タイムスタンプ、現在の会話分岐だけでは判定しない。別 ID の記録、所有者 ID のない旧書式、および旧書式の別種のエントリは読み飛ばし、書き換えない。一致する記録がなければ空の一覧とする。一致する最後のエントリの `workspaces` が `string[]` でない場合、空文字列・相対パス・NUL を含む文字列がある場合、またはパスが重複する場合は読み取りエラーとし、以前の記録には戻らない。

同じセッションを再開してもヘッダーの ID は変わらないため、担当を維持する。fork 先のヘッダーには新しい ID が付くため、コピーされた元セッションの記録は採用しない。

| 条件 | 更新結果 |
| --- | --- |
| 更新後の一覧が現在値と異なる | 標準の custom エントリ追記 API でスナップショットを1件追記する。既存のセッションヘッダーと履歴本文を保持する |
| 更新後の一覧が現在値と同じ | スナップショットを追記しない |
| セッションが初回保存前 | 標準 API が受け付けたスナップショットを、pi の通常の初回保存に含める |
| ファイル保存を使わないセッション | 同じ標準 API でメモリ上のスナップショットを更新する |
| 標準 API が失敗する | 更新を失敗として扱い、成功結果や成功通知を返さない |
| 非同期処理中にセッションが切り替わる | その処理による更新と通知を取りやめる |

更新成功は標準 API の正常受付を意味し、独自のディスク保存済み保証を加えない。一覧はセッション全体の関連を表し、会話内の分岐移動では変化しない。自動更新では既存の登録先も確認し、現存しない worktree を一覧から取り除く。更新先は呼び出し元のセッションに限る。

## Bash操作への自動追従

登録済み Bash ツールの呼び出しに現れる通常の `git worktree add`・`git worktree move`・`git worktree remove` を扱う。`git -C <path>` と `cd <path> && git ...` による操作場所の指定、空白を含む引用パス、同一コマンド内の複数操作、別ツールからの入れ子呼び出しにも追従する。パスは Bash の通常の引数として解釈し、先頭の `@` と、引用またはエスケープされた `~/` は文字通り扱う。パスの位置に現れる空の語（空の引用引数や変数に由来するもの）は監視対象から外し、`-C` のオペランドが空の語のときはその `git` 呼び出しを監視しない。

| 操作前後の Git worktree一覧 | 関連データの更新 |
| --- | --- |
| `add` により新しい worktree が残った | 既存の現存担当を保持し、そのパスを末尾へ追加する |
| `move` により登録済み worktree のパスが変わった | 元の位置で新しいパスへ置換する |
| `remove` により登録済み worktree がなくなった | その関連を解除する |
| 操作が失敗・未実行であり、一覧に変化がない | その操作を成功したものとして登録・置換・解除しない |
| 操作後の別コマンドが失敗したが、worktree操作の変化が残った | 残った変化を反映する |
| 作成後に同じコマンド内で削除され、最終状態に残らない | そのパスを登録しない |

追従の判断には、コマンドで指定された対象と、呼び出し中に観測した Git の実状態を使う。同時期に別の操作が作成した、指定対象でない worktree は登録しない。

## SCM の表示対象と書き込み権限

SCM でセッションを選択すると、そのセッションが属するリポジトリの main worktree と、採用した一覧に含まれる同じリポジトリの現存 worktree だけを表示する。開始 `cwd` が linked worktree 内にある場合も、開始位置そのものは担当の根拠にしない。担当がない場合は、そのリポジトリの main worktree だけを表示する。

メタデータの記録・読み取りや SCM の選択は、書き込み権限を付与・変更しない。Bash 操作の権限は [Guardrails の設定](../guardrails/SPEC.md) に従う。

## 自動更新の通知

| 結果 | モデルへの通知 | TUI表示 |
| --- | --- | --- |
| 一覧が変わり、標準 API がスナップショットを受け付けた | 別の `custom_message` で更新済みの事実・追加/置換/解除内容・現在の `workspaces` を伝える | 変更件数を含む短い表示。展開すると通知本文を読める |
| 一覧が変わらない | 更新通知を出さない | 更新通知を出さない |
| コマンドの解析が失敗する | 通知を出さず、そのコマンドの追跡をスキップする | 失敗表示を出さない |
| Git 照会・スナップショットの読み取り・標準 API の追記が失敗した | 別の `custom_message` で更新失敗と理由を伝える | 短い失敗表示 |

通知のcustomTypeは `session-worktrees` とする。モデル向けの情報は `content` に含め、`details` はTUI表示用に使う。更新通知は再登録を求めず、Bash の返値・本文・エラーフラグを変更しない。`display: true`、`deliverAs: "steer"`、`triggerTurn` 省略により、実行中のモデルには次の応答までに通知を渡し、待機中のセッションでは通知だけを保存してモデルの応答を開始しない。
