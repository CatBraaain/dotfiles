# Session worktreeメタデータ仕様

本書は、pi の session が作業に使う Git worktree を管理し、その関連を記録する `worktree` 拡張の入出力・状態・エラーを定める。読者は拡張の保守者と、session ファイルを読む外部ツールの開発者である。目的と重要制約は [REQUIREMENTS.md](./REQUIREMENTS.md) に従う。保存形式は pi の標準 [CustomEntry](https://github.com/earendil-works/pi/blob/v1.5.0/packages/coding-agent/docs/session-format.md#customentry) を使う。

## 記録形式と保存

Bash 操作への自動追従で得た一覧を、`customType: "session-worktree-metadata"` の `data.workspaces: string[]` にsnapshotとして記録する。利用宣言とは別の一覧であり、書き込み許可や SCM 表示の根拠にしない。各要素は現存する Git worktree ルートの絶対パスであり、実体パスへ正規化する。重複は持たず、登録順を保つ。同一Bash呼び出しで複数の `add` が残った場合、新規登録分は操作後に観測した Git worktree一覧の順に追加する。関連がなければ `[]` とする。

```json
{
  "type": "custom",
  "customType": "session-worktree-metadata",
  "id": "entry-id",
  "parentId": "previous-entry-id",
  "timestamp": "2026-11-09T00:00:00.000Z",
  "data": {
    "workspaces": ["/worktrees/app/feature"]
  }
}
```

外部ツールと拡張は、session全体のエントリを追記順に読み、`type: "custom"` かつ上記customTypeである最後のエントリを現在値として採用する。末尾の行、timestamp、現在の会話分岐だけでは判定しない。該当エントリがなければ空の一覧とする。最新snapshotのデータ型が不正、パスが相対パス・空・NULを含む、または重複する場合は読み取りエラーとする。

| 条件 | 更新結果 |
| --- | --- |
| 更新後の一覧が現在値と異なる | 標準customエントリ追記APIでsnapshotを1件追記する。既存の session header と履歴本文を保持する |
| 更新後の一覧が現在値と同じ | snapshotを追記しない |
| session が初回保存前 | 標準APIが受け付けたsnapshotを、pi の通常の初回保存に含める |
| ファイル保存を使わない session | 同じ標準APIでメモリ上のsnapshotを更新する |
| 標準APIが失敗する | 更新を失敗として扱い、成功結果や成功通知を返さない |
| 非同期処理中に session が切り替わる | その処理による更新と通知を取りやめる |

更新成功は標準APIの正常受付を意味し、独自のディスク保存済み保証を加えない。一覧は session全体の関連を表し、会話内の分岐移動では変化しない。自動更新では既存の登録先も確認し、現存しない worktree を一覧から取り除く。更新先は呼出sessionに限る。

## Bash操作への自動追従

自動追従は `session_worktree` とは別の記録経路である。登録された Bashツールの呼び出しに現れる通常の `git worktree add`・`move`・`remove` を扱う。`git -C <path>` と `cd <path> && git ...` による操作場所の指定、空白を含む引用パス、同一コマンド内の複数操作、別ツールからの nested呼び出しにも追従する。パスは Bash の通常の引数として解釈し、先頭の `@` と、引用またはエスケープされた `~/` は文字通り扱う。パスの位置に現れる空の語（空の引用引数や変数に由来するもの）は監視対象から外し、`-C` のオペランドが空の語のときはその `git` 呼び出しを監視しない。

| 操作前後の Git worktree一覧 | 関連データの更新 |
| --- | --- |
| `add` により新しい worktree が残った | そのパスを末尾へ登録する |
| `move` により登録済み worktree のパスが変わった | 元の位置で新しいパスへ置換する |
| `remove` により登録済み worktree がなくなった | その関連を解除する |
| 操作が失敗・未実行であり、一覧に変化がない | その操作を成功したものとして登録・置換・解除しない |
| 操作後の別コマンドが失敗したが、worktree操作の変化が残った | 残った変化を反映する |
| 作成後に同じコマンド内で削除され、最終状態に残らない | そのパスを登録しない |

追従の判断には、コマンドで指定された対象と、呼び出し中に観測した Git の実状態を使う。同時期に別の操作が作成した、指定対象でない worktree は登録しない。

## 管理ツール `session_worktree`

| 引数 | 入力 |
| --- | --- |
| `action` | 必須。`add`（作成または再利用して宣言）、`remove`（削除）のいずれか |
| `name` | 必須。`^[a-z0-9]+(?:-[a-z0-9]+)*$` に合う名前。パスや Git オプションは受け付けない |
| `project` | 任意。`~/projects` 直下にある Git リポジトリのディレクトリ名1つ |
| `discard` | `remove` のみ指定できる任意の真偽値。省略時は `false` |

### リポジトリと対象パス

`project` を省略すると、session の開始 `cwd` が属する Git リポジトリを選ぶ。指定した場合は `~/projects/<project>` の実体が `~/projects` 直下の Git リポジトリのルートであることを確認する。空文字列、パス、存在しない名前、Git リポジトリのルートでないディレクトリを指定した場合はエラーとし、開始 `cwd` にフォールバックしない。いずれの経路でも main worktree を特定できなければエラーとする。

対象パスは `~/.agents/worktrees/<選択したリポジトリの main worktree の basename>/<name>` とする。`agents-` または `copilot-` で始まる名前ではフォルダ名だけに `wt-` を付ける。変換後の名前との衝突を避けるため、`wt-agents-` または `wt-copilot-` で始まる入力名はエラーにする。

既存の対象は、管理範囲内の実ディレクトリで、選択したリポジトリの Git 登録と一致する現存サブworktree に限る。通常フォルダ、シンボリックリンクを経由する対象、別リポジトリの worktree、管理範囲外に解決される対象は変更しない。モデルから任意のパス・shell 本文を受け付けず、リポジトリ由来のコードに管理操作の権限を渡さない。

### 管理操作の書き込み保護

`add`・`remove` は、宣言先への書き込み許可とは別に、管理操作が変更・削除する範囲に Guardrails の明示的な `write` の `deny` と `credentials` の保護を適用する。対象パスだけでなく、変更・削除が及ぶ子孫と、変更する Git 共有メタデータも確認する。保護に抵触するか、変更・削除範囲または保護の適用を確認できない場合は、操作に着手せずエラーを返す。

専用 `add`・`remove` が対象の確認・変更に使う Git 操作はすべて登録済み Bash を通る。一般の書き込み許可がない場所や別 `project` でも、保護と対象の検証を満たせば、[Git の呼び出し単位の一時権限](../guardrails/SPEC.md#信頼済み拡張の単発実行)で書き込める。実際の Git コマンドに対する明示的な拒否は維持し、追加確認は出さない。親フォルダや Git 共有メタデータへの一般の書き込み許可を生じさせない。Git 構成を検証できない場合は、管理対象の変更を開始せずエラーを返す。

worktree 拡張が対象リポジトリを検証し、固定の Git 実行ファイル・引数・環境・作業ディレクトリと必要な書き込み範囲を決める。Linux ではシステム Git を使い、リポジトリを変更する管理処理には形式だけを反映した合成設定を渡す。worktree 削除では対象の親と Git 登録の更新領域を、ブランチ削除では参照ロックに必要な共有 Git 管理領域を一時的に書き込み可能にする。非 Linux は登録済み Bash の既存フォールバックを使い、実行前に対象と Git 設定を検証する。

### `add`

同じ session で別リポジトリの現存サブworktree が同じ名前で宣言済みの場合、または対象に対する書き込み許可の追加が Guardrails の保護に抵触する場合は、Git と宣言を変更せずエラーを返す。

| 条件 | 結果 |
| --- | --- |
| 対象パスに検証済みのサブworktree がある | 既存の作業内容とブランチを保持し、その絶対パスを宣言する。同じ対象を再度宣言しても宣言を重複させない |
| 対象パスも同名ローカルブランチも存在しない | 選択したリポジトリの main worktree の HEAD から同名ローカルブランチとサブworktree を作成し、作成先を宣言する |
| 対象パスに検証済みのサブworktree がなく、パスまたは同名ローカルブランチが存在する | 既存の内容を変更せずエラーを返す |

成功時は対象名、絶対パス、作成または再利用の区別、現在の宣言一覧を返す。

### `remove`

削除できるのは、選択したリポジトリで検証済みの管理サブworktree のうち、Git 登録上 `refs/heads/<name>` を checkout しているものと、そのローカルブランチだけとする。detached HEAD、別ブランチ、対応を検証できないものは、どちらのモードでも何も変更せずエラーを返す。main worktree、開始 `cwd` とその配下、および開始 `cwd` を含む worktree は削除しない。

| `discard` | 削除条件 |
| --- | --- |
| 省略または `false` | 対応ブランチの先端が main worktree の HEAD と同じコミットかその祖先であり、ステージ済み・未ステージの変更および未追跡項目（Git の無視対象を含む）が残っていない場合だけ削除する。条件を満たさない場合は worktree とブランチを両方保持してエラーを返す |
| `true` | マージ済み・変更なしを条件とせず、対象の作業内容ごと worktree と対応ブランチを強制削除する |

エージェントは [AGENTS.md の「Git Worktree Strategy」](../../../../.agents/AGENTS.md#git-worktree-strategy) に従って事前承認を得る。ツールは追加の確認ダイアログを出さない。

- finish：選択したリポジトリの main worktree で Bash の `git merge --ff-only refs/heads/<name>` を実行し、統合後に `discard` を省略するか `false` で `remove` を呼ぶ。
- discard：承認を得たら `discard: true` で `remove` を呼ぶ。

`git worktree list` で prunable な参照が残っていれば、従来どおり必要に応じて Bash で `git worktree prune` を実行する。

1. worktree の削除直前に、特定した実体・Git 登録・ブランチとその先端が一致し、選択したモードの削除条件と書き込み保護を満たすことを再確認する。不一致または確認不能なら何も変更せずエラーを返す。
2. worktree を削除する。削除に失敗した場合、または対象パスと Git 登録の両方の消失を確認できない場合は、ブランチの削除へ進まない。パスだけが消えて Git 登録が残った場合は、ブランチを保持し、[書き込み許可を失効](#宣言書き込み許可失敗時の結果)させて部分失敗を報告する。
3. ブランチの削除直前に、対象パスと Git 登録が引き続き存在しないこと、ブランチ参照が特定時と同じ先端を指し、他の worktree で checkout されていないこと、適用される統合条件と書き込み保護を満たすことを再確認する。条件を満たさないか確認できない場合は、参照を削除せず部分失敗を報告する。削除時点でも参照が確認済みコミットを指すことを条件とする。同じコミットを指す参照の再作成は区別しない。他の worktree での checkout や統合先の状態は直前の照合結果に基づき、別プロセスによる同時変更との一括処理までは保証しない。

成功時は対象名、絶対パス、削除したブランチ、現在の宣言一覧を返す。

### 宣言・書き込み許可・失敗時の結果

宣言一覧は `type: "custom"`、`customType: "session-worktree-declarations"`、`data.worktrees: { name: string, path: string }[]` として pi の標準 custom エントリ追記 API で保存する。内容が変わらない場合は追記しない。同じセッションの並行要求は先行更新を保持して順に反映する。正規化した絶対パスを宣言順に保持し、名前・パスの重複を許さない。異なるリポジトリの別名の宣言を同じ一覧に保持する。既存の自動追従エントリは移行しない。読み手はセッション全体の追記順で最後の宣言一覧を採用する。エントリがなければ空一覧、不正なエントリは読み取り失敗とする。宣言時に現存しない対象は一覧から除き、外部の読み手も現存する対象だけを使う。現存性は各宣言先について確認し、今回選んだリポジトリと異なることだけを理由に他の宣言を除かない。

`add` は宣言が受理され、呼出session が変わっていないことを確認してから、[Guardrails の拡張向け API](../guardrails/SPEC.md#7-run-tools-cli-によるfs-io) で対象の絶対パスに書き込み許可を追加する。確認ダイアログは出さない。この経路で許可するのは対象サブworktree だけで、親フォルダや Git 共有メタデータは含めない。Guardrails の明示的な拒否と機密ファイルの保護は維持する。既存の開始 `cwd` 配下の許可は変えない。

`remove` で対象パスが消失した場合は、Git 登録や対応ブランチが残っていても、呼出session のその対象の宣言を外し、この経路で追加した許可だけを失効させる。自動追従の一覧に同じパスがあれば、その関連も解除する。他の宣言や別経路の許可は変更しない。対象が削除・移動・再作成され、宣言時と同じ対象だと確認できない場合も、再宣言までこの経路の許可を適用しない。宣言エントリを読むだけでは、再開・分岐先・別session に許可は生じない。Agent Kit での表示切り替えは書き込み許可に影響しない。

対象の検証、Git 操作、宣言の保存または許可の変更に失敗した場合は、対象と理由をエラーで返し、その操作で新たな書き込み許可を与えない。途中まで変更した場合は worktree のパスとブランチ名を示し、それぞれの作成・削除・残存の実状態と、宣言・許可の更新結果を伝える。状態を確認できなかった箇所は未確認と伝える。消失した対象の宣言を外す記録に失敗しても、失効した書き込み許可は復元しない。

## 自動更新の通知

| 結果 | モデルへの通知 | TUI表示 |
| --- | --- | --- |
| 一覧が変わり、標準APIがsnapshotを受け付けた | 別の `custom_message` で更新済みの事実・追加/置換/解除内容・現在の `workspaces` を伝える | 変更件数を含む短い表示。展開すると通知本文を読める |
| 一覧が変わらない | 更新通知を出さない | 更新通知を出さない |
| コマンドの解析が失敗する | 通知を出さず、そのコマンドの追跡をスキップする | 失敗表示を出さない |
| Git照会・snapshotの読み取り・標準APIの追記が失敗した | 別の `custom_message` で更新失敗と理由を伝える | 短い失敗表示 |

通知のcustomTypeは `session-worktrees` とする。モデル向けの情報は `content` に含め、`details` はTUI表示用に使う。更新通知は再登録を求めず、Bash の返値・本文・エラーフラグを変更しない。`display: true`、`deliverAs: "steer"`、`triggerTurn` 省略により、実行中のモデルには次の応答までに通知を渡し、idle のsessionでは通知だけを保存してモデルの応答を開始しない。
