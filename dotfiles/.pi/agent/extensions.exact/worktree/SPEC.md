# Session worktreeメタデータ仕様

本書は、pi の session に関連する Git worktree を記録する `worktree` 拡張の入出力・状態・エラーを定める。読者は拡張の保守者と、session ファイルを読む外部ツールの開発者である。目的と重要制約は [REQUIREMENTS.md](./REQUIREMENTS.md) に従う。保存形式は pi の標準 [CustomEntry](https://github.com/earendil-works/pi/blob/v1.5.0/packages/coding-agent/docs/session-format.md#customentry) を使う。

## 記録形式と保存

Bash 操作への自動追従で得た一覧を、`customType: "session-worktree-metadata"` の `data.workspaces: string[]` にsnapshotとして記録する。利用宣言とは別の一覧であり、書き込み許可や SCM 表示の根拠にしない。各要素は現存する Git worktree ルートの絶対パスであり、実体パスへ正規化する。重複は持たず、登録順を保つ。同一Bash呼び出しで複数の `add` が残った場合、新規登録分は操作後に観測した Git worktree一覧の順に追加する。関連がなければ `[]` とする。

```json
{
  "type": "custom",
  "customType": "session-worktree-metadata",
  "id": "entry-id",
  "parentId": "previous-entry-id",
  "timestamp": "2026-11-09T00:00:00.000Z",
  "data": {
    "workspaces": ["/worktrees/app/feature"]
  }
}
```

外部ツールと拡張は、session全体のエントリを追記順に読み、`type: "custom"` かつ上記customTypeである最後のエントリを現在値として採用する。末尾の行、timestamp、現在の会話分岐だけでは判定しない。該当エントリがなければ空の一覧とする。最新snapshotのデータ型が不正、パスが相対パス・空・NULを含む、または重複する場合は読み取りエラーとする。

| 条件 | 更新結果 |
| --- | --- |
| 更新後の一覧が現在値と異なる | 標準customエントリ追記APIでsnapshotを1件追記する。既存の session header と履歴本文を保持する |
| 更新後の一覧が現在値と同じ | snapshotを追記しない |
| session が初回保存前 | 標準APIが受け付けたsnapshotを、pi の通常の初回保存に含める |
| ファイル保存を使わない session | 同じ標準APIでメモリ上のsnapshotを更新する |
| 標準APIが失敗する | 更新を失敗として扱い、成功結果や成功通知を返さない |
| 非同期処理中に session が切り替わる | その処理による更新と通知を取りやめる |

更新成功は標準APIの正常受付を意味し、独自のディスク保存済み保証を加えない。一覧は session全体の関連を表し、会話内の分岐移動では変化しない。自動更新では既存の登録先も確認し、現存しない worktree を一覧から取り除く。更新先は呼出sessionに限る。

## Bash操作への自動追従

登録された Bashツールの呼び出しに現れる通常の `git worktree add`・`move`・`remove` を扱う。`git -C <path>` と `cd <path> && git ...` による操作場所の指定、空白を含む引用パス、同一コマンド内の複数操作、別ツールからの nested呼び出しにも追従する。パスは Bash の通常の引数として解釈し、先頭の `@` と、引用またはエスケープされた `~/` は文字通り扱う。パスの位置に現れる空の語（空の引用引数や変数に由来するもの）は監視対象から外し、`-C` のオペランドが空の語のときはその `git` 呼び出しを監視しない。

| 操作前後の Git worktree一覧 | 関連データの更新 |
| --- | --- |
| `add` により新しい worktree が残った | そのパスを末尾へ登録する |
| `move` により登録済み worktree のパスが変わった | 元の位置で新しいパスへ置換する |
| `remove` により登録済み worktree がなくなった | その関連を解除する |
| 操作が失敗・未実行であり、一覧に変化がない | その操作を成功したものとして登録・置換・解除しない |
| 操作後の別コマンドが失敗したが、worktree操作の変化が残った | 残った変化を反映する |
| 作成後に同じコマンド内で削除され、最終状態に残らない | そのパスを登録しない |

追従の判断には、コマンドで指定された対象と、呼び出し中に観測した Git の実状態を使う。同時期に別の操作が作成した、指定対象でない worktree は登録しない。

## 利用宣言ツール `session_worktree`

呼出session が作業に使うサブworktree を名前で指定する。`action: "declare"` で書き込み許可を得る。`action: "unregister"` で宣言とその許可を外す。入力 `name` は `^[a-z0-9]+(?:-[a-z0-9]+)*$` に合う名前とし、パスや Git のオプションは受け付けない。

宣言先は、session の開始 `cwd` が属するリポジトリの `~/.agents/worktrees/<main worktree の basename>/<name>` とする。`agents-` または `copilot-` で始まる名前ではフォルダ名に `wt-` を付ける。変換後の名前との衝突を避けるため、`wt-agents-` または `wt-copilot-` で始まる入力名はエラーにする。

| 条件 | 結果 |
| --- | --- |
| 指定先に同じリポジトリの現存サブworktree がある | 既存の作業ツリーとブランチを保持し、その絶対パスを宣言する |
| 指定先と同名ブランチが存在しない | main worktree の HEAD から同名ブランチとサブworktree を作成し、作成先を宣言する |
| サブworktree がなく同名ブランチがある、指定先が別リポジトリ・通常フォルダ・シンボリックリンクである、または作成先が管理範囲外へ解決される | 既存の内容を変更せず、エラーを返す |
| 同じ名前を再度宣言する | 重複を作らず、現存する対象を確認して許可する。同じ対象がすでに許可済みならその状態を保つ |
| `unregister` を呼ぶ | 名前に対応する許可を失効させ、宣言を一覧から外す。未登録なら一覧を変えず成功する。パスが消えていても解除でき、ファイル・パス・ブランチは削除しない。解除の保存に失敗した場合はエラーとし、許可は失効したままとする |
| `cwd` がリポジトリ外、対象を Git で確認できない、または作成・記録に失敗する | 対象と理由をエラーで返し、その操作で新たな書き込み許可を与えない。作成済みなら残ったパスも伝える |

宣言一覧は `type: "custom"`、`customType: "session-worktree-declarations"`、`data.worktrees: { name: string, path: string }[]` として pi の標準 custom エントリ追記 API で保存する。内容が変わらない場合は追記しない。同じセッションの並行要求は先行更新を保持して順に反映する。正規化した絶対パスを宣言順に保持し、名前・パスの重複を許さない。既存の自動追従エントリは移行しない。読み手はセッション全体の追記順で最後の宣言一覧を採用する。エントリがなければ空一覧、不正なエントリは読み取り失敗とする。宣言時に現存しない対象は一覧から除き、外部の読み手も現存する対象だけを使う。

作成・所属確認・宣言記録は `worktree` 拡張が担当する。作成は現在のリポジトリと検証済みの名前から決まるパスに限る。モデル指定の任意パス・shell 本文や、リポジトリ由来のコードに作成権限を渡さない。

宣言が受理され、呼出session が変わっていないことを確認してから、[Guardrails の拡張向け API](../guardrails/SPEC.md#7-run-tools-cli-によるfs-io) に対象の絶対パスを渡す。この経路で許可するのは対象サブworktree だけで、親フォルダや Git 共有メタデータは含めない。API が拒否した場合は成功を返さない。宣言解除時はこの経路で追加した許可だけを外す。対象が削除・移動・再作成され、宣言時と同じ対象だと確認できない場合も、再宣言までこの経路の許可を適用しない。宣言エントリを読むだけでは、再開・分岐先・別session に許可は生じない。Agent Kit での表示切り替えは書き込み許可に影響しない。

`declare` の成功時は対象名、絶対パス、作成または再利用の区別、現在の宣言一覧を返す。`unregister` の成功時は対象名、一覧が変わったかどうか、現在の宣言一覧を返す。

### 管理対象の削除

`action: "remove"` は宣言と同じ命名規則で対象を解決する。現在のリポジトリに Git が登録しており、管理パスに現存する同じリポジトリのサブworktree だけを削除できる。現在の session の利用宣言は前提にしない。

1. 対象の絶対パスを確認ダイアログに表示する。確認できない環境、拒否、またはキャンセルでは削除しない。
2. 承認後に対象と Git の管理情報を再検証し、[Guardrails の単発削除用権限](../guardrails/SPEC.md#管理対象-worktree-の単発削除)を取得する。登録済み Bash の1回で強制オプションなしの `git worktree remove` を実行し、成功・失敗・キャンセルにかかわらず一時権限を解除する。ブランチは保持する。
3. パスと Git 登録の両方が消えた場合だけ、現在の session の対象の宣言と宣言による書き込み許可を外し、名前・絶対パス・削除済み状態・現在の宣言一覧を返す。対象が関連データに登録されていれば、その関連も解除する。片方だけが消えた場合はエラーを返す。

削除時の Git はリポジトリ形式だけを引き継ぎ、リポジトリ・ユーザーの設定を読み込まない。例えば `core.autocrlf=true` によってチェックアウトした CRLF のファイルは、通常の Git でクリーンでも削除時の未変更チェックで拒否される場合がある。

## 自動更新の通知

| 結果 | モデルへの通知 | TUI表示 |
| --- | --- | --- |
| 一覧が変わり、標準APIがsnapshotを受け付けた | 別の `custom_message` で更新済みの事実・追加/置換/解除内容・現在の `workspaces` を伝える | 変更件数を含む短い表示。展開すると通知本文を読める |
| 一覧が変わらない | 更新通知を出さない | 更新通知を出さない |
| コマンドの解析が失敗する | 通知を出さず、そのコマンドの追跡をスキップする | 失敗表示を出さない |
| Git照会・snapshotの読み取り・標準APIの追記が失敗した | 別の `custom_message` で更新失敗と理由を伝える | 短い失敗表示 |

通知のcustomTypeは `session-worktrees` とする。モデル向けの情報は `content` に含め、`details` はTUI表示用に使う。更新通知は再登録を求めず、Bash の返値・本文・エラーフラグを変更しない。`display: true`、`deliverAs: "steer"`、`triggerTurn` 省略により、実行中のモデルには次の応答までに通知を渡し、idle のsessionでは通知だけを保存してモデルの応答を開始しない。
