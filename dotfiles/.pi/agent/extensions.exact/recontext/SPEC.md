# recontext拡張機能Spec

この拡張は、エージェントによる手動圧縮用の `recontext` ツールと、コンテキストサイズ超過時の自動圧縮機能を提供する。対象読者は、長いセッションを続けるユーザーとmain agentである。この拡張による置換は以後のモデル入力だけに作用し、raw履歴・TUIの原文・セッションIDを維持する。

## 入力

| 入力 | 条件 | 意味 |
| --- | --- | --- |
| `reason` | 前後の空白を除いて空でない文字列 | コンテキストを切り替える理由 |
| `handoff` | 前後の空白を除いて空でない文字列 | 次のphaseへの自然言語プロンプト |
| `class` | 省略可。前後の空白を除いて空でない文字列 | 次のphaseの実効クラス |

`handoff` は続行目的、承認済みspecとworkファイルのパス、決定事項、作業・検証状態、未決事項、完了条件を含められる。次のagentは指定されたファイルを読んで続行する。

## 利用条件

`recontext` はmain agentだけが使う。コンテキストをリセットして長い次の作業phaseへ移る場合に限り、収束ループ開始前、またはseniorによるレビュー・実装の完了後に次の長いphaseがある場合に呼び出す。レビュー・実装の完了だけでは呼び出さない。

`finish wt`・`discard` の承認待ち、user の判断待ち、単なる作業完了報告では呼び出さず、main agent は `Ready` または `Waiting` として通常の質問で終了する。切替後のmain agentは次のphaseを別のseniorへ委譲する。

収束条件を満たしたmain agentは、`recontext` を呼び出さずユーザーへ結果を報告する。

## クラス指定

`class` を指定したときは、切替後の実効クラスをその名前に変更することを求める。省略したときは現在のクラスを維持する。切替条件と必要な承認を確認した後、agents拡張の汎用 `agents:class-change` イベントへ要求し、その適用処理の完了を待ってからコンテキストを置換する。切替条件を満たさないときは要求しない。クラスの候補評価・モデル切替処理は持たず、agents拡張に委ねる。

要求には `preserveManualSelection: true`・`requiredAgent: "main"`・`source: "agent"` を指定する。適用された場合のクラス表示は `(agent)` となる。手動モデル選択中はクラス変更を無視し、コンテキスト切替だけを行う。agents拡張がない場合も待ち続けず、コンテキスト切替だけを行う。適用処理が例外で失敗した場合はエラー通知して置換しない。適用待ちの後も中断・セッション変更を確認する。クラス変更そのものの条件と結果はagents拡張のSpec「クラス変更イベント」が定める。

## ツール行の描画

`recontext` のツール行の表示は tool-renderer 拡張が担う。表示仕様の正本は `../tool-renderer/SPEC.md` を参照。

## コンテキスト切替

有効な入力による呼出しを含むturnのツール結果が保存された時点で切り替える。`handoff` を前後の空白除去以外は変更せず保存し、それ以前の編集可能な会話・ツール結果をモデル入力から外す。要約を生成するLLM呼出しは行わない。モデルには既存のsystem prompt・tool定義、pi標準の要約ラッパーに入った `handoff`、切替後のメッセージを渡し、その文脈で自動続行する。待機キューのユーザー入力も保持する。

手動切替と自動圧縮は同じ置換動作を使う。置換後も、live表示・履歴の再構築・resumeで切替前の原文を表示できる。tree移動では移動先branchの置換だけを使う。system情報は維持する。既存の標準compaction・branch summaryは保存内容を変更せず、置換対象となった要約を以後のモデル入力から外す。標準手動 `/compact` はpi本来の動作を保つ。

## 容量超過時の自動圧縮

通常要求の送信前に、実際に選ばれたモデルのcontext上限、要求の応答枠、変換後の構造化入力を使って容量を見積もる。通常要求が収まる場合はそのまま送信する。収まらない場合は古い履歴の要約を試みる。標準自動圧縮は無効とする。

「完結した往復」は、ユーザー入力から最終応答までのまとまりである。tool call・対応する全tool result・後続応答は同じまとまりに含む。現在の未完結な入力・tool処理のsuffixも原文で保持する。

| 条件・操作 | 結果 |
| --- | --- |
| 通常要求の容量が不足する | 最新の完結往復1単位と未完結suffixを原文保持し、それ以前を要約候補にする |
| 要約要求が収まらない | 保持を2単位、3単位と有限に広げて旧prefixを短くする |
| 候補の容量を判定する | 旧prefix＋短い要約指示＋要約出力枠と、summary＋保持原文＋通常応答枠の両方が収まる候補を使う |
| 要約を要求する | 通常要求と同じ実モデル・system・tools・更新情報・旧prefix・認証・cache affinityを保ち、末尾へ短い要約指示を足す |
| 要約指示を読むモデル | 後続に保持原文が続く前提で、目的・決定・制約・作業状態・未完了事項を引き継ぎ、作業を続けず要約だけを返す |
| 正常終了した非空の要約が得られる | session・branch末尾・対象prefixが有効で、実際のsummaryを使っても予算内なら、古い編集可能範囲をsummaryで置換し、保持原文を無改変で続ける |
| 要約が失敗・中断・空・出力上限終了・tool要求となる、候補が尽きる、適用前に対象が変わる | 新しい置換を適用せず原文を保持する。過大な通常要求を下層Providerへ送らず、通知して中断する |

同じsessionの要約・通常要求・cache warmingは順序を保ち、同じcache affinityを同時利用しない。要約由来のpayload・応答・stream・429等の通常run向け通知は通常要求へ混入しない。モデル同期・認証・catalog更新・reload後も送信前の判定を維持し、別の登録ownerの更新を撤去処理で巻き戻さない。

成功した要約は通常要求が失敗しても保持する。branch移動、queue、新しい入力、resumeでは有効なbranchの置換を引き継ぐ。別モデル、会話録テキスト化、無制限retryへ自動切替しない。cache維持に適した入力構造を保つが、providerの実cache hit自体は保証しない。

## 自動圧縮プロンプト

容量超過時の自動圧縮でモデルへ追加する要約指示の正本文面は次のとおりである。

```text
次のエージェントが続きを理解できるよう、古い会話を要約せよ。この要約の後に、最新のやり取りが原文のまま続く。要約には、目的、決定事項、制約、現在の作業、未完了のタスクを含めよ。後続の原文から参照される対象と選択肢を明確にせよ。作業を続行せず、ツールを呼び出さず、引継ぎ要約だけを出力せよ。
```

## 承認と回数

回数は現在のbranch上で成功した手動ツールの自動承認による切替回数である。容量超過時の自動圧縮はこの回数を消費しない。通常のユーザー入力または承認以降、次の周期を繰り返す。

| 回数 | 次の切替 | 成功後の回数 |
| --- | --- | --- |
| 0 | 自動 | 1 |
| 1 | 自動 | 2 |
| 2 | 理由と `handoff` を表示して承認を求める | 承認時は0 |

通常入力は対話画面またはRPCからのユーザー入力を指し、回数を0へ戻す。拡張が送る合成入力では戻さない。再開・reloadだけでは回数を戻さない。tree移動では移動先branchの回数を使う。保存された回数が不正なら承認を求める。

承認UIは選択式の `Yes, recontext` と `No, stay (reason next)` を使う。選択式UIがなければ確認ダイアログを使う。拒否・選択キャンセル時は任意の理由を入力し、`no(<理由>)` を現在のagentへfollowUp送信する。理由が空または入力キャンセルなら `no()` を送る。拒否では切替も回数加算も行わない。

## `recontext` で切り替えない条件

| 条件 | 結果 |
| --- | --- |
| 入力が欠落・文字列以外・空白のみ | ツールエラーを返す |
| 対話UIがない | エラーを通知する。手動ツールの自動承認による切替にも同じ条件を適用する |
| 同じturnに複数のhandoff呼出しがある | 現在の文脈と回数を維持する |
| turnまたは同じturnのツールがエラー・中断で終了する。入れ子のツール記録が不完全、失敗、未完了である | 現在の文脈と回数を維持する |
| 承認UIが失敗する | エラーを通知し、現在の文脈と回数を維持する |
| 選択・確認・拒否理由の入力待ちの間にセッションやbranch末尾が変わる | 警告を通知し、切替と拒否通知を止める。現在の文脈と受信した入力を維持する |

## 既存の新セッション操作

`/new-session`、`/ns`、pi組み込みの `/new` は、ユーザーが空の新セッションを開始する操作として維持する。
