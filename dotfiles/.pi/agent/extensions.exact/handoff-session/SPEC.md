# handoff-session 拡張機能 Spec

この拡張は、作業phaseを終えたagentが次のagentへの自然言語プロンプトを用意し、オーナーの確認後に完全な新セッションへ移るための `handoff_session` ツールを提供する。対象読者は、phase境界でコンテキストを切り替えるオーナーとagentである。

## 入力

`handoff_session` は次の入力を受け取る。

| 入力 | 条件 | 意味 |
|---|---|---|
| `reason` | 前後の空白を除いて空でない文字列 | 現セッションを終える理由 |
| `handoff` | 前後の空白を除いて空でない文字列 | 次のagentへ自動送信する自然言語プロンプト |

`handoff` は続行目的、承認済みspecのパス、決定事項、作業・検証状態、未決事項、完了条件を含められる。ファイルパスを含める場合、次のagentはそのファイルを読んで続行する。

## セッション移行

| 開始時の状態 | 操作 | 結果 |
|---|---|---|
| 有効な `reason` と `handoff` がある | agentが `handoff_session` を呼ぶ | 現在のagent turnが完了した後、理由と次のagentへのプロンプトを表示する確認ダイアログを開く |
| 確認ダイアログで承認する | セッション移行 | 前セッションの会話、要約、ファイル参照をLLMコンテキストへ渡さない完全な新セッションを開始する |
| 新セッションの開始後 | 初回プロンプトを自動送信する | `handoff` を内容を変えずに初回のユーザープロンプトとして送信する |

前セッションへ自動で戻らない。新セッションは自動送信された `handoff` だけを前段の作業入力として扱う。

## 移行しない条件

| 条件 | 結果 |
|---|---|
| `reason` が欠落している、文字列でない、または空 | エラーを表示し、現在のセッションを維持する |
| `handoff` が欠落している、文字列でない、または空 | エラーを表示し、現在のセッションを維持する |
| 対話UIを利用できない | エラーを表示し、現在のセッションを維持する |
| オーナーが確認ダイアログで拒否する | 現在のセッションを維持する |
| セッション移行が拒否または失敗する | エラーを表示し、現在のセッションを維持する |

新セッションの開始後に初回プロンプトの送信が失敗した場合、新セッションを維持してエラーを表示する。前セッションへ自動で戻らない。

## 既存の新セッション操作

`/new-session`、`/ns`、Pi組み込みの `/new` は変更しない。これらはオーナーが任意に空の新セッションを開始する操作として維持する。
