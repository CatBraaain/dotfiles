# Downloads起動ガードの要件

本書は、pi の Downloads起動ガードを利用・保守する人に向けて、目的、振る舞い、制約を定める。

## 目的

ダウンロードされた指示文書やエージェント用フォルダが存在する作業場所で、ユーザーが意図せず作業を続けることを防ぐ。

## 適用範囲

- pi の拡張として提供し、Linux と Windows を対象とする。
- Linux では XDG の Downloads設定を利用し、取得できない場合はユーザーホーム直下の `Downloads` を使う。
- Windows ではユーザーホーム直下の標準 `Downloads` を使う。OS設定で別の場所へ移動した Downloads は対象に含めない。
- 作業ディレクトリが Downloads自身またはその配下にある場合に適用する。名前が似た兄弟ディレクトリや、別の場所にある同名フォルダは対象に含めない。
- 実体パスを取得できる場合は、シンボリックリンクなどの別名も判定する。取得できない場合は指定されたパスで判定する。

## 起動時の振る舞い・受入条件

| 作業場所・検査結果 | 警告・エラー表示 | 結果 |
| --- | --- | --- |
| Downloads の範囲外 | この拡張による表示なし | 続行する |
| Downloads の範囲内、対象なし | 作業ディレクトリと Downloads の場所を示して警告する | 続行する |
| Downloads の範囲内、対象あり | 警告に加え、終了理由と検出したパスを示す | 入力処理へ進まず、非ゼロの終了コードで終了する |
| Downloads の範囲内、存在検査を完了できない | 警告に加え、検査できなかった理由を示す | 非ゼロの終了コードで終了する |

セッション開始時の確認として実施し、再読み込みやセッション置換でセッションが開始された場合も同じ判定を行う。インタラクティブ端末で終了するときは端末の状態を復元する。JSON・RPC の構造化された標準出力に、警告やエラーの平文を混在させない。

## 存在検査

作業ディレクトリから Downloads までの各祖先を、Downloads自身を含めて確認する。Downloads より上の祖先や、関係しない子ディレクトリを再帰的に走査しない。

ファイル名・フォルダ名と種類で判定し、対象の本文を読まない。対象フォルダの内部にも進入しない。名前の大小文字は区別しない。

| 種類 | 検出対象 |
| --- | --- |
| 指示文書・スキル文書 | `AGENTS.override.md` / `AGENTS.md` / `SKILL.md` / `CLAUDE.md` / `SYSTEM.md` / `APPEND_SYSTEM.md` |
| エージェント用フォルダ | `.pi` / `.agents` / `.claude` / `.cursor` / `.codex` / `.gemini` / `.opencode` |

シンボリックリンクはリンク先の種類が対象と一致するときに検出する。通常のダウンロードファイルや、`SKILL.md.bak` のような別名は対象に含めない。

## 制約

- pi本体を変更せず、拡張だけで動作する。
- ホーム側の通常の指示・スキル・設定を変更しない。
- 拡張が動作する前に行われる設定の読み取りや他拡張の実行は取り消せない。完全な読み込み前遮断ではなく、検出後の作業継続を防ぐ仕組みとする。
