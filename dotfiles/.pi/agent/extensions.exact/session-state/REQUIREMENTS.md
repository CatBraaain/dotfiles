# session-state の要件

この文書は、pi extension session-state が解決する課題・目的・期待する成果と重要な制約を定める。読者は、実装前や改修時にこの拡張を確認する user と coding agent である。具体的なイベントと状態遷移は `SPEC.md` で定める。

## 解決する課題と目的

セッション一覧に残す会話の所属と、pi の現在の実行フェーズは寿命が異なる。所属は pi や tmux サーバーの停止後も保持する必要がある。一方、実行フェーズは稼働中の pi に属し、終了した pi の状態を表示し続けてはならない。

session-state は、pi 本体で観測した自セッションの実行フェーズを、専用tmux の pane に公開する。永続的な所属は `session-state.json` に保持し、実行フェーズと分離する。読み手（vscode-pi-sessions）は、所属の一覧と稼働中の実行フェーズを組み合わせた表示・更新を担う。

アーカイブ済みの会話で作業を再開した場合は、プロンプト送信を契機に自セッションを既定の一覧へ戻す。pi TUI からも、自セッションのアーカイブ・アーカイブ解除を操作できる。

## 機能要件

この文書でいう自セッションは、この拡張が動作している pi の現在のセッションを指す。自ワークスペースは、自セッションの作業ディレクトリを指す。

ストア更新・コマンド提供・実行フェーズの公開は、subagent として起動されていないトップレベルセッションに適用する。subagent は、subagentツールまたは画像入力の自動vision委譲が起動する子セッションを指し、新規・resume・fork を含む。agent名・役割は親子の判定条件にしない。

subagent では、ストアを作成・変更せず、実行フェーズを公開しない。この拡張の `/archive`・`/unarchive` も提供しない。既に保存されている子セッションの entry はそのまま保持する。

| 操作 | トリガー | `active-sessions` の更新 | `lock` への扱い | 通知 |
| --- | --- | --- | --- | --- |
| 自動アーカイブ解除 | プロンプトの送信（`input` イベント） | 自セッションの entry を作成する。既に載っていれば書き込まない | entry が無いときは `lock: false` で作成し、載っていれば参照しない・変更しない | 失敗のみ |
| `/archive` | コマンドの実行 | 自セッションの entry を削除する。載っていなければ書き込まず成功として通知する | 自セッションの entry の `lock` が `true` なら書き込まずロック中を通知する | 成功・ロック中・失敗 |
| `/unarchive` | コマンドの実行 | 自セッションの entry を作成する。既に載っていれば書き込まず成功として通知する | entry が無いときは `lock: false` で作成する | 成功・失敗 |

- 自動アーカイブ解除はプロンプトの送信ごとに動く。スラッシュコマンドの実行では動かない。
- ロックはアーカイブからの保護のみに効き、アーカイブ解除を妨げない。
- pi の終了だけでは、所属の登録を解除しない。

ストア更新や実行フェーズの公開に失敗しても、メッセージの送信と pi の動作を止めない。通知は TUI 上の短いメッセージで返す。

## 実行フェーズの書き出し

専用tmux 管理下の自セッションについて、agent ターン実行中・承認 UI 待ち・user のターン待ちを、対応する pane の user option として公開する。実行フェーズの値は `running`・`waiting-approval`・`waiting-user` とし、pane の公開値を実行フェーズ表示の正本とする。

公開先は、初期化時に専用tmux の socket・pane・pi自身の PID の対応を確認した pane に限る。実行実体の生存は専用pane の生存に基づき、pi の終了時に公開を終える。pane の終了後は、その実体の実行フェーズを表示しない。

初期化時は user のターン待ちを公開し、その後は agent の実行開始、承認 UI の開始・終了、agent の確定停止に伴って実行フェーズが変わるときだけ更新する。承認 UI 待ちの表示は、並行処理の進展でも保持する。承認 UI が閉じた後は、agent の実行状況に対応するフェーズへ戻す。

実行フェーズの変化だけでは所属ストアを書き換えない。tmux サーバーの停止で実行フェーズが失われても、所属の登録は残す。

tmux CLI の呼出しは、背景処理からも Tools が登録する Bashツールの実行経路を使う。Guardrails が通常の登録Bashツールと共有する認可状態に基づくサンドボックスとコマンド承認を適用する。

要求元は、実行の成功・失敗・中断を判別できる。必要な受信口が不在または無効なら失敗として扱い、認可やサンドボックスを通らない経路へ切り替えない。

直接のプロセス起動や、登録前の Bashツールの保持・再生成による迂回は行わない。

## メタデータストアの契約

ストアは、workspace ごとのセッション所属を次の構造で保持する。

```json
{
  "active-workspaces": {
    "<workspace path>": {
      "active-sessions": {
        "<session id>": { "lock": false }
      }
    }
  }
}
```

| 項目 | 契約 |
| --- | --- |
| ストアのパス | pi の agent directory（環境変数 `PI_CODING_AGENT_DIR`。未設定時は `~/.pi/agent`）配下の `session-state.json` |
| workspace のキー | workspace の絶対パス。この拡張は自セッションの作業ディレクトリを使う |
| workspace の登録 | `session-state.json` の `active-workspaces` が登録の唯一の正本。key の存在が、vscode-pi-sessions の既定の一覧に表示する workspace の登録を表す |
| 登録の操作 | vscode-pi-sessions の `New Workspace` は workspace エントリを作成し、`Unregister` はエントリを削除する |
| 空の workspace | `active-sessions` が空でも、workspace エントリが存在すれば登録として有効 |
| `active-sessions` | workspace エントリ直下の map。key はセッション ID。載っているセッションが既定の一覧に載るセッションで、載っていないセッションはアーカイブ済み |
| entry | アーカイブ管理属性を持ち、既存の `state` と未知の属性を保持する |
| `lock` | `true` のときアーカイブから保護される。省略時は `false`。この拡張は `lock` を書き換えず、`lock: true` の entry の削除を拒否する |
| 更新の範囲 | 自 workspace エントリの自セッション entry のみを変更する |
| entry の作成 | この拡張は、自セッション entry の作成時に、自 workspace のエントリか `active-sessions` が無い、またはオブジェクトでないときは、作成・置き換える。pi を起動した cwd は、この作成により自動登録される |
| 登録解除後の再登録 | 稼働中のセッションがある cwd を vscode-pi-sessions で登録解除しても、次のプロンプト送信でこの拡張が workspace エントリを作成し直し、再登録する |
| 新規作成 | ファイルが無いときは空のストアとして作成する |
| 保持 | 自セッション entry の自分が更新しないフィールド、自 workspace エントリの未知の属性、他の workspace エントリ、未知の root キーを保持する |
| 不正なストア | JSON として読めない、ルートまたは `active-workspaces` がオブジェクトでない、ルートに旧 `workspaces` オブジェクトがある（`active-workspaces` と併存する場合を含む）、workspace エントリの `active-sessions` が配列（旧形式）の、いずれかのときは書き換えずに失敗として扱う |
| 書込みの安全性 | 書込みの中断で保存済みの内容を壊さず、この拡張による更新は順序を保って反映する |

## 検証要件

- subagent の新規・resume・fork と画像入力の自動vision委譲では、起動・入力・実行フェーズ遷移・終了を通じてストアを作成・変更せず、実行フェーズも公開しない。`/archive`・`/unarchive` も提供しない。
- アーカイブ済みの会話を再開してプロンプトを送ると、自セッションが既定の一覧へ戻る。他の会話の所属と保持対象の属性は変わらない。
- `/archive` はロックされていない自セッションの entry を削除し、`/unarchive` は自セッションの entry を追加する。既に目的の所属になっている場合は、ストアを書き換えず成功を通知する。
- 初期照合に一致した専用tmux の pane に、初期化時の user 待ちと、実行開始・承認 UI の開始と終了・確定停止による実行フェーズの変化が公開される。実行フェーズの変化だけでは JSON を書き換えない。
- pi の終了時に公開が終わり、pane が終了すると実行フェーズの表示が消える。所属の登録は残る。
- 所属更新では既存の `state` と未知属性を保持し、不正なストアは上書きしない。実行フェーズ表示には pane の公開値を使う。
- tmux CLI の操作は、背景処理からも登録Bashツールの実行経路に入り、Guardrails が共有する認可状態に従う。
- 実行の成功・失敗・中断を要求元が判別できる。必要な受信口が不在または無効なら失敗として扱い、認可・隔離を省略した実行を行わない。
