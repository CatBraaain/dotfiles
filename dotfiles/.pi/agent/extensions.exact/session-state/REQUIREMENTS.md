# session-state の要件

この文書は、pi extension session-state が解決する課題・目的・期待する成果と重要な制約を定める。読者は、実装前や改修時にこの拡張を確認する user と coding agent である。具体的なイベントと状態遷移は `SPEC.md` で定める。

## 解決する課題と目的

pi の現在の実行フェーズは稼働中の pi に属する。利用者が、作業中・承認待ち・user 待ちを区別でき、終了した pi の状態を表示し続けないことが必要である。

session-state の責務は、pi 本体で観測した自セッションの実行フェーズと保存済みタイトルを、専用tmux の pane に公開することに限る。セッション一覧の正本は `pi-mux list` とし、復元用JSONの読込み・更新は pi-mux が担う。

## 機能要件

この文書でいう自セッションは、この拡張が動作している pi の現在のセッションを指す。

実行フェーズの公開は、subagent として起動されていないトップレベルセッションに適用する。subagent は、subagentツールまたは画像入力の自動vision委譲が起動する子セッションを指し、新規・resume・fork を含む。agent名・役割は親子の判定条件にしない。

実行フェーズの公開に失敗しても、メッセージの送信と pi の動作を止めない。通知は TUI 上の短いメッセージで返す。

## 実行フェーズの書き出し

専用tmux 管理下の自セッションについて、agent ターン実行中・承認 UI 待ち・user のターン待ちを公開する。実行フェーズの値は `running`・`waiting-approval`・`waiting-user` とし、pane の公開値を実行フェーズ表示の正本とする。

公開先は、専用tmux の socket・pane・pi自身の PID の対応を確認した pane に限る。実行実体の生存は専用pane の生存に基づき、pi の終了時に公開を終える。pane の終了後は、その実体の実行フェーズを表示しない。

公開値は自セッションの現在の実行フェーズを表す。承認 UI 待ちの表示は並行処理の進展でも保持し、承認 UI が閉じた後は agent の実行状況に対応するフェーズを表す。

自セッションのタイトルは、pi が保存したセッション名を正本とし、対応する pane に共有用の値を公開する。初回リクエストの agent ループ終了より遅れてタイトルの生成・保存が完了した場合も、セッションのアクティブ化を待たずに反映する。実行フェーズが変わらなくてもタイトルの変更を公開し、既存の実行フェーズとセッション識別情報を保持する。初期化時は保存済みのタイトルを共有し、その後の実行フェーズの変更でもタイトルを保持する。

tmux CLI の呼出しは、背景処理からも Tools が登録する Bashツールの実行経路を使う。Guardrails が通常の登録Bashツールと共有する認可状態に基づくサンドボックスとコマンド承認を適用する。

要求元は、実行の成功・失敗・中断を判別できる。必要な受信口が不在または無効なら失敗として扱い、認可やサンドボックスを通らない経路へ切り替えない。

直接のプロセス起動や、登録前の Bashツールの保持・再生成による迂回は行わない。
