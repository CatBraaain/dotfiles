# Session worktreeメタデータの要件

本書は、pi の session と、その session が扱う Git worktree の関連データを供給する拡張の課題・目的・重要制約を定める。読者は本拡張の保守者と、連携するエージェント管理ツールの開発者である。

## 課題と目的

人間がレビューするとき、外部のエージェント管理ツールで選択した session に対応する worktree群を機械可読で取得できるようにする。チャット本文の解析に依存せず、レビュー対象に合った VS Code workspace を選ぶためのデータを提供する。

## 期待する成果

- 外部ツールは、session JSONL に customエントリとして追記された関連データから、最新の worktree の絶対パス一覧を取得できる。
- 登録された Bashツールによる通常の worktree の作成・改名・削除に、関連データが自動追従する。
- チャットで指定された既存の worktree や、AI が別の session から引き継ぐ worktree を扱う場合にも、エージェントツールで関連を明示的に登録・解除できる。
- 自動更新の事実・変更内容・現在値を、Bash結果そのものを保った別通知としてモデルコンテキストに伝え、TUI にも短く表示する。この通知は更新済みの事実を伝えるものであり、重ねて登録を要求しない。

## 重要な制約

- データ供給側の pi拡張として、pi本体を変更せずに実現する。
- 更新する関連は操作を実行した session のものに限り、現在の関連として扱うのは現存する worktree だけとする。
- pi のメモリ上と session ファイル上で関連データを整合させる。保存には標準の customエントリ追記API を使い、既存の session header と履歴本文を保持する。
- 自動追従には、外部で直接実行した操作や任意のスクリプト内の Git操作をすべて検知する保証を求めない。これらで生じる関連の補正にも、明示登録・解除を使える。
- 保存に失敗した更新を成功として通知しない。
