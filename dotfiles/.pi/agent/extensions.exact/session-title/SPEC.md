# session-title拡張機能Spec

piセッションの表示名を、会話の主題を表す短いタイトルとして生成・設定する。対象読者は、この機能を使うユーザーと実装・検証の担当者である。

## 応答完了と生成タイミング

「応答完了」は、ユーザー入力に対する最終応答が正常に終了し、ツール実行・自動retry・待機中の入力による自動続行が終わった状態を指す。途中のツール実行を含むLLMの1応答とは区別する。

| 契機 | 生成・設定するタイミング |
| --- | --- |
| セッションの初回応答 | 初めて応答完了になったとき |
| ユーザーコマンド `/retitle` | 待機中なら実行時。応答処理中なら、その応答完了後 |
| `recontext` による文脈置換 | 適用成功後、置換した文脈で初めて応答完了になったとき |

初回応答による自動生成はセッションごとに1回とする。再開・拡張reloadでも完了済みの初回判定を維持し、通常の2回目以降の応答完了だけでは再生成しない。同じ応答完了で複数の生成契機が重なった場合は、1回の生成・設定にまとめる。

`recontext` の要求・承認待ち・拒否・失敗は、適用成功として扱わない。文脈置換の成立条件は [recontext拡張の仕様](../recontext/SPEC.md) に従う。

## 生成入力とタイトル

生成開始時点の現在の分岐に保存された、ユーザー・assistantのテキスト本文を入力にする。`recontext` で通常のモデル入力から外れた本文も含める。`handoff`・自動要約の本文、システム指示、思考過程、ツール呼び出し、ツール結果は入力に含めない。

タイトルはセッション一覧から会話を識別するため、対象と主題だけを表す1行の文字列とし、会話の主な言語に合わせる。経緯・詳細なエラー・完了報告は含めず、生成理由などの説明を付けない。長さは言語を問わず30文字以内とし、生成と再リクエストの指示では20文字以内を求める。生成指示では、出力前に文字数を確認し、20文字を超える場合は短縮するよう求める。

生成結果の連続する空白を半角スペース1つに置き換え、前後の空白を除いてから、Unicodeコードポイント数で文字数を検査する。30文字を超えた場合は、実際の文字数を添えて、タイトルだけを返すよう1回だけ再リクエストする。例えば64文字だった場合は「64文字だった。20文字以内のタイトルだけ返す」と伝える。再リクエストの結果にも同じ空白整形と文字数検査を適用する。

## 生成モデル

タイトル生成には、生成開始時点の実効modeにおける `low` クラスを使う。候補の評価・選択は [モデル選択の仕様](../agents/model-routing.spec.md) に従う。親セッションのクラスやモデルの価格によって、タイトル用クラスを変更しない。

タイトル生成によって親セッションのモデル・クラス・思考設定を変更しない。

## 表示名の保存

文字数検査を通過したタイトルをセッションの表示名に設定する。保存済みセッションでは、JSONLの `session_info.name` に新しい名前が追記され、最新の名前を取得できる。以前の名前を持つentryは履歴として残る。

補助推論の指示・応答は通常の会話メッセージとして追加せず、生成結果は表示名に反映する。

## 失敗と適用先

| 状態 | 結果 |
| --- | --- |
| 生成に使える会話本文がない | 名前を維持し、理由を通知する |
| `low` の利用可能なモデルがない、推論が失敗・中断する、生成結果が空になる | 名前を維持し、失敗理由を通知する |
| 再リクエストの結果も30文字を超える | 名前を維持し、実際の文字数と拒否したタイトルを警告する |
| 再リクエストが失敗する | 名前を維持し、失敗理由を警告する |
| 生成中に対象セッションまたは分岐が変わる | 生成結果を適用せず、変更先の表示名を維持する |

タイトル生成の失敗によって、通常の会話の応答完了を失敗扱いにしない。
