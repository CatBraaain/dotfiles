# pi-mux-bridge の実行フェーズ・タイトル公開仕様

この文書は、pi拡張 `pi-mux-bridge` による専用tmux paneへの実行フェーズ・タイトル公開を定める。読者は、この拡張と外部の読み書き手を保守する user と coding agent である。課題・目的・重要な制約の正本は [公開要件](session-state.requirements.md) とする。

## 適用対象

実行フェーズの公開はトップレベルセッションに適用する。現在の session directory が、そのcwdの subagent用directory と一致する子セッションでは、pane公開を行わない。この判定は新規・resume・fork・画像入力の自動vision委譲に共通し、agent名・役割・親ヘッダーの有無では変わらない。

公開にはスラッシュコマンドではなくライフサイクルイベントを使う。自セッションは、この拡張が動作しているpiの現在のセッションを指す。

| 入力・状態 | pane公開 |
| --- | --- |
| トップレベルの `input` | 現在値を維持する |
| トップレベルの `session_start` | 公開世代を開始する |
| トップレベルの `resources_discover` | 管理下を照合し、`waiting-user` を公開する |
| 実行フェーズ・保存名の変化 | 下記イベント表に従う |
| `session_shutdown` | 新規公開を止め、optionの除去を試みる |
| 専用tmux管理外のトップレベル | 公開しない |

## workspace登録・復元との境界

セッション一覧の正本は `pi-mux list` とし、復元用JSONの読込み・更新はpi-muxが担う。拡張は、自セッションの実行フェーズと保存済みタイトルを [pi-muxのstate操作](../../../../.local/cli.exact/pi-mux/SPEC.md#state) へ通知し、pane optionに公開する。状態metadataを直接書き換えず、終了時の除去も同じ公開CLIへ依頼する。

起動・入力・実行フェーズ遷移・終了の全期間で、workspace登録と復元記録の取得・更新はpi-muxが担う。拡張自身は保存storeを直接読み書きせず、会話の既存エントリを変更・削除しない。`running` 通知に伴う一時再開からの昇格と復元記録更新はpi-muxが行う。

## 管理paneの初期照合

専用socketは、POSIX では `${XDG_RUNTIME_DIR:-/run/user/<uid>}/pi-tmux/server.sock`、Windows では `~/.local/state/pi-tmux/server.sock` の絶対パスとする。全tmux操作で `-S <絶対パス>` を指定し、既存サーバーに接続する。Windows では実socketをファイルシステムで確認しない。

`TMUX` のsocketが専用pathと一致し、`TMUX_PANE` がある場合だけ候補とする。POSIX では実socketをファイルシステムで確認した後、`display-message` のtab区切り応答から次の値を照合する。

| 照合値 | 一致条件 |
| --- | --- |
| socket path | 専用socketの絶対パス |
| server PID | 応答のserver PIDが正の整数であること |
| pane ID | `TMUX_PANE` |
| 起動トークン | 応答のpaneの起動記録(`@pi-mux-launch`)にトークンがある場合、`PI_TMUX_LAUNCH_TOKEN` 環境変数と一致すること。起動記録がないpane(CLIによらず起動したpi)はこの照合を省略する |

全項目が一致したpaneだけを公開先にする。CLIが起動したpiは `PI_TMUX_LAUNCH_TOKEN` 環境変数を受け取り、それを公開メタデータ(`@pi-tmux-session`)のトークンとして記録する。CLIによらず起動したpiは、拡張が生成したトークンを同じ環境変数と公開メタデータに設定して使う。照合は各世代の `resources_discover` で、全拡張の `session_start` 初期化が完了した後に行う。その世代では捕捉済みの接続先を使う。

state操作の `--source` には、socket・server PID・pane ID・pi PIDとともに起動トークンを渡す。server PID は `TMUX` 環境変数ではなく応答の `#{pid}` から捕捉する。トークンは起動ごとに新しいため、PID・pane ID の再利用や server の再起動後は同じ通知元と見なされない。再送時にも捕捉済みsourceを維持し、古い通知を新server・新pane・新piへ付け替えない。pi-muxは変更の直前に通知元を再照合する。

## 状態通知の公開契約

公開先の形式は [pi-muxのpane option公開契約](../../../../.local/cli.exact/pi-mux/SPEC.md#pane-optionの公開契約) に従う。通常の通知には `state <会話ID> <state> --source <JSON> --title <JSON>` を使う。終了時には `state <会話ID> --clear --source <JSON>` を使う。

タイトルの正本はpiの保存済みセッション名とし、名前がない場合は `null` を通知する。sourceとtitleはそれぞれJSON化し、単一のliteral引数として渡す。

同じ世代では、直前に成功した通知からstate・titleが変わらず、新しい確定終了も未完了の通知もなければCLIを呼ばない。失敗した通知は成功済みと見なさず、同値の次の要求でも再送できる。titleだけが変わった場合は、現在のstateと会話IDを維持して通知する。その後のstate変更でも現在のtitleを保持する。世代開始時は、同じ会話ID・state・titleでも初期値を通知する。公開のためにpane optionを読み取らず、外部上書きだけでは再通知しない。

### 最新状態への合流

同じ世代で受け付けたstate・titleの組のうち、最後の組を最新値とする。確定終了後は同じ組でも再通知する。実行中や復旧待ちにも受付を続け、未実行・再送待ちの通知は最新値へ置き換える。次に開始する通常公開ではその組を送り、置き換えた旧値は送らない。

公開成功は送信した組と、その通知開始時点までの確定終了にだけ対応付ける。実行結果は受付済みの最新値を変更しない。新しい組があるか、入力待ちの通知開始後に別の確定終了があった場合は、公開を続ける。

### 実行の区間とイベント

run区間は `agent_start` から `agent_settled` までとし、中断による確定停止も含む。リトライ・自動圧縮・キュー継続をまたいで維持する。`agent_end` は確定停止を表さない。

管理paneの自セッションは `agent_settled` の受信時刻（epoch ms）と `aborted` を中断時も含めて記録する。Pi のセッションファイルに `customType` が `pi-mux-last-run` の `custom` エントリを追記し、`data` は `sessionId`・`atMs`・`aborted` を持つ。記録後はstateとtitleが変わらなくても通知する。追記が失敗したら1回だけやり直し、再度失敗してもフェーズ遷移は継続する。CLI に終了記録は引数として渡さない。

承認UI待ちは `ui_prompt_start` から `ui_prompt_end` までの外側の待ち区間とする。対象はSDKの `select`・`confirm`・`input`・`editor`・`custom` によるUI待ちである。

| イベント | 処理 |
| --- | --- |
| `session_start` | 起動・resume・reload時に旧世代を失効させ、run区間外・承認待ちなしで公開世代を開始する。現在の保存名を取得し、titleの初期値にする |
| `resources_discover` | 管理paneを初期照合し、`waiting-user` と現在のtitleを公開する |
| `session_info_changed` | 保存後の `event.name` を現在のtitleとし、stateと会話IDを維持して公開する。`undefined` は `null` として公開する |
| `agent_start` | run区間に入り、承認待ちでなければ `running` を公開する |
| `ui_prompt_start` | 承認待ちに入り、`waiting-approval` を公開する |
| `ui_prompt_end` | 承認待ちを解除し、run区間内なら `running`、区間外なら `waiting-user` を公開する |
| `agent_settled` | run区間を終了し、確定終了を記録する。承認待ちでなければ `waiting-user` を公開する。承認待ちなら表示を維持し、UI 終了時の通知で確定終了を公開する |
| `session_shutdown` | 新規公開と再送を止め、未実行分を失効させ、可能ならoptionを除去する |

保存名の変更は標準の `session_info_changed` で受け取る。初回リクエストのagentループ終了より遅れて保存された場合も、セッションのアクティブ化や次のstate変更を待たずに公開する。初期照合前の保存名変更はtitleの現在値に反映し、公開CLIは `resources_discover` 以降に実行する。

その他の進展イベントでは公開しない。承認待ち中は、進展・繰り返しの `agent_start`・確定停止によって表示を `running` へ戻さない。UI終了後は、その時点のrun区間に対応するstateへ戻す。

### 世代と終了

公開処理はrunの `ctx.signal` と独立し、呼び出し元のsignalをCLIへ渡さない。会話ID・接続候補は世代に対応付けて捕捉する。世代失効では、その世代の再送・未実行の公開・古い結果（成功を含む）・古い操作の失敗通知を破棄する。

開始済みのCLIは世代失効だけを理由に強制中断しない。本書の実行終端は、開始したプロセスの終了を確認した時点とする。timeout・起動失敗などの結果が失敗であっても、プロセスの終端を確認できれば終端済みとして扱う。

同じpiプロセスでは、古い通知や除去の実行終端を確認してから後続CLIを開始する。この順序は、新しい会話・reload・factoryの再生成をまたいで保持する。終端後は、その時点で有効な世代の通知を処理する。CLIのtimeoutは1秒とし、timeoutによる停止後も実行終端を待つ。

### 自動復旧

「実行経路と失敗」の結果表で自動復旧に振り分けられた場合、有効な世代は復旧待ちに入る。最新値の公開が成功するまで、失敗とロック競合が交互に続いても再送を続ける。起動・復元のロックを持つ呼出元の完了を待つ循環を作らず、resources_discoverとpiの初期化・入力を継続する。

| 復旧待ちの条件 | 処理と結果 |
| --- | --- |
| 開始済み実行の終端が未確認 | その終端を追跡し、後続CLIの開始を待つ |
| 実行終端または未実行を確認済み | 確認から所定の再送間隔が経過したら、失敗した初期照合または未反映の最新値を背景で再送する |
| 再送も失敗またはロック競合 | 次の再送間隔で復旧待ちを続ける |
| 初期照合の再送に成功 | その世代の公開先を確定し、未反映の最新値を公開する |
| 通知の再送に成功 | 送信した組を成功済みとし、未反映の最新値があれば公開を続ける |
| 世代が失効 | その世代の再送と未実行分を破棄し、開始済み実行の終端追跡だけを保持する |
| shutdownを受信 | 再送を止め、終了処理に移る |

再送間隔は、Windows では連続する失敗・ロック競合に対して 1、2、4、8、16、30秒とし、以後は30秒を維持する。初期照合または通知が成功したら、次の復旧待ちは1秒から始める。POSIX では常に1秒とする。

開始済みプロセスが終端し、CLIと専用tmuxが利用可能になれば、有効な世代の最新値の公開が成功するまで自動復旧を続ける。再送は、追加入力・実行フェーズ変更・会話切替・reloadを待たずに行う。

### 終了処理

終了時は新規受付と再送を止め、未実行分を失効させる。開始済みCLIは1秒timeoutを維持して実行終端を待ち、終端を確認してからoptionの除去を1回依頼する。実行終端を確認できない場合は、追加のcleanupを実行せずに終了を継続する。終了処理から戻った後も、同じpiプロセスが存続する間は開始済み実行の終端追跡を保持し、後続世代のCLIをその終端より後にする。paneが終了すると、pane-local optionも消滅する。

## 実行経路と失敗

初期照合のtmux CLIと通知のpi-mux CLIは、拡張が決めた固定補助処理として通常のプロセス起動で実行する。会話ID・source・state・titleはliteral引数として扱い、タイトルなどの内容をshellコマンドとして評価しない。

| 結果 | 扱い |
| --- | --- |
| 中断・timeoutのない通常終端で終了コード0、完全な出力 | 結果を用いて照合・公開を進める |
| 通常公開のstate操作が非0終了（終了コード75を含む） | 上記の自動復旧に従う |
| shutdownの除去が終了コード75 | 終了を継続する |
| 中断・timeout・切詰めのない通常終端で、初期照合またはshutdownの除去が上記以外の非0終了 | 操作失敗として扱う |
| 起動不能・中断・timeout・出力切詰め、初期照合または通常公開 | 上記の自動復旧に従う |
| 起動不能・中断・timeout・出力切詰め、shutdownの除去 | 再送せず終了を継続する |
| 出力の欠落・切り詰め・照合不一致 | 管理paneとして採用しない |

公開・照合・除去の失敗でも、inputとpi本体の動作を継続する。
