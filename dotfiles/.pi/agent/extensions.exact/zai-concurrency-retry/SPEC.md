# zai-concurrency-retry

Z.AI coding plan の同時実行制限エラーに対して、待機してから再試行を繰り返す拡張。

## 対象

| 条件       | 値                                                                                                                                                                                                                                               |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| プロバイダ | `zai`、`zai-coding-cn`（`dotfiles/.pi/agent/extensions.exact/model-sync` が登録する Z.AI プロバイダ）                                                                                                                                            |
| エラー     | 最終 assistant エラーの `errorMessage` に Z.AI の同時実行系エラー（業務コード `1302`「Rate limit reached for requests」、`1305`「The service may be temporarily overloaded」）が含まれること。文言のみ、または生 JSON ボディのいずれの形でもよい |

対象外: quota 系エラー（`1113`、`1308`〜`1321`）と z-ai 以外のプロバイダ。これらには本拡張は何もしない（quota 系は `agents` 拡張の既存のレート制限フォールバックに従う）。

同時実行エラーは別モデルへの fallback を起こさない。Z.AI の同時実行制限はアカウント単位のため切替では解決せず、`agents` 拡張と共有する判定（`shared/zai-concurrency.ts`）で fallback 対象から除外する。

## ターン内リトライ

同時実行エラーの assistant エラーを受けたら、待機してから pi 本体の自動リトライに再試行させる（エラー文言を再試行可能な形式へ置き換える）。

| 入力                                                                 | 操作             | 結果                                                                        |
| -------------------------------------------------------------------- | ---------------- | --------------------------------------------------------------------------- |
| 同時実行エラーを受けた                                               | 待機時間だけ待つ | エラー文言を再試行可能な形式へ置き換え、pi 本体が同じリクエストを再試行する |
| 待機中にユーザーが abort した                                        | 待機を中断する   | エラー文言を置き換えない。ターンは元のエラーで終了する                      |
| 同時実行エラー以外の結果でメッセージが確定した（成功・abort を含む） | —                | 連続エラー回数を 0 に戻す                                                   |

pi 本体のリトライ回数上限（`settings.json` の `retry.maxRetries`）に達するとターンはエラー終了する。続きは「ターン確定後の再実行」が担う。

## 待機時間

連続エラー回数 `n` に対し `5s × 2^(n-1)`（上限 60s）に ±20% のジッタを加えた値を待つ。連続エラー回数はターンをまたいで引き継ぎ、成功で 0 に戻る。ターン確定後の再実行の待機も同じ回数に数える。

直前の Z.AI 429 が `Retry-After` ヘッダーを伴った場合、ターン内リトライの待機はヘッダーの値（秒数または HTTP-date、過去の日時は 0）を優先する。ターン確定後の再実行の待機には使わない。

## ターン確定後の再実行

ターンが（pi 本体のリトライを含めて）完全に終了したとき、最後のエラーが同時実行エラーなら、待機してから同じターンを再実行する。再実行は上限なく繰り返す。

| 状態                                                    | 操作             | 結果                                                                                 |
| ------------------------------------------------------- | ---------------- | ------------------------------------------------------------------------------------ |
| ターンが同時実行エラーで確定した                        | 待機時間だけ待つ | `Z.AI concurrency limit; retrying in <秒>s (attempt <回数>)` を通知する              |
| 待機完了時点で idle である                              | —                | 非表示のカスタムメッセージでターンを再実行する（ユーザーメッセージの履歴は増えない） |
| 待機完了時点で idle でない（ユーザーが入力した）        | —                | 再実行しない                                                                         |
| ターンが同時実行エラー以外（abort、他エラー）で確定した | —                | 再実行しない                                                                         |
| 保留メッセージがある                                    | —                | 再実行しない                                                                         |

## 表示

| 状況                       | 表示                                                                                                 |
| -------------------------- | ---------------------------------------------------------------------------------------------------- |
| ターン内リトライの待機中   | ステータス領域に `Z.AI concurrency limit; retrying in <秒>s (attempt <回数>)` を表示し、待機後に消す |
| ターン確定後の再実行の待機 | 通知（info）で上記と同文言を出す                                                                     |
