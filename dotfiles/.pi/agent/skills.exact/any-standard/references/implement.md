# standard・汎用スキル作成手続き（any-implement 用）

any-implement が any-standard と組み合わせるときに適用する、standard・汎用スキルの作成・改修手続き。規則セットの組み立て、推測で書き始めない停止規則、Verify による自己検証の骨格は any-implement が所有し、ここでは繰り返さない。

## 入力と完了範囲の確定

書き始め前に次を整理する:

- 対象の種別: standard の新規作成 / 既存 standard の改修 / 汎用3スキルの改修 / 単発スキルの作成
- スキルが所有するドメインと目的、適用条件
- 変更してよい範囲

## 対象の判別

新しいスキルを作るとき、まず standard スキルにするかを判断する:

| スキルの性質 | 形態 |
| --- | --- |
| ドメインの規則（oracle）を所有し、汎用3スキルの骨格と組み合わせて使う | `xxx-standard` |
| 規則を持たず、単発の調査・対話で完結する | 単発スキル |

## standard の新規作成

1. ドメインを定義する。汎用3スキル・既存の `xxx-standard`・その他の規則スキルと所有範囲が重複しないか確認する。重複する場合は新規作成せず、既存 standard の改修として扱う。
2. `xxx-standard` で命名する。
3. SKILL.md に規則本体（適用条件・記法・Verify）を書く。本文の品質は instruction-standard の規則に従う。
4. 汎用のデフォルトプロトコルで足りない固有手続きがあるときだけ、対応する `references/`（implement.md / review.md / workflow.md）を書く。
5. 手続きの骨格（規則セットの組み立て・検証・出力形式・指摘形式）を SKILL.md や `references/` へコピーしない。

## 既存 standard の改修

- 規則の変更は SKILL.md（正本）に対して行う。
- `references/` の新設・撤去は、汎用3スキルのデフォルトプロトコルと衝突しないか確認する。

## 汎用3スキルの改修

- 手続きの骨格のみを変更する。ドメイン規則を追加しない。
- 変更が特定ドメインの都合しか満たさない場合、それは該当 standard の `references/` へ移す候補として扱い、汎用へ持ち込まない。

## 依頼種別ごとの停止点

| 依頼 | 実行する範囲 | 停止条件 |
| --- | --- | --- |
| standard を新規作成して | ドメイン定義 → 命名 → SKILL.md → 必要なら `references/` → Verify | Verify が通り、汎用3スキルと組み合わせ可能になったら |
| standard を改修して | 対象の読解 → 正本への変更 → Verify | 変更前後の差分を報告し、Verify が通る |
| 汎用スキルを改修して | 対象の読解 → 骨格の変更 → Verify | 変更前後の差分を報告し、Verify が通る |
| 規則スキル構成をレビューして | any-review + `references/review.md` によるレビューへ切り替える | 指摘リストを出力した時点（対象を編集しない） |
