# Readable Docs

## 可読性の指標

唯一の指標は **読者が文書だけで目的を果たすまでにかかる時間**。

## 最小完全性

読者が目的を果たすために必要な情報を不足なく、それ以上に含めない。行数・文字数・削減量ではなく、読者が正しく判断できることを成果とする。

## 重複の排除

主張・定義・手順は一箇所にだけ置く。他の節の要約、同じ意味の別節、本文を写した図表、空節は、読者の判断に必要な独自情報を増やす場合だけ残す。

## 文書の自己完結

文書は、過去の会話、変更履歴、執筆過程、編集中のリポジトリに関する知識なしに理解できる最小前提を含める。

## 記法の選択

段落、リスト、表、図のうち、情報の関係を最も直接的に読める記法を選ぶ。構造を散文より明確にできない場合は、記法を増やさない。
表と図は、読者の問いに答える本文を置換するときだけ使う。1つの図表は1つの問いに答え、本文には図表の読み上げではなく結論を置く。

## 削除

定義、適用範囲、必要な境界、参照される記述は、削除後も解釈が一意に定まる場合だけ削る。

## 編集手順

編集は、削る・統合する・記法を直すといった最小の介入から試し、文の書き直しは最後の手段にする。削除・統合した内容ごとに、保持・統合・削除のいずれかと、読者が失う意味を確認する。

## 冒頭と用語

冒頭で対象・目的・適用範囲・読者を特定し、用語を文書内で定義する。

## 本文と規範の形式

文書の対象に属さない作業メモや経緯は、依頼された場合を除き本文へ持ち込まない。成果物には、読者が目的を果たすための文書だけを置く。規範は肯定形で書き、除外・禁止は安全または判断の境界を定める場合だけ書く。例は読者一般に通じる題材を選ぶ。

## 具体性

主観語は判断者と基準を添えるか、観測可能な条件へ置き換える。数値・名前・出力形式は具体的に示し、形式の解釈を一意にしたい場合は例を1つ添える。

- 悪: 「テストは十分に書くこと」 — 「十分」の基準がなく、読者ごとに判断が分かれる。
- 良: 「各 spec の照合単位ごとに、観測可能な振る舞いを検証するテストを置く」

## 既存文書の構造リファクタリング

複数の節またはファイルを簡素化・整理・統合する場合に適用する。局所的な誤字修正、明白な重複の削除、記法修正だけには適用しない。

分類単位は、1つの操作の対象として識別できる最小の節またはファイルとする。親ファイルとその内部の節は重複して分類しない。

### 操作

- `keep`: 変更しない。
- `merge`: 複数の分類単位を1つの正本に統合する。
- `move`: 本文を変えずに移動する。
- `delete`: 正本を残さず削除する。
- `rewrite`: 1つの分類単位の本文を再記述する。

1. 編集前に、対象の各分類単位を操作へ分類する。
2. 各非`keep`操作について、変更元のファイルパスと節見出し（ファイル全体なら `ファイル全体`）および編集前の本文を自己照合用に記録する。この記録は報告に転載しない。変更ブロックは1操作に1つ作り、`merge` では統合元をすべて記録する。
3. 分類した操作を実施する。
4. 完了後、自己照合用の記録と成果物を比較する。各変更ブロックへ正本または移動先のファイルパスと節見出し、編集した理由を追記して報告する。`delete` では正本なしと記録する。
5. 行数・文字数・削減率を受入条件や委譲条件にしない。改行削除、言い換え、散文の圧縮だけでは構造リファクタリングの完了としない。
6. 規則を原則へ統合するときも、許可・禁止、停止条件、承認、出力形式など読者の行動を直接分ける契約は明示的に残す。

### 照合

編集後、自己照合用の記録、各変更ブロック、成果物を照合する。変更元、操作、正本・移動先または正本なし、保持した意味、意図的に失った意味と理由が対応し、安全または判断の境界が失われず、構造変更の結果を報告できることを確認する。
