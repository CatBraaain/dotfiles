# SDD Standard

このスキルは、SDD の仕様作成と適合性レビューが共有する規約を定義する。実行フローは `sdd-strategy`、適合性レビューの手順は `sdd-review` が担う。`sdd-strategy` または `sdd-review` と併用するときは、このスキルの規約を適用する。

## 仕様ソースと oracle

ロジックを伴う成果物は **spec（＝観測可能な振る舞いの仕様書）** を唯一の仕様ソースとして扱う。要件文書と spec を分離して二重管理しない。適合性レビューでは spec を **oracle（真実の基準）** とし、テストと実装を照合する。

オーナーは spec だけを読んで要件を承認する。実装コードやテストの詳細は go/no-go の判断材料にしない。

## 観測可能な振る舞い

spec に記載するのは、ユーザーが直接または間接に観測できる振る舞いだけとする。

- **書く**：入出力、状態、エラー、振る舞い、パフォーマンス特性など、ユーザーに現れる結果。
- **書かない**：結果が同じなら観測できない内部最適化、関数名、クラス名、モジュール構造、DBスキーマ、内部データ構造、APIシグネチャ。
- 内部処理でも、結果としてユーザーに現れるものは書く。

## 独立した仕様書

spec は1ファイルで完結し、過去の仕様・要件文書・会話履歴なしで理解できるようにする。冒頭で対象の名称・目的・適用範囲・利用者の役割を示す。

- 現在形で書く。廃止・削除・変更前後などの履歴を書かない。
- 仕様の対象と、機能を識別する用語を文書内で定義する。
- 仕様に含める対象と振る舞いを肯定形で記載する。候補・却下案・非目標を持ち込まない。
- 「今回」「前述の要件」「先ほどの案」「既存のもの」など、文書外の文脈を参照しない。
- 変更理由・意思決定の経緯を書かない。背景は判断記録の責務である。

## 重複の排除

各振る舞いは1箇所にのみ定義する。同じ振る舞いを複数のセクション、図、テーブルに重複して書かない。別角度から触れる場合は定義を再掲せず、該当セクションを参照する。具体例の再掲は、直近の定義を理解するために必要な場合だけ許可する。

## 入力と配置

会話で合意した内容から、観測可能な振る舞いだけを抽出する。観測可能な具体値が定まらない場合は推測せず、ユーザーへ質問する。

- 単一機能・小規模：`SPEC.md`
- 複数機能：`spec/<feature-name>.md`
- 1プロジェクト内で `spec/` と `SPEC.md` を混在させない。既存の配置があれば維持する。
- 機能は実装モジュールではなく、ユーザーが認識する単位で切る。
- 要件文書・設計書を別ファイルで作らない。specを唯一の仕様ソースにする。

## フォーマット

Markdownで記述し、分岐・状態・時系列・順序を視覚的に構造化する。フラットな自然言語による分岐の羅列は避ける。

| 構造 | 記法 |
| --- | --- |
| 条件で結果が変わる分岐 | マトリクステーブル |
| 状態の変化 | Mermaid `stateDiagram-v2` |
| 時系列のやり取り | Mermaid `sequenceDiagram` |
| 順序付き手続き | Mermaid `flowchart` |

Mermaidは1図1主題とし、ノード名は意味のある名詞・動詞句、矢印ラベルは短い条件・イベント名にする。状態遷移は `LR`、シーケンスは既定の縦方向、フローは内容に応じた `TD` / `LR` を使う。

`flowchart` のノード形状は次のとおりとする。分岐は必ずひし形にする。

| 役割 | 形 | 記法 |
| --- | --- | --- |
| 開始 / 終了 | 丸（スタジアム） | `id([開始])` |
| 処理 | 四角 | `id[処理]` |
| 分岐 | ひし形 | `id{条件?}` |
| 入出力 | 平行四辺形 | `id[/入力/]` |

分岐を条件と結果の表にできる場合は、flowchartではなくマトリクステーブルを使う。

## 振る舞いの照合単位

spec の視覚的構造を、テストと実装を照合する振る舞いの単位へ分解する。

| spec の構造 | 振る舞いの単位 | Given / When / Then の読み替え |
| --- | --- | --- |
| **マトリクステーブル** | 1行 = 1振る舞い | 列を Given（条件・状態・入力）・When（操作）・Then（結果）へ読み替える。結果を変える行は別振る舞い。 |
| **状態遷移図**（`stateDiagram-v2`） | 1遷移 = 1振る舞い | `A --> B: イベント` を Given=A / When=イベント / Then=B にする。 |
| **シーケンス図**（`sequenceDiagram`） | 観測点群 | 時系列の観測可能な検証点を振る舞い単位へ割り当てる。1シーケンス=1振る舞い、または観測点ごとに分割する。1テスト=1振る舞いの原則に従う。 |

## spec セルフチェック

- [ ] すべてユーザーが観測可能な振る舞いか
- [ ] 観測不能な内部最適化や実装構造がないか
- [ ] 分岐・状態・時系列・手続きが適切な視覚表現に委ねられているか
- [ ] 各振る舞いが1箇所にのみ定義されているか
- [ ] Mermaidの各図が1主題で、ノード名・矢印ラベルが意味を持つか
- [ ] flowchartの分岐がすべてひし形か
- [ ] 冒頭だけで対象・目的・適用範囲・利用者を特定できるか
- [ ] 用語が定義され、会話中だけ通じる省略語がないか
- [ ] 履歴、文書外の文脈、候補・却下案・非目標、変更理由が混入していないか
- [ ] 配置がプロジェクト内で統一され、既存specを重複作成していないか
- [ ] 要件文書と別管理せず、specが唯一の仕様ソースになっているか
