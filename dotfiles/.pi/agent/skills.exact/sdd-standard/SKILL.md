# SDD Standard

この標準は、SDD の規則本体（spec の書き方・照合単位）と、汎用スキルへ提供する固有手続き（`references/`）を所有する。手続きの骨格は汎用スキルが担い、この標準の規則を適用する:

| 作業 | 手続き | 適用する規則 |
| --- | --- | --- |
| spec の作成・修正 | any-implement | この SKILL.md |
| spec・テスト・実装の適合性レビュー | any-review | `references/review.md`（4軸・種別・指摘形式） |
| 依頼モードと収束の管理 | any-workflow | `references/workflow.md`（依頼モード・フェーズ・収束ルール・乖離検知） |

判断の背景（旧 TDD からの転換、統合の経緯、トレードオフ）は `note.md` が記録する。

## 仕様ソースと oracle

ロジックを伴う成果物は **spec（＝観測可能な振る舞いの仕様書）** を唯一の仕様ソースとして扱う。要件文書と spec を分離して二重管理しない。適合性レビューでは spec を **oracle（真実の基準）** とし、テストと実装を照合する。

オーナーは spec だけを読んで要件を承認する。実装コードやテストの詳細は go/no-go の判断材料にしない。

## 観測可能な振る舞い

spec に記載するのは、ユーザーが直接または間接に観測できる振る舞いだけとする。

- **書く**：入出力、状態、エラー、振る舞い、パフォーマンス特性など、ユーザーに現れる結果。
- **書かない**：結果が同じなら観測できない内部最適化、関数名、クラス名、モジュール構造、DBスキーマ、内部データ構造、APIシグネチャ。
- 内部処理でも、結果としてユーザーに現れるものは書く。

## 独立した仕様書

spec は1ファイルで完結する。文書としての自己完結の規則は readable-docs-standard（`../readable-docs-standard/SKILL.md` §文書の自己完結）が所有し、spec でも適用する。spec 固有の追加規則:

- 仕様に含める対象と振る舞いを肯定形で記載する。候補・却下案・非目標を持ち込まない。

## 重複の排除

各振る舞いは1箇所にのみ定義する。重複排除の一般規則は readable-docs-standard（§重複の排除）に従う。

## 入力と配置

会話で合意した内容から、観測可能な振る舞いだけを抽出する。観測可能な具体値が定まらない場合は推測せず、ユーザーへ質問する。

- 単一機能・小規模：`SPEC.md`
- 複数機能：`spec/<feature-name>.md`
- 1プロジェクト内で `spec/` と `SPEC.md` を混在させない。既存の配置があれば維持する。
- 機能は実装モジュールではなく、ユーザーが認識する単位で切る。
- 要件文書・設計書を別ファイルで作らない。specを唯一の仕様ソースにする。

## フォーマット

Markdownで記述し、分岐・状態・時系列・順序を視覚的に構造化する。記法の選択と図表の作法は readable-docs-standard（§記法の選択・§図表の作法）に従う。

## 振る舞いの照合単位

spec の視覚的構造を、テストと実装を照合する振る舞いの単位へ分解する。

| spec の構造 | 振る舞いの単位 | Given / When / Then の読み替え |
| --- | --- | --- |
| **マトリクステーブル** | 1行 = 1振る舞い | 列を Given（条件・状態・入力）・When（操作）・Then（結果）へ読み替える。結果を変える行は別振る舞い。 |
| **状態遷移図**（`stateDiagram-v2`） | 1遷移 = 1振る舞い | `A --> B: イベント` を Given=A / When=イベント / Then=B にする。 |
| **シーケンス図**（`sequenceDiagram`） | 観測点群 | 時系列の観測可能な検証点を振る舞い単位へ割り当てる。1シーケンス=1振る舞い、または観測点ごとに分割する。1テスト=1振る舞いの原則に従う。 |

## spec セルフチェック

- [ ] すべてユーザーが観測可能な振る舞いか
- [ ] 観測不能な内部最適化や実装構造がないか
- [ ] 候補・却下案・非目標が混入していないか
- [ ] readable-docs-standard のセルフチェックを満たしているか
- [ ] 配置がプロジェクト内で統一され、既存specを重複作成していないか
- [ ] 要件文書と別管理せず、specが唯一の仕様ソースになっているか
