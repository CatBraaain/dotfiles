# Any Workflow

依頼の完了範囲を決め、要件合意 → 成果物作成 → レビュー → 承認 → 収束の順で進める。成果物の作成は any-implement の手続き、レビューは any-review の手続きに従う。

## 完了範囲

依頼文から完了範囲を決める。明示がなければ確認してから進める。

| 完了範囲 | 実行する範囲 | 停止条件 |
| --- | --- | --- |
| 成果物のみ | 要件合意 → 成果物作成 | 成果物と Verify 報告を出力したら停止 |
| 作成まで | 要件合意 → 成果物作成 → レビュー | レビューの指摘を出力したら停止 |
| レビューのみ | レビュー | 指摘のみ出力して停止 |
| 収束 | 承認済み指摘の修正 → 検証 → 再レビュー | 「高」相当の指摘が 0 件になったら完了 |

## 規則セットの組み立て

| ソース | 扱い |
| --- | --- |
| プロンプトで与えられた基準 | 最優先で採用する（ファイル化を強制しない） |
| standard スキル | SKILL.md を read する。`references/workflow.md` があればそのフェーズ・停止条件も採用する |
| 規則ドキュメント | AGENTS.md、references/ 等の規則を所有するファイルを read して採用する |

1. プロンプト基準があれば採用する。
2. タスクの性質を各 standard の適用条件と照らし、該当する standard を検出する（複数同時に該当してよい）。該当した standard の SKILL.md を read する。
3. 規則ドキュメントがあれば read して採用する。
4. 該当する規則が1つも検出できなければ質問して止まる。
5. 衝突は「プロンプト基準 > より特定された standard > より一般的な standard」の順で解決する。解決不能な衝突は任意に解釈せず質問して止まる。

## フェーズ

1. **要件合意** — 対象・目的・完了条件を依頼元と確定する。
2. **成果物作成** — any-implement の手続きで成果物を作る。
3. **レビュー** — any-review の手続きで指摘を出す。指摘のみで停止し、この時点では対象を編集しない。
4. **承認** — 依頼元が指摘と修正方針を承認する。
5. **収束** — 承認後に指摘を修正し、規則セットの検証と再レビューを繰り返す。「高」相当の指摘が 0 件になったら完了する。

standard スキルに `references/workflow.md` があれば、そのフェーズ・停止条件を本フェーズの代わりに適用する。

## 収束ルール

「高」「低」は any-review の指摘の重要度（デフォルト）を指す。standard スキルの `references/review.md` が重要度を変更する場合は、その定義に従う。

- 承認前に成果物を直さない。
- 承認後は承認済みの指摘だけを修正する。
- 「低」の指摘は残っていても完了を妨げない。残す場合は完了報告に理由を記載する。

## 境界（やらないこと）

- 完了範囲を依頼文から確定できないまま、推測で進めない。
- レビューと修正を同じタイミングで行わない。レビューは指摘で停止する。
