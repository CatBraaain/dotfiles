# Review

## 前提と知識

- コンテキストは、対象、目的、契約、原則、根拠からなる。入力はどの文書形式でもよく、これらに対応する名称や区分を持つ必要はない。
- 契約は、対象が満たすと表明・要求された、成否を確認できる約束である。
- 原則は、目的に向けた判断軸であり、契約のように直接の成否を確認できないことがある。
- 根拠は、対象またはコンテキスト内の、判定を裏付ける箇所・事実である。
- 反証テストは、原則の前提を保ったまま、その原則と両立しない結果を示せるかを確かめるテストである。skip は、対象外または評価しない項目とその理由を示す記録である。

## 原則

- 入力の名称、節構成、規則間の優先順位ではなく、与えられたコンテキストに含まれる対象、目的、契約、原則、根拠を判断の基準にする。

## 契約

1. コンテキストから対象、目的、契約、原則、根拠を特定する。入力がどのように記述されていても、対応する内容を抽出する。
2. 契約ごとに、対象と根拠を照合し、成功・失敗・判定不能のいずれかを決める。
3. 原則ごとに、その前提と両立する反証テストを組み、対象と根拠に適用する。結果を反証あり・反証なし・判定不能として記録し、反証ありまたは判定不能には重要度を付ける。
- 原則への適合を宣言で済ませず、前提と両立する反証を探す。
4. 契約、原則、skip、サマリを出力する。各契約には判定と根拠を、各原則には反証テスト、結果、重要度、根拠を含める。

- 契約の失敗・判定不能と、原則の反証あり・判定不能には、対象内の場所、重要度、根拠、目的に適合する修正案を付ける。重要度は高または低とし、放置すると目的または契約の達成を妨げるものを高、それ以外を低とする。重要度は修正・承認・収束の自動判断には使わない。
- 対象、コンテキスト、目的のいずれかが評価に必要な範囲で不足するときは、不足情報を質問して停止する。このとき対象を編集せず、契約を再定義せず、修正を承認せず、収束しない。
- 評価中も対象を編集せず、契約を再定義せず、修正を承認せず、収束しない。
- 出力は次の区分をすべて含める。該当項目がない区分は「なし」とし、評価しない項目は skip に理由を記録する。

| 区分 | 必須内容 |
| --- | --- |
| 契約 | 契約ごとの判定（成功・失敗・判定不能）、失敗・判定不能時の重要度（高・低）、根拠 |
| 原則 | 原則ごとの反証テスト、結果（反証あり・反証なし・判定不能）、反証あり・判定不能時の重要度（高・低）、根拠 |
| skip | 評価しない項目と理由 |
| サマリ | 対象ごとの高・低の件数と最高重要度（高・低・該当なし）。対象が複数なら対象ごとに契約・原則・skipを分ける。 |
