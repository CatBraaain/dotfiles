# Any Review

規則セットを組み立て、対象を照合軸に従って評価し、指摘のみを出力する。対象を編集しない。

## 規則セットの組み立て

| ソース | 扱い |
| --- | --- |
| プロンプトで与えられた基準 | 最優先で採用する（ファイル化を強制しない） |
| standard スキル | SKILL.md を read する。`references/review.md` があればその照合軸・種別・指摘形式も採用する |
| 規則ドキュメント | AGENTS.md、references/ 等の規則を所有するファイルを read して採用する |

1. プロンプト基準があれば採用する。
2. タスクの性質を各 standard の適用条件と照らし、該当する standard を検出する（複数同時に該当してよい）。該当した standard の SKILL.md を read する。
3. 規則ドキュメントがあれば read して採用する。
4. 該当する規則が1つも検出できなければ質問して止まる。
5. 衝突は「プロンプト基準 > より特定された standard > より一般的な standard」の順で解決する。解決不能な衝突は任意に解釈せず質問して止まる。

## 照合軸

standard スキルに `references/review.md` があれば、その軸・種別・指摘形式を適用する。無ければ次の内蔵2軸で照合する。軸ごとの種別は次の通り:

- **oracle 適合** — 対象が規則の規範・Verify に適合するか。種別は出典（違反した規則の該当セクション等）とする。
- **目的適合** — 対象が本来の目的を観測可能な振る舞いとして満たすか。種別は欠落 / ズレ / 過剰とする。目的は依頼元からの供与を優先し、無ければ対象から推定する。

## 実行プロセス

1. 規則セットを組み立てる（上記の手順に従う）。
2. 照合軸を決定する（`references/review.md` または内蔵2軸）。
3. 軸ごとに独立したコンテキスト（sub-agent 等）で評価し、書き手のバイアスを抜く。レビューへの入力は対象と規則セットに限定する（依頼元から目的が供与された場合は加える）。
4. 指摘（場所・種別・重要度・引用・修正案）のみを出力する。
5. 推定不能で評価できなかった項目は skip として報告する。

## 指摘の重要度（デフォルト）

- **高** — 指摘を放置すると目的不達成・誤実行につながる。
- **低** — 品質・整理の改善にとどまる。

重要度の段階をドメイン向けに変えるときは、standard 側の `references/review.md` が宣言する。

## 出力形式

軸ごとに見出しを分けて指摘を列挙する。指摘がない軸は「指摘なし」と記載する。対象が複数の場合は、対象ごとに軸の見出しを分けて報告する。目的を推定して評価した軸は、推定した目的と根拠を見出し直下に1回だけ明示する。skip は出力の末尾に1回だけ列挙し、末尾に軸ごとの指摘数と最高重要度のサマリを付ける。

````markdown
## <軸名>

（目的を推定した場合）推定した目的: <対象のどこを根拠に推定したか>

- 対象: <ファイルパス> / 重要度: <高|低> / 種別: <軸の定義する種別>
  該当箇所:
  ```markdown
  （対象の該当箇所を引用する）
  ```
  修正案: （具体的な文・構造の提案）

skip: <評価できなかった項目、または「なし」>

## サマリ

- <軸名>: <指摘数>件（最高重要度: <高/低> または 指摘なし）
````

指摘リストと skip 報告以外の出力（対象の編集、依頼外のファイル変更、余計な解説）はしない。

## 境界（やらないこと）

- **修正を適用しない** — 指摘のリストアップまで。修正は依頼元、または承認後の収束フェーズ（any-workflow）で行う。
- **規則を再定義しない** — standard スキル・規則ドキュメントを正とする。規則自体の変更提案は出さない。
