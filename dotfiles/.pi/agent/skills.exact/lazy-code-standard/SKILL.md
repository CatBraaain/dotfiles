# Lazy Code

動作要件と安全境界を満たす、保守対象が最も小さいコードを選ぶ。上書きより削除、賢いコードより退屈なコード、自作より既存の仕組みを優先する。

readable-code-standard は、ここで残したコードを読みやすくする規則を所有する。

## 適用範囲

- 適用する: コードの実装・修正・リファクタ・設計・依存選定・レビュー。
- 適用しない: コードを変更・評価しない調査、文書、設定だけの作業。残ったコードの名前・構造・コメントの可読性は readable-code-standard が所有する。

実装前に、変更対象と実際のデータ・制御の流れを読む。バグ修正では、変更候補の関数の呼び出し元をすべて検索し、根本原因を変更対象にする。

## Decision Ladder：最小の実装

### 目標

明示された受入条件と安全境界を満たす最初の段で止める。

### 適用範囲

上記の適用範囲にある作業で、実装方法を選ぶときに使う。

### 段

#### 第1段：変更しない

- 適用条件：現状が明示された受入条件を満たす、または要求が投機的である。
- 実行内容：コードを変更せず、満たしている根拠または不要な理由を記録する。
- 停止条件：明示された要求に未達がない。
- エスカレーション条件：受入条件が未達である。

#### 第2段：既存の仕組みを再利用する

- 適用条件：既存の helper、型、パターンが受入条件を満たせる。
- 実行内容：既存の仕組みを再利用する。
- 停止条件：重複実装なしに受入条件を満たす。
- エスカレーション条件：既存の仕組みだけでは受入条件を満たせない。

#### 第3段：標準ライブラリを使う

- 適用条件：言語の標準ライブラリだけで受入条件を満たせる。
- 実行内容：標準ライブラリを使う。
- 停止条件：新規依存や自作の汎用処理なしに受入条件を満たす。
- エスカレーション条件：標準ライブラリだけでは受入条件を満たせない。

#### 第4段：プラットフォーム機能を使う

- 適用条件：ブラウザ、CSS、DB制約などのプラットフォーム機能だけで受入条件を満たせる。
- 実行内容：プラットフォーム機能を使う。
- 停止条件：アプリケーションコードを追加せずに受入条件を満たす。
- エスカレーション条件：プラットフォーム機能だけでは受入条件を満たせない。

#### 第5段：既存の依存を使う

- 適用条件：導入済みの依存だけで受入条件を満たせる。
- 実行内容：導入済みの依存を使う。
- 停止条件：新規依存や自作の汎用処理なしに受入条件を満たす。
- エスカレーション条件：導入済みの依存だけでは受入条件を満たせない。

#### 第6段：単一式で実装する

- 適用条件：1つの式または文で、受入条件と安全境界を満たせる。
- 実行内容：単一式または文を追加・変更する。
- 停止条件：抽象、設定、補助ファイルを増やさずに受入条件を満たす。
- エスカレーション条件：単一式または文では受入条件を満たせない。

#### 第7段：最小の固有コードを書く

- 適用条件：上位の段では受入条件を満たせない。
- 実行内容：必要な固有コードだけを追加・変更する。
- 停止条件：投機的な抽象、将来用の設定、未使用の拡張点を含まずに受入条件を満たす。
- エスカレーション条件：新規依存、許可範囲外の変更、または要件不明のため、実装前の承認が必要である。

### 例外

- 明示要求、信頼境界での入力検証、データ損失を防ぐエラーハンドリング、セキュリティ、アクセシビリティの基本は、より小さい段のために省略しない。
- 新規依存は、明示要求または承認なしに追加しない。

### 最終フォールバック

受入条件、入力、完了条件を特定できない場合は、推測で実装せず確認を求める。複雑な要求で最小版と完全版のどちらを求めるか特定できない場合は、最小版の範囲と省略範囲を示して確認を求める。明示された受入条件を満たす実装では、確認のために停止しない。

### 検証

対象と実際の流れを読んだ根拠、選択した段、受入条件を満たすテストまたは観測結果を確認する。バグ修正では、呼び出し元の検索結果と根本原因への変更を確認する。

## 禁止

- 要求されていない抽象、将来用のスキャフォールド、使われないパラメータや設定を追加しない。
- 同じ機能を既存実装の探索なしに再実装しない。
- 既知の上限を持つ簡略化を、上限と移行条件の記録なしに採用しない。

既知の上限を持つ簡略化には、上限とアップグレード条件を示す `ponytail:` コメントを残す。例: `# ponytail: account は 100 件以下。超えたら indexed lookup に置き換える`。

## 出力

コードをチャットに出力する場合だけ、コードの後に省略したものと追加条件を最大3行で示す。実装していない追加ファイル、抽象、依存は出力しない。

例:

```text
skipped: retry queue, add when the API exposes retryable failures
```

## Verify

該当する項目をすべて満たす。

- [ ] Decision Ladder の最初に受入条件を満たす段を選んだ。
- [ ] 対象と実際の流れを読んでから変更した。
- [ ] 明示要求と安全境界を省略していない。
- [ ] 新規依存、投機的な抽象、未使用の拡張点を追加していない。
- [ ] 既知の上限を持つ簡略化に `ponytail:` コメントがある。
- [ ] バグ修正では、呼び出し元を検索し根本原因を変更した。
