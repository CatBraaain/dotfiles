# Instruction Review

レビューで収束させる。書いた本人のコンテキストから離れ、別コンテキストで2軸を確認する。

## 入力

| 入力 | 必須/任意 | 内容 |
| --- | --- | --- |
| 対象指示テキスト（ファイルとして残るもの） | 必須 | ファイルパスまたはテキスト本文 |
| 本来の目的 | 任意 | Spec 軸の評価基準。欠如時は対象テキストから書かれている目的を推定し、推定不能な項目は skip 報告する |

## 実行プロセス

1. **対象を同定** — 残る指示テキスト（ファイル）か確認する。対象外の判定は境界に従う。対象外と判定した場合は、その旨と境界の該当項目を報告して停止する（指摘は出力しない）。
2. **基準を読み込む** — `../instruction-standard/SKILL.md`（品質基準・記法・配置規範・Forbidden / Output Contract / Verify）を read する。
3. **2軸で評価** — Standards 軸と Spec 軸は、それぞれ別の独立したコンテキスト（sub-agent セッション等）で評価し、書いた本人のバイアスを抜く。レビューへの入力は対象テキストと基準に限定する（依頼元から本来の目的が供与された場合はそれを加える）。
   - **Standards 軸** — 対象テキストが instruction-standard の規範を満たすか。
   - **Spec 軸** — 対象テキストが本来の目的を観測可能な振る舞いとして縛っているか。観点は次の3つ:
     - **欠落** — 目的達成に必要な観測可能な完了条件・出力・停止点が抜けていないか。
     - **ズレ** — 手続きを守っても目的が達成されない、または目的達成に不要なステップがないか。
     - **過剰** — 目的と無関係な縛り・手続きがないか。
4. **集約して報告** — 軸間で統合・再ランキングしない。対象テキストの全セクションを両軸の全観点で評価し、各軸の指摘（または「指摘なし」）と skip 報告を出力した時点で完了とする。

## 指摘の重要度

各指摘に次の3段階を付ける:

- **高** — 指摘を放置すると指示の誤解釈・誤実行につながる。
- **中** — 指摘を放置すると品質・保守性が下がる。
- **低** — 表現・整理の改善にとどまる。

## 出力形式

2軸を併記する。指摘がない軸は「指摘なし」と記載する。対象が複数の場合は、対象ファイルごとに Standards / Spec の見出しを分けて報告し、推定した目的と根拠もファイルごとに1回とする。指摘1件の必須要素は、Standards 軸が「対象・重要度・出典（instruction-standard のセクション名）・該当箇所の引用・修正案」、Spec 軸が「対象・重要度・該当箇所の引用・欠落/ズレ/過剰の区別・修正案」（推定した目的と根拠は Spec セクション冒頭に1回）。skip した項目は Spec セクションの末尾に列挙する（なければ「skip なし」）。指摘リストと skip 報告以外の出力（対象テキストの編集、依頼外のファイル変更、余計な解説）はしない。

````markdown
## Standards

- 対象: instruction-hoge/SKILL.md / 重要度: 中 / 出典: Forbidden「重複する記述」
  該当箇所:
  ```markdown
  （対象テキストの該当箇所を引用する）
  ```
  修正案: （具体的な文・構造の提案）

## Spec

- 推定した目的: （対象テキストのどこを根拠に推定したかを引用する）
- 対象: instruction-hoge/SKILL.md / 重要度: 中 / 種別: 欠落
  該当箇所:
  ```markdown
  （対象テキストの該当箇所を引用する）
  ```
  修正案: （具体的な文・構造の提案）

skip: なし

## サマリ

- Standards: <指摘数>件（最高重要度: <高/中/低> または 指摘なし）
- Spec: <指摘数>件（最高重要度: <高/中/低> または 指摘なし）
````

## 境界（やらないこと）

- **修正を適用しない** — 指摘のリストアップまで。対象テキストの編集は依頼元が行う。
- **方針を再定義しない** — `../instruction-standard/SKILL.md` を正とする。規範自体の変更提案は出さない。
- **コード・spec・設定は対象外** — 残る指示テキスト以外は review しない。
- **使い捨てプロンプトは対象外** — 収束の必要がないため instruction-standard の Verify で完結する。
