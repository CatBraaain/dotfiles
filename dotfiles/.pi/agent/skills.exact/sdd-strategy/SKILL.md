# SDD Strategy

作業開始時に `sdd-standard` スキルを読み、SDD の共通規約を適用する。

本スキルは、spec の作成だけを行う場合を含め、SDD の入口と収束フローを一つに定める。背景・判断経緯・トレードオフは `note.md` に置く。共通の spec 作成規約は `sdd-standard` スキル、spec・テスト・実装の適合性レビューは `sdd-review` が担う。

## 依頼モード

依頼文に明示された完了範囲を次の表で決める。明示がないロジック変更は、spec-only か実装まで行うかを確認してから進める。

| 依頼 | 実行する範囲 | 変更してよいもの | 停止条件 |
| --- | --- | --- | --- |
| specだけ作成・specを整理 | 要件確認 → spec作成・修正 → specセルフチェック | specのみ | specを出力し、実装・テスト・レビューを行わず停止 |
| 実装して | 要件確認 → spec → go/no-go → 実装・テスト → `sdd-review` | spec、テスト、本番コード | `sdd-review` のギャップレポートと修正案を提示して停止 |
| 適合性をレビューして | `sdd-review` による spec・テスト・実装の照合 | 変更しない | ギャップレポートのみを出力して停止 |
| 指摘を直して収束して | 承認済み `sdd-review` 結果に基づく修正 → 検証 → `sdd-review` | 承認された範囲のspec、テスト、本番コード | blocking 指摘が0件になり、検証が通る |

spec-only モードでは、要件が曖昧・欠落している場合に推測で spec を完成させず、追加質問で停止する。spec の変更は要件変更に相当するため、実装中に spec を変更した場合は go/no-go をやり直す。

## 全体フロー

1. **要件合意** — 会話で対象、利用者、観測可能な振る舞い、適用範囲を確定する。
2. **spec 整備** — 下記の spec 作成規約に従い、`SPEC.md` または `spec/<feature-name>.md` を新規作成・修正する。
3. **go/no-go** — オーナーが spec を読み、要件を承認する。spec-only モードはここで停止する。
4. **実装** — 承認済み spec に対応するテストと本番コードを作る。テストは AI の収束作業用で、オーナーは内容を確認しない。
5. **適合性レビュー** — `sdd-review` を使い、spec・テスト・実装を照合する。レビューでは編集・テスト実行をしない。
6. **収束** — オーナーがレビュー結果を承認した後、承認範囲のギャップを修正し、通常の検証と `sdd-review` による再レビューを繰り返す。blocking 指摘0件で完了する。

設定ファイル群だけの変更は、このフローの対象外とする。ただし、設定がユーザーに観測可能なロジックを持つ場合は対象に含める。

## 収束ルール

- `sdd-review` による初回レビューは指摘のみとし、テスト・本番コード・specを編集せず、テストも実行しない。
- 初回レビューの出力は、ギャップの場所・種別・重要度と、修正案までに限定する。修正を適用せず停止する。
- オーナーが収束実行を承認した場合は `/new-session` で切り替えてから、specと現状コードを入力として収束を開始する。前段の会話ノイズを持ち込まない。
- 収束実行では、承認済みの修正範囲だけを変更し、format・lint・typecheck・testなどプロジェクトの検証を実行してから再レビューする。
- specを変更する修正は要件変更である。変更後はオーナーの再承認なしに実装・再レビューを続けない。
- 適合性レビューの照合軸・指摘種別・出力形式は `sdd-review/SKILL.md` に従う。
- informational 指摘は残っていても blocking 指摘0件なら完了条件を満たす。ただし、残した理由を完了報告に記載する。

## 乖離検知

- commit/PRなどの変更確認では、変更ファイルに対応する spec セクションを差分ベースで AI に一致チェックさせる。全文一致は行わない。
- spec とテストをIDで機械的に紐付けない。specとテストの対応、テストと実装の忠実性、実装のspec外振る舞いは、`sdd-review` が照合する。
- 最終防波堤は AI レビューである。テストの実行成功だけを、specとの一致の証拠として扱わない。

spec の作成規約とセルフチェックは `sdd-standard` スキルに従う。
