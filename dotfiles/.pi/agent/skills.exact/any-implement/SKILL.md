# Any Implement

作業開始時に規則セットを組み立て、その規則に従って成果物を作る。規則の本体（適用条件・記法・Verify）は standard スキルや規則ドキュメントが所有し、このスキルは手続きの骨格だけを持つ。

## 規則セットの組み立て

| ソース | 扱い |
| --- | --- |
| プロンプトで与えられた基準 | 最優先で採用する（ファイル化を強制しない） |
| standard スキル | SKILL.md を read する。`references/implement.md` があればその作成手続きも採用する |
| 規則ドキュメント | AGENTS.md、references/ 等の規則を所有するファイルを read して採用する |

1. プロンプト基準があれば採用する。
2. タスクの性質を各 standard の適用条件と照らし、該当する standard を検出する（複数同時に該当してよい）。該当した standard の SKILL.md を read する。
3. 規則ドキュメントがあれば read して採用する。
4. 該当する規則が1つも検出できなければ質問して止まる。
5. 衝突は「プロンプト基準 > より特定された standard > より一般的な standard」の順で解決する。解決不能な衝突は任意に解釈せず質問して止まる。

## 成果物を作る

組み立てた規則に従って成果物を作る。standard スキルに `references/implement.md` があればその手続きを適用する。入力・完了条件・出力範囲が確定しないときは、推測で書き始めず質問して止まる。

## 自己検証して出力する

- 規則セットの Verify（チェックリスト等）で自己検証し、未達項目を潰してから出力する。
- 成果物とともに `Verify: n/n 合格` の形式で検証結果を報告する。Verify を持つ規則がなければ、完了条件への適合を観測可能な形（テスト成功・生成ファイルのパス等）で報告する。
- Verify 項目のうち対象に適用できないものは、理由を添えて適用外として列挙する（例: `Verify: 3/3 合格（適用外: 記法の項目 — 対象が手続きを持たないため）`）。
- 依頼された成果物と検証結果だけを出力し、依頼外の追加をしない。

## 境界（やらないこと）

- 規則が1つも検出できないまま成果物を作らない。
- レビュー・承認・収束の管理は扱わない。そこまで伴う依頼は any-workflow に従う。
