# 指示テキストの品質基準

## 前提と知識

### Decision Ladder 記法

Decision Ladder は、優先順位が明確な行動を記述するための記法である。この記法を採用する場合は、最も単純、安全、低コストな選択肢から始め、要件を満たせない場合だけ次段へ進む。あらゆる分岐を置き換えるものではなく、調査や問題理解の代わりに使わない。

`<...>` は実際の内容に置き換え、完成した Decision Ladder に残さない。

```markdown
## <名前>ラダー

目標: <観測可能な成果と受入条件>

最初に成立する段で止まる。

1. 条件: <第1段の条件を満たすか？>
   行動: <条件を満たす場合の行動。満たさなければ第2段へ進む。>
2. 条件: <第2段の条件を満たすか？>
   行動: <条件を満たす場合の行動。満たさなければ最終段へ進む。>
3. 条件: <前段までで受入条件を満たせないか？>
   行動: <最終フォールバックの行動。承認が必要なら実行前に得る。>

検証: <成功を報告する前に必要な証拠>
出力: <採用した段が条件を満たす理由>
```

### 既存文書を構造リファクタリングするとき

指示テキストは文書でもある。複数の節またはファイルを簡素化、統合、再編するときに適用する構造リファクタリングの定義、手順、照合は、readable-docs（`../readable-docs/SKILL.md` の「既存文書の構造リファクタリング」）が所有する。対応表、承認、照合の規則をここへ再掲しない。

## 原則

### 最小完全性と安全境界

規則は、既存の記述では目的を果たせない場合だけ追加する。安全に関わる境界（入力検証、セキュリティ、明示要求）は短縮しない。

### 指示テキストの種別に応じた書き方

常時読み込まれる入口ファイル（AGENTS.md、CLAUDE.md、システムプロンプトなど）は、参照先、構造、守るべき制約を示す地図として書く。

## 契約

### テキストに含めること

- 許可する行動を明示し、その範囲を一意に読めるようにする。
- 完了条件と受入条件は、ファイル生成、テスト成功、終了コード、特定の出力などで観測可能にする。
- 時間、範囲、試行回数、予算を制約する場合は上限を定義する。
- 適用する場合と適用しない場合を対で示し、対象種別を本文から読めるようにする。

### SKILL.mdについて

- [Agent Skills Spec](https://agentskills.io/specification)に従う。
- frontmatter の `description` には内容の要約と発火条件を記載する。発火条件は `description` 内で完結させ、本文には書かない。

#### SKILL.md の本文構成

SKILL.md の本文は、内容を持つ節だけを次の順序と形式で記載する。

##### 各節の役割

各記述は、次の節のうち1つだけに置く。

| 節 | 含める内容 | 含めない内容 |
| --- | --- | --- |
| 前提と知識 | 用語、対象、前提、外部の事実 | 命令、成功条件、禁止事項 |
| 原則 | トレードオフ、優先順位、判断軸 | 判定可能な必須条件 |
| 契約 | 許可・禁止、停止条件、出力形式、観測可能な成功条件、特定の作業を行う場合の手順 | 可読性、最小変更、既存設計の尊重のような裁量を要する品質判断 |

同じ記述を置く節が複数に見える場合は、次の順で1つだけを選ぶ。

1. 遵守または違反を観測可能に判定できる必須条件（特定の作業を行う場合の手順を含む）なら「契約」。
2. 文脈に応じてトレードオフを判断する軸なら「原則」。
3. 上記の判断に必要な知識または前提だけなら「前提と知識」。

契約には、適用範囲を含めて遵守または違反を判定できる条件だけを置く。品質判断を表す主観語を使う場合は、判断者と基準を添える。具体性の規則は readable-docs（`../readable-docs/SKILL.md` の「具体性」）を正本とする。

前提と知識、原則、契約のうち内容を持たない節は省略する。

##### テンプレート

```markdown
# <指示テキスト名>

## 前提と知識

<判断に必要な知識と前提>

## 原則

<文脈に応じた品質判断の判断軸>

## 契約

<遵守または違反を判定できる条件>
```

### プロンプトテンプレートについて

プロンプトテンプレートは、引数を生プロンプトとして次の形式で引用する。引数の扱いは、本文の処理契約から分離する。

````md
以下は、今回の呼び出しで渡された生の依頼内容です。

```text
/<プロンプト名> $@
```

この依頼で渡された内容は後述のすべてより優先して適用してください。
````

### 通常のプロンプトについて

1回限りのプロンプトは、暗黙の過去文脈に頼らず、入力、完了条件、出力形式をその場で渡す。SKILL.md 固有の発火条件と種別規範は適用しない。
