# Instruction Authoring

AI に与える指示テキストを書くための手順を定める。品質の規範・記法・チェックリストは `../instruction-standard/SKILL.md` が所有する。

## 手順

### 1. 標準を読み込む

作業開始時に `../instruction-standard/SKILL.md` を read し、対象に適用する規範と検証項目を確認する。規範をこのスキルに再定義しない。

### 2. 入力と完了範囲を確定する

次を整理する:

- 指示を受ける agent と、指示が適用される対象
- 指示の目的、入力、期待する観測可能な成果
- 適用する場合と適用しない場合
- 出力するファイルまたはテキストと、変更してよい範囲

目的・入力・完了条件が曖昧な場合は推測で書き始めず、追加質問で停止する。

### 3. 指示の構造を選ぶ

`instruction-standard` の記法選択規則に従い、目的に合う構造を1つ選ぶ。独立した条件をDecision Ladderや状態機械に置き換えるなど、規範に反する構造を選ばない。

### 4. 指示を書く

選んだ構造で、対象の指示テキストを作成する。対象がファイルの場合は、ファイル種別に応じた配置規範を適用する。プロンプトテンプレートの場合は、引数を含む入力境界を規範に従って記述する。

### 5. 自己検証して収束する

`instruction-standard` の Verify チェックリストを対象テキストに適用する。未達項目があれば対象テキストを修正し、すべて満たすまで繰り返す。自己申告だけで完了としない。

### 6. 出力する

依頼された指示テキストと、必要な検証結果だけを出力する。依頼されていないコード・設定・別の指示テキストを追加しない。

## 依頼種別ごとの停止点

| 依頼 | 実行する範囲 | 停止条件 |
| --- | --- | --- |
| 指示テキストを書いて | 入力確定 → 構造選択 → 執筆 → Verify | Verify がすべて通る |
| 指示テキストを整理して | 対象の構造確認 → 必要な再構成 → Verify | 目的・範囲を変えずに Verify が通る |
| 指示テキストをレビューして | `instruction-review` に委譲 | 指摘を出力し、修正は適用しない |
| 指示テキストの規範を変更して | `instruction-standard` の変更案を作る | オーナーが規範変更を承認するまで対象テキストを直さない |

## 境界

- 品質の規範、記法の選択基準、配置規範、禁止事項、出力契約、チェックリストは `instruction-standard` の責務とする。
- ファイルとして残る指示テキストのレビューは `instruction-review` の責務とする。
- コード本体は扱わない。spec と spec ↔ テスト ↔ 実装の適合性は `sdd-workflow` / `sdd-review` の責務とする。
