# Instruction Authoring

## 手順

### 1. 標準を読み込む

作業開始時に `../instruction-standard/SKILL.md` を read し、対象に適用する規範と検証項目を確認する。

### 2. 入力と完了範囲を確定する

次を整理する:

- 指示を受ける agent と、指示が適用される対象
- 指示の目的、入力、期待する観測可能な成果
- 適用する場合と適用しない場合
- 出力するファイルまたはテキストと、変更してよい範囲

目的・入力・完了条件・指示を受ける agent と適用対象・適用する場合としない場合・出力先と変更範囲のうち、依頼者から確認できないものがある場合は、推測で書き始めず追加質問で停止する。

### 3. 指示の構造を選ぶ

`instruction-standard` の記法選択規則（性質と記法の対応表）に従い、目的に合う構造を1つ選ぶ。判断ロジックをフラットな箇条書きで羅列しない。

### 4. 指示を書く

選んだ構造で、対象の指示テキストを作成する。骨格は「目的 → 適用する場合と適用しない場合 → 手続き（選んだ記法） → 完了条件と出力形式」の順を基本とする。対象がファイルの場合は、ファイル種別に応じた配置規範を適用する。プロンプトテンプレートの場合は、引数を含む入力境界を規範に従って記述する。

### 5. 自己検証して収束する

`instruction-standard` の Verify チェックリストを対象テキストに適用する。未達項目があれば対象テキストを修正し、すべて満たすまで繰り返す。自己申告だけで完了としない。

### 6. 出力する

依頼された指示テキストと、必要な検証結果だけを出力する。指示テキスト本体の形は手順4の骨格と手順3で選んだ構造に従う。依頼されていないコード・設定・別の指示テキストを追加しない。「直して」「整理して」の依頼では、Verify 行に加えて依頼種別ごとの停止点が定める対比を報告する。検証結果は次の形式で報告する（適用した Verify 項目数に置き換える。適用外の項目は理由を添えて列挙する）:

```text
Verify: 14/14 合格（適用外: trigger、スキル配置 3項目 — 対象が入口ファイルのため）
```

## 依頼種別ごとの停止点

| 依頼 | 実行する範囲 | 停止条件 |
| --- | --- | --- |
| 指示テキストを書いて | 入力確定 → 構造選択 → 執筆 → Verify | Verify の適用項目がすべて通る |
| 指示テキストを整理して | 対象の構造確認 → 必要な再構成 → Verify | 整理前後で目的・入力・適用範囲の一致を対比して報告し、Verify が通る |
| 指示テキストを直して | 問題箇所の読解 → 当該箇所の修正 → Verify | 指摘ごとに解消後の該当箇所を対比して報告し、Verify が通る |
| 指示テキストをレビューして | `instruction-review` に委譲 | 指摘リストを出力した時点（対象テキストは編集しない） |
| 指示テキストの規範を変更して | `instruction-standard` の変更案を作る | 変更案を出力して承認待ちで停止する（承認前に対象テキストを直さない） |

## 境界

- 適用対象の種別は `instruction-standard` の適用条件に従う。
- 品質の規範、記法の選択基準、配置規範、禁止事項、出力契約、チェックリストは `instruction-standard` の責務とする。
- ファイルとして残る指示テキストのレビューは `instruction-review` の責務とする。
- コード本体は扱わない。spec と spec ↔ テスト ↔ 実装の適合性は `sdd-workflow` / `sdd-review` の責務とする。
