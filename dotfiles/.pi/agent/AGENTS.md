# AGENTS.md

## 動作

- チャットでは必ず日本語で回答すること
- プログラミングのソースコードでは必ず英語を使用すること
- 実装・編集を行うのは、成果物を伴う動詞(実装・編集・修正・追加・削除・リファクタ・変更など)による明示的な指示のときだけ。「直せる？」「やってくれる？」「～お願い」「～して」等の依頼表現も指示に含む
- 「～してほしい」「～と思う」「～と思っている」「～かな」「どう思う？」等は意志表明・意見募集であり指示ではないので相談として扱い、実装しない
- 質問・相談には回答のみを行い、明示的な指示がない限りファイルを編集しない。判断に迷ったときは実装せず確認を返す

## タスク管理

複数ステップの計画は `{プラン名}.plan.md` を作り、ファイルベースでタスク管理を行う

## 技術スタック

- `python`は直接使わずに `uv` 経由で使う。独立した単一スクリプトは先頭に PEP 723 インラインメタデータを入れ、`pyproject.toml` 不要で `uv run script.py` だけで実行できるようにする。
- タスクランナーは基本的に `just` を使う。ただし JS プロジェクトの場合は `package.json` の npm-scripts を使う。
- JS/TS のパッケージマネージャー（pnpm, bun, vp 等）はプロジェクトごとに確認。
- 上記で規定されていない事項は都度確認。

## ビルド

- ビルド成果物は `dist/` ディレクトリに出力する。ただし cargo の場合はデフォルトの `target/` ディレクトリを使う。

## テスト

テストコードは品質保証判定の最終成果物であり、自然言語に近い読みやすさが求められる。テストでは常に可読性を優先する。
以下は可読性を上げるためのルールである。

- 変数名は、入っているデータを具体的に名詞で表す。`data` `info` `value` のような中身が不明な名前は避ける。
- コメントは原則禁止。変数名などソースコードで意味が理解できるようにする。ただし、イレギュラーな処理などに対するwhyの説明部分のみコメントは許される。
- 1つのテスト単位（it/test）では1つの確認に絞る。複数ケースは別テストに分ける。
- assert では説明変数を優先し、何と何を比較してどうなっているかが自然言語の感覚で読めるようにする（自明な場合は省略してよい）。

## 品質管理

編集後は必ず該当するリンター、フォーマッター、タイプチェック、テストを実行すること。プロジェクトに既存の設定・依存があればそれを優先し、なければ以下のデフォルトを使う。

- **Python**: `ruff format`, `ruff check`, `ty`, `pytest`
- **JavaScript/TypeScript**: (`vp format` or `oxfmt`), (`vp check` or `oxlint`), `vitest`
