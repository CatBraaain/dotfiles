# AGENTS.md

## 動作

- チャットは日本語で、常体（だ・である調・体言止め）で簡潔に書く。敬体（です・ます）と前置き・言い換えの重複は省く
- プログラミングのソースコードでは必ず英語を使用すること
- 実装・編集を行うのは、成果物を伴う動詞(実装・編集・修正・追加・削除・リファクタ・変更など)による明示的な指示のときだけ。「直せる？」「やってくれる？」「～お願い」「～して」等の依頼表現も指示に含む
- 「～してほしい」「～と思う」「～と思っている」「～かな」「どう思う？」等は意志表明・意見募集であり指示ではないので相談として扱い、実装しない
- 質問・相談には回答のみを行い、明示的な指示がない限りファイルを編集しない。判断に迷ったときは実装せず確認を返す
- チャットで markdownコードブロック を出力するときは、それを4 backticks で囲み。markdown以外のコードブロックは3 backticks で囲う

## タスク管理

複数ステップの計画は `{プラン名}.plan.md` を作り、ファイルベースでタスク管理を行い、計画実装の完了時はそのパスを明示すること。

## Abbreviations

- `kwsk`: 詳しく教えて
- `is nani`: ~は何?

## 技術スタック

- `python`は直接使わずに `uv` 経由で使う。独立した単一スクリプトは先頭に PEP 723 インラインメタデータを入れ、`pyproject.toml` 不要で `uv run script.py` だけで実行できるようにする。
- タスクランナーは基本的に `just` を使う。ただし JS プロジェクトの場合は `package.json` の npm-scripts を使う。
- JS/TS のパッケージマネージャー（pnpm, bun, vp 等）はプロジェクトごとに確認。
- 上記で規定されていない事項は都度確認。

## ビルド

- ビルド成果物は `dist/` ディレクトリに出力する。ただし cargo の場合はデフォルトの `target/` ディレクトリを使う。

## テスト

テストを書くときは必ず `~/.pi/agent/references/readable-test.md` を読み、可読性ルールに従うこと。

## 編集前の確認

ファイルを編集する前に必ず read し、対象ファイルの現状を確認する。会話途中で読んだ内容や以前の read 結果を記憶で信用して編集せず、常に最新の read 結果を正とする。記憶と現状が乖離している場合は現状に合わせる。

## 品質管理

編集後は必ず該当するリンター、フォーマッター、タイプチェック、テストを実行すること。プロジェクトに既存の設定・依存があればそれを優先し、なければ以下のデフォルトを使う。

- **Python**: `ruff format`, `ruff check`, `ty`, `pytest`
- **JavaScript/TypeScript**: (`vp format` or `oxfmt`), (`vp check` or `oxlint`), `vitest`

## 調査タスク

検索結果・ウェブサイト・コードベース（リポジトリ・ファイル・関数など）など、何かを説明・言及・引用するときは、該当箇所へクリックでジャンプできるリンクを必ず添える。

- ウェブ上のものは markdown link（`[text](url)`）
- ローカルファイル・コードベース内は平文のパス（markdown link にしない）

## SDD開発フロー

ロジックを伴う成果物は **spec（＝観測可能な振る舞いの仕様書）** を唯一の仕様ソースとして開発する（SDD: Spec Driven Development）。オーナーは spec だけ読んで go/no-go を出し、実装コードの詳細は読まない。フェーズ・収束ルールの詳細は `/skill:sdd-workflow` を参照。

## コーディング規範（lazy）

動く最小コードを優先する。コーディング（実装・修正・リファクタ・レビュー・設計・依存選定）の際は必ず `~/.pi/agent/references/coding-lazy.md` を読むこと。
