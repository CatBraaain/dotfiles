# オーナーへの質問

確認が必要なときは、番号付きの質問にして、質問文が単独で yes/no で答えられる形になるようにする。オーナーの認知コストを下げることが目的。

番号は質問への回答を対応させるための識別子であり、報告本文のリストとは無関係に、質問だけで 1 から振る。

- 回答記号は `y`=yes / その他は `a` から順に振る（小文字）とする
- 選択肢数にかかわらず `y/a/b/...` で統一する（`n`=no は使わない）
- 推奨案を質問文に組み込み、`(y)` を「はい」に固定する（具体値や「（おすすめ）」は置かない）
- 全選択肢を行で併記する
- 質問と選択肢をコードブロック（フェンス）で囲まず、素のテキストとして出力する
- 質問は `## 質問` 見出しのセクションに置く。見出しで質問ブロックの開始を構造的に示し、本文のリストとの連番誤結合を防ぐ
- 進め方・手順など本文の番号付きリストの連番を、質問の番号として引き継がない。質問は常に 1 から振り直す

## Bad

````
1. この実装をすすめますか？それとも計画までとしますか (y/a)
   (y) 実装をすすめる
   (a) 計画まで進める

2. テストランナーは、どうしますか？ (y/a/b)
   (y) vitest（推奨）
   (a) jest
   (b) node:test

```
3. 実装まで進めてよいですか？ (y/a)
   (y) はい
   (a) 計画までで止める
```

進め方の連番を質問に引き継いだ例:

1. rules 拡張を調査する
2. asking-format.md を修正する
3. テストを実行する

4. この手順ですすめますか？ (y/a)
   (y) はい
   (a) 手順を見直す
````

前半の例は、選択肢としては記号で答えられるが、質問文単体では yes/no で答えられないため認知コストが高い。また例2は推奨案（vitest）が質問文に乗っておらず、`(y)` が「はい」ではなく具体値になっている。例3はフォーマット自体は正しいが、質問全体をフェンスで囲んでいる。回答は記号1文字で打つため囲む利点がなく、読みづらさが増す。

後半の例は、進め方の連番 1〜3 を質問が引き継ぎ `4.` になっている。番号は質問への回答を対応させる識別子であり、本文リストの続き番号ではない。

## Good

```
## 質問

1. 実装まで進めてよいですか？ (y/a)
   (y) はい
   (a) 計画までで止める

2. テストランナーは vitest でいいですか？ (y/a/b)
   (y) はい
   (a) jest
   (b) node:test
```

本文の番号付きリストに続けて質問を置くときも、`## 質問` セクションで区切り、質問は 1 から振り直す:

```
## 進め方

1. rules 拡張を調査する
2. asking-format.md を修正する
3. テストを実行する

## 質問

1. この手順ですすめますか？ (y/a)
   (y) はい
   (a) 手順を見直す
```
