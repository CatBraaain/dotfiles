# SCM自動折りたたみ 要件

この文書は、dotfiles が配布する VS Code 用カスタムスクリプト `scm-collapse`（ソース管理ビューのリポジトリ行の自動折りたたみ）の要件を、利用者と開発者に向けて定める。

## 背景

ソース管理ビューでは、リポジトリの読み込み後にリポジトリ行が展開され、変更ファイルの一覧が並ぶ。利用者は折りたたまれた一覧を好むが、ビューを開くたびに展開へ戻るため、折りたたみ操作を繰り返していた。

## 目的

ソース管理ビューを開いたとき、リポジトリ行が利用者の追加操作なしで折りたたまれた一覧になること。

## 要件・制約

- 折りたたみは、ソース管理ビューが提供する「すべて折りたたみ」操作の実行で行う。DOM への直接の書き換えや、キーバインド・ビュー操作の上書きはしない
- ソース管理ビューが表示されるたびに、リストの行が表示された時点で折りたたみを一度だけ実行する。折りたたまれた行も行の表示に含める
- ビューを閉じて再度開いた場合は、折りたたみをもう一度実行する
- 折りたたみの実行は表示ごとに一度だけである。表示中に後から現れた展開は、次にビューを開くまでそのままにする
- 行が表示されないまま15秒が経過した場合は、折りたたみを諦める
- 対象は、Custom CSS and JS Loader でこのスクリプトが注入される VS Code のデスクトップ環境（Windows と Linux）である
- スクリプトは workbench の描画前に注入される。対象のビューが存在しない・表示されていない間は何もせず、エラーを出さない

## 受け入れ条件

- ソース管理ビューを開くと、リポジトリ行が折りたたまれた一覧になる
- すべて折りたたまれた状態でビューを開いた場合も、利用者が手動で開いた行は閉じられない
- ビューを閉じて開き直すと、折りたたみがもう一度実行される
- 表示中に refresh 等で現れた展開は、ビューを開き直すまで残る
