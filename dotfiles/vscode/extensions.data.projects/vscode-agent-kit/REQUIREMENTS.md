# Pi Sessions の要件

この文書は、VS Code拡張 Pi Sessions の目的・期待する成果・重要な制約を定める。読者は、この拡張の役割や変更範囲を判断する owner と開発者である。

具体的な振る舞いは `SPEC.md` に定める。`SPEC.md` はこの文書に準拠し、この文書の変更には owner の承認を必要とする。

## 解決する課題と目的

Pi（pi-coding-agent）で複数の会話を並行して進める際、Pi TUIだけではセッションを俯瞰し、目的の会話へ切り替えるための一覧が不足する。

Pi Sessions は、VS Code内にセッションの一覧・切替の入口を提供する。複数の作業ディレクトリにまたがる会話を見分け、Pi TUIで作業を続けるための選択・再開の負担を減らす。

## 期待する成果

- 会話の名前、更新日時、作業ディレクトリ（cwd）を手掛かりに、表示対象のセッションを見分けられる。
- 作成元にかかわらず、明示的にアーカイブしていない保存済みの会話を一覧で見つけられる。外部の Pi CLI で始めた会話も同じ入口から再開できる。
- 選んだ会話を対応する作業ディレクトリで再開できる。この拡張で開いた会話は、表示用ターミナルの開閉や会話の切替とPiの稼働を切り離し、生存しているPiへ戻って作業を続けられる。
- VS Code内から新しいPi会話を始め、一覧から切り替えられる会話に加えられる。
- 明示的なアーカイブで会話を一覧から整理し、複数の会話をまとめてアーカイブできる。一覧から外すことと、会話の削除や実行中のPiの終了を切り離し、会話と作業を保持したまま整理できる。
- 残したい会話をロックして、個別・一括のどちらの操作でも、ロックを解除するまでアーカイブされないよう保護できる。
- セッションIDを取り出して、対象の会話を識別・参照できる。
- Pi側などで保存された変更を必要なときに一覧へ反映し、保存された情報に基づいて会話を選べる。

## 重要な制約

- 会話の操作・表示は Pi TUI が担い、拡張は一覧・切替を補助する。独自のチャットUIやメッセージ表示で Pi TUI を置き換えない。
- セッションとエージェントの正本は Pi が持つ。拡張はPiの会話原本を読み取り専用で扱い、作成・更新を Pi CLI に任せる。原本の変更・削除・移動や、独自形式への変換を行わない。
- アーカイブとロックは一覧を整理・保護するための補助状態であり、Piプロセスの稼働状態を表すものではない。
- 拡張が保存する補助状態は会話原本と分離する。更新時は既存の属性を保持し、書き込みの中断で保存済みの内容を壊さない。
- 補助状態の保存形式は VS Code専用にせず、異なるクライアントでも同じ情報を共有できる形を保つ。

## 作業先と編集・差分の連携

会話を切り替えられても、担当する作業先のファイルや変更差分を別に探す必要があると、会話と編集対象の対応を見失いやすい。複数プロジェクトとworktreeを一つのVS Codeウィンドウで扱い、会話の選択から対応する作業の確認・編集までをつなぐ。

- 各会話がどのプロジェクト・作業先に対応するかを見分けられる。同じプロジェクトの本体と別worktreeも区別できる。
- 会話に対応する作業先のファイルと変更差分へ移り、別のプロジェクトやworktreeの同名ファイルと取り違えずに確認・編集できる。
- アーカイブの有無にかかわらず、保存済みの会話を探して再開できる。現在取り組んでいる会話がない作業先の履歴も利用できる。
- 新しい会話を始める際に、意図したプロジェクト・作業先で開始できる。別の作業先で誤って開始することを避けられる。
- ファイル閲覧・編集、差分確認、Git操作は、使い慣れたVS Codeの既存機能を活かす。これらを独自エディターや独自Git GUIで置き換えることを目的としない。
