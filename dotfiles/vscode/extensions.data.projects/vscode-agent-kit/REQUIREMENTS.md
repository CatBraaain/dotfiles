# Pi Sessions の要件

この文書は、VS Code拡張 Pi Sessions の目的・期待する成果・重要な制約を定める。読者は、この拡張の役割や変更範囲を判断する owner と開発者である。

具体的な振る舞いは `SPEC.md` に定める。`SPEC.md` はこの文書に準拠し、この文書の変更には owner の承認を必要とする。

## 解決する課題と目的

Pi（pi-coding-agent）で複数のセッションを並行して進める際、Pi TUIだけではセッションを俯瞰し、目的のセッションへ切り替えるための一覧が不足する。

Pi Sessions は、VS Code内にセッションの一覧・切替の入口を提供する。複数の作業ディレクトリにまたがるセッションを見分け、Pi TUIで作業を続けるための選択・再開の負担を減らす。

## 期待する成果

- セッションの名前、更新日時、作業ディレクトリ（cwd）を手掛かりに、表示対象のセッションを見分けられる。
- active なセッションを既定の一覧で見つけられる。Pi でメッセージを送ったセッションと、拡張で未アーカイブ化したセッションは active になり、外部の Pi CLI で始めたセッションも同じ入口から再開できる。active でないセッションも All 表示で見つけて再開できる。
- 選んだセッションを対応する作業ディレクトリで再開できる。この拡張で開いたセッションは、表示用ターミナルの開閉やセッションの切替とPiの稼働を切り離し、生存しているPiへ戻って作業を続けられる。
- VS Code内から新しい Pi セッションを始め、一覧から切り替えられるセッションに加えられる。
- 明示的なアーカイブでセッションを一覧から整理し、複数のセッションをまとめてアーカイブできる。対象のセッションのために拡張が保持する Pi を終了し、その tmux セッションを削除して稼働資源を解放できる。アーカイブ済みのセッションも保持し、再び選んだときに同じセッションから作業を再開できる。
- セッションIDを確認して、対象のセッションを識別・参照できる。
- Pi側などで保存された変更を必要なときに一覧へ反映し、保存された情報に基づいてセッションを選べる。
- VS Code内から専用tmuxの設定を再適用し、進行中のセッションを続けられる。接続先の指定やシェル操作を利用者に求めない。

## 重要な制約

- 会話の操作・表示は Pi TUI が担い、拡張は一覧・切替を補助する。独自のチャットUIやメッセージ表示で Pi TUI を置き換えない。
- セッションとエージェントの正本は Pi が持つ。拡張はPiのセッションファイルを読み取り専用で扱い、作成・更新を Pi CLI に任せる。原本の変更・削除・移動や、独自形式への変換を行わない。
- アーカイブ（active から外すこと）は一覧を整理するための補助状態であり、active は Pi プロセスの生存を示すものではない。active の付与は Pi 側（メッセージ送信時）と拡張側（未アーカイブ化・新規セッションの検出）の両方が行える。
- 拡張が保存する補助状態はセッションファイルと分離する。更新時はセッションの `lock` 属性を除く既存の属性を保持し、書き込みの中断で保存済みの内容を壊さない。
- 補助状態の保存形式は VS Code専用にせず、pi 拡張を含む異なるクライアントでも同じ情報を共有できる形を保つ。
- 専用tmuxの設定適用では、通常のマウス選択・スクロールとマウス機能の有効状態を維持し、Ctrl＋左ドラッグによるペイン作成だけを無効化する。稼働中の tmux サーバー・tmux セッション・pane・Piプロセスと、利用者の通常tmux環境を維持する。

## 作業先の識別とセッションの開始・再開

- 各セッションがどのプロジェクト・作業先に対応するかを見分けられる。同じプロジェクトの本体と別worktreeも区別できる。
- アーカイブの有無にかかわらず、セッションファイルからセッションを再開できる。現在取り組んでいるセッションがない作業先の履歴も利用できる。
- 新しいセッションを始める際に、意図したプロジェクト・作業先で開始できる。別の作業先で誤って開始することを避けられる。
