# VS Code Pi Session Manager spec

Pi（pi-coding-agent）のセッションを VS Code のサイドバーで一覧し、選択して Editor Area の Terminal で Pi TUI を開く VS Code 拡張機能の仕様。この拡張機能は Pi TUI を置き換えず、チャット UI やメッセージ表示も持たない。複数セッションの一覧・切替、明示的なアーカイブによる一覧の整理、pi-mux の workspace と本体リポジトリの worktree の `workspaceFolders` への同期を提供する。読者は利用者と拡張機能の開発者である。セッション一覧は VS Code 標準の TreeView ではなく、拡張機能が描画する Webview UI を使う。保存 E2E のテストケースを「テストケース」節に一覧し、各ケースの期待する結果から各定義節を参照する読み方をする。

## 用語

- セッション: Pi での会話を識別・再開する単位。tmux の管理単位は「tmux セッション」と区別する。
- 会話: セッション内のやりとりの内容。
- セッションファイル: Pi が会話を保存する JSONL ファイル。場所と形式は Pi のドキュメント（[sessions](https://github.com/earendil-works/pi-mono/blob/main/packages/coding-agent/docs/sessions.md) / [session format](https://github.com/earendil-works/pi-mono/blob/main/packages/coding-agent/docs/session-format.md)）に従う。
- セッション ID: 稼働セッションでは `pi-mux list`、保存済み会話ではセッションファイルのヘッダーが持つ ID。既定は UUID で、Pi の SDK や `--session-id` によるカスタム ID もある（Pi のドキュメントに従う）。ファイル名は `<timestamp>_<session-id>.jsonl` で、ファイル名の末尾セグメントと一致する。
- 一時 Pi（temporary）: pi-mux により一時再開され、通常の保持・復元対象になっていない稼働 Pi。`pi-mux list` のセッション要素に `temporary: true` があることで識別する。
- 未アーカイブセッション: 「データソース」で定める通常 Pi の集合。既定の表示対象になる。
- アーカイブ済みセッション: 「データソース」で定める一時 Pi と、通常 Pi の一覧に無い保存済み会話。`All` 表示で現れる。
- 実行フェーズ: agent ターン実行中（`running`）・承認待ち（`waiting-approval`）・user のターン待ち（`waiting-user`）の区別。取得元と表示は「実行フェーズの表示」節に従う。
- 登録済みワークスペース: `pi-mux list` が返す workspace の `cwd`。セッションが0件でもグループとして表示する。
- 追加済みワークスペース: Session List に追加された cwd。「workspace 登録と永続情報」に従って保持する。
- pi-mux: Pi を専用 tmux 内で起動・再接続する CLI。専用 tmux の管理と設定適用、セッション ID の採番と固定、保存済みセッションの再開を担う。拡張は pi-mux を通じて Pi を起動・再開し、pi-mux の稼働一覧（`pi-mux list`）で稼働中のセッションを確認する。仕様は dotfiles リポジトリの `pi-mux` SPEC に従う。
- 本体リポジトリ: worktree でないリポジトリ本体。pi-mux list に載る workspace であり、worktree の検出起点になる。
- worktree: `git worktree` で作った作業用 worktree。追加・削除と表示名は「workspaceFolders 同期」に従う。
- フォルダ0: ワークスペースの最初のフォルダ。起動時の付け替え後は `~/.agents/workspace` を固定で使い、同期対象から除く。
- 管理フォルダ: 拡張機能が「workspaceFolders 同期」に従って追加・削除・並べ替えするフォルダ。folder 1 以降。
- untitled ワークスペース: 保存していないマルチルートワークスペース。フォルダ0と管理フォルダをこの形式で扱う。
- フォルダモード: フォルダをワークスペースとして開いた状態。保存済みワークスペースでも untitled ワークスペースでもない単一フォルダの状態。
- 同じ実体: パスを正規化し symlink を解決した後の絶対パスが一致すること。

### E2E結果の確認

開発者は `bun run test:e2e` で保存 E2E を実行し、プロジェクト直下の `e2e-gallery.html` をブラウザーで直接開いて、同じ実行で得た画面と自動テストの結果を確認できる。`e2e-gallery.html` はバージョン管理する固定のビューアーであり、テスト実行時には画像と結果データだけを `dist/e2e-gallery/` に出力する。画面の撮影は、通常の E2E の操作・確認と同じ step に含める。撮影対象は「テストケース」表の「撮影」欄が定める画面だけとし、操作のたびに撮影しない。同じ操作の反復で確認する事項は、反復の最終状態だけを撮影する。各ケースの撮影は「撮影」欄で定めた比較単位に従う。E2E-11 はメイン領域にタブがない状態で、メニュー表示中と登録解除後を撮影する。E2E-14 は pi-mux から取得した3つの実行フェーズを一覧に表示し、メイン領域にタブがない状態で、ほかのケースと同じ VS Code のウィンドウ全体を1枚撮影する。E2E-15 は実 Webview への一覧応答を制御し、初回取得中・既存一覧を保つ再取得中・成功空・取得エラーの4状態を、同じ VS Code のウィンドウ全体で撮影する。ほかの比較ケースは前後1組を撮影する。「撮影」欄のラベルをそのまま画像の添付名として付ける。添付名はギャラリーのセル見出しとして使う。ギャラリーは短い文言と画像だけで結果を一目で確認する構成とし、この文書のテストケースの説明や期待する結果の全文、文書のスナップショットは表示しない。ケースの詳細はこの文書を参照する。各ケースは画像をセルとする表で示し、「撮影」欄の順に並ぶ。セルの見出しは画像の添付名（「撮影」欄のラベル）だけとする。

| 条件・操作 | 結果 |
| --- | --- |
| 保存 E2E の実行が終了する | ケースごとに ID とテストケース名を1行に切り詰めた見出しと、画像をセルとする表を表示する |
| 「テストケース」表の「撮影」欄が「なし」のケース | ギャラリーに表示しない |
| ケースが失敗、未実行、または画像を持たない | 失敗・未実行・画像なしを区別する短い文言を表示する。失敗のエラーは最初の行だけ表示する。画像があることを自動テストの成功や見た目の正しさとして扱わない |
| 並列実行・再試行で画像を保存する | ケース・step・実行環境・試行を識別でき、画像を上書きせず対応する結果から参照できる |
| 過去の実行で保存した画像がある | 今回の撮影結果として表示しない |
| スクリーンショットを開く | 原寸の画像を確認できる |
| プロジェクト直下の `e2e-gallery.html` をファイルとして直接開く | 今回の結果データと画像を相対パスで読み込み、サーバーなしで表示する |
| 結果データがまだ出力されていない | E2Eの実行を案内し、実行結果や画像を表示済みのものとして扱わない |

自動テストの合否はテストランナーの結果、見た目の判断は利用者の目視確認に基づく。Playwright 標準HTMLレポートは診断用の別の出力として保持する。

## データソース

拡張機能は `pi-mux list` を pi-mux の workspace 登録と稼働 Pi の正本とする。応答は `[{cwd,sessions:[{id,file,state,title,publishPending?:{attemptAt:number}|null,temporary?:true}],empty:[{id,file,temporary?:true}]}]` の JSON 配列であり、cwd と file は絶対パス、state と title は文字列または null である。`publishPending` は実行フェーズ公開の未完了を示す pi-mux の中継値であり、`{attemptAt}`（最後の公開試行の Unix epoch ミリ秒）または null を取る。省略と null は遅延なしとして扱い、`attemptAt` が正の整数でないオブジェクトやその他の値は不正応答として扱う。値の利用は「実行フェーズの表示」に従う。`temporary` は一時 Pi にだけ `true` で存在し、省略は通常 Pi を表す。`false` やその他の値は不正応答として扱う。`sessions` には会話ファイルが存在する pane だけが載り、未作成分は `empty` に載る。空 workspace は `sessions: []`・`empty: []` として含まれる。独自のセッション所属集合や復元集合を保存しない。

保存済み会話は `pi-mux history` から得る。応答は `[{id,cwd,file,title,btime,mtime,size}]` の JSON 配列（`mtime` 降順、`mtime` が `null` の要素は後方、同値は `file` 昇順）であり、pi-mux が登録済み workspace の保存会話の `*.jsonl` を列挙し（既定の保存先では group ディレクトリ直下、`PI_CODING_AGENT_SESSION_DIR` 指定時はその直下）、各ファイルのヘッダー id・cwd を正とする。`btime` は初回 user メッセージの送信日時（Unix epoch ミリ秒）で、初回 user メッセージが未保存なら `null` になる。有限の `number` と `null` のみを受け入れ、それ以外は不正応答として扱う。`mtime` はファイル内で物理的に最後の `message`/`compaction` エントリの `timestamp`（ミリ秒、該当エントリが無いとき `null`）である。title はセッション名（最後の `session_info` の `name`）で解決し、解決できないとき最初の user メッセージ（80 code points で丸め）を使い、いずれも無いとき `null` になる。

| 項目 | 値 |
| --- | --- |
| エージェントディレクトリ | `PI_CODING_AGENT_DIR`（未設定・空文字なら `~/.pi/agent`） |
| セッションディレクトリ | `PI_CODING_AGENT_SESSION_DIR`（未設定・空文字なら、呼び出し時の cwd の `.pi/settings.json` と `<エージェントディレクトリ>/settings.json` の `sessionDir` 設定を順に参照し、いずれも無ければ `<エージェントディレクトリ>/sessions`） |
| 未アーカイブ一覧 | list の通常 Pi（`temporary` が省略されたセッション） |
| アーカイブ済み一覧 | list の一時 Pi と、下記の保存済み会話のうち通常 Pi の一覧に同じ ID が無いもの |
| All 一覧 | 未アーカイブ一覧とアーカイブ済み一覧の和集合。同じ ID は1行にまとめる |
| 稼働 Pi の保持 | `sessions` の行を state/title が null でも残す。`empty`（会話ファイル未作成分）は一覧に表示せず、生存判定と保存履歴の更新に使う |
| 保存済み会話 | `pi-mux history` のエントリのうち、cwd が list の登録済み workspace に含まれるもの |
| セッション ID・cwd・file | 稼働 Pi は list の id・workspace.cwd・file を正とする。保存済み会話は history の id・cwd・file を使う。同じ ID は list を優先する |
| 開始日時・更新日時 | 下記「開始日時・更新日時」の規則に従う |

エージェントディレクトリは、`~` をホームディレクトリへ、`~/` で始まるパスをホームディレクトリ配下へ展開する。絶対パスはその場所を使い、相対パスは拡張 host の `process.cwd()` を基準に絶対化する。この cwd は拡張機能から呼び出す pi-mux CLI の cwd と揃える。解決後のエージェントディレクトリを、`settings.json` の読み取りと既定のセッションディレクトリの解決に共通して使う。

保存先設定から解決するセッションディレクトリの監視先は、拡張機能の起動時に決定する。保存先の設定を変更した後は、拡張機能を再起動して監視先と一覧を更新する。

登録済み workspace が無い正常応答 `[]` はセッション行を空にし、このとき history は問い合わせない。list・history の失敗・不正応答は取得エラーとし、既存の一覧・実行観測・未読を保持する。

### 保存履歴の更新

保存履歴は次の契機で `pi-mux history` から全登録 workspace 分を一括取得し、成功応答の全体を一覧へ反映する。次の更新までは、表示用の最後の正常取得結果を使う。稼働 Pi の集合・title・実行フェーズ・未読の自動更新は「実行フェーズの表示」に従う。

| 条件・変化 | 保存履歴の取得と一覧への反映 |
| --- | --- |
| 初めて一覧を表示する | 登録済み workspace の保存履歴を取得する |
| 保存履歴と workspace 登録に変更がない | 取得済みの保存履歴を最新の list と組み合わせる。list の定期取得だけを理由に history を再取得しない |
| cwd の登録有無にかかわらず、監視対象の保存会話ファイルの作成・追記・セッション名変更・削除・改名の通知を受ける | 全登録 workspace の保存履歴を再取得し、作成・更新・削除を自動反映する。同じセッション ID は1行にまとめ、稼働 Pi の行は「データソース」の優先規則に従って保持する |
| 履歴取得中に変更通知を受ける | 更新要求を保持し、進行中の取得完了後に追加通知をまとめて次の1回の取得へ反映する。同時に履歴を重複取得せず、変更を取りこぼさず反映する |
| list に workspace が追加される | 全登録 workspace の保存履歴を取得する |
| list から workspace が除かれる | その workspace の保存履歴を一覧から外す。除かれた workspace の取得結果が後から届いても一覧へ戻さない |
| 一覧が非表示になる | 新たな保存履歴の取得と UI 配信を停止し、その間の変更は再表示時の更新対象とする |
| 一覧を再表示・再生成する | 最新の list を取得する。保存履歴の未取得または保留中の更新があれば全登録 workspace の保存履歴を取得し、それ以外は表示用の最後の正常取得結果を使う |
| 手動の `Refresh Sessions` を実行する | list と全登録 workspace の保存履歴を読み直す |
| 保存履歴の取得が失敗する | 最後の正常な一覧・実行観測・未読を保持する。表示中は失敗した履歴の自動再試行を行うが、list の250ミリ秒周期とは分け、失敗が続く間は再試行間隔を延ばす |

変更通知による更新では、上表の表示状態・取得中の追加通知・再試行の規則に従い、通知後の待機タイマーを設けず、直ちに次の取得経路へ進む。

| 条件 | 取得経路 |
| --- | --- |
| 一覧が表示中で、直近に完了した list が正常、登録済み workspace があり、保存履歴を取得済み。履歴取得中でも失敗後の再試行待ちでもない | history を取得する。通知を理由に追加する list 呼出は0回とし、進行中の list の完了や次の定期取得を待たない |
| 保存履歴が未取得、または直近の list 取得が失敗 | list を取得し、正常な登録情報に基づいて上表の規則で保存履歴を取得する |

「直ちに」は通知後に意図的な待機を挟まないことを意味し、OS・拡張 host の実行待ちや CLI の所要時間を含む実時間を保証するものではない。

履歴取得は同時に重ねず、古い取得結果で新しい履歴を上書きしない。各取得は全登録 workspace の保存履歴を対象とするため、履歴量に応じた取得時間がかかる。

新しいセッションを伴う反映も含め、一覧の切替方法は「一覧更新のアニメーション」に従う。

### 開始日時・更新日時

開始日時は history エントリの `btime` を使い、`null` のときも開始日時不明として一覧に残す。更新日時は `mtime` を使い、`null` のときは日時欄を空欄とする。稼働 Pi が history に無いときは日時不明として一覧に残し、日時欄は空欄とする。

### 表示名

セッション項目の表示名は次の順で決める。

1. 稼働 Pi は list.title が非空文字列ならその値
2. history.title（pi-mux が解決したタイトル。セッション名（`/name` や `pi --name` で設定される値）、解決できないとき最初の user メッセージ）
3. いずれも無い場合 `Untitled`

一時 Pi も稼働 Pi として上記の規則に従う。history に無い稼働 Pi は `Untitled` とする。

### workspace 登録と永続情報

pi-mux の workspace 登録と復元候補の永続管理は pi-mux が担う。拡張機能は `pi-mux list` の cwd を登録判定の正とし、登録の追加・解除は各アクションに定める公開 CLI で行う。セッションの所属も pi-mux の起動・再接続と一覧に従う。

Session List は list の cwd を重複なく自動追加する。追加済み workspace は同じ VS Codeプロファイル内で共有し、拡張機能の再起動後も保持する。list から消えても見出しを保持し、削除は「ワークスペース登録解除」の成功時だけ行う。削除後に list へ再び現れた cwd は自動追加する。Session List への追加・保持は `workspaceFolders` を変更せず、`workspaceFolders` への反映は「workspaceFolders 同期」に従う。

拡張機能は pi-mux の管理ファイルを直接読み書き・監視しない。

セッションファイルは読み取り専用として扱い、変更・削除・移動をしない。セッションの作成と更新は Pi CLI が行う。

## サイドバービュー

Activity Bar に view container `Agent Kit` を追加し、その中に拡張機能が管理する Webview view を表示する。VS Code 標準の TreeView は使わない。Webview は VS Code のテーマ色を使い、サイドバー幅に合わせて再配置される。セッションのファイル内容・pi-mux の workspace・セッション情報は Webview に渡す表示用データだけに変換し、Webview からファイルシステムを直接操作しない。

### Webview の表示

サイドバーは次の順で表示する。

1. VS Code 標準のビュータイトルに `Sessions` と「Refresh アクション」の更新操作を表示する
2. Webview 内に cwd ごとのグループを、枠線を持たない余白で区切ったセクションで表示する。一覧に現れるグループは追加済みワークスペースだけである。セッション行は「データソース」に従う。グループ見出しに開閉の chevron、basename、省略メニュー、「表示モード」に従うモード切替、そのワークスペースで新しい Pi を起動する `New session` 操作を表示する。登録解除の入口は「ワークスペース登録解除」に従う。見出しのホバーのヒントに cwd のフルパスを表示し、同じ basename のプロジェクトや worktree を区別する。chevron または見出し名を選ぶと、そのグループの行の表示を開閉する。見出し名の通常の `Enter` / `Space` はグループ開閉として使える。開閉状態の既定は開いた状態で、VS Code 再起動後も維持しない
3. グループ内にセッションを行として表示する。行は表示名とセッションの状態（選択・アーカイブ済み・実行フェーズ）を示す。左端の状態アイコンと行ホバーのヒントは「実行フェーズの表示」の対応表に従う
4. 各行の右端には、更新日時（等幅の数字で表示する）と、`Archive` または `Unarchive` 操作をこの順で表示する。`Archive` と `Unarchive` はアーカイブのアイコンとアーカイブからの復帰のアイコンで示す。ホバーのヒントは `Archive` または `Unarchive` とする
5. 未アーカイブの行には `Archive` 操作を、アーカイブ済みの行には `Unarchive` 操作を同じ位置に表示する。アーカイブ済みの行は All 表示でのみ現れ、行の表示を薄くしてアーカイブ済みであることを示す
6. セッション行全体を選択領域とし、選択の視覚表示は行の右端まで及ぶ。更新日時、`Archive` または `Unarchive` は行の右端に重ねて表示する。行内操作のクリックは、行の選択やセッションの再開として扱わない
7. 一覧の下にフッタを表示する。フッタの `New workspace` の操作は「New Workspace アクション」に従う

表示名・更新日時・グループ・並び順は「グルーピングとソート」の規則に従う。行・見出し・操作の寸法と色の値は `DESIGN.md` が定める。

### 一覧のスクロール

Webview 全体を document の標準スクロールで移動する。スクロール位置は右端に重ねたバーで示し、外観は `DESIGN.md` に従う。

| 条件・状態 | 操作・変化 | 結果 |
| --- | --- | --- |
| 一覧を表示中 | `Unarchived` / `All` の切替、行の増減、グループの開閉で縦 overflow が出入りする | 共通する行の左右位置と幅を保つ |
| 縦 overflow がある | ホイール、トラックパッド、通常のキーボードスクロールを使う | document が標準どおりスクロールし、つまみが位置に追従する |
| 縦 overflow がある | つまみをドラッグする | ドラッグ量に応じて document をスクロールする。ドラッグ中はバーを表示し続ける |
| 縦 overflow がある | トラックをクリックする | クリック位置に対応する document の位置へ移動する。ドラッグなしの単一ポインター操作で位置を指定できる |
| バーにキーボードフォーカスがある | 上下矢印、PageUp / PageDown、Home / End を押す | 上下移動、ページ移動、先頭 / 末尾移動を行う。フォーカス中はバーを表示し、支援技術へ操作対象・範囲・現在位置を示す |
| 一覧・フォームを表示中 | モード切替、グループの開閉、一覧データの更新、フォームの開閉、viewport のリサイズが起きる | 現在の表示範囲と全体の高さに合わせて、つまみの長さ・位置・バーの有無を更新する |
| 縦 overflow がない | 一覧を表示する | バーを隠し、キーボードのフォーカス対象から外す |

### セッション行の選択表示

選択表示は Webview が独自に持つ状態ではなく、共有表示用 Terminal が今表示しているセッションを一覧の行に示すものである。選択の正本は拡張機能 host が保持する表示先セッション ID であり、Webview は受け取った一覧データの中からそのセッション ID の行に選択表示を付ける。

| 操作 | 選択表示の変化 | Terminal |
| --- | --- | --- |
| 行をクリック | 表示先がそのセッションへ切り替わり、選択表示もその行へ移る | 「セッション選択と Terminal」の規則でセッションを開く |
| `New session` を起動 | 新規セッションが Terminal に表示された時点で、それまでの行の選択表示を解除する。一覧に現れるまでは、選択表示を持つ行が無い状態にする | 新しい Pi を共有 Terminal へ接続する |
| 新規セッションが一覧に現れる | Terminal でそのセッションを表示中なら、その行に選択表示を付ける | 表示先を維持する |
| 表示用 Terminal のタブを閉じる | 選択表示は変化しない | 表示用の接続だけを閉じる |

- 修飾キー（Ctrl / Cmd / Shift）付きのクリックも通常のクリックと同じ扱いにする。選択だけを変える操作、全選択、選択範囲へのアンカーは持たない
- 表示モードの切替や再読み込みをまたいで、表示先のセッションの行に選択表示を付ける。表示先の行が現在の表示モードに現れないとき（アーカイブ済みで `Unarchived` 表示のときなど）は、選択表示を持つ行が無い状態として表示する
- 表示用 Terminal が Editor Area の裏タブに回っても表示先は変わらないため、選択表示も変化しない

### 表示モード

モードは追加済みワークスペースの cwd ごとに独立して持つ。各グループ見出しのボタンは、そのワークスペースの `Unarchived` / `All` を切り替える。

| モード | そのワークスペースの表示対象 | ボタンのヒント・アクセシブル名 |
| --- | --- | --- |
| Unarchived（既定） | 未アーカイブのセッションのみ | `Show all sessions` |
| All | アーカイブ済みを含む全セッション。アーカイブ済みの行は薄く表示する | `Show unarchived sessions` |

| 条件・状態 | 操作・変化 | 結果 |
| --- | --- | --- |
| 追加済みワークスペースのグループ | セッションが0件、全件アーカイブ済み、または折りたたみ中 | グループ見出しとモード切替ボタンを常時表示する |
| グループ見出しのモード切替ボタン | クリック、Enter、Space で実行する | 対象 cwd のモードだけを切り替え、ほかの cwd のモード・行選択・グループ開閉状態を保つ |
| 同じ basename の異なる cwd がある | 一方のモードを切り替える | 各 cwd を別のワークスペースとして扱う |
| Webview を表示中 | Refresh または一覧データの更新が起きる | 各 cwd のモードを保つ。新しく現れた cwd は Unarchived で表示する |
| Webview を初期表示・再生成する（VS Code 再起動を含む） | 一覧を表示する | すべての cwd を Unarchived で表示する |

モードの切替はセッション行（アイテム）の表示を切り替えるだけで、表示するグループ自体はモードによらず追加済みワークスペースだけである。登録済みワークスペースなら `All` でアーカイブ済みのセッションを選択・再開できる。一時 Pi はアーカイブ済みの表示と `Unarchive` 操作を維持する。list の同じ ID から `temporary` が無くなると、次の取得で未アーカイブとして表示する。稼働終了で list から外れた保存済み会話は All のアーカイブ済み行になる。

### 実行フェーズの表示

実行フェーズは `pi-mux list` の応答でセッション ID が一致する項目の `state` から取得する。拡張機能はフェーズの取得・表示を理由に、workspace 登録や復元候補の更新操作を行わない。

| 条件 | 表示 |
| --- | --- |
| 未アーカイブで、pi-mux の稼働一覧にそのセッションがあり、`state` が `running` / `waiting-approval` / `waiting-user` | 次の対応表に従ってフェーズを表示する |
| pi-mux の正常応答で稼働一覧にそのセッションが無い | フェーズ情報なしとして扱う |
| pi-mux の正常応答でそのセッションの `state` が `null` または有効な値でない | フェーズ情報なしとして扱う |
| pi-mux への問い合わせが失敗する | 既存の一覧とフェーズを保ち、取得エラーを表示する |
| アーカイブ済み | フェーズを表示しない |

表示対象のフェーズと未読を、次の優先順で左端の状態アイコンへ対応させる。行ホバーのヒントには表示名とセッション ID に加え、表の追加行を表示する。「なし」の行では、ヒントへ追加しない。

| 条件 | 左端の状態アイコン | ヒントの追加行 |
| --- | --- | --- |
| アーカイブ済み | なし | なし |
| 未アーカイブ・`running` | 回転する spinner | `Running` |
| 未アーカイブ・`waiting-approval` | 一時停止マーク | `Waiting for approval` |
| 未アーカイブ・`waiting-user`・未読 | 輪郭線のベル | `Waiting for user`・`Unread` |
| 未アーカイブ・`waiting-user`・既読 | なし | `Waiting for user` |
| 未アーカイブ・フェーズ情報なし | なし | なし |

アイコンがない行も左端のスロットを保持し、表示名の開始位置を揃える。`prefers-reduced-motion: reduce` では spinner を静止表示する。アイコンの寸法・色・線と回転の詳細は `DESIGN.md` に従う。右端のアーカイブ操作は左端のアイコンと独立して表示する。

実行フェーズの表示とは独立に、各セッション行へ公開遅延標識を付ける。判定には list 応答の `publishPending` を使い、基準時刻はその list 応答に基づいて一覧を更新する時刻とする。

| 条件 | 表示 |
| --- | --- |
| `publishPending` が `attemptAt` を持ち、`attemptAt` が基準時刻から10秒以内 | 状態アイコンのスロットへ公開遅延ドットを置き、ヒントへ `State update delayed` を追加する |
| `publishPending` が省略・`null`・不正な値、または `attemptAt` が基準時刻から10秒を超える | 公開遅延ドットもヒント行も追加しない |

公開遅延標識の判定は、アーカイブ済み・フェーズ情報なしの行でもフェーズの表示から独立に行う。フェーズの表示と公開遅延標識は同時に成立する。ヒントの行順は、表示名、セッション ID、フェーズの追加行、`State update delayed`、`Unread` とする。公開遅延ドットの見た目は `DESIGN.md` に従う。

拡張機能の起動から終了まで、直前の list 取得が成功または失敗してから約250ミリ秒後に list の次の取得を開始する。同時に list 取得を重ねず、古い応答で新しい状態を上書きしない。表示中は稼働 Pi の集合・workspace・title・実行フェーズを更新する。非表示中も list を取得し、UI 配信は停止する。初回失敗後も list の定期取得を続ける。保存済み会話の取得と再表示時の更新は「保存履歴の更新」に従う。

未読は実行フェーズと別の補助状態であり、拡張機能のメモリ内だけで保持する。次の表の「表示中」は、共有表示用 Terminal の表示先セッションを指す。

| 条件・状態 | 操作・変化 | 未読の結果 |
| --- | --- | --- |
| Pi が生存する未アーカイブセッション | 拡張機能が `running` を観測する | それまでの未読を解除し、その実行を観測対象にする |
| 観測対象の実行 | `waiting-approval` になる | 実行の観測を保ち、承認待ちとして表示する |
| 観測対象の実行（表示中を含む） | `waiting-user` になる | 未読にする |
| Pi が生存する未アーカイブセッション・`waiting-user`・未読 | 表示中のまま一覧を更新する | 未読を保つ |
| 未読のセッション（表示中を含む） | 一覧のセッション行を選び、正常に開く | 未読を解除し、表示中のベルをフェードアウトして消す。`prefers-reduced-motion: reduce` では即時に消す |
| `running` をまだ観測していないセッション | 初回から `waiting-user` を読み取る | 過去の完了を推測せず、既読として扱う |
| pi-mux への問い合わせが一時的に失敗する | 一覧を更新する | 実行の観測と未読、既存の一覧表示を保持する |
| pi-mux の正常応答で `state` が `null` または有効な値でない、稼働一覧から消失が確定した、アーカイブ済み、または一覧の対象から外れたセッション | 一覧を更新する | 実行の観測と未読を解除する |
| Webview を再生成する | 同じ拡張機能で一覧を表示する | メモリ内の未読を保つ |
| 拡張機能を再起動・再読み込みする | 一覧を表示する | 実行の観測と未読を初期化する |

セッションを開くことに失敗した場合は、未読とベルを保つ。ベルのフェード中も最新のフェーズ・未読・アーカイブ状態を優先して表示する。フェードの見た目は `DESIGN.md` に従う。

一覧の更新が重なっても、新しい実行や既読化を過去の状態へ戻さない。未読はセッションファイル・pi-mux の管理情報・tmux・VS Code の保存 state へ書き込まない。

### 一覧と拡張機能の操作

| 一覧の操作 | 拡張機能の処理 | Webview の結果 |
| --- | --- | --- |
| 一覧の初期表示・再生成・再表示 | 「保存履歴の更新」に従って一覧を更新し、受信準備のできた Webview に最新の一覧を送る | Refresh を選ばずにセッションへ戻れる |
| 一覧取得中に Webview の表示準備完了が通知される | 再取得せず、進行中の取得結果を完了後に Webview へ送る | 取得中の表示を保ち、完了時に最新の一覧または取得エラーを表示する |
| 一覧取得完了後に Webview の表示準備完了が通知される | 再取得せず、最新の取得結果を Webview へ送る | 最新の一覧または取得エラーを表示し、取得待ちへ戻らない |
| グループ見出しのモード切替を選択 | 「表示モード」の規則で Webview の表示を切り替える | 対象ワークスペースの行だけが切り替わる |
| 標準ビュータイトルの `Refresh Sessions` を選択 | pi-mux の一覧と保存済み会話を読み直す | 最新の一覧が表示される |
| グループ見出しの `New session` を選択 | 「New Session アクション」の規則でそのワークスペースの cwd で新しい Pi を起動し、共有の表示用 Terminal へ接続する | 起動後に一覧が更新され、選択表示は「セッション行の選択表示」に従う |
| 追加済みグループ見出しのメニューで `Unregister workspace` を選択 | 「ワークスペース登録解除」の規則で登録を削除し、一覧を再読込する | 対象 cwd のグループが一覧から外れる |
| フッタの `New workspace` を選択し、入力欄で `Enter` を押す | 「New Workspace アクション」の規則でワークスペースを登録し、一覧を再読込する | list に載った cwd のグループを、セッションが無くても表示する |
| フォームで `Escape` を押す | フォームを閉じ、入力を捨てる | 一覧・workspace 登録・現在の表示先を変えない |
| セッション行をクリック | 「セッション選択と Terminal」の規則でセッションを開く | Editor Area の共有 Terminal に選択先の Pi TUI が前面表示され、選択表示がその行へ移る |
| 行の `Archive` を選択 | 「アーカイブ・未アーカイブアクション」の規則でその行の Pi を終了してアーカイブする | 一覧を再読込し、アーカイブ後の行・グループを「表示モード」の規則で表示する |
| アーカイブ済みの行の `Unarchive` を選択 | 「アーカイブ・未アーカイブアクション」の規則で通常 open によりそのセッションを開く | 一覧を再読込し、戻し後の行・グループを「表示モード」の規則で表示する。Editor Area の共有 Terminal にそのセッションの Pi TUI が前面表示され、選択表示がその行へ移る |

一覧と拡張機能の通信状態は「一覧の通信状態」に従う。workspace 登録の追加・解除の失敗は、それぞれのアクションの規則に従う。アーカイブの失敗と表示先の扱いは「アーカイブ・未アーカイブアクション」に従う。Webview の操作によるメッセージにはセッション ID や開始先・登録先のパスなど、その操作に必要な引数だけを含める。任意のコマンドを実行できる値を含めない。

### 単一行更新の性能

Webview に一覧を描画済みで、グループ・行の集合と順序、表示モード、開閉状態、表示に使うローカル日付が直前と同じとき、1セッションの表示名・更新日時・実行フェーズ・未読だけが変わる一覧データの受信には、次の件数予算を適用する。一覧のほかの値は直前と同じとする。

| 変更対象行の状態 | 受信1回当たりの変更対象行の再生成 | 受信1回当たりの未変更行の再生成 |
| --- | --- | --- |
| 表示モードの表示対象で、グループが開いている | 1行 | 0行 |
| 表示モードの表示対象から除外されている | 0行 | 0行 |
| グループが折りたたまれている | 0行 | 0行 |

表示対象には、スクロール領域内で viewport の外にある行も含む。行表示内容の再生成とは、表示名・日時・ヒント・状態アイコン・行内操作などの表示内容を構築し直す処理であり、件数はその対象行数とする。入力値の比較だけは計上しないが、比較のために行表示内容を構築し直した対象は計上する。

更新後の表示・日時・ヒント・操作対象は「Webview の表示」「グルーピングとソート」「実行フェーズの表示」および各操作の規則に従う。

件数予算はデータ件数にかかわらず上記の条件で適用する。代表負荷は、1500セッションのうち80%がアーカイブ済みで、登録済み workspace が1件または10件の一覧更新とする。`Unarchived` / `All` の両表示とグループの開閉を含む。代表負荷の件数・割合は、一覧の収容件数の上限でも、件数予算の適用を限定する条件でもない。

件数予算は行表示内容の再生成を制限するものであり、CLI 実行、通信、JSON の直列化・解析、ブラウザーの layout・paint を含む一覧更新全体の所要時間や、一定の速度倍率を保証しない。

### 一覧の取得状態

初期表示・再生成・再表示、手動の Refresh、ファイル監視や操作後の再読込は、取得開始から成功または失敗まで取得中として扱う。選択表示は取得状態にかかわらず「セッション行の選択表示」に従う。

| 条件・状態 | 表示 |
| --- | --- |
| 初回取得中、または直前の一覧が0グループで再取得中 | 一覧領域に `Loading sessions…` を表示する |
| 手動の Refresh で、直前の一覧にグループがあり再取得中 | 既存の一覧・表示モード・開閉状態を保ち、状態欄に `Refreshing sessions…` を表示する |
| 手動の Refresh 以外の契機で、直前の一覧にグループがあり再取得中 | 既存の一覧・表示モード・開閉状態を保ち、状態欄の `Refreshing sessions…` を表示しない |
| 取得成功 | 最新の一覧を表示し、取得中や取得エラーの表示を解除する。0グループなら一覧領域に `No sessions yet` を表示する。セッションが0件の追加済みワークスペースは空グループとして表示する |
| 取得失敗（直前の一覧にグループあり） | 既存の一覧・表示モード・開閉状態を保ち、取得中の表示を解除する |
| 取得失敗（直前の一覧が0グループ） | 一覧領域に `Failed to load sessions. Retrying…` を表示し、取得中の表示を解除する。状態欄には表示しない |
| 一覧取得以外の操作の失敗 | 一覧の取得状態と表示を保ち、操作のエラーメッセージを受信から2秒間、状態欄に表示する。手動の Refresh による再取得中は `Refreshing sessions…` と併記する |
| 操作エラーの表示中に新しい操作エラーを受信する | 新しいエラーメッセージへ更新し、その受信から2秒間表示する。同じメッセージを再受信した場合も同じとする |
| 操作エラーの表示中に一覧の取得開始・成功・失敗、通信確認への応答を受信する | 操作エラーの内容と表示期限を保つ。自動更新と手動の Refresh のどちらでも同じとする |
| 最後の操作エラーの受信から2秒経過する | 操作エラーだけを解除し、一覧の取得状態と表示、ワークスペース登録フォームと入力を保つ |

一覧取得の失敗で VS Code の通知は出さず、失敗の原因も一覧・状態欄に表示しない。原因は出力チャネル `Agent Kit` に error レベルで記録し、ビューを表示していない間の失敗も同じく記録する。

### 一覧の通信状態

一覧を表示している間は、初回の取得中も含めて拡張機能との通信を確認する。一覧の取得時間ではなく、通信確認への応答で通信状態を判断する。

| 条件・状態 | 表示・動作 |
| --- | --- |
| 表示中に通信確認への応答が10秒間ない | 一覧上部に `Connection lost. Retrying…` をエラーとして表示する。既存の一覧・選択表示・表示モード・開閉状態と取得状態を保つ |
| 通信が回復する | 拡張機能から受け取った最新の一覧または取得状態を表示し、通信エラーを解除する |
| 取得処理が長引いていても通信確認に応答する | 取得状態を保ち、通信エラーを表示しない |
| 一覧が非表示になる | 通信確認を停止する。非表示の時間を障害判定に含めず、再表示時は新しく通信を確認する |
| 通信確認への応答が通常の一覧更新より遅れて届く | 新しく受け取った一覧や取得状態を過去の状態へ戻さない |
| 一覧取得以外の操作のエラーがある | 操作エラーと取得状態は既存の一覧下部の状態欄で表示し、一覧上部の通信エラーと分ける。通信確認への応答だけでは操作のエラーを解除しない |

一覧更新の通信障害は一覧内で表示し、VS Code の通知を重ねない。

### 変更がない定期更新の処理量

初期取得と必要な再取得・配信が完了した一覧では、取得済みの保存履歴、list の全フィールド、保存先、表示先セッション、実行観測、未読、取得状態が前回の正常配信時と同一で、再取得・再送が不要な状態を「変更なし」とする。

| 条件・状態 | 操作・変化 | 結果 |
| --- | --- | --- |
| 変更なしの一覧を表示中 | 定期的な list 取得が成功する | list の定期取得を続け、1回の更新あたり history 取得0回、履歴一覧の再加工0件、一覧送信0回とする |
| 一覧の入力または表示状態が変わる | 保存履歴・workspace 登録・稼働情報・実行観測・未読・表示先・取得状態の変更を反映する | 各定義節に従う最新の一覧・選択表示を維持し、変更前の表示を同一とみなして残さない |
| 一覧内容が同じでも配信が必要 | 取得中・エラーからの復帰、Webview の表示準備完了に伴う再送、一覧送信失敗後の再試行が起きる | 「一覧と拡張機能の操作」「一覧の取得状態」に従って必要な一覧を配信する |

履歴一覧の再加工件数は、保存履歴のエントリを表示用一覧へ結合・変換・整列・グループ構成する処理の対象件数とする。同一判定のために一覧全体を再生成する場合も再加工に数え、取得済み入力の単純な比較だけは除く。この契約は履歴件数によらず適用する。1500件の保存履歴は代表負荷であり、適用条件や製品上限ではない。

### 一覧更新のアニメーション

一覧の反映で表示が切り替わるときの切替方法を定める。

| 条件・状態 | 結果 |
| --- | --- |
| 待機中の Archive・Unarchive 要求に伴う一覧の再読込 | 反映前後で位置が変わった行をアニメーションで移動する。前回の表示に無かった行は移動せず即時に表示する |
| 一覧の反映で、反映直前の表示になかったセッション行が、表示モード・開閉状態を適用した一覧に現れる | 反映前後で位置が変わった行をアニメーションで移動する。現れた行は移動せず即時に表示する |
| それ以外の一覧更新、初回表示 | 即時に切り替える |
| `prefers-reduced-motion: reduce`、アニメーションが使えない環境 | アニメーション対象の反映でも即時に切り替える |

表示モード・開閉状態の変更だけではアニメーションしない。アニメーションの見た目は `DESIGN.md` に従う。

### グルーピングとソート

両モード共通の規則。

| 対象 | 規則 |
| --- | --- |
| グループ | 追加済みワークスペースごとに 1 グループ。セッションが無い cwd も空のグループを表示する。セッション行は「データソース」、ラベルとパスの表示は「Webview の表示」に従う |
| グループ順 | ラベル（グループ見出しの basename）のアルファベット順。大文字小文字は区別しない。セッションが無いグループも同じ順で並べる。同一ラベルなら cwd の昇順 |
| グループ内セッション順 | 開始日時の降順。同一ならセッション ID の昇順。開始日時不明のセッションは有効な開始日時を持つセッションの後方に並べ、不明同士はセッション ID の昇順とする |
| セッション行の更新日時 | 日時がある場合は、更新日時のローカル日付が表示時点の当日なら時刻（`HH:mm`、24時間・0埋め）だけ、それ以外は月日（`MM/DD`、0埋め）だけを表示する |
| セッション行の補足情報 | 表示名、セッション ID、cwd、更新日時、実行フェーズを確認できる。セッション ID と実行フェーズは行ホバーのヒント、cwd はグループ見出しのホバーのヒントで確認する |
| 空のとき | 「一覧の取得状態」に従う |

開始日時が変わらない限り、メッセージや compaction の追記、ファイルの更新日時の変更、Refresh を経ても、セッション同士の相対順を保つ。

### Pi の停止

Pi の停止は、対象の完全なセッション ID を渡す pi-mux の公開操作で行う。pi-mux が対象 Pi の終了と復元候補の除去を担う。

| 停止の目的・条件 | 公開操作と結果 |
| --- | --- |
| 明示的な Archive | `pi-mux close <セッション ID>` を呼ぶ。対象 Pi が停止済み、list に不在、または専用 server が不在でも呼び、server を起動せず残った復元候補を除く |
| 別会話選択または New Session で正常に開いた後、直前の表示先が一時 Pi | `pi-mux close --if-temporary <セッション ID>` を呼ぶ。pi-mux が停止時の一時状態を判定する。list の取得後に通常 Pi へ昇格している場合も、停止も復元候補除去もせず成功する |

| close の結果 | 拡張機能の処理 |
| --- | --- |
| 終了コード0（stdout・stderr は空） | 停止成功として後続処理へ進む |
| CLI が利用できない、または非0終了 | 対象と失敗内容を示すエラーを表示する。直接 tmux を終了する代替処理・自動再試行・Pi の自動再起動を行わない。非0終了は Pi の生存を意味せず、停止後の復元候補除去に失敗した可能性もある |

close は保存済み会話・workspace 登録を保持する。同居する別 Pi・pane とシェル、最後の Pi を止めた後の専用 server も保持する。表示先の扱いは、それぞれの操作の規則に従う。

### アーカイブ・未アーカイブアクション

| 条件 | 操作 | 結果 |
| --- | --- | --- |
| 未アーカイブの行の `Archive` をクリックまたはキーボードで実行 | 確認を挟まず、その行のアーカイブ要求を1回送る。「Pi の停止」の通常 close を呼び、成功後に一覧を再読込する | アーカイブ後の表示は「表示モード」に従う。対象を共有表示用 Terminal のタブで表示中なら、別のセッションに切り替えず、そのタブを閉じて選択表示を解除する。別セッションを表示中ならその表示を維持し、タブが無ければ作成しない |
| Archive 対象の保持中 Pi が無い | 同じ通常 close 操作を呼ぶ | 残った復元候補も除き、保存済みのセッションをアーカイブできる |
| Archive または Unarchive の対象が一覧で確認済みのセッション ID でない | エラーメッセージを表示し、操作しない | Pi・表示先・一覧は変わらない |
| close に失敗する | エラーメッセージを表示し、表示先の解除へ進まない | 拡張が保持する表示先を保つ。稼働状態と一覧の表示区分は、次の list の応答に従う |
| アーカイブ済みの行の `Unarchive` を実行 | `pi-mux open <セッション ID>` を呼び、同じセッションへ接続する。既存 Pi・表示用 Terminal の有無によらず、この通常 open を実行する | 実行開始を待たず通常保持へ移る。既存 Pi は重複起動せず、共有 Terminal にその Pi TUI を前面表示する。正常に開いた後に選択表示を移し、一覧を再読込する |
| Unarchive の Terminal 作成前の処理・Terminal 作成・既存 Terminal の切替に失敗する | 「セッション選択と Terminal」のエラー・表示復旧の規則に従う | 先行して表示区分を変えず、従前の表示先と Pi を保持する。表示区分は list の応答に従う |

終了対象は拡張が確認済みのセッションから決める。別セッションの Pi と通常の tmux 環境は維持する。アーカイブ・未アーカイブともセッションファイルを変更・削除・移動しない。同一 VS Code window の行選択は「セッション選択と Terminal」の規則に従う。省略されなかった行選択・新規起動・アーカイブ・未アーカイブは受け付けた順に処理する。

`Archive` と `Unarchive` の待機表示は、セッション行ごとに次の規則で切り替える。見た目は `DESIGN.md` に従う。

| 条件・状態 | 操作・変化 | 結果 |
| --- | --- | --- |
| 行の `Archive` または `Unarchive` | クリックまたはキーボードで実行する | 操作直後にその行の待機表示を開始する |
| 要求が待機中 | 同じ行または別の行の `Archive`・`Unarchive` を実行する | 追加の要求も受け付ける。各セッションの待機表示は独立し、処理は受け付けた順に従う |
| 待機中の Archive 要求 | 「Pi の停止」の通常 close と一覧の再読込を終える | その要求の待機を終了する |
| 待機中の Unarchive 要求 | Terminal の作成または接続先切替、前面表示、一覧の再読込を終える | その要求の待機を終了する |
| 待機中の要求 | 対象の確認、close、または Terminal 作成・切替に失敗する | その要求の待機を終了し、既存の失敗規則に従ってエラーを表示する |
| 待機中の要求 | workspace 登録解除で意図的なキャンセルとして終了する | その要求の待機を終了し、失敗通知は出さない |
| 同じ行の要求が複数待機中 | 一部の要求の待機が終了する | その行のすべての要求の待機が終了するまで待機表示を保つ |

待機中の Archive・Unarchive 要求に伴う一覧の切替方法は「一覧更新のアニメーション」に従う。

### 静的プレビュー

Storybook のカタログで、VS Code API と実セッションファイルを使わずに Webview の見た目と操作を確認できる。`bun run storybook` でカタログをブラウザに表示でき、`bun run storybook:build` の静的出力は任意の静的サーバで単独表示できる。カタログはサンプルデータで次の状態を確認できる。

| ストーリーの軸 | 値 |
| --- | --- |
| データ | 複数の cwd グループ、セッションの無い登録済みワークスペース、アーカイブ済みを含むセッション / あるワークスペースを `All` に切り替えた状態 / 全ワークスペースに未アーカイブが 0 件で履歴を開ける状態 / 公開遅延中のセッションを含む状態 |
| 幅 | narrow（320px・既定）/ wide（720px） |

カタログ上でグループ見出しのモード切替、表示中セッションの行の選択表示、`Archive`、`Unarchive`、グループ見出しの `New session`、`New workspace` のフォーム操作、登録済みグループ見出しの省略メニューとコンテキストメニューからの `Unregister workspace` をサンプルデータに対して実行できる。グループ見出しの New session はそのグループのサンプルデータへ未アーカイブの行を追加し、New workspace は入力した cwd をサンプルデータへ登録し、Unregister workspace はサンプルデータから登録を外す（Terminal は起動しない）。カタログの操作は実セッションファイル、pi-mux の管理情報、VS Code Terminal に影響しない。静的出力は拡張機能を起動せずにスクリーンショットを撮影できる。

### Refresh アクション

Sessions の標準ビュータイトルにある更新操作の名前とツールチップは `Refresh Sessions` とする。

この更新操作の取得対象は「保存履歴の更新」に従い、取得結果で一覧を再描画する。稼働 Pi の自動更新は「実行フェーズの表示」、保存済み会話の自動更新は「保存履歴の更新」に従う。セッション行は「データソース」、workspace の表示と保持は「workspace 登録と永続情報」に従う。

### New Workspace アクション

フッタの `New workspace` で開くフルパス入力フォームの振る舞い。

| 項目 | 値 |
| --- | --- |
| フォーム | フッタの `New workspace` を選ぶと、ボタンをフルパスの入力欄1つに置き換える。開いた時点で入力は空で、入力欄にフォーカスする。`Enter` で登録し、登録成功で入力を捨ててボタンへ戻る。キャンセルは同表の規則に従う |
| パス展開 | New Workspace の入力を検証する前に、先頭の `~`（`~` 単体と `~/` 始まり）をホームディレクトリへ置き換える。保存済みの cwd は再展開しない |
| 登録 | `Enter` で入力を検証し、有効なら `pi-mux workspace register <cwd>` を呼び、成功後に一覧を再読込する。登録する cwd は展開と正規化の後の絶対パスとする。登録した cwd は VS Code 再起動後もセッションが無くても list に載り、グループとして表示される |
| 既存セッション | 表示区分は「データソース」の規則に従う。登録前の保存済み会話と稼働 Pi も同じ区分で表示する |
| 無効なパス | 絶対パスでない、存在しない、またはディレクトリでない入力はエラーを表示し、登録しない。フォームは開いたまま入力を保持する |
| 空の入力 | `Enter` を押してもフォームと入力を変えない |
| list に登録済みの cwd | 入力が既に登録済みの cwd と同じディレクトリを指す場合、再登録せずフォームだけを閉じる。一覧・workspace 登録は変えない。登録していない cwd（セッションファイルのある cwd を含む）への登録は常に受け付ける |
| 登録 CLI の結果 | 終了コード0（stdout・stderr は空）なら登録成功とする。CLI が利用できない、または非0終了なら対象と失敗内容を示すエラーを表示し、フォームと入力を保持する |
| キャンセル | `Escape`、入力欄から別要素へのフォーカス移動、Webview 外へのフォーカス移動で、入力の有無によらず入力を捨ててボタンへ戻る。フォーカス移動によるキャンセルでは移動先のフォーカスと操作を保つ。キャンセルだけでは登録せず、一覧・workspace 登録・現在の表示先を変えない |

### ワークスペース登録解除

追加済みワークスペースのグループ見出しの省略メニューとコンテキストメニューで開く `Unregister workspace` の振る舞い。

| 項目 | 値 |
| --- | --- |
| メニュー | どの入口からも `Unregister workspace` だけを含む同じメニューを開く。メニュー操作はポインターで行う。空・折りたたみ中のグループでも使える。開くだけではグループ開閉・表示モード・行選択・workspace 登録を変えない |
| 省略メニューの開閉 | 見出し名の隣の省略メニューボタンをクリックすると、同じワークスペースのメニューが開いている場合は閉じ、それ以外はボタンの左下を基準にメニューを開く。ボタンのヒントとアクセシブル名は `Workspace actions` とし、支援技術へメニューを開閉する操作であることと開閉状態を示す |
| 右クリックで開く | グループ見出しを右クリックすると、ポインター位置にメニューを開く |
| メニューを閉じる | メニュー外のポインター操作・スクロール・リサイズ・Webview のフォーカス喪失で閉じる。閉じるだけでは登録解除を実行しない |
| 対象の更新 | メニューを開いたグループが一覧から消えたらメニューを閉じる。別グループのメニューを開くと対象をその cwd に切り替える。同じ basename の cwd も区別する |
| 対象 | `Unregister workspace` が選ばれたグループの cwd。その cwd の稼働中・起動途中の Pi を終了し、終了を確認してから workspace 登録と同じ cwd の復元候補を除く。他 workspace と保存済み会話を保持する |
| 実行 | メニューの `Unregister workspace` をクリックすると、メニューを閉じ、確認を挟まずその cwd の登録解除要求を1回送り、`pi-mux workspace unregister <cwd>` を呼ぶ。成功後に対象 cwd を追加済み workspace から除き、一覧を再読込する |
| 解除受付時のセッション選択・未アーカイブ化 | 同じ cwd で待機中・接続中のセッション選択・未アーカイブ化の要求を意図的なキャンセルとして終了し、VS Code と Webview の失敗通知を出さない。遅れて接続結果が返っても Terminal の表示・選択を復活させない。別 cwd の要求と、解除によらない接続失敗は通常の規則に従う |
| 解除 CLI の結果 | 終了コード0（stdout・stderr は空）なら解除成功とする。CLI が利用できない、または非0終了なら対象と失敗内容を示すエラーを表示し、追加済み workspace は保持する。既に終了した Pi は再起動しない |
| 未追加のグループ | 一覧に現れない |

### New Session アクション

拡張機能は `New session` の要求ごとに新しい Pi を起動する。拡張機能の起動・再読み込み、workspace の登録、会話の保存だけでは新しい Pi を起動しない。

| 項目 | 値 |
| --- | --- |
| 起動 cwd | グループ見出しの `New session` が選ばれたグループの cwd を開始先とする。開始先の選択操作はなく、pi-mux を通じてその cwd の新規セッションへ接続する |
| 無効な開始先 | 絶対パスでない、存在しない、またはディレクトリでない開始先は対象を含むエラーを表示し、Pi・表示用 Terminal・workspace 登録・現在の表示先を変えない |
| Terminal の即表示 | cwd の検証が済んだ要求を受けた時点で、既存の共有 Terminal があれば Editor Area で直ちに前面表示する。先行要求の接続が未完了でも、その完了や受付順の到来を待たずに再表示する。共有 Terminal が無い場合も、セッションの作成・接続先セッション ID の確定・一覧の取得・接続の確認を待たずに、表示用 Terminal を作成・表示する |
| 接続先の確定・切替 | Terminal の前面表示と分離し、受け付けた順に処理する。前面表示だけでは接続先・選択表示を変えない。選択先の保持中 Pi が無い場合などで表示用 Terminal の作り直しが必要なときは、「セッション選択と Terminal」の旧タブ閉鎖完了を待ってから作成する。閉鎖中に次の要求を受けた場合も同じ閉鎖完了を待ち、共有 Terminal を同時に最大1個に保つ |
| 起動・接続 | pi-mux が開始先の cwd で新しい空の Pi を確保する。共有 Terminal が無い場合、表示用 Terminal が `pi-mux new --cwd <開始先の cwd>` を実行して接続し、拡張はその Terminal のプロセス ID を使う `pi-mux current` で接続先のセッション ID を確定する。表示用 Terminal の起動 cwd は「セッション選択と Terminal」に従い、開始先の cwd に依存しない。共有 Terminal がある場合、拡張が `pi-mux new --detached` を実行し、接続先のセッション ID が確定したら既存の共有 Terminal を `pi-mux switch` で切り替える |
| 未保存の新規セッションが同じ cwd に稼働している | pi-mux は稼働中の未保存新規セッションを選ばず、開始先の cwd で新しい独立した Pi を起動する。共有 Terminal は表示を新しい Pi の tmux セッションへ切り替えて表示する。最初の通常メッセージが保存される前に連続して実行しても、各要求は独立した会話を作る |
| 正常に開いた後 | Webview を再読込する。所属と行の表示は「データソース」に従う。新しい Pi が表示先になり、選択表示はそのセッションの行が現れた後にその行へ移る。直前の表示先の一時 Pi は「セッション選択と Terminal」の切替後停止に従う |
| 起動した Pi との対応 | 接続先のセッション ID をその Pi へ対応づける。以後そのセッションの選択では、生存している同じ Pi へ接続する |
| 起動・接続の失敗 | 対象の cwd と失敗内容を示すエラーを表示し、先行して一覧の表示区分を変えない。Terminal 作成前の失敗・Terminal 作成失敗・既存 Terminal の切替失敗と表示復旧は「セッション選択と Terminal」に従い、再利用した Terminal では従前の表示先を保つ。新規 Terminal 内の接続と失敗処理も同節に従う |

`New session` の待機表示は、ワークスペースの cwd ごとに次の規則で切り替える。見た目は `DESIGN.md` に従う。

| 条件・状態 | 操作・変化 | 結果 |
| --- | --- | --- |
| グループ見出しの `New session` | クリックまたはキーボードで実行する | 操作直後にその cwd の待機表示を開始する |
| 起動・接続の要求が待機中 | 同じ cwd または別の cwd の `New session` を実行する | 追加の要求も受け付ける。各 cwd の待機表示は独立し、接続先の確定・切替は既存の受付順に従う |
| 待機中の要求 | 新規 Terminal の作成または既存 Terminal の接続先切替を終え、Terminal の前面表示を要求する処理を終える | その要求の待機を終了する。一覧の再読込完了は待たない |
| 待機中の要求 | 開始先の検証、起動または接続に失敗する | その要求の待機を終了し、既存の失敗規則に従ってエラーを表示する |
| 同じ cwd の要求が複数待機中 | 一部の要求の待機が終了する | その cwd のすべての要求の待機が終了するまで待機表示を保つ |

待機の終了は Terminal の表示要求までを表し、Terminal の描画完了や Pi の入力準備完了を保証しない。

## workspaceFolders 同期

拡張機能は pi-mux list の workspace と本体リポジトリの worktree を、VS Code の `workspaceFolders` へ反映する。フォルダ0は `~/.agents/workspace` に固定し、同期対象は folder 1 以降の管理フォルダに限る。`workspaceFolders` は、フォルダ0、pi-mux list の順に並ぶ workspace、各 workspace の直後に続くその本体リポジトリの worktree フォルダだけを持つ。

### 起動時のワークスペース遷移

| 条件 | 動作 |
| --- | --- |
| フォルダ0が `~/.agents/workspace` と同じ実体で起動する | 単一フォルダのときは、フォルダ0を同一内容で保持したまま untitled ワークスペースへ遷移する。それ以外の構成では遷移せず、その構成のまま同期を続ける |
| フォルダ0が `~/.agents/workspace` と異なる実体で起動する（フォルダモード・保存済みワークスペース・複数フォルダ・untitled ワークスペースを含む） | `~/.agents/workspace` を位置0へ挿入し、もとのフォルダ0を位置1へ移す1回の編集でフォルダ0を付け替える。保存済みワークスペースでは、この編集がワークスペースファイルに反映される。フォルダモードでは、この編集自体が untitled ワークスペースへの遷移になる |
| フォルダが1つも無いウィンドウで起動する | フォルダが現れるのを待ち、現れた時点で、その時点の構成に起動時と同じ遷移と同期を適用する。待ちの間は worktree の検出も `workspaceFolders` の適用も行わない |
| ワークスペースファイルを持たないウィンドウで、フォルダが現れないまま空ウィンドウ判定のタイムアウト (10秒) を過ぎる | 空ウィンドウとみなし、現在のウィンドウで `~/.agents/workspace` を開き直す。開き直ったウィンドウの次の起動で、通常どおり遷移と同期が始まる |
| `~/.agents/workspace` が存在しない | フォルダ0として登録する前にディレクトリを作成する |
| 付け替えの編集が拒否される | 付け替えを中止し、通知しない。次の同期の適用前に再試行する |
| 単一フォルダの untitled 昇格が拒否される、遷移待ちの間にフォルダが増える | 遷移を中止し、通知しない。フォルダの追加適用時に untitled への遷移が起こる |

### worktree の検出

検出対象の本体リポジトリを次の方法で収集し、各本体リポジトリで `git worktree list --porcelain` を実行して worktree を検出する。本体リポジトリ自身（main worktree）は検出結果の worktree に含めない。

| 条件 | 動作 |
| --- | --- |
| pi-mux list に載る cwd | 本体リポジトリ候補にする |
| 管理フォルダのうち `.git` ファイルを持ち、その `gitdir:` から本体リポジトリの `.git` ディレクトリを解決できるフォルダ | その本体リポジトリを候補にする |
| bare リポジトリ、不完全な porcelain ブロック | 管理対象に含めない |
| git コマンドが利用できない、実行が失敗する | worktree の検出を保留し、list に基づく同期は続ける |

検出周期は 2500 ミリ秒とする。検出の実行を重ねず、進行中の検出の完了後に次の検出を行う。worktree フォルダの表示名は worktree のブランチ名とし、detached HEAD のときは `(detached <HEADの先頭7文字>)` とする。worktree フォルダの並び順は、表示名のアルファベット順とする。

### フォルダの並び

`workspaceFolders` の並びは次の規則に従う。順序がこの規則と異なる管理フォルダは、フォルダを追加・削除しない1回の編集で並べ替える。並べ替えでエディタタブは閉じない。

| 対象 | 位置 |
| --- | --- |
| フォルダ0（`~/.agents/workspace`） | 先頭 |
| pi-mux list の各 workspace | フォルダ0の直後から pi-mux list の並び順 |
| 本体リポジトリの worktree | その本体リポジトリのフォルダの直後に、表示名のアルファベット順 |
| 本体リポジトリのフォルダが無い worktree | ほかのグループの末尾に、表示名のアルファベット順 |
| pi-mux list の cwd と worktree の両方に該当するフォルダ | pi-mux list の位置を優先し、既存のフォルダ名を維持する |

### 管理フォルダの同期

pi-mux list の取得結果と worktree の検出結果を現在の `workspaceFolders` と突き合わせ、差分と並び順を適用する。適用の契機は、list の取得完了ごとに list に基づく差分、worktree の検出完了ごとに worktree に基づく差分とする。folder 1 以降のフォルダはすべて管理フォルダとして扱い、最初の適用は起動後の list の初回取得成功後に限る。この拡張機能が担うのはフォルダの追加・削除・並べ替えまでであり、SCM への反映は VS Code 内蔵 Git がフォルダの追加・削除に反応して行う。

| 条件・変化 | 動作 |
| --- | --- |
| pi-mux list に載る cwd が `workspaceFolders` に無い | その cwd を「フォルダの並び」の位置に管理フォルダとして追加する |
| 管理フォルダの cwd が pi-mux list から消える | そのフォルダを削除する。削除前にそのフォルダ配下のエディタタブを閉じる。未保存の変更があるタブは VS Code の確認ダイアログに従う |
| worktree が検出結果に現れる | その worktree を管理フォルダとして追加する。pi-mux へは登録しない |
| worktree が検出結果から消える、または prunable になる | そのフォルダを削除する。ただし pi-mux list に載る cwd と同じ実体のフォルダは保持する。削除前にそのフォルダ配下のエディタタブを閉じる。未保存の変更があるタブは VS Code の確認ダイアログに従う |
| フォルダ0と同じ実体の cwd が pi-mux list に載る | 重複追加せず、フォルダ0をその workspace として扱う |
| folder 1 以降に、pi-mux list の cwd と検出済み worktree のどちらとも一致しないフォルダがある | そのフォルダを削除する。削除前のタブの扱いは上の削除と同じ |
| フォルダ0以外に `~/.agents/workspace` と同じ実体のフォルダがある | そのフォルダを削除する。削除前のタブの扱いは上の削除と同じ |
| ユーザーが管理フォルダを `workspaceFolders` から外す | pi-mux list に載り続ける、または worktree が生存する限り、次の同期で再追加する |
| エディタタブの確認ダイアログがキャンセルされる、フォルダの追加・削除・並べ替えの適用が拒否される、git の実行が失敗する | 通知せず同期状態を維持し、次の同期で再試行する。キャンセル・拒否された削除対象は管理フォルダに残す |

### タイトルバー

| 条件 | 動作 |
| --- | --- |
| フォルダ0が `~/.agents/workspace` である untitled ワークスペース | `window.title` のテンプレートを `${dirty}${activeEditorShort}${separator}${profileName}${separator}${appName}` にし、workspace スコープへ書き込む。拡張機能の起動時に書き、既存値を上書きする。付け替えが起動後の再試行で達成された場合も、達成時に書く |

## セッション選択と Terminal

セッション項目をクリックすると、選択したセッションの Pi TUI を Editor Area の共有 Terminal に前面表示する。この拡張の表示用 Terminal は VS Code ウィンドウごとに同時に最大1個とし、表示しない通常 Pi は裏で稼働を続ける。続けてセッションを選択した場合は、実行中の処理を終えてから、最新の選択先だけを処理する。Pi の起動・再接続先はセッションの cwd である。

Terminal のタイトルは、Pi TUI が通知するタイトルをそのまま表示する。拡張は通知されたタイトルを変更せず、独自のタイトルを付けない。`terminal.integrated.tabs.title` 設定が通知タイトルを採用しない環境（既定の `${process}` など）では、代わりにプロセス名 `tmux` が表示される。表示用 Terminal の起動 cwd は利用者のホームディレクトリとし、セッションの cwd に依存しない。タブの cwd 補助ラベルは起動 cwd のみを示し、セッションの切り替えで変化しない。

Pi は pi-mux が管理する専用 tmux 内でセッションごとに保持し、表示用 Terminal の開閉と稼働を切り離す。実行環境では `pi-mux` を利用できる必要がある。tmux 側の一覧は表示せず、セッションの選択は拡張の一覧から行う。pi-mux の専用環境は利用者の通常の tmux 環境と分離し、拡張は利用者の他のターミナル・tmux セッション・設定を変更しない。

表示用 Terminal は、セッションの選択・未アーカイブでは `pi-mux open` を、新規セッションでは `pi-mux new --cwd <セッションの cwd>` を起動する設定で作成し、作成後すぐに前面表示を要求する。選択・未アーカイブでは、拡張はプロセス ID の取得や接続確認を待たず、作成・表示要求をもって正常に開いたものとして表示先・選択表示・既読化を更新する。新規セッションでは、表示先・選択表示は接続先セッション ID の確定後に更新する。Terminal 内の tmux への接続とその失敗処理は pi-mux CLI が担う。

既存 Terminal の表示切替と表示中セッションの確認は tmux を直接操作せず、pi-mux CLI で行う。切替は `pi-mux switch <セッション ID> --client-pid <表示用 Terminal のプロセス ID>`、確認は `pi-mux current --client-pid <同じ PID>` を使う。既存 Terminal が tmux クライアントとして attach し切っていない間は、切替が成功するまで一定間隔で再試行する。

専用 tmux のステータスバー・prefix・タイトル転送・修飾キーの報告形式・マウス割り当ては、pi-mux が管理する設定であり、拡張はそれを変更しない。pi-mux の専用 tmux は、Pi が修飾キー付きキー（Shift+Enter など）を区別できるよう報告形式を設定し、Ctrl+左ドラッグによる floating pane 作成だけを無効にする。

VS Code の Terminal は修飾キー付き Enter を報告しないため、tmux を介した Pi では Shift+Enter が通常の Enter と区別できない。そこでこの拡張機能は、Terminal へフォーカスがあるときの `Shift+Enter` を `sendSequence` で CSI-u 形式（`ESC [ 13 ; 2 u`）の送信に束ねる。pi-mux の専用 tmux はこのシーケンスを `S-Enter` キーイベントとして受け、同じ CSI-u シーケンスで pane へ転送する。tmux を介さない環境でも、Pi TUI は CSI-u シーケンスを Shift+Enter として認識する。

| 条件・操作 | 動作 |
| --- | --- |
| 一覧で確認済みのセッション ID でない対象を選択する | 対象のセッション ID を含むエラーメッセージを表示し、Pi・表示先・一覧を保持する |
| セッションファイルが存在しない | 選択先が pi-mux の稼働一覧にあるなら、その Pi へ表示を切り替える（ファイルの再作成はしない）。稼働一覧にもない場合、エラーメッセージを表示し、Pi の起動や現在の表示先の切替を行わない |
| cwd が絶対パスでない、存在しない、またはディレクトリでない | 対象を含むエラーメッセージを表示し、Pi・表示先・workspace 登録を変えない |
| アーカイブ済みセッションを通常選択する | `pi-mux open --temporary <セッション ID>` で一時再開・接続する。通常 Pi が既にあれば通常状態を維持し、一時状態へ降格させない |
| 未アーカイブセッションを選択する | 通常の `pi-mux open <セッション ID>` による再開・接続を使う |
| 選択したセッションの Pi が生存している | Pi を起動し直さず、共有 Terminal をその Pi へ切り替えて表示する。一時 Pi の再選択は一時 open または表示再接続として扱い、通常 open による昇格を起こさない |
| 選択したセッションの保持中 Pi が無い、または終了済み | 上記の表示区分に対応する open で、pi-mux が保存済みセッションを元の cwd で再開し、表示用 Terminal がその Pi へ接続する。表示用 Terminal が無い場合は作って実行する |
| 表示用 Terminal が開いている状態でセッションを選択し、その Pi が生存している | 現在の表示用 Terminal で選択先の Pi TUI を表示する。拡張が付けた固定名 `Pi` が残っている場合は、旧表示タブの閉鎖完了後に表示用 Terminal だけを作り直し、同じ Pi へ接続する |
| 表示用 Terminal が開いている状態で、選択先の保持中 Pi が無い | 旧表示タブの閉鎖完了後、表示用 Terminal を作り直して選択先の Pi へ接続する。保持中の Pi とセッションとの対応は維持する |
| 表示用 Terminal のタブを閉じる | 表示用の接続だけを閉じ、保持中の Pi とセッションとの対応を維持する |
| 表示タブが閉じた状態でセッションを再選択する | Editor Area に表示用 Terminal を1個作り、生存している同じ Pi へ再接続する |
| Pi が終了する | 自動で再起動せず、次回選択時に保存されたセッションを再開する |
| Terminal 作成前の処理、または既存 Terminal の切替に失敗する | 対象と失敗内容を示すエラーを表示する。同じセッションの Pi を重複起動せず、先行して一覧の表示区分を変えない。従前の表示先と Pi を保持する |

表示用 Terminal の作り直しで、旧タブの閉鎖後に拡張が新しい Terminal の作成失敗を検出した場合は、次の規則で表示を復旧する。復旧の試行は1回とし、生存中の同じ Pi への表示接続だけを作り直す。Pi の再起動や一時状態から通常状態への昇格は行わない。復旧用 Terminal にも新規 Terminal の即表示の規則を適用する。

| 条件・状態 | 動作 |
| --- | --- |
| 切替前の表示先を保持しており、その Pi の生存を確認できる | 元の Pi への表示用 Terminal を作成して前面表示し、従前の選択表示を保つ。失敗した切替先と原因、元の会話を再表示したことを VS Code の通知と一覧の操作エラーで伝える |
| 切替前の表示先が無い、またはその Pi が生存していない | 表示の再作成を行わず、元の切替失敗を通知する |
| 元の Pi の生存確認、または復旧用 Terminal の作成に失敗する | 元の切替失敗と復旧失敗を併記して通知し、復旧を繰り返さない |
| 要求が取り消された、切替先または復旧先の workspace の登録解除を受け付けた、または拡張機能が終了・再読み込みされた | 復旧を中断する。遅れて復旧処理が完了しても、Terminal の表示や選択表示を復活させない。登録解除による取消の通知は「ワークスペース登録解除」に従う |

pi-mux による再開は既存のセッションファイルへの追記として行われ、新しいセッションファイルは作られない。

一時再開から通常保持への昇格は pi-mux が担う。Pi が実行開始を通知した場合、または明示 Unarchive の通常 open を受けた場合に通常保持へ移り、復元対象となる。拡張は list の `temporary` によって区分を反映し、state 通知の送信や JSONL の独自メッセージ監視で昇格させない。起動・閲覧だけの待機状態やタイトル変更では一時状態を維持し、昇格後の待機状態でも通常状態を維持する。

| 条件・状態 | 操作・変化 | 直前の表示先の扱い |
| --- | --- | --- |
| 直前の表示先が一時 Pi | 別会話の選択または New Session で正常に開き、表示先が別の ID へ移る | 「Pi の停止」の条件付き close を直前の表示先だけに呼ぶ。外部の一時 Pi をまとめて停止しない |
| 直前の表示先が通常 Pi | 表示先が別の ID へ移る | Pi を保持する |
| 同じセッションを再選択、Terminal 作成前の処理・Terminal 作成・既存 Terminal の切替に失敗する | 表示先 ID は変わらない | 直前の Pi を停止しない |
| 切替後の条件付き close に失敗する | 対象と失敗内容を示すエラーを表示する | 新しい表示先への切替は成立したまま保つ |
| 表示用 Terminal のタブを閉じる、または拡張を再読み込みする | 表示接続を閉じる | この操作だけを理由に Pi を停止しない |

切替後の停止判定は list の一時属性に従う。表示先 ID の保持は、同じ拡張 host 内で既に確定した表示先を対象とする。再読み込み時に汎用的な表示先 ID の復元は行わない。

### Pi の起動環境

拡張が `pi-mux new --detached` を直接起動するときは、子プロセスへ渡す環境を次の規則で補完する。

| 条件 | 子プロセスへ渡す環境 |
| --- | --- |
| `COLORTERM` が未設定 | `COLORTERM=truecolor` を補完する |
| `COLORTERM` が設定済み（空文字を含む） | 既存値を保持する |

補完は子プロセスの環境にだけ適用し、拡張 host の環境を変更しない。表示用 Terminal で pi-mux を実行するときは、VS Code 標準の Terminal 環境を利用する。拡張は既存の `PI_TRUE_COLOR` と Pi の `terminal.trueColor` 設定を変更せず、色モードの選択は Pi に従う。

### VS Code 再起動

再起動後は保持した追加済み workspace と最新の list・保存済み会話から一覧が復元され、全ワークスペースのモードは未アーカイブ表示（既定）に戻る。untitled ワークスペースは VS Code が復元し、復元後の管理フォルダは「workspaceFolders 同期」に従う。セッションを再選択した際は pi-mux で稼働状態を確認し、生存している Pi があれば同じプロセスへ再接続する。生存 Pi が無い場合は保存されたセッションを再開する。拡張 host の再起動だけを理由に既存の Pi を起動し直さない。表示用 Terminal はウィンドウ内で1個に保つ。

## 開発補助: e2e 用 VS Code の準備

e2e テストが拡張機能の読み込み先として使う固定バージョンの VS Code を、1 コマンドで準備する。利用者はこのリポジトリで開発するコントリビュータで、テスト実行前にこのコマンドでバイナリを取得する。

| 項目 | 値 |
| --- | --- |
| コマンド | `bun run setup` |
| 準備対象 | e2e テストが拡張機能の読み込み先として使う Linux 版 VS Code（スクリプトに定義した固定バージョン） |
| 保存先 | `~/.cache/agent-kit-screenshots/vscode-<固定バージョン>/`（例: `vscode-1.138.0/`） |
| バージョン管理 | ダウンロードした VS Code とその展開物は git の管理対象外 |

| 条件 | 動作 |
| --- | --- |
| `bun run setup` を実行 | 固定バージョンの Linux 版 VS Code が保存先に存在しなければダウンロードして展開し、存在すれば取得済みのものを再利用する。コマンド 1 回で完了する |
| 保存先ディレクトリが存在しない | 準備の前に作成する |
| 準備に成功 | コマンドは終了コード 0 で終了し、保存した実行ファイルのパスを標準出力に表示する |
| 準備に失敗 | コマンドは非ゼロの終了コードで終了し、失敗の原因を標準エラー出力に表示する |

## 設計上の制約

- Pi がセッションとエージェントの source of truth である。拡張機能は Pi を再実装せず、Pi セッション形式の独自変換も行わない
- Pi の保持先は pi-mux が管理する専用 tmux である。拡張は専用 tmux への socket 接続や tmux コマンドを直接使わず、表示の切替と表示中セッションの確認は pi-mux CLI（`switch` / `current`）、Pi の停止は公開操作 `pi-mux close` を使う。pi-mux の設定・管理対象を変更しない
- workspace 登録と復元候補の共有は pi-mux の公開 CLI を通じて行う。拡張機能による永続情報の扱いは「workspace 登録と永続情報」に従う
- `workspaceFolders` の同期は pi-mux list と `git worktree list` を正とする。フォルダ0 (`~/.agents/workspace`) を固定で使い、同期は folder 1 以降の管理フォルダに限る
- セッションファイルは read-only として扱い、セッションの作成・更新は Pi CLI に行わせる
