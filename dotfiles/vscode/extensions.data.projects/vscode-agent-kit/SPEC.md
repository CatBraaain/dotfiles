# VS Code Pi Session Manager spec

Pi（pi-coding-agent）のセッションを VS Code のサイドバーで一覧し、選択して Editor Area の Terminal で Pi TUI を開く VS Code 拡張機能の仕様。この拡張機能は Pi TUI を置き換えず、チャット UI やメッセージ表示も持たない。複数セッションの一覧・切替、明示的なアーカイブによる一覧の整理とロックによる保護を提供する。読者は利用者と拡張機能の開発者である。セッション一覧は VS Code 標準の TreeView ではなく、拡張機能が描画する Webview UI を使う。保存 E2E のテストケースを「テストケース」節に一覧し、各ケースの期待する結果から各定義節を参照する読み方をする。

## 用語

- セッションファイル: Pi が会話を保存する JSONL ファイル。場所と形式は Pi のドキュメント（[sessions](https://github.com/earendil-works/pi-mono/blob/main/packages/coding-agent/docs/sessions.md) / [session format](https://github.com/earendil-works/pi-mono/blob/main/packages/coding-agent/docs/session-format.md)）に従う。
- セッション ID: セッションファイルのヘッダーが持つ UUID。ファイル名は `<timestamp>_<session-id>.jsonl` で、ファイル名の末尾セグメントと一致する。
- メタデータストア: セッション ID をキーに、この拡張機能が管理する状態（アーカイブ・ロックなど）を保存する JSON ファイル。
- アーカイブ済みセッション: メタデータストアで `active` が `false` のセッション。既定の表示対象から除外される。
- ロック中セッション: メタデータストアで `locked` が真のセッション。ロックを解除するまでアーカイブされない。

## テストケース

保存 E2E（`tests/e2e/phase-one.spec.ts`）は、実機連携の振る舞いを次のテストケースで検証する。各ケースの期待する結果は、対応する定義節に従う。

| ID | テストケース | 期待する結果（節） | 撮影 | 検証手段 |
| --- | --- | --- | --- | --- |
| E2E-1 | 未アーカイブ 0 件の作業先で All に切り替え、保存済みの履歴を表示できる | サイドバービュー・表示モードどおりの表示と切替 | 一番上のグループの Unarchived（切替前）／All（履歴） | 保存 E2E |
| E2E-2 | A/B の会話を切り替える | Pi TUI が通知するタイトルのままの表示と選択cwdの補助ラベル、実 Pi の PID 不変、表示タブ最大1個、一覧で対象だけが選択され他の行は通常背景、選択先の Pi TUI が通常の入力待ち状態、タブ閉鎖後の同一 Pi への復帰、原本と Git の不変 | A の Pi TUI／B の Pi TUI | 保存 E2E |
| E2E-3 | SCM から Sessions へ戻っても、Refresh なしで一覧を復元する | Webview と拡張機能のメッセージどおりの再配信 | SCM 表示中／Sessions 復元後 | 保存 E2E |
| E2E-5 | workspace 未登録の作業先で会話を開き、別の会話との切替後も同じ Pi へ戻れる | 登録状態にかかわらない cwd での再開、Pi PID と workspace folder の保持、共有表示タブ1個 | 未登録 cwd の Pi TUI／再選択後の Pi TUI | 保存 E2E |
| E2E-6 | New Session がフルパス候補を出し、キャンセル・無効な開始先・別フォルダ選択を安全に扱う | New Session アクションどおりの候補と安全処理 | 候補一覧／別フォルダで起動 | 保存 E2E |
| E2E-7 | 存在しない cwd・削除済みセッションファイルの選択を安全に扱い、セッション原本と Git を変更しない | エラー表示、Terminal なし、メタデータ不変、原本・Git 不変 | 不在 cwd のエラー／削除済みのエラー | 保存 E2E |

既知の未達と範囲外課題は、この文書に書かず tickets で管理する。

### E2E結果の確認

開発者は `bun run test:e2e` で保存 E2E を実行し、プロジェクト直下の `e2e-gallery.html` をブラウザーで直接開いて、同じ実行で得た画面と自動テストの結果を確認できる。`e2e-gallery.html` はバージョン管理する固定のビューアーであり、テスト実行時には画像と結果データだけを `dist/e2e-gallery/` に出力する。画面の撮影は、通常の E2E の操作・確認と同じ step に含める。撮影対象は「テストケース」表の「撮影」欄が定める画面だけとし、操作のたびに撮影しない。同じ操作の反復で確認する事項は、反復の最終状態だけを撮影する。各ケースの撮影は比較の前後を1組とし、「撮影」欄のラベルをそのまま画像の添付名として付ける。添付名はギャラリーのセル見出しとして使う。ギャラリーは短い文言と画像だけで結果を一目で確認する構成とし、この文書のテストケースの説明や期待する結果の全文、文書のスナップショットは表示しない。ケースの詳細はこの文書を参照する。各ケースは画像をセルとする表で示し、比較の前後が並ぶ。セルの見出しは画像の添付名（「撮影」欄のラベル）だけとする。

| 条件・操作 | 結果 |
| --- | --- |
| 保存 E2E の実行が終了する | 走行の要約（合否・日時・枚数）を1行で示し、ケースごとに ID とテストケース名を1行に切り詰めた見出しと、画像をセルとする表を表示する |
| ケースが失敗、未実行、または画像を持たない | 失敗・未実行・画像なしを区別する短い文言を表示する。失敗のエラーは最初の行だけ表示する。画像があることを自動テストの成功や見た目の正しさとして扱わない |
| 並列実行・再試行で画像を保存する | ケース・step・実行環境・試行を識別でき、画像を上書きせず対応する結果から参照できる |
| 過去の実行で保存した画像がある | 今回の撮影結果として表示しない |
| スクリーンショットを開く | 原寸の画像を確認できる |
| プロジェクト直下の `e2e-gallery.html` をファイルとして直接開く | 今回の結果データと画像を相対パスで読み込み、サーバーなしで表示する |
| 結果データがまだ出力されていない | E2Eの実行を案内し、実行結果や画像を表示済みのものとして扱わない |

自動テストの合否はテストランナーの結果、見た目の判断は利用者の目視確認に基づく。Playwright 標準HTMLレポートは診断用の別の出力として保持する。

## データソース

拡張機能は Pi のセッションディレクトリを直接読んで一覧を作る。独自のセッションデータベースは持たない。この拡張機能の導入以前に Pi で作成されたセッションも、以後に作成されるセッションも同じ方法で一覧される。

| 項目 | 値 |
| --- | --- |
| エージェントディレクトリ | `PI_CODING_AGENT_DIR`（未設定・空文字なら `~/.pi/agent`） |
| セッションディレクトリ | `PI_CODING_AGENT_SESSION_DIR`（未設定・空文字なら `<エージェントディレクトリ>/sessions`） |
| 一覧対象 | `<セッションディレクトリ>/<cwd ディレクトリ>/` 直下の `*.jsonl` |
| 除外 | `subagents/` ディレクトリ配下のファイル（一覧対象ディレクトリ直下の `subagents/` を含む） |
| セッション ID と cwd | 各ファイル 1 行目のヘッダー `{"type":"session",...}` の `id` と `cwd`。cwd はディレクトリ名から復元せず、ヘッダーを正とする |
| 更新日時 | セッションファイルの mtime |

セッションディレクトリが存在しない、または `*.jsonl` が 1 件も無い場合、一覧は空になる。セッションディレクトリの読み取りに失敗した場合、エラーメッセージを表示する。

### 表示名

セッション項目の表示名は次の順で決める。

1. セッションファイル内の最新の `session_info` エントリの `name`（`/name` や `pi --name` で設定される値）。空文字はタイトル解除とみなし、次の規則へ進む
2. `text` を持つ最初のユーザーメッセージの、text 全体の前後の空白を取り除いた 1 行目（先頭 80 文字）
3. いずれも無い場合 `Untitled`

### メタデータストア

| 項目 | 値 |
| --- | --- |
| パス | `<エージェントディレクトリ>/session-metadata.json` |
| 形式 | 下記の JSON。文字コードは UTF-8 |
| 書き込み | 一時ファイルと rename による原子的置換。中断しても既存内容を壊さない |
| 同時書き込み | ファイル全体の読み書きの最後の書き込みが残る |

```json
{
  "version": 1,
  "sessions": {
    "<session-id>": { "active": false, "locked": true }
  }
}
```

- `active` が `false` のセッションをアーカイブ済みとみなす。キーが無い、`active` が `true`、またはフラグが欠落したセッションは未アーカイブとみなす。作成元や登録の有無にかかわらず、保存済みのセッションは未アーカイブとして既定の一覧に表示される
- `locked` が真のセッションをロック中とみなす。ロックは `locked` 真偽値属性として永続化する
- アーカイブは当該エントリの `active` を `false` に更新する。エントリ自体と他の属性は保持する
- 一括アーカイブは 1 回のメタデータ更新として書き込む。書き込みに失敗した場合、一部だけアーカイブされた状態にしない
- 読み書きで未知のキー・属性を保持する（将来の `pinned` / `title` / `tags` 等の追加に備える）
- ファイルが存在しない場合はメタデータ無しとして振る舞い、初回の書き込みで作成する
- 読み込み時に JSON を解析できない、または所定の構造でない場合（ルートと `sessions` がオブジェクトでない）はメタデータ無しとして振る舞い、書き込みは行わずエラーを表示する

Pi のセッション関連ファイルのうち、拡張機能が書き換えてよいのはメタデータストアのみである。セッションファイルは読み取り専用として扱い、変更・削除・移動をしない。セッションの作成と更新は Pi CLI が行う。

## サイドバービュー

Activity Bar に view container `Agent Sessions` を追加し、その中に拡張機能が管理する Webview view を表示する。VS Code 標準の TreeView は使わない。Webview は VS Code のテーマ色を使い、サイドバー幅に合わせて再配置される。セッションのファイル内容とメタデータストアの値は Webview に渡す表示用データだけに変換し、Webview からファイルシステムを直接操作しない。

### Webview の表示

Webview は次の順で表示する。

1. ヘッダーに `Sessions`、`New session`、`Refresh` を表示する
2. cwd ごとのグループを、枠線を持たない余白で区切ったセクションで表示する。グループ見出しに開閉の chevron、basename、そのワークスペースのモード切替（`Unarchived` / `All`）を表示する。見出しのホバーのヒントに cwd のフルパスを表示し、同じ basename のプロジェクトや worktree を区別する。chevron または見出し名を選ぶと、そのグループの行の表示を開閉する。開閉状態の既定は開いた状態で、VS Code 再起動後も維持しない
3. グループ内にセッションを行として表示する。行の左端にセッションの状態の印を置き、未アーカイブは塗り、ロック中は警告色、アーカイブ済みは中抜きで示す。行は表示名とセッションの状態（選択・ロック・アーカイブ済み）を示す
4. 各行の右端には、更新日時（等幅の数字で表示する）と、その行のセッション ID をクリップボードへコピーする `Copy` 操作、`Lock` / `Unlock` 操作、`Archive` 操作をこの順で表示する。`Copy` は copy アイコン、`Lock` / `Unlock` は鍵のアイコン、`Archive` はアーカイブのアイコンで示す。ホバーのヒントは `Copy session ID`、`Lock` または `Unlock`、`Archive` とする
5. 未アーカイブの行には `Archive` 操作を表示する。ロック中の行では `Archive` は実行できない無効な表示になり、ロック中であることを行の表示で確認できる。アーカイブ済みの行は All 表示でのみ現れ、行の表示を薄くしてアーカイブ済みであることを示す
6. セッション行全体を選択領域とし、選択の視覚表示は行の右端まで及ぶ。更新日時、`Copy`、`Lock` / `Unlock`、`Archive` は行の右端に重ねて表示する。行内操作のクリックは、行の選択やセッションの再開として扱わない

表示名・更新日時・グループ・並び順は「グルーピングとソート」の規則に従う。セッション行を選択する操作は、キーボードからも実行できる。行・見出し・操作の寸法と色の値は `DESIGN.md` が定める。

### セッション行の選択

| 操作 | 選択結果 | Terminal |
| --- | --- | --- |
| 行を通常クリック | その行だけの単一選択に置き換える | 「セッション選択と Terminal」の規則でセッションを開く |
| 行を Ctrl / Cmd + クリック | その行の選択を追加または解除する | 開かない |
| 行を Shift + クリック | アンカーとなる行からその行まで、表示順の範囲を選択する。範囲は cwd をまたぐ現在の表示順で扱う | 開かない |
| 一覧にフォーカスがある状態で Ctrl / Cmd + A | 表示中の未アーカイブ・非ロックのセッションを cwd 横断ですべて選択する | 開かない |

- 通常クリックと Ctrl / Cmd + クリックがアンカーを更新し、Shift + クリックはアンカーからクリック行までの範囲を選択する
- Ctrl / Cmd + A は一覧の要素にフォーカスがあるときだけ全選択に使う。一覧外の要素や入力欄の同名ショートカットは奪わない
- 選択は表示モードの切替や再読み込みをまたいで保持してよい。アーカイブの対象は「アーカイブアクション」のとおり表示中の選択対象に限る
- 折りたたんだグループの行は選択を保持し、表示中の行には含めない。`Ctrl / Cmd + A` の全選択とアーカイブの対象から外れる

### 表示モード

モードはワークスペースごとに独立して持ち、そのグループ見出しの `Unarchived` / `All` で切り替える。ワークスペース間で影響し合わない。

| モード | そのワークスペースの表示対象 |
| --- | --- |
| Unarchived（既定） | そのワークスペースの未アーカイブのセッションのみ。0 件でもグループ見出しとモード切替を表示する |
| All | そのワークスペースの全セッション。アーカイブ済みのセッション項目は薄い表示でアーカイブ済みであることを示す |

モードの切替状態は VS Code 再起動後も維持しない。保存済みセッションがあるすべての cwd で `All` を選択でき、アーカイブ済みの会話を選択・再開できる。過去のセッションが自動的にアーカイブされることはない。

### Webview と拡張機能のメッセージ

| Webview の操作 | 拡張機能の処理 | Webview の結果 |
| --- | --- | --- |
| 一覧の初期表示・再生成・再表示 | セッションディレクトリとメタデータストアを読み、受信準備のできた Webview に最新の一覧を送る | Refresh を選ばずに保存済みの会話へ戻れる |
| ワークスペースの `Unarchived` / `All` を選択 | Webview 内でそのワークスペースの表示だけを切り替える | そのワークスペースの行が切り替わる |
| `Refresh` を選択 | セッションディレクトリとメタデータストアを読み直す | 最新の一覧が表示される |
| `New session` を選択 | 「New Session アクション」の規則で新しい Pi を起動し、共有の表示用 Terminal へ接続する | 起動後に一覧が更新される |
| セッション行を通常クリック | その行を単一選択にして「セッション選択と Terminal」の規則でセッションを開く | Editor Area の共有 Terminal に選択先の Pi TUI が前面表示される |
| セッション行を Ctrl / Cmd / Shift でクリック | 「セッション行の選択」の規則で選択だけを更新する | Terminal は開かない |
| 行の `Copy` を選択 | セッション ID をクリップボードへ書き込む | 一覧の表示は変えない。クリップボードへの書き込み成否にかかわらず、Webview 内では選択した `Copy` が約1秒チェックマークの表示に変わる |
| 未選択の行の `Archive` を選択 | 「アーカイブアクション」の規則でその行だけをアーカイブする | 一覧を再読込し、アーカイブ後の行・グループを「表示モード」の規則で表示する |
| 選択済みの行の `Archive` を選択 | 「アーカイブアクション」の規則で、表示中の選択対象のうち未アーカイブ・非ロックをまとめてアーカイブする | 一覧を再読込し、アーカイブ後の行・グループを「表示モード」の規則で表示する |
| 行の `Lock` / `Unlock` を選択 | メタデータストアで当該セッション ID の `locked` を更新する | 一覧を再読込し、ロック状態と `Archive` の有効・無効を表示する |

拡張機能から Webview への一覧データ送信に失敗した場合、Webview はエラー状態を表示する。メタデータの書き込みに失敗した場合、エラーメッセージを表示し、表示中の一覧を変更しない。クリップボードへの書き込みに失敗した場合もエラーメッセージを表示し、表示中の一覧を変更しない。Webview の操作によるメッセージにはセッション ID などの必要な引数だけを含め、任意のファイルパスやコマンドを実行できる値を含めない。

### グルーピングとソート

両モード共通の規則。

| 対象 | 規則 |
| --- | --- |
| グループ | セッションの `cwd` ごとに 1 グループ。ラベルとパスの表示は「Webview の表示」に従う |
| グループ順 | 所属セッションの最新更新日時の降順。同一なら cwd の昇順 |
| グループ内セッション順 | 更新日時の降順。同一ならセッション ID の昇順 |
| セッション行の更新日時 | 更新日時のローカル日付が表示時点の当日なら時刻（`HH:mm`、24時間・0埋め）だけ、それ以外は月日（`MM/DD`、0埋め）だけを表示する |
| セッション行の補足情報 | 表示名、セッション ID、cwd、更新日時を確認できる。セッション ID は行ホバーのヒントと `Copy` によるクリップボード、cwd はグループ見出しのホバーのヒントで確認する |
| 空のとき | 保存済みセッションが 1 件も無いとき `No saved sessions` を表示する |

### アーカイブアクション

| 条件 | 操作 | 結果 |
| --- | --- | --- |
| 未選択・未アーカイブ・非ロックの行の `Archive` を実行 | メタデータストアで当該セッション ID の `active` を `false` に更新し、一覧を再読込 | アーカイブ後の表示は「表示モード」に従う。Terminal は終了せず、セッションファイルは変化しない |
| 選択済みの行の `Archive` を実行 | 表示中の選択対象のうち未アーカイブ・非ロックのセッション ID をまとめ、1 回のメタデータ更新でアーカイブし、一覧を再読込 | アーカイブ済み・ロック中の選択対象と、表示中でない選択対象はアーカイブされない |
| ロック中の行の `Archive` | 実行できない（無効） | 選択中の一覧は変わらない |
| 拡張機能 host がアーカイブの要求を受ける | 受信時に最新のメタデータを読み、ロック中のセッションをアーカイブ対象から除外する | 古い表示や Webview を経由しないメッセージでも、ロック中のセッションはアーカイブされない |
| アーカイブ対象に存在しないセッション ID が含まれる | アーカイブを行わずエラーメッセージを表示する | メタデータと一覧は変わらない |
| メタデータの書き込みに失敗 | — | エラーメッセージを表示し、ビューは変化しない |

アーカイブは Terminal の終了、セッションファイルの削除とは別の操作である。セッションファイルの削除はこの拡張機能の操作に含まれない。

### 静的プレビュー

Storybook のカタログで、VS Code API と実セッションファイルを使わずに Webview の見た目と操作を確認できる。`bun run storybook` でカタログをブラウザに表示でき、`bun run storybook:build` の静的出力は任意の静的サーバで単独表示できる。カタログはサンプルデータで次の状態を確認できる。

| ストーリーの軸 | 値 |
| --- | --- |
| データ | 複数の cwd グループとアーカイブ済み・ロック中を含むセッション / あるワークスペースを `All` に切り替えた状態 / 全ワークスペースに未アーカイブが 0 件で履歴を開ける状態 |
| 幅 | narrow（320px・既定）/ wide（720px） |

カタログ上でワークスペースごとのモード切替、行の選択（Ctrl / Cmd / Shift / 全選択）、`Copy`、`Lock` / `Unlock`、`Archive`（単一・一括）、`Refresh`、`New session` をサンプルデータに対して実行できる。`Copy` はブラウザの Clipboard API に対象のサンプルセッション ID を書き込む。New session はサンプルデータへ未アーカイブの行を追加する（Terminal は起動しない）。カタログの操作は実セッションファイル、メタデータストア、VS Code Terminal に影響しない。静的出力は拡張機能を起動せずにスクリーンショットを撮影できる。

### Refresh アクション

Webview の Refresh を実行すると、セッションディレクトリとメタデータストアを読み直して一覧を再描画する。Pi CLI、別の VS Code window、将来の他クライアントによるディスク上の変更は、この Refresh で反映される。ファイル監視による自動更新は行わない。

### New Session アクション

| 項目 | 値 |
| --- | --- |
| 起動 cwd | `Start Pi session in…` で開始先を選択する。候補は初期候補、file scheme の workspace folder、保存済みセッションの cwd（重複除去）。初期候補は最初の file workspace folder、無ければアクティブエディタの file のディレクトリ、それも無ければホーム。候補には basename とフルパスを表示する。`Choose another folder…` からフォルダーを選ぶこともできる |
| キャンセル | 候補またはフォルダー選択をキャンセルした場合は Pi や表示用 Terminal を追加せず、一覧・メタデータ・現在の表示先を変えない |
| 無効な開始先 | 絶対パスでない、存在しない、またはディレクトリでない開始先はエラーを表示し、Pi や表示用 Terminal を追加しない |
| 起動コマンド | 選択した cwd で新しい Pi を tmux 内に起動する。既存の Pi を新規会話として使い回さず、表示には共有 Terminal を使う |
| 起動後 | Webview を再読込し、検出した新規セッションを未アーカイブとして対応する cwd のグループに表示する |
| 起動した Pi との対応 | 検出した新規セッション ID を起動した Pi へ対応づける。以後そのセッションの選択では、生存している同じ Pi へ接続する |

## セッション選択と Terminal

セッション項目をクリックすると、選択した会話の Pi TUI を Editor Area の共有 Terminal に前面表示する。この拡張の表示用 Terminal は VS Code ウィンドウごとに同時に最大1個とし、他の会話の Pi は裏で稼働を続ける。続けて会話を選択した場合は、受け付けた順で処理する。会話の cwd は workspace folder への登録状態にかかわらず、Pi の起動・再接続先として使う。

Terminal のタイトルは、Pi TUI が通知するタイトルをそのまま表示する。拡張は通知されたタイトルを変更せず、独自のタイトルを付けない。`terminal.integrated.tabs.title` 設定が通知タイトルを採用しない環境（既定の `${process}` など）では、代わりにプロセス名 `tmux` が表示される。cwd の補助ラベルも VS Code 標準の表示規則に従い、選択した会話の cwd に対応する。

Pi は tmux 内で会話ごとに保持し、表示用 Terminal の開閉と稼働を切り離す。実行環境では `tmux` と `pi` を利用できる必要がある。tmux 側の一覧は表示せず、会話の選択は拡張の一覧から行う。拡張の保持対象は利用者の通常の tmux 環境と分離し、利用者の他のターミナル・tmux セッション・設定を変更しない。

| 条件・操作 | 動作 |
| --- | --- |
| セッションファイルが存在しない | エラーメッセージを表示し、Pi の起動や現在の表示先の切替を行わない |
| cwd が絶対パスでない、存在しない、またはディレクトリでない | 対象を含むエラーメッセージを表示し、Pi・表示先・メタデータを変えない |
| 選択した会話の Pi が生存している | Pi を起動し直さず、共有 Terminal をその Pi へ切り替えて表示する |
| 選択した会話の保持中 Pi が無い、または終了済み | 会話の cwd で `pi --session <セッションファイルのパス>` を tmux 内に起動し、共有 Terminal へ接続する。他の会話の Pi は維持する |
| 表示用 Terminal が開いている状態で同じ cwd の会話を選択する | 現在の表示用 Terminal で選択先の Pi TUI を表示する。拡張が付けた固定名 `Pi` が残っている場合は、旧表示タブの閉鎖完了後に表示用 Terminal だけを作り直し、同じ Pi へ接続する |
| 表示用 Terminal が開いている状態で異なる cwd の会話を選択する | 旧表示タブの閉鎖完了後、選択した会話の cwd で表示用 Terminal を作り直して接続する。保持中の Pi と会話との対応は維持する |
| 表示用 Terminal のタブを閉じる | 表示用の接続だけを閉じ、保持中の Pi と会話との対応を維持する |
| 表示タブが閉じた状態で会話を再選択する | Editor Area に表示用 Terminal を1個作り、生存している同じ Pi へ再接続する |
| Pi が終了する | 自動で再起動せず、次回選択時に保存された会話を再開する |
| tmux が利用できない、または起動・接続に失敗する | 対象と失敗内容を示すエラーを表示する。同じ会話の Pi を重複起動せず、一覧・メタデータを変更しない |

`pi --session` による再開は既存のセッションファイルへの追記として行われ、新しいセッションファイルは作られない。

アーカイブ済みのセッション（All モードにのみ現れるセッション）を選択して開いた場合も、上の表と同じ Pi 起動・再接続の動作になり、開いた時点で未アーカイブに戻って既定の一覧に現れる。Ctrl / Cmd / Shift による複数選択の操作では Pi を開かず、現在の表示先も切り替えない。

### VS Code 再起動

再起動後はセッションディレクトリとメタデータストアから一覧が復元され、全ワークスペースのモードは未アーカイブ表示（既定）に戻る。会話を再選択した際は tmux 内の保持対象を確認し、生存している Pi があれば同じプロセスへ再接続する。生存 Pi が無い場合は保存された会話を再開する。拡張 host の再起動だけを理由に Pi を起動し直さず、表示用 Terminal はウィンドウ内で1個に保つ。

## 開発補助: 自動スクショ

この拡張機能の UI を、1 コマンドで自動的にスクリーンショットする。利用者はこのリポジトリで開発するコントリビュータで、撮影した画像を目視レビューに使う。

| 項目 | 値 |
| --- | --- |
| コマンド | `bun run screenshot` |
| 撮影内容 | Agent Sessions ビューを開いた VS Code ウィンドウ全体 |
| 保存先 | `.screenshots/<YYYYMMDD-HHmmss>.png`（例: `20260919-183000.png`） |
| セッションデータ | 撮影スクリプトが作成した分離環境のダミーセッション 3 件（すべて未アーカイブ）を表示する。実環境のセッションデータとメタデータストアは読み書きしない |
| バージョン管理 | `.screenshots/` は git の管理対象外 |

| 条件 | 動作 |
| --- | --- |
| `bun run screenshot` を実行 | TypeScript のビルド、このリポジトリの拡張機能を読み込んだ撮影用 VS Code の起動、Agent Sessions ビューを開いた状態での撮影、VS Code の終了まで、コマンド 1 回で完了する |
| 撮影用の VS Code が未取得 | スクリプトに定義した固定バージョンの Linux 版 VS Code を撮影の前にダウンロードし、2 回目以降は取得済みのものを再利用する |
| 保存先ディレクトリが存在しない | 撮影の前に作成する |
| 撮影に成功 | コマンドは終了コード 0 で終了し、保存した画像のパスを標準出力に表示する |
| 撮影に失敗 | コマンドは非ゼロの終了コードで終了し、失敗の原因を標準エラー出力に表示する |

## 設計上の制約

- Pi がセッションとエージェントの source of truth である。拡張機能は Pi を再実装せず、Pi セッション形式の独自変換も行わない
- メタデータストアの読み書きは VS Code API に依存しないモジュールとして分離し、保存場所とデータ形式は将来の Web UI・CLI からも同じデータを参照できるようクライアント非依存にする
- セッションファイルは read-only として扱い、セッションの作成・更新は Pi CLI に行わせる
