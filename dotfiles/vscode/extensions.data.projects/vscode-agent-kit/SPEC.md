# VS Code Pi Session Manager spec

Pi（pi-coding-agent）のセッションを VS Code のサイドバーで一覧し、選択して Editor Area の Terminal で Pi TUI を開く VS Code 拡張機能の仕様。この拡張機能は Pi TUI を置き換えず、チャット UI やメッセージ表示も持たない。複数セッションの一覧・切替、明示的なアーカイブによる一覧の整理を提供する。読者は利用者と拡張機能の開発者である。セッション一覧は VS Code 標準の TreeView ではなく、拡張機能が描画する Webview UI を使う。保存 E2E のテストケースを「テストケース」節に一覧し、各ケースの期待する結果から各定義節を参照する読み方をする。

## 用語

- セッションファイル: Pi が会話を保存する JSONL ファイル。場所と形式は Pi のドキュメント（[sessions](https://github.com/earendil-works/pi-mono/blob/main/packages/coding-agent/docs/sessions.md) / [session format](https://github.com/earendil-works/pi-mono/blob/main/packages/coding-agent/docs/session-format.md)）に従う。
- セッション ID: セッションファイルのヘッダーが持つ ID。既定は UUID で、Pi の SDK や `--session-id` によるカスタム ID もある（Pi のドキュメントに従う）。ファイル名は `<timestamp>_<session-id>.jsonl` で、ファイル名の末尾セグメントと一致する。
- セッション状態ストア: セッションの active 状態（`active-sessions` への所属）・実行フェーズを保存する JSON ファイル。pi 拡張 `session-state` と共有する（「セッション状態ストア」節）。
- active セッション: セッション状態ストアで、所属ワークスペースの `active-sessions` の key になっているセッション。既定の表示対象になる。pi 側ではメッセージ送信時に、拡張側では `Unarchive` 操作時に active になる。
- アーカイブ済みセッション: 所属ワークスペースの `active-sessions` に key が無いセッション。既定の表示対象から除外され、`All` 表示でのみ現れる。
- 実行フェーズ: pi 拡張 `session-state` がセッションの entry の `state` へ書き出す、agent ターン実行中（`running`）・承認待ち（`waiting-approval`）・user のターン待ち（`waiting-user`）の区別。
- 登録済みワークスペース: セッション状態ストアの `active-workspaces` の key に存在する cwd。この cwd のグループだけが一覧に現れる。pi 拡張が Pi を起動した cwd のエントリを作成するため、その cwd は自動的に登録される。

## テストケース

保存 E2E（`tests/e2e/`）は、実機連携の振る舞いを次のテストケースで検証する。各ケースの期待する結果は、対応する定義節に従う。

| --- | --- | --- | --- | --- |
| E2E-1 | ワークスペースごとの All 切替で、未アーカイブ 0 件の作業先にも保存済みの履歴を表示できる | サイドバービュー・表示モードどおりの表示と切替 | Unarchived（切替前）／All（履歴） | 保存 E2E |

| E2E-13 | Archive で対象 Pi を終了し、Unarchive と再選択で保存済み会話を再開できる | アーカイブ・未アーカイブアクションどおりの直接実行、対象だけの終了、原本保持、非起動の復帰と再開 | Archive 後（アーカイブ済み行）／Unarchive 後（未アーカイブ） | 保存 E2E |

既知の未達と範囲外課題は、この文書に書かず tickets で管理する。

### E2E結果の確認

開発者は `bun run test:e2e` で保存 E2E を実行し、プロジェクト直下の `e2e-gallery.html` をブラウザーで直接開いて、同じ実行で得た画面と自動テストの結果を確認できる。`e2e-gallery.html` はバージョン管理する固定のビューアーであり、テスト実行時には画像と結果データだけを `dist/e2e-gallery/` に出力する。画面の撮影は、通常の E2E の操作・確認と同じ step に含める。撮影対象は「テストケース」表の「撮影」欄が定める画面だけとし、操作のたびに撮影しない。同じ操作の反復で確認する事項は、反復の最終状態だけを撮影する。各ケースの撮影は「撮影」欄で定めた比較単位に従う。E2E-11 はメイン領域にタブがない状態で、メニュー表示中と登録解除後を撮影する。E2E-14 は状態ストアに設定した3つの実行フェーズを一覧に表示し、メイン領域にタブがない状態で、ほかのケースと同じ VS Code のウィンドウ全体を1枚撮影する。E2E-15 は実 Webview への一覧応答を制御し、初回取得中・既存一覧を保つ再取得中・成功空・取得エラーの4状態を、同じ VS Code のウィンドウ全体で撮影する。ほかの比較ケースは前後1組を撮影する。「撮影」欄のラベルをそのまま画像の添付名として付ける。添付名はギャラリーのセル見出しとして使う。ギャラリーは短い文言と画像だけで結果を一目で確認する構成とし、この文書のテストケースの説明や期待する結果の全文、文書のスナップショットは表示しない。ケースの詳細はこの文書を参照する。各ケースは画像をセルとする表で示し、「撮影」欄の順に並ぶ。セルの見出しは画像の添付名（「撮影」欄のラベル）だけとする。

| 条件・操作 | 結果 |
| --- | --- |
| 保存 E2E の実行が終了する | ケースごとに ID とテストケース名を1行に切り詰めた見出しと、画像をセルとする表を表示する |
| 「テストケース」表の「撮影」欄が「なし」のケース | ギャラリーに表示しない |
| ケースが失敗、未実行、または画像を持たない | 失敗・未実行・画像なしを区別する短い文言を表示する。失敗のエラーは最初の行だけ表示する。画像があることを自動テストの成功や見た目の正しさとして扱わない |
| 並列実行・再試行で画像を保存する | ケース・step・実行環境・試行を識別でき、画像を上書きせず対応する結果から参照できる |
| 過去の実行で保存した画像がある | 今回の撮影結果として表示しない |
| スクリーンショットを開く | 原寸の画像を確認できる |
| プロジェクト直下の `e2e-gallery.html` をファイルとして直接開く | 今回の結果データと画像を相対パスで読み込み、サーバーなしで表示する |
| 結果データがまだ出力されていない | E2Eの実行を案内し、実行結果や画像を表示済みのものとして扱わない |

自動テストの合否はテストランナーの結果、見た目の判断は利用者の目視確認に基づく。Playwright 標準HTMLレポートは診断用の別の出力として保持する。

## データソース

拡張機能は Pi のセッションディレクトリを直接読んで一覧を作る。独自のセッションデータベースは持たない。この拡張機能の導入以前に Pi で作成されたセッションも、以後に作成されるセッションも同じ方法で一覧される。

| 項目 | 値 |
| --- | --- |
| エージェントディレクトリ | `PI_CODING_AGENT_DIR`（未設定・空文字なら `~/.pi/agent`） |
| セッションディレクトリ | `PI_CODING_AGENT_SESSION_DIR`（未設定・空文字なら `<エージェントディレクトリ>/sessions`） |
| 一覧対象 | 登録済みワークスペースの cwd に対応する `<セッションディレクトリ>/<cwd ディレクトリ>/` 直下の `*.jsonl`。登録されていない cwd グループのファイルは読まない |
| 除外 | `subagents/` ディレクトリ配下のファイル（一覧対象ディレクトリ直下の `subagents/` を含む） |
| セッション ID と cwd | 各ファイルの最初の非空行にあるヘッダー `{"type":"session",...}` の `id` と `cwd`。cwd はディレクトリ名から復元せず、ヘッダーを正とする |
| 開始日時 | 下記「開始日時」の規則に従う |
| 更新日時 | 下記「更新日時」の規則に従う |

登録済みワークスペースが無い場合、または対象グループに `*.jsonl` が 1 件も無い場合、一覧は空になる。セッションディレクトリの読み取りに失敗した場合、エラーメッセージを表示する。

### 開始日時

開始日時は、セッションファイルの最初の非空行にあるセッションヘッダーの、有効な日時文字列の `timestamp` とする。Unix epoch（1970-01-01T00:00:00.000Z）も有効な開始日時である。ヘッダーの `timestamp` が無い場合や不正な場合は、開始日時不明として一覧に残す。

### 更新日時

更新日時は次の優先順で決め、セッション行の日時表示に使う。

| 優先 | 条件 | 更新日時 |
| --- | --- | --- |
| 1 | 有効な日時文字列の `timestamp` を持つ `message` または `compaction` エントリがある。`message` の role は問わない | 該当するエントリのうち、セッションファイル内で物理的に最後に現れるエントリ自身の `timestamp` |
| 2 | 該当する活動エントリが無く、セッションヘッダーに有効な日時文字列の `timestamp` がある | セッションヘッダーの `timestamp` |
| 3 | どちらにも有効な日時が無い | 日時不明として一覧に残し、日時欄は空欄とする |

### 表示名

セッション項目の表示名は次の順で決める。

1. セッションファイル内の最新の `session_info` エントリの `name`（`/name` や `pi --name` で設定される値）。空文字はタイトル解除とみなし、次の規則へ進む
2. `text` を持つ最初のユーザーメッセージの、text 全体の前後の空白を取り除いた 1 行目（先頭 80 文字）
3. いずれも無い場合 `Untitled`

アーカイブ済みセッションも同じ規則でファイルから表示名を決める。

### セッション状態ストア

| 項目 | 値 |
| --- | --- |
| パス | `<エージェントディレクトリ>/session-state.json` |
| 形式 | 下記の JSON。文字コードは UTF-8 |
| 書き込み | 一時ファイルと rename による原子的置換。中断しても既存内容を壊さない |
| 同時書き込み | ファイル全体の読み書きの最後の書き込みが残る |
| 共有 | pi 拡張 `session-state` が同じファイルを読み書きする。pi 側はメッセージ送信時に自セッションの entry を作成し、`/archive`・`/unarchive` コマンドと実行フェーズ（`state`）の書き出しを行う |

```json
{
  "active-workspaces": {
    "/absolute/path": {
      "active-sessions": {
        "<session-id>": { "state": "running" }
      }
    }
  }
}
```

- `active-workspaces` は cwd ごとのセッション状態で、key が登録済みワークスペース（一覧に表示する cwd）を表す。`active-sessions` と同じく、key に載っていることが active（既定の一覧に出る）を意味する。キーは絶対パス。`active-sessions` が空のエントリも登録として有効で、セッションが無いワークスペースの空グループとして表示される
- ワークスペースエントリの `active-sessions` は key がセッション ID の map である。key に列挙されたセッション（entry の値がオブジェクトのもの）を active セッションとみなし、列挙されていないセッションはアーカイブ済み（未 active）で、既定の一覧には現れず `All` でのみ現れる。新規登録直後のワークスペースの既存セッションはアーカイブ済みとして取り込む（「New Workspace アクション」節）
- entry の `state` は実行フェーズ（`running`・`waiting-approval`・`waiting-user`）で、pi 拡張だけが書き出す。省略時はフェーズ情報なし
- アーカイブは当該セッションの entry を `active-sessions` から削除する。未アーカイブは entry が無いとき `{}` で作成し、既存の entry の所属は変えない
- 一括アーカイブ・一括未アーカイブは 1 回のストア更新として書き込む。書き込みに失敗した場合、一部だけ反映された状態にしない
- 状態変更による保存時は、書き戻すストア内のすべてのセッション entry から `lock` 属性を削除する。`state` とその他の未知のキー・属性（`pinned` / `title` / `tags` 等）は保持する。読み込みだけでは保存せず、状態変更のない操作では書き込みを省く
- ファイルが存在しない場合は状態無しとして振る舞い、初回の書き込みで作成する
- ルートまたは `active-workspaces` がオブジェクトでないとき、または旧形式（ワークスペースエントリの `active-sessions` が配列、ルートに改名前の `workspaces` オブジェクトが残っている）のときは、状態無しとして扱い、書き込みは行わずエラーを表示する

Pi のセッション関連ファイルのうち、拡張機能が書き換えてよいのはセッション状態ストアのみである。セッションファイルは読み取り専用として扱い、変更・削除・移動をしない。セッションの作成と更新は Pi CLI が行う。

## サイドバービュー

Activity Bar に view container `Pi Sessions` を追加し、その中に拡張機能が管理する Webview view を表示する。VS Code 標準の TreeView は使わない。Webview は VS Code のテーマ色を使い、サイドバー幅に合わせて再配置される。セッションのファイル内容とセッション状態ストアの値は Webview に渡す表示用データだけに変換し、Webview からファイルシステムを直接操作しない。

### Webview の表示

サイドバーは次の順で表示する。

1. VS Code 標準のビュータイトルに `Sessions` と「Refresh アクション」の更新操作を表示する
2. Webview 内に cwd ごとのグループを、枠線を持たない余白で区切ったセクションで表示する。一覧に現れるグループは登録済みワークスペース（`active-workspaces` の key）だけである。登録されていない cwd の保存済みセッションは、どの表示モードでも一覧に現れない。グループ見出しに開閉の chevron、basename、「表示モード」に従うモード切替、そのワークスペースで新しい Pi を起動する `New session` 操作を表示する。登録解除の入口は「ワークスペース登録解除」に従う。見出しのホバーのヒントに cwd のフルパスを表示し、同じ basename のプロジェクトや worktree を区別する。chevron または見出し名を選ぶと、そのグループの行の表示を開閉する。開閉状態の既定は開いた状態で、VS Code 再起動後も維持しない
3. グループ内にセッションを行として表示する。行は表示名とセッションの状態（選択・アーカイブ済み・実行フェーズ）を示す。左端の状態アイコンと行ホバーのヒントは「実行フェーズの表示」の対応表に従う
4. 各行の右端には、更新日時（等幅の数字で表示する）と、`Archive` または `Unarchive` 操作をこの順で表示する。`Archive` と `Unarchive` はアーカイブのアイコンとアーカイブからの復帰のアイコンで示す。ホバーのヒントは `Archive` または `Unarchive` とする
5. 未アーカイブの行には `Archive` 操作を、アーカイブ済みの行には `Unarchive` 操作を同じ位置に表示する。アーカイブ済みの行は All 表示でのみ現れ、行の表示を薄くしてアーカイブ済みであることを示す
6. セッション行全体を選択領域とし、選択の視覚表示は行の右端まで及ぶ。更新日時、`Archive` または `Unarchive` は行の右端に重ねて表示する。行内操作のクリックは、行の選択やセッションの再開として扱わない
7. 一覧の下にフッタを表示する。フッタの `New workspace` の操作は「New Workspace アクション」に従う

表示名・更新日時・グループ・並び順は「グルーピングとソート」の規則に従う。行・見出し・操作の寸法と色の値は `DESIGN.md` が定める。

### 一覧のスクロール

Webview 全体を document の標準スクロールで移動する。スクロール位置は右端に重ねたバーで示し、外観は `DESIGN.md` に従う。

| 条件・状態 | 操作・変化 | 結果 |
| --- | --- | --- |
| 一覧を表示中 | `Unarchived` / `All` の切替、行の増減、グループの開閉で縦 overflow が出入りする | 共通する行の左右位置と幅を保つ |
| 縦 overflow がある | ホイール、トラックパッド、通常のキーボードスクロールを使う | document が標準どおりスクロールし、つまみが位置に追従する |
| 縦 overflow がある | つまみをドラッグする | ドラッグ量に応じて document をスクロールする。ドラッグ中はバーを表示し続ける |
| 縦 overflow がある | トラックをクリックする | クリック位置に対応する document の位置へ移動する。ドラッグなしの単一ポインター操作で位置を指定できる |
| バーにキーボードフォーカスがある | 上下矢印、PageUp / PageDown、Home / End を押す | 上下移動、ページ移動、先頭 / 末尾移動を行う。フォーカス中はバーを表示し、支援技術へ操作対象・範囲・現在位置を示す |
| 一覧・フォームを表示中 | モード切替、グループの開閉、一覧データの更新、フォームの開閉、viewport のリサイズが起きる | 現在の表示範囲と全体の高さに合わせて、つまみの長さ・位置・バーの有無を更新する |
| 縦 overflow がない | 一覧を表示する | バーを隠し、キーボードのフォーカス対象から外す |

### セッション行の選択表示

選択表示は Webview が独自に持つ状態ではなく、共有表示用 Terminal が今表示しているセッションを一覧の行に示すものである。選択の正本は拡張機能 host が保持する表示先セッション ID であり、Webview は受け取った一覧データの中からそのセッション ID の行に選択表示を付ける。

| 操作 | 選択表示の変化 | Terminal |
| --- | --- | --- |
| 行をクリック | 表示先がそのセッションへ切り替わり、選択表示もその行へ移る | 「セッション選択と Terminal」の規則でセッションを開く |
| `New session` を起動 | 検出された新規セッションが表示先になり、選択表示もその行へ移る | 新しい Pi を共有 Terminal へ接続する |
| 表示用 Terminal のタブを閉じる | 選択表示は変化しない | 表示用の接続だけを閉じる |

- 修飾キー（Ctrl / Cmd / Shift）付きのクリックも通常のクリックと同じ扱いにする。選択だけを変える操作、全選択、選択範囲へのアンカーは持たない
- 表示モードの切替や再読み込みをまたいで、表示先のセッションの行に選択表示を付ける。表示先の行が現在の表示モードに現れないとき（アーカイブ済みで `Unarchived` 表示のときなど）は、選択表示を持つ行が無い状態として表示する
- 表示用 Terminal が Editor Area の裏タブに回っても表示先は変わらないため、選択表示も変化しない

### 表示モード

モードは登録済みワークスペースの cwd ごとに独立して持つ。各グループ見出しのボタンは、そのワークスペースの `Unarchived` / `All` を切り替える。

| モード | そのワークスペースの表示対象 | ボタンのヒント・アクセシブル名 |
| --- | --- | --- |
| Unarchived（既定） | 未アーカイブのセッションのみ | `Show all sessions` |
| All | アーカイブ済みを含む全セッション。アーカイブ済みの行は薄く表示する | `Show unarchived sessions` |

| 条件・状態 | 操作・変化 | 結果 |
| --- | --- | --- |
| 登録済みワークスペースのグループ | セッションが0件、全件アーカイブ済み、または折りたたみ中 | グループ見出しとモード切替ボタンを常時表示する |
| グループ見出しのモード切替ボタン | クリック、Enter、Space で実行する | 対象 cwd のモードだけを切り替え、ほかの cwd のモード・行選択・グループ開閉状態を保つ |
| 同じ basename の異なる cwd がある | 一方のモードを切り替える | 各 cwd を別のワークスペースとして扱う |
| Webview を表示中 | Refresh または一覧データの更新が起きる | 各 cwd のモードを保つ。新しく現れた cwd は Unarchived で表示する |
| Webview を初期表示・再生成する（VS Code 再起動を含む） | 一覧を表示する | すべての cwd を Unarchived で表示する |

モードの切替はセッション行（アイテム）の表示を切り替えるだけで、表示するグループ自体はモードによらず登録済みワークスペースだけである。登録済みワークスペースの保存済みセッションなら `All` でアーカイブ済みの会話を選択・再開できる。pi でメッセージを送った会話は pi 拡張により active になり、次の一覧表示から既定の表示対象に戻る。過去のセッションが自動的にアーカイブされることはない。

### 実行フェーズの表示

実行フェーズの正本は pi 拡張がセッション状態ストアへ書き出す `state` であり、この拡張はそれを読んで表示するだけである。

| 条件 | 表示 |
| --- | --- |
| entry の `state` が `running` / `waiting-approval` / `waiting-user` で、そのセッションの Pi を収めた tmux セッションに生存する pane がある | 次の対応表に従ってフェーズを表示する |
| フェーズがあるが tmux セッションに pane が無い（異常終了などで `state` が残留） | フェーズを表示から落とす（フェーズ情報なしとして扱う）。ストアの entry 自体は削除しない |
| tmux への問い合わせが失敗する | フェーズを表示しない（安全側） |
| entry に `state` が無い、またはアーカイブ済み | フェーズを表示しない |

表示対象のフェーズと未読を、次の優先順で左端の状態アイコンへ対応させる。行ホバーのヒントには表示名とセッション ID に加え、表の追加行を表示する。「なし」の行では、ヒントへ追加しない。

| 条件 | 左端の状態アイコン | ヒントの追加行 |
| --- | --- | --- |
| アーカイブ済み | なし | なし |
| 未アーカイブ・`running` | 回転する spinner | `Running` |
| 未アーカイブ・`waiting-approval` | 一時停止マーク | `Waiting for approval` |
| 未アーカイブ・`waiting-user`・未読 | 輪郭線のベル | `Waiting for user`・`Unread` |
| 未アーカイブ・`waiting-user`・既読 | なし | `Waiting for user` |
| 未アーカイブ・フェーズ情報なし | なし | なし |

アイコンがない行も左端のスロットを保持し、表示名の開始位置を揃える。`prefers-reduced-motion: reduce` では spinner を静止表示する。アイコンの寸法・色・線と回転の詳細は `DESIGN.md` に従う。右端のアーカイブ操作は左端のアイコンと独立して表示する。

セッション状態ストアの変更は拡張機能が監視しており、フェーズの変化は次の一覧表示（監視による再読込を含む）で反映される。

未読は実行フェーズと別の補助状態であり、拡張機能のメモリ内だけで保持する。表示中とは共有表示用 Terminal の表示先セッションを指す。

| 条件・状態 | 操作・変化 | 未読の結果 |
| --- | --- | --- |
| 未アーカイブの生存セッション | 拡張機能が `running` を観測する | それまでの未読を解除し、その実行を観測対象にする |
| 観測対象の実行 | `waiting-approval` になる | 実行の観測を保ち、承認待ちとして表示する |
| 観測対象の実行（表示中を含む） | `waiting-user` になる | 未読にする |
| 未アーカイブの生存セッション・`waiting-user`・未読 | 表示中のまま一覧を更新する | 未読を保つ |
| 未読のセッション（表示中を含む） | 一覧のセッション行を選び、正常に開く | 未読を解除する |
| `running` をまだ観測していないセッション | 初回から `waiting-user` を読み取る | 過去の完了を推測せず、既読として扱う |
| tmux への問い合わせが一時的に失敗する | 一覧を更新する | 実行の観測と未読を保持し、不明の間はフェーズ・未読のアイコンとヒントを隠す |
| entry に有効な `state` が無い、正常な tmux 応答で pane 消失が確定した、アーカイブ済み、または一覧の対象から外れたセッション | 一覧を更新する | 実行の観測と未読を解除する |
| Webview を再生成する | 同じ拡張機能で一覧を表示する | メモリ内の未読を保つ |
| 拡張機能を再起動・再読み込みする | 一覧を表示する | 実行の観測と未読を初期化する |

一覧の更新が重なっても、新しい実行や既読化を過去の状態へ戻さない。未読はセッション原本・セッション状態ストア・tmux・VS Code の保存 state へ書き込まない。

### 一覧と拡張機能の操作

| 一覧の操作 | 拡張機能の処理 | Webview の結果 |
| --- | --- | --- |
| 一覧の初期表示・再生成・再表示 | セッションディレクトリとセッション状態ストアを読み、受信準備のできた Webview に最新の一覧を送る | Refresh を選ばずに保存済みの会話へ戻れる |
| グループ見出しのモード切替を選択 | 「表示モード」の規則で Webview の表示を切り替える | 対象ワークスペースの行だけが切り替わる |
| 標準ビュータイトルの `Refresh Sessions` を選択 | セッションディレクトリとセッション状態ストアを読み直す | 最新の一覧が表示される |
| グループ見出しの `New session` を選択 | 「New Session アクション」の規則でそのワークスペースの cwd で新しい Pi を起動し、共有の表示用 Terminal へ接続する | 起動後に一覧が更新され、検出された新規セッションへ選択表示が追従する |
| 登録済みグループ見出しのコンテキストメニューで `Unregister workspace` を選択 | 「ワークスペース登録解除」の規則で登録を削除し、一覧を再読込する | 登録だけが外れる |
| フッタの `New workspace` を選択し、入力欄で `Enter` を押す | 「New Workspace アクション」の規則でワークスペースを登録し、一覧を再読込する | 登録した cwd のグループが、セッションが無くても表示される |
| フォームで `Escape` を押す | フォームを閉じ、入力を捨てる | 一覧・状態ストア・現在の表示先を変えない |
| セッション行をクリック | 「セッション選択と Terminal」の規則でセッションを開く | Editor Area の共有 Terminal に選択先の Pi TUI が前面表示され、選択表示がその行へ移る |
| 行の `Archive` を選択 | 「アーカイブ・未アーカイブアクション」の規則でその行の Pi を終了してアーカイブする | 一覧を再読込し、アーカイブ後の行・グループを「表示モード」の規則で表示する |
| アーカイブ済みの行の `Unarchive` を選択 | 「アーカイブ・未アーカイブアクション」の規則でその行だけを未アーカイブに戻す | 一覧を再読込し、戻し後の行・グループを「表示モード」の規則で表示する |

拡張機能から Webview への一覧データ送信に失敗した場合、Webview はエラー状態を表示する。セッション状態ストアの書き込みに失敗した場合、エラーメッセージを表示し、一覧の所属を変更しない。アーカイブで既に終了した Pi と表示先の扱いは「アーカイブ・未アーカイブアクション」に従う。Webview の操作によるメッセージにはセッション ID や開始先・登録先のパスなど、その操作に必要な引数だけを含める。任意のコマンドを実行できる値を含めない。

### 一覧の取得状態

初期表示・再生成・再表示、手動の Refresh、ファイル監視や操作後の再読込は、取得開始から成功または失敗まで取得中として表示する。

| 条件・状態 | 表示 |
| --- | --- |
| 初回取得中、または直前の一覧が0グループで再取得中 | 一覧領域に `Loading sessions…` を表示する |
| 直前の一覧にグループがあり再取得中 | 既存の一覧・選択・表示モード・開閉状態を保ち、状態欄に `Refreshing sessions…` を表示する |
| 取得成功 | 最新の一覧を表示し、取得中やエラーの表示を解除する。0グループなら一覧領域に `No saved sessions` を表示する。セッションが0件の登録済みワークスペースは空グループとして表示する |
| 取得失敗 | エラーメッセージを表示し、取得中の表示を解除する。既存の一覧と選択を保ち、0グループなら空の案内を表示しない |
| 一覧取得以外の操作の失敗 | 一覧の取得状態と表示を保ち、操作のエラーメッセージを表示する。再取得中は状態欄の `Refreshing sessions…` と併記する |

### グルーピングとソート

両モード共通の規則。

| 対象 | 規則 |
| --- | --- |
| グループ | 登録済みワークスペース（`active-workspaces` の key）ごとに 1 グループ。セッションが無い登録済みの cwd も空のグループを表示する。登録していない cwd の保存済みセッションはどのモードでも表示しない。ラベルとパスの表示は「Webview の表示」に従う |
| グループ順 | ラベル（グループ見出しの basename）のアルファベット順。大文字小文字は区別しない。セッションが無いグループも同じ順で並べる。同一ラベルなら cwd の昇順 |
| グループ内セッション順 | 開始日時の降順。同一ならセッション ID の昇順。開始日時不明のセッションは有効な開始日時を持つセッションの後方に並べ、不明同士はセッション ID の昇順とする |
| セッション行の更新日時 | 日時がある場合は、更新日時のローカル日付が表示時点の当日なら時刻（`HH:mm`、24時間・0埋め）だけ、それ以外は月日（`MM/DD`、0埋め）だけを表示する |
| セッション行の補足情報 | 表示名、セッション ID、cwd、更新日時、実行フェーズを確認できる。セッション ID と実行フェーズは行ホバーのヒント、cwd はグループ見出しのホバーのヒントで確認する |
| 空のとき | 「一覧の取得状態」に従う |

セッションヘッダーの開始日時が変わらない限り、メッセージや compaction の追記、ファイルの更新日時の変更、Refresh を経ても、セッション同士の相対順を保つ。

### アーカイブ・未アーカイブアクション

| 条件 | 操作 | 結果 |
| --- | --- | --- |
| 未アーカイブの行の `Archive` をクリックまたはキーボードで実行 | 確認を挟まず、その行のアーカイブ要求を1回送る。対象会話のために拡張が専用 tmux 環境で保持する Pi を終了し、その tmux セッションだけを削除する。その後、状態ストアの当該 entry をワークスペースの `active-sessions` から削除し、一覧を再読込する | アーカイブ後の表示は「表示モード」に従う。対象を表示中なら共有表示用 Terminal を閉じ、選択表示を解除する。別会話の表示は維持する |
| 対象の保持中 Pi・tmux セッションが無い | 終了済みとして所属の削除へ進む | 保存済みの会話をアーカイブできる |
| 対象が一覧で確認済みのセッション ID でない、または停止前の状態ストア読取に失敗する | エラーメッセージを表示し、停止とアーカイブを行わない | Pi・表示先・状態ストア・一覧は変わらない |
| Pi・tmux セッションの終了に失敗する | 対象と失敗内容を示すエラーメッセージを表示し、所属の削除へ進まない | アーカイブ済みとして扱わない |
| 終了後に状態ストアの書き込みに失敗する | Pi の終了は完了したがアーカイブの保存に失敗したことを表示する | 所属は保存前のまま。停止済み Pi を自動で再起動せず、対象の選択表示と表示用 Terminal は解除済みの状態を保つ |
| アーカイブ済みの行の `Unarchive` を実行 | セッション状態ストアで当該セッションの entry が無ければ `{}` で作成し、一覧を再読込。既存の entry の所属は変えない | 未アーカイブ後の表示は「表示モード」に従う。Pi の起動・表示先の切替は行わない |
| 未アーカイブの対象が一覧で確認済みのセッション ID でない、または保存に失敗する | エラーメッセージを表示する | 状態ストアと一覧の所属は変わらない |

終了対象は拡張が確認済みの会話から決める。別会話の Pi・tmux セッションと通常の tmux 環境は維持する。アーカイブ・未アーカイブともセッションファイルを変更・削除・移動しない。同一 VS Code window のセッション選択・新規起動・アーカイブ・未アーカイブは受け付けた順に処理する。

セッションを開く（再開する）ことは未アーカイブを意味しない。アーカイブ後も All から「セッション選択と Terminal」の規則で同じ保存済み会話を再開できる。`Unarchive` だけでは Pi を起動せず、次回選択時に必要なら起動する。

### 静的プレビュー

Storybook のカタログで、VS Code API と実セッションファイルを使わずに Webview の見た目と操作を確認できる。`bun run storybook` でカタログをブラウザに表示でき、`bun run storybook:build` の静的出力は任意の静的サーバで単独表示できる。カタログはサンプルデータで次の状態を確認できる。

| ストーリーの軸 | 値 |
| --- | --- |
| データ | 複数の cwd グループ、セッションの無い登録済みワークスペース、アーカイブ済みを含むセッション / あるワークスペースを `All` に切り替えた状態 / 全ワークスペースに未アーカイブが 0 件で履歴を開ける状態 |
| 幅 | narrow（320px・既定）/ wide（720px） |

カタログ上でグループ見出しのモード切替、表示中セッションの行の選択表示、`Archive`、`Unarchive`、グループ見出しの `New session`、`New workspace` のフォーム操作、登録済みグループ見出しのコンテキストメニューの `Unregister workspace` をサンプルデータに対して実行できる。グループ見出しの New session はそのグループのサンプルデータへ未アーカイブの行を追加し、New workspace は入力した cwd をサンプルデータへ登録し、Unregister workspace はサンプルデータから登録を外す（Terminal は起動しない）。カタログの操作は実セッションファイル、セッション状態ストア、VS Code Terminal に影響しない。静的出力は拡張機能を起動せずにスクリーンショットを撮影できる。

### Refresh アクション

Sessions の標準ビュータイトルにある更新操作の名前とツールチップは `Refresh Sessions` とする。

この更新操作を実行すると、セッションディレクトリとセッション状態ストアを読み直して一覧を再描画する。セッション状態ストアのファイル変更は拡張機能が監視し、pi 拡張による所属・実行フェーズの更新と、他クライアントによるワークスペース登録の変更を Refresh なしで一覧へ反映する。セッションディレクトリ上のファイルの追加・削除など、それ以外のディスク上の変更はこの Refresh で反映される。Pi CLI、別の VS Code window、将来の他クライアントによる変更も同様である。

### New Workspace アクション

フッタの `New workspace` で開くフルパス入力フォームの振る舞い。

| 項目 | 値 |
| --- | --- |
| フォーム | フッタの `New workspace` を選ぶと、ボタンをフルパスの入力欄1つに置き換える。開いた時点で入力は空で、入力欄にフォーカスする。`Enter` で登録し、登録成功で入力を捨ててボタンへ戻る。キャンセルは同表の規則に従う |
| パス展開 | New Workspace の入力を検証する前に、先頭の `~`（`~` 単体と `~/` 始まり）をホームディレクトリへ置き換える。保存済みの cwd は再展開しない |
| 登録 | `Enter` で入力を検証し、有効ならセッション状態ストアの `active-workspaces` へ当該 cwd のエントリを `active-sessions` が空の状態で作成して一覧を再読込する。登録する cwd は展開と正規化の後の絶対パスとする。登録した cwd は VS Code 再起動後もセッションが無くてもグループとして表示される |
| 既存セッション | 登録前に存在したセッションは `active-sessions` に載っていないためアーカイブ済みとして扱われ、既定の表示モード（`Unarchived`）では非表示になり、`All` への切替で表示される。pi が既にエントリを作っていた cwd は自動登録済みのため「登録済みの cwd」の扱いになる |
| 無効なパス | 絶対パスでない、存在しない、またはディレクトリでない入力はエラーを表示し、登録しない。フォームは開いたまま入力を保持する |
| 空の入力 | `Enter` を押してもフォームと入力を変えない |
| 登録済みの cwd | 入力が既に登録済みの cwd と同じディレクトリを指す場合、再登録せずフォームだけを閉じる。一覧・状態ストアは変えない。登録していない cwd（保存済みセッションのある cwd を含む）への登録は常に受け付ける |
| キャンセル | `Escape`、入力欄から別要素へのフォーカス移動、Webview 外へのフォーカス移動で、入力の有無によらず入力を捨ててボタンへ戻る。フォーカス移動によるキャンセルでは移動先のフォーカスと操作を保つ。キャンセルだけでは登録せず、一覧・状態ストア・現在の表示先を変えない |

### ワークスペース登録解除

登録済みワークスペースのグループ見出しのコンテキストメニューにある `Unregister workspace` の振る舞い。

| 項目 | 値 |
| --- | --- |
| メニューを開く | グループ見出しを右クリックすると、ポインター位置に `Unregister workspace` だけを含むメニューを開き、項目にフォーカスする。空・折りたたみ中のグループでも使える。開くだけではグループ開閉・表示モード・行選択・状態ストアを変えない |
| キーボードで開く | グループ見出し内の操作にフォーカスがあるとき、`Shift+F10` またはコンテキストメニューキーで、その操作の近くに同じメニューを開く。見出し名の通常の `Enter` / `Space` はグループ開閉として使える |
| メニューを閉じる | `Escape` はメニューを閉じ、開いた見出し内の操作へフォーカスを戻す。右クリックで開いた場合は見出し名へ戻す。`Tab` はメニューを閉じて見出し内の起動元から次のフォーカス対象へ進む。メニュー外のポインター操作・スクロール・リサイズ・Webview のフォーカス喪失でも閉じる。閉じるだけでは登録解除を実行しない |
| 対象の更新 | メニューを開いたグループが一覧から消えたらメニューを閉じる。別グループのメニューを開くと対象をその cwd に切り替える。同じ basename の cwd も区別する |
| 対象 | `Unregister workspace` が選ばれたグループの登録（セッション状態ストアの `active-workspaces` から当該 cwd のエントリを、`active-sessions` ごと削除する）。セッションファイルと稼働中の Pi は変更しない |
| 実行 | メニューの `Unregister workspace` をクリックまたは `Enter` / `Space` で実行すると、メニューを閉じ、確認を挟まずその cwd の登録解除要求を1回送り、エントリを削除して一覧を再読込する。一覧は登録済みワークスペースだけを表示するため、登録を外した cwd はセッションの有無にかかわらずグループごと消える。エントリの削除で `active-sessions` も失われるため、再登録（New Workspace アクション）後の既存セッションはアーカイブ済みとして現れる。その cwd で稼働中の Pi がある場合、次のメッセージ送信で pi 拡張がエントリを作り直すため、グループが再び現れる |
| 未登録のグループ | 一覧に現れない |

### New Session アクション

| 項目 | 値 |
| --- | --- |
| 起動 cwd | グループ見出しの `New session` が選ばれたグループの cwd で開始する。開始先の選択操作はなく、選んだワークスペース以外の cwd で起動しない |
| 無効な開始先 | 絶対パスでない、存在しない、またはディレクトリでない開始先はエラーを表示し、Pi や表示用 Terminal を追加しない |
| 起動コマンド | 選択した cwd で新しい Pi を tmux 内に起動する。既存の Pi を新規会話として使い回さず、表示には共有 Terminal を使う |
| 検出前の起動が同じ cwd にある | 新しい Pi を起動せず、その Pi の tmux セッションへ共有 Terminal を切り替えて表示する。その Pi が終了した場合と検出が完了した後は、再度選ぶと新しい Pi を起動する |
| 起動後 | Webview を再読込し、検出した新規セッションを未アーカイブとして対応する cwd のグループに表示する。新しい Pi が表示先になるため、選択表示も検出した新規セッションへ追従する |
| 起動した Pi との対応 | 検出した新規セッション ID を起動した Pi へ対応づける。以後そのセッションの選択では、生存している同じ Pi へ接続する |

## セッション選択と Terminal

セッション項目をクリックすると、選択した会話の Pi TUI を Editor Area の共有 Terminal に前面表示する。この拡張の表示用 Terminal は VS Code ウィンドウごとに同時に最大1個とし、他の会話の Pi は裏で稼働を続ける。続けて会話を選択した場合は、受け付けた順で処理する。Pi の起動・再接続先は会話の cwd である。

Terminal のタイトルは、Pi TUI が通知するタイトルをそのまま表示する。拡張は通知されたタイトルを変更せず、独自のタイトルを付けない。`terminal.integrated.tabs.title` 設定が通知タイトルを採用しない環境（既定の `${process}` など）では、代わりにプロセス名 `tmux` が表示される。cwd の補助ラベルも VS Code 標準の表示規則に従い、選択した会話の cwd に対応する。

Pi は tmux 内で会話ごとに保持し、表示用 Terminal の開閉と稼働を切り離す。実行環境では `tmux` と `pi` を利用できる必要がある。tmux 側の一覧は表示せず、会話の選択は拡張の一覧から行う。拡張の保持対象は利用者の通常の tmux 環境と分離し、利用者の他のターミナル・tmux セッション・設定を変更しない。

拡張の専用 tmux サーバーでは、Pi が修飾キー付きキー（Shift+Enter など）を区別できるよう `extended-keys` を on にし、その報告形式を `csi-u` に設定する。形式の設定は `extended-keys-format` オプションを持つ tmux でのみ行い、持たない tmux では Pi を通常どおり起動する。

拡張の専用 tmux サーバーでは、Ctrl+左ドラッグによる floating pane 作成を無効にするため、root テーブルの `C-MouseDrag1Pane` と `C-MouseDrag1Empty` だけを解除する。通常のクリック・ドラッグ選択・ホイールの割り当てと、マウス機能の有効状態は維持する。対象キーの割り当てがない場合も、同じ設定を適用できる。

VS Code の Terminal は修飾キー付き Enter を報告しないため、tmux を介した Pi では Shift+Enter が通常の Enter と区別できない。そこでこの拡張機能は、Terminal へフォーカスがあるときの `Shift+Enter` を `sendSequence` で CSI-u 形式（`ESC [ 13 ; 2 u`）の送信に束ねる。tmux はこのシーケンスを `S-Enter` キーイベントとして受け、専用サーバーではそれを同じ CSI-u シーケンスで pane へ転送する bind を設定する。bind の設定は hex 形式の `send-keys` や `S-Enter` キー名を持たない tmux では行わず、Pi を通常どおり起動する。tmux を介さない環境でも、Pi TUI は CSI-u シーケンスを Shift+Enter として認識する。

| 条件・操作 | 動作 |
| --- | --- |
| セッションファイルが存在しない | エラーメッセージを表示し、Pi の起動や現在の表示先の切替を行わない |
| cwd が絶対パスでない、存在しない、またはディレクトリでない | 対象を含むエラーメッセージを表示し、Pi・表示先・状態ストアを変えない |
| 選択した会話の Pi が生存している | Pi を起動し直さず、共有 Terminal をその Pi へ切り替えて表示する |
| 選択した会話の保持中 Pi が無い、または終了済み | 会話の cwd で `pi --session <セッションファイルのパス>` を tmux 内に起動し、共有 Terminal へ接続する。他の会話の Pi は維持する |
| 表示用 Terminal が開いている状態で同じ cwd の会話を選択する | 現在の表示用 Terminal で選択先の Pi TUI を表示する。拡張が付けた固定名 `Pi` が残っている場合は、旧表示タブの閉鎖完了後に表示用 Terminal だけを作り直し、同じ Pi へ接続する |
| 表示用 Terminal が開いている状態で異なる cwd の会話を選択する | 旧表示タブの閉鎖完了後、選択した会話の cwd で表示用 Terminal を作り直して接続する。保持中の Pi と会話との対応は維持する |
| 表示用 Terminal のタブを閉じる | 表示用の接続だけを閉じ、保持中の Pi と会話との対応を維持する |
| 表示タブが閉じた状態で会話を再選択する | Editor Area に表示用 Terminal を1個作り、生存している同じ Pi へ再接続する |
| Pi が終了する | 自動で再起動せず、次回選択時に保存された会話を再開する |
| tmux が利用できない、または起動・接続に失敗する | 対象と失敗内容を示すエラーを表示する。同じ会話の Pi を重複起動せず、一覧・状態ストアを変更しない |

`pi --session` による再開は既存のセッションファイルへの追記として行われ、新しいセッションファイルは作られない。

アーカイブ済みのセッション（All モードにのみ現れるセッション）を選択して開いた場合も、上の表と同じ Pi 起動・再接続の動作になり、開くだけではセッション状態ストアの active 状態を変えない。アーカイブ済みのセッションは、行の `Unarchive` 操作でのみ未アーカイブに戻って既定の一覧に現れる。

### tmux設定の再適用

利用者はコマンドパレットの `Pi Sessions: Reapply tmux Settings`（`piSessions.reapplyTmuxSettings`）から、拡張の専用tmuxへ設定を再適用できる。接続先は拡張が現在使用する agent・セッションディレクトリに対応する専用サーバーであり、ソケット名・パスの入力は不要である。

| 条件・操作 | 動作 |
| --- | --- |
| 専用サーバーに管理セッションがある状態でコマンドを実行 | 一覧の表示対象やアーカイブ状態にかかわらず、既存の全管理セッションに新規起動時と同じ設定を適用する。ステータスバー非表示、prefixなし、paneタイトルの転送、および上記の修飾キー・マウス割り当てを反映する |
| 設定を正常に適用 | `tmux settings reapplied.` と通知する |
| 専用サーバーが未起動、または管理セッションがない | `No tmux sessions to update.` と通知し、サーバー・セッション・Piを新規作成しない |
| 接続や設定の適用に失敗 | `Failed to reapply tmux settings` と失敗内容をエラー通知する。上記の旧版tmuxで利用できない報告形式・Shift+Enter割り当ては、その互換動作に従う |
| コマンドを繰り返し実行 | 同じ設定を反映し、稼働中のサーバー・セッション・pane・Piプロセスと通常のマウス設定を維持する |
| 修正版拡張のロード後にコマンドを実行 | 保持中のtmuxへその場で設定を反映する。通常の再接続や `Developer: Reload Window` では、既存のstatus・prefix・修飾キー・マウス割り当てを維持する |

### VS Code 再起動

再起動後はセッションディレクトリとセッション状態ストアから一覧が復元され、全ワークスペースのモードは未アーカイブ表示（既定）に戻る。会話を再選択した際は tmux 内の保持対象を確認し、生存している Pi があれば同じプロセスへ再接続する。生存 Pi が無い場合は保存された会話を再開する。拡張 host の再起動だけを理由に Pi を起動し直さず、表示用 Terminal はウィンドウ内で1個に保つ。

## 開発補助: e2e 用 VS Code の準備

e2e テストが拡張機能の読み込み先として使う固定バージョンの VS Code を、1 コマンドで準備する。利用者はこのリポジトリで開発するコントリビュータで、テスト実行前にこのコマンドでバイナリを取得する。

| 項目 | 値 |
| --- | --- |
| コマンド | `bun run setup` |
| 準備対象 | e2e テストが拡張機能の読み込み先として使う Linux 版 VS Code（スクリプトに定義した固定バージョン） |
| 保存先 | `~/.cache/pi-sessions-screenshots/vscode-<固定バージョン>/`（例: `vscode-1.138.0/`） |
| バージョン管理 | ダウンロードした VS Code とその展開物は git の管理対象外 |

| 条件 | 動作 |
| --- | --- |
| `bun run setup` を実行 | 固定バージョンの Linux 版 VS Code が保存先に存在しなければダウンロードして展開し、存在すれば取得済みのものを再利用する。コマンド 1 回で完了する |
| 保存先ディレクトリが存在しない | 準備の前に作成する |
| 準備に成功 | コマンドは終了コード 0 で終了し、保存した実行ファイルのパスを標準出力に表示する |
| 準備に失敗 | コマンドは非ゼロの終了コードで終了し、失敗の原因を標準エラー出力に表示する |

## 設計上の制約

- Pi がセッションとエージェントの source of truth である。拡張機能は Pi を再実装せず、Pi セッション形式の独自変換も行わない
- セッション状態ストアの読み書きは VS Code API に依存しないモジュールとして分離し、保存場所とデータ形式は将来の Web UI・CLI からも同じデータを参照できるようクライアント非依存にする。ストアは pi 拡張 `session-state` と共有し、pi 側のメッセージ送信・`/archive`・`/unarchive` コマンド・実行フェーズの書き出しも同じストアを更新する。拡張機能はストアのファイル変更を監視して一覧へ反映する
- セッションファイルは read-only として扱い、セッションの作成・更新は Pi CLI に行わせる
