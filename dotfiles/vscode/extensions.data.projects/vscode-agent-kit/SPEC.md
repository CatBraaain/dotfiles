# VS Code Pi Session Manager spec

Pi（pi-coding-agent）のセッションを VS Code のサイドバーで一覧し、選択して Editor Area の Terminal で Pi TUI を開く VS Code 拡張機能の仕様。この拡張機能は Pi TUI を置き換えず、チャット UI やメッセージ表示も持たない。複数セッションの一覧・切替と、対応する作業先のファイル・差分への移動を提供する。読者は利用者と拡張機能の開発者である。セッション一覧は VS Code 標準の TreeView ではなく、拡張機能が描画する Webview UI を使う。保存 E2E のテストケースを「テストケース」節に一覧し、各ケースの期待する結果から各定義節を参照する読み方をする。

## 用語

- セッションファイル: Pi が会話を保存する JSONL ファイル。場所と形式は Pi のドキュメント（[sessions](https://github.com/earendil-works/pi-mono/blob/main/packages/coding-agent/docs/sessions.md) / [session format](https://github.com/earendil-works/pi-mono/blob/main/packages/coding-agent/docs/session-format.md)）に従う。
- セッション ID: セッションファイルのヘッダーが持つ UUID。ファイル名は `<timestamp>_<session-id>.jsonl` で、ファイル名の末尾セグメントと一致する。
- メタデータストア: セッション ID をキーに、この拡張機能が管理する状態（active マーキングなど）を保存する JSON ファイル。
- アクティブセッション: メタデータストアで `active` が真のセッション。ビューの既定の表示対象になる。

## テストケース

保存 E2E（`tests/review/phase-one.spec.ts`）は、実機連携の振る舞いを次のテストケースで検証する。各ケースの期待する結果は、対応する定義節に従う。

| ID | テストケース | 期待する結果（節） | 検証手段 |
| --- | --- | --- | --- |
| E2E-1 | 同名の本体・worktree フォルダを見分け、active 0 件の作業先の履歴を All モードで開ける | サイドバービュー・表示モードどおりの表示と切替 | 保存 E2E |
| E2E-2 | A/B の会話選択で実 Pi の Terminal を再利用し、ネイティブ diff と SCM 対象へ追従する | 生存 Terminal の PID 不変、`pi --session` による追記再開、diff・SCM・Graph・branch の追従、原本と Git の不変 | 保存 E2E |
| E2E-3 | SCM から Sessions へ戻っても、Refresh なしで一覧を復元する | Webview と拡張機能のメッセージどおりの再配信 | 保存 E2E |
| E2E-4 | 会話選択を受け付けた時点のエディタが、対象の変更ファイルを決める | 作業先のファイルと差分どおりの diff 選択 | 保存 E2E |
| E2E-5 | 単一ルートへの明示的なフォルダ追加が、拡張 host 再起動後の再選択でも成立する | 明示同意のみの追加、再起動後の diff・SCM 復帰 | 保存 E2E |
| E2E-6 | New Session がフルパス候補を出し、キャンセル・無効な開始先・別フォルダ選択を安全に扱う | New Session アクションどおりの候補と安全処理 | 保存 E2E |
| E2E-7 | 存在しない cwd・削除済みセッションファイルの選択を安全に扱い、セッション原本と Git を変更しない | エラー表示、Terminal なし、メタデータ不変、原本・Git 不変 | 保存 E2E |
| E2E-8 | 非表示リポジトリ・固定 Graph・active pin での SCM 追従 | 作業先のファイルと差分の一般条件どおりの追従 | 保存 E2E（未実行。tickets 管理） |
| E2E-9 | 実 Pi の最初の assistant 応答による新規セッションの検出と active 付与 | New Session アクションどおりの検出と active 付与 | 保存 E2E（未実行。tickets 管理） |

保存 E2E 以外の振る舞いは、unit がメタデータストア・セッション読み取り・表示名・グルーピング・Webview の描画・メッセージプロトコル・Terminal 対応付け・New Session・作業先移動の各契約を検証し、Storybook 静的カタログの smoke が Webview の表示と操作を検証する。各契約の詳細は後続の定義節に従う。

既知の未達と範囲外課題は、この文書に書かず tickets で管理する。

## データソース

拡張機能は Pi のセッションディレクトリを直接読んで一覧を作る。独自のセッションデータベースは持たない。この拡張機能の導入以前に Pi で作成されたセッションも、以後に作成されるセッションも同じ方法で一覧される。

| 項目 | 値 |
| --- | --- |
| エージェントディレクトリ | `PI_CODING_AGENT_DIR`（未設定・空文字なら `~/.pi/agent`） |
| セッションディレクトリ | `PI_CODING_AGENT_SESSION_DIR`（未設定・空文字なら `<エージェントディレクトリ>/sessions`） |
| 一覧対象 | `<セッションディレクトリ>/<cwd ディレクトリ>/` 直下の `*.jsonl` |
| 除外 | `subagents/` ディレクトリ配下のファイル（一覧対象ディレクトリ直下の `subagents/` を含む） |
| セッション ID と cwd | 各ファイル 1 行目のヘッダー `{"type":"session",...}` の `id` と `cwd`。cwd はディレクトリ名から復元せず、ヘッダーを正とする |
| 更新日時 | セッションファイルの mtime |

セッションディレクトリが存在しない、または `*.jsonl` が 1 件も無い場合、一覧は空になる。セッションディレクトリの読み取りに失敗した場合、エラーメッセージを表示する。

### 表示名

セッション項目の表示名は次の順で決める。

1. セッションファイル内の最新の `session_info` エントリの `name`（`/name` や `pi --name` で設定される値）。空文字はタイトル解除とみなし、次の規則へ進む
2. `text` を持つ最初のユーザーメッセージの、text 全体の前後の空白を取り除いた 1 行目（先頭 80 文字）
3. いずれも無い場合 `Untitled`

### メタデータストア

| 項目 | 値 |
| --- | --- |
| パス | `<エージェントディレクトリ>/session-metadata.json` |
| 形式 | 下記の JSON。文字コードは UTF-8 |
| 書き込み | 一時ファイルと rename による原子的置換。中断しても既存内容を壊さない |
| 同時書き込み | ファイル全体の読み書きの最後の書き込みが残る |

```json
{
  "version": 1,
  "sessions": {
    "<session-id>": { "active": true }
  }
}
```

- `active` が `true` のセッションをアクティブセッションとみなす。キーが無い、または `active` が真でないセッションは非アクティブとみなす
- アクティブ解除は当該エントリの `active` を `false` に更新する。エントリ自体と他の属性は保持する
- 読み書きで未知のキー・属性を保持する（将来の `pinned` / `title` / `tags` 等の追加に備える）
- ファイルが存在しない場合はメタデータ無しとして振る舞い、初回の書き込みで作成する
- 読み込み時に JSON を解析できない、または所定の構造でない場合（ルートと `sessions` がオブジェクトでない）はメタデータ無しとして振る舞い、書き込みは行わずエラーを表示する

Pi のセッション関連ファイルのうち、拡張機能が書き換えてよいのはメタデータストアのみである。セッションファイルは読み取り専用として扱い、変更・削除・移動をしない。セッションの作成と更新は Pi CLI が行う。

## サイドバービュー

Activity Bar に view container `Agent Sessions` を追加し、その中に拡張機能が管理する Webview view を表示する。VS Code 標準の TreeView は使わない。Webview は VS Code のテーマ色を使い、サイドバー幅に合わせて再配置される。セッションのファイル内容とメタデータストアの値は Webview に渡す表示用データだけに変換し、Webview からファイルシステムを直接操作しない。

### Webview の表示

Webview は次の順で表示する。

1. ヘッダーに `Sessions`、`New session`、`Refresh` を表示する
2. cwd ごとのグループをカード状のセクションで表示し、グループ見出しに basename とそのワークスペースのモード切替（`Active` / `All`）を表示する。見出しの下に cwd のフルパスを表示し、同じ basename のプロジェクトや worktree を区別する。長いパスはサイドバー幅で折り返す
3. グループ内にセッションを行として表示し、表示名と active 状態を示す
4. 各行の右端には、更新日時と、その行のセッション ID をクリップボードへコピーする `Copy` 操作をこの順で表示する。`Copy` は copy アイコンで示し、ホバーのヒントは `Copy session ID` とする
5. active な行には active の視覚的な印と `Archive` 操作を表示する。`Archive` はアーカイブのアイコンで示し、ホバーのヒントは `Archive` とする
6. セッション行全体を選択領域とし、選択の視覚表示は行の右端まで及ぶ。更新日時、`Copy`、`Archive` は行の右端に重ねて表示する

表示名・更新日時・グループ・並び順は「グルーピングとソート」の規則に従う。セッション行を選択する操作は、キーボードからも実行できる。

### 表示モード

モードはワークスペースごとに独立して持ち、そのグループ見出しの `Active` / `All` で切り替える。ワークスペース間で影響し合わない。

| モード | そのワークスペースの表示対象 |
| --- | --- |
| Active（既定） | そのワークスペースのアクティブセッションのみ。0 件でもグループ見出し・パス・モード切替を表示し、`No active sessions. Select All to browse saved sessions.` と案内する |
| All | そのワークスペースの全セッション。active なセッション項目は印で active であることを示す |

モードの切替状態は VS Code 再起動後も維持しない。保存済みセッションがあるすべての cwd で `All` を選択でき、active が 0 件の作業先からも過去の会話を選択・再開できる。

### Webview と拡張機能のメッセージ

| Webview の操作 | 拡張機能の処理 | Webview の結果 |
| --- | --- | --- |
| 一覧の初期表示・再生成・再表示 | セッションディレクトリとメタデータストアを読み、受信準備のできた Webview に最新の一覧を送る | Refresh を選ばずに保存済みの会話へ戻れる |
| ワークスペースの `Active` / `All` を選択 | Webview 内でそのワークスペースの表示だけを切り替える | そのワークスペースの行が切り替わる |
| `Refresh` を選択 | セッションディレクトリとメタデータストアを読み直す | 最新の一覧が表示される |
| `New session` を選択 | 「New Session アクション」の規則で新しい Terminal を起動する | 起動後に一覧が更新される |
| セッション行を選択 | 「セッション選択と Terminal」の規則でセッションを開く | Terminal が Editor Area に表示され、対応する作業先のファイル・差分へ移動する |
| 行の `Copy` を選択 | セッション ID をクリップボードへ書き込む | 一覧の表示は変えない。クリップボードへの書き込み成否にかかわらず、Webview 内では選択した `Copy` が約1秒チェックマークの表示に変わる |
| active 行の `Archive` を選択 | メタデータストアで当該セッション ID の `active` を `false` に更新する | 一覧を再読込し、active 更新後の行・グループを「表示モード」の規則で表示する |

拡張機能から Webview への一覧データ送信に失敗した場合、Webview はエラー状態を表示する。メタデータの書き込みに失敗した場合、エラーメッセージを表示し、表示中の一覧を変更しない。クリップボードへの書き込みに失敗した場合もエラーメッセージを表示し、表示中の一覧を変更しない。Webview の操作によるメッセージにはセッション ID などの必要な引数だけを含め、任意のファイルパスやコマンドを実行できる値を含めない。

### グルーピングとソート

両モード共通の規則。

| 対象 | 規則 |
| --- | --- |
| グループ | セッションの `cwd` ごとに 1 グループ。ラベルとパスの表示は「Webview の表示」に従う |
| グループ順 | 所属セッションの最新更新日時の降順。同一なら cwd の昇順 |
| グループ内セッション順 | 更新日時の降順。同一ならセッション ID の昇順 |
| セッション行の更新日時 | ロケールに応じた日時文字列で表示する |
| セッション行の補足情報 | 表示名、セッション ID、cwd、更新日時を確認できる。セッション ID は行ホバーのヒントと `Copy` によるクリップボード、cwd はグループ見出し下のパスとホバーのヒントで確認する |
| 空のとき | 保存済みセッションが 1 件も無いとき `No saved sessions` を表示する |

### アーカイブアクション

| 条件 | 操作 | 結果 |
| --- | --- | --- |
| active なセッション行の `Archive` を実行 | メタデータストアで当該セッション ID の `active` を `false` に更新し、一覧を再読込 | active 更新後の表示は「表示モード」に従う。Terminal は終了せず、セッションファイルは変化しない |
| メタデータの書き込みに失敗 | — | エラーメッセージを表示し、ビューは変化しない |

アーカイブは Terminal の終了、セッションファイルの削除とは別の操作である。セッションファイルの削除はこの拡張機能の操作に含まれない。

### 静的プレビュー

Storybook のカタログで、VS Code API と実セッションファイルを使わずに Webview の見た目と操作を確認できる。`bun run storybook` でカタログをブラウザに表示でき、`bun run storybook:build` の静的出力は任意の静的サーバで単独表示できる。カタログはサンプルデータで次の状態を確認できる。

| ストーリーの軸 | 値 |
| --- | --- |
| データ | 複数の cwd グループと active セッション / あるワークスペースを `All` に切り替えた状態 / 全作業先の active が 0 件で履歴を開ける状態 |
| 幅 | narrow（320px・既定）/ wide（720px） |

カタログ上でワークスペースごとのモード切替、`Copy`、`Archive`、`Refresh`、`New session` をサンプルデータに対して実行できる。`Copy` はブラウザの Clipboard API に対象のサンプルセッション ID を書き込む。New session はサンプルデータへ行を追加して active マーキングを付ける（Terminal は起動しない）。カタログの操作は実セッションファイル、メタデータストア、VS Code Terminal に影響しない。静的出力は拡張機能を起動せずにスクリーンショットを撮影できる。

### Refresh アクション

Webview の Refresh を実行すると、セッションディレクトリとメタデータストアを読み直して一覧を再描画する。Pi CLI、別の VS Code window、将来の他クライアントによるディスク上の変更は、この Refresh で反映される。ファイル監視による自動更新は行わない。

### New Session アクション

| 項目 | 値 |
| --- | --- |
| 起動 cwd | `Start Pi session in…` で開始先を選択する。候補は初期候補、file scheme の workspace folder、保存済みセッションの cwd（重複除去）。初期候補は最初の file workspace folder、無ければアクティブエディタの file のディレクトリ、それも無ければホーム。候補には basename とフルパスを表示する。`Choose another folder…` からフォルダーを選ぶこともできる |
| キャンセル | 候補またはフォルダー選択をキャンセルした場合は Terminal を作らず、一覧・メタデータを変えない |
| 無効な開始先 | 絶対パスでない、存在しない、またはディレクトリでない開始先はエラーを表示し、Terminal を作らない |
| 起動コマンド | 選択した cwd で新しい Terminal を作り `pi` を実行する（既存 Terminal は再利用しない） |
| 起動後 | Webview を再読込し、検出した新規セッションに active マーキングを付与して対応する cwd のグループに表示する |
| Terminal 対応 | 起動した Terminal は、検出された新規セッション ID に対応づけられ、以後そのセッションの選択で再利用される |

## セッション選択と Terminal

セッション項目をクリックすると、そのセッションの Pi TUI を Editor Area の Terminal で開く。続けて会話を選択した場合は、受け付けた順で Terminal と作業先への移動を実行する。Terminal は `vscode.window.createTerminal` の Editor 位置を使い、下部の Terminal Panel には表示しない。Terminal の名前はセッションの表示名にする。

| 条件 | 動作 |
| --- | --- |
| セッションファイルが存在しない | エラーメッセージを表示し、Terminal を起動しない |
| cwd が絶対パスでない、存在しない、またはディレクトリでない | 対象を含むエラーメッセージを表示し、Terminal を起動・再表示せず active を変えない |
| 当該セッション ID に対応する Terminal が生存している | 新しいプロセスを起動せず、その Terminal を Editor Area に表示する |
| 対応する Terminal が無い、または既に閉じている | Terminal の cwd をそのセッションの `cwd` として Editor 位置に Terminal を作り、`pi --session <セッションファイルのパス>` を実行する |
| Terminal が閉じた | セッション ID との対応関係を解消する |

`pi --session` による再開は既存のセッションファイルへの追記として行われ、新しいセッションファイルは作られない。

active でないセッション（All モードにのみ現れるセッション）を選択して開いた場合も、上の表と同じ Terminal の動作になり、開いた時点で active マーキングが付与されて Active モードの一覧に現れる。

### 作業先のファイルと差分

会話の担当先はセッションヘッダーの cwd である。作業先への移動では絶対パスを正規化する。会話を開いた際は、生存 Terminal の再利用時も含め、次の規則で VS Code の既存機能へ接続する。開いている別作業先のエディタは閉じず、ファイル内容や Git の index を変更しない。

| 条件 | 結果 |
| --- | --- |
| cwd が workspace folder 内にある | Explorer でその cwd を選択・表示する |
| cwd が workspace に無い | フルパスを示して `Add folder to workspace` を提示する。明示的に選択した場合だけ workspace に追加する。通知への応答待ちでほかの会話の選択を妨げない。選択しなくても TUI は開いたままとし、workspace を変えない |
| workspace への追加 | ウィンドウが再読込される場合があることを案内する。追加後は会話を再選択してファイル・差分へ移動できる |
| workspace 追加を開始できない | 対象を含むエラーを表示する |
| 登録済み cwd に Git の変更がある | VS Code Git拡張でリポジトリを開いて変更を取得し、cwd 内の変更を対象にする。会話選択を受け付けた時点のエディタのファイルがその変更にあればそれを選び、無ければ作業ツリー、index の順で最初の変更を選ぶ。既存 SCMビューを表示し、そのファイルを Git拡張の差分エディタで開く。SCMの対象リポジトリ、Git Graph、ステータスバーのブランチ表示も会話の作業先に一致する |
| 登録済み cwd に Git の変更が無い | 対象 cwd と変更が無い旨を案内し、Explorer の作業先を保持する |
| 登録済み cwd に Gitリポジトリが無い | 対象 cwd とリポジトリが無い旨を案内し、Explorer の作業先を保持する |
| VS Code Git拡張が利用できない | ファイルの作業先を表示し、Git拡張を有効にすると差分を確認できる旨を案内する |
| ファイル・差分への移動に失敗 | エラーを表示する。開いた TUI と active 印は維持する |

### VS Code 再起動

Terminal とセッション ID の対応関係は永続化しない。再起動後はセッションディレクトリとメタデータストアから一覧が復元され、全ワークスペースのモードは Active に戻る。セッションを選択した時点で新しい Terminal で `pi --session` が実行される。

## 開発補助: 自動スクショ

この拡張機能の UI を、1 コマンドで自動的にスクリーンショットする。利用者はこのリポジトリで開発するコントリビュータで、撮影した画像を目視レビューに使う。

| 項目 | 値 |
| --- | --- |
| コマンド | `bun run screenshot` |
| 撮影内容 | Agent Sessions ビューを開いた VS Code ウィンドウ全体 |
| 保存先 | `.screenshots/<YYYYMMDD-HHmmss>.png`（例: `20260919-183000.png`） |
| セッションデータ | 撮影スクリプトが作成した分離環境のダミーセッション 3 件（すべて active）を表示する。実環境のセッションデータとメタデータストアは読み書きしない |
| バージョン管理 | `.screenshots/` は git の管理対象外 |

| 条件 | 動作 |
| --- | --- |
| `bun run screenshot` を実行 | TypeScript のビルド、このリポジトリの拡張機能を読み込んだ撮影用 VS Code の起動、Agent Sessions ビューを開いた状態での撮影、VS Code の終了まで、コマンド 1 回で完了する |
| 撮影用の VS Code が未取得 | スクリプトに定義した固定バージョンの Linux 版 VS Code を撮影の前にダウンロードし、2 回目以降は取得済みのものを再利用する |
| 保存先ディレクトリが存在しない | 撮影の前に作成する |
| 撮影に成功 | コマンドは終了コード 0 で終了し、保存した画像のパスを標準出力に表示する |
| 撮影に失敗 | コマンドは非ゼロの終了コードで終了し、失敗の原因を標準エラー出力に表示する |

## 設計上の制約

- Pi がセッションとエージェントの source of truth である。拡張機能は Pi を再実装せず、Pi セッション形式の独自変換も行わない
- メタデータストアの読み書きは VS Code API に依存しないモジュールとして分離し、保存場所とデータ形式は将来の Web UI・CLI からも同じデータを参照できるようクライアント非依存にする
- セッションファイルは read-only として扱い、セッションの作成・更新は Pi CLI に行わせる
