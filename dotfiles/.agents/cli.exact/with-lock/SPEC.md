# with-lock CLI

`with-lock` は、ロック名ごとに1プロセスだけが保持できるロックを取ってからコマンドを実行する独立CLIである。`flock(1)` と同じ引数形で呼べる代替であり、`~/.agents/cli/with-lock`（Windows は `with-lock.exe`）に配布され、`browse`・`startup` などが排他制御のために呼ぶ。利用者と保守担当者が、引数・待機・終了コード・ロックの排他と解放を確認するための振る舞い正本である。この文書は、コマンドの入力と終了コード、ロックの排他・待機・解放を外部から観測できる形で定め、「実現方法として固定する」節に書いた方式も定める。それ以外の実現方法は実装に委ねる。

## コマンド

```text
usage: with-lock [-n] [-w <seconds>] [-E <code>] <name> <command> [args...]
```

| 入力 | 結果 |
| --- | --- |
| `with-lock <name> <command> [args...]` | `<name>` のロックを取れるまで待つ。取ったら `<command>` を実行して終了を待ち、ロックを解放して `<command>` の終了コードで終わる |
| `with-lock -n ...` | ロックを1回だけ試みる。取れなければ `<command>` を実行せず、`-E` の終了コード（既定 1）で終わる |
| `with-lock -w <seconds> ...` | ロックを最大 `<seconds>` 秒待つ。取れなければ `<command>` を実行せず、`-E` の終了コード（既定 1）で終わる |
| `with-lock -E <code> ...` | ロックを取れなかったときの終了コードを `<code>`（0以上255以下の整数）にする |
| `<name>` なし、`<command>` なし、`-` で始まる不明なオプション、`-w`・`-E` の値なし・値不正 | stderrに `with-lock: <理由>` と使用方法を出し、終了コード 2で終わる |

オプションは `<name>` より前に置く。`-n` と `-w` を両方指定したときは、後に指定した方を採る。`<name>` 以降は `<command>` とその引数であり、`-` で始まっていてもオプションとして解釈しない。`--` は `<name>` の前後どちらにも置け、`<name>` の後に置いたときは `<command>` の先頭から除く。

## ロック

`<name>` は任意の文字列で、パスを含めてよい。同じ文字列は同じロックを指し、異なる文字列は異なるロックを指す。ロックは `<name>` ごとに同時に1プロセスだけが保持する。保持していたプロセスが終了した時点（クラッシュや kill も含む）でロックは解放され、待っていた実行のどれか1つが次に取得する。

| 環境 | 排他の範囲 |
| --- | --- |
| Linux | 同じホストの同じユーザー（uid）のプロセス間 |
| Windows | 同じホストのプロセス間 |
| 上記以外 | ロックを取らずに `<command>` を実行する。`-n`・`-w` でも競合は起きない |

ネットワーク越しの排他はしない。

## 待機

| 指定 | 振る舞い |
| --- | --- |
| `-n` | 1回だけ試みる |
| `-w <seconds>` | `<seconds>` は 0以上の数（小数可）。空文字列や空白だけの値は無効。その秒数を過ぎても取れなければ諦める |
| なし | 取れるまで待つ |

待機中は何も出力しない。

## コマンドの実行

`<command>` はシェルを介さず、with-lock の stdin・stdout・stderr・環境変数・カレントディレクトリをそのまま引き継いで起動する。

with-lock は SIGTERM と SIGINT を受け取ると `<command>` へ同じシグナルを転送し、`<command>` の終了を待ってからロックを解放して終わる。終了コードは下表の `<command>` の終了状態に従う。

| 状況 | 終了コード |
| --- | --- |
| `<command>` が自ら終了した | `<command>` の終了コード |
| `<command>` がシグナルで終了した | 128 + シグナル番号 |
| `-n`・`-w` でロックを取れなかった | `-E` の値（既定 1） |
| 引数の誤り | 2 |
| 他の実行が保持中以外の理由でロックの取得に失敗した | 2 |
| `<command>` の起動に失敗した | 2 |

ロックの取得に失敗したときと `<command>` の起動に失敗したときは、stderrに `with-lock: <理由>` を出す。

## 実現方法として固定する

- ロックは OS の排他で保持する。Linux は抽象 Unix ドメインソケット `\0with-lock-<hash>-<uid>`、Windows は名前付きパイプ `\\.\pipe\with-lock-<hash>` への1リスナーとして表す。`<hash>` は `<name>` の sha256 の先頭16桁（hex）、`<uid>` は実行ユーザーの uid である。
- 保持プロセスが終了すると OS がロックを解放する。ロックファイルなどファイルシステム上の実体は持たず、異常終了の後も残骸は残らない。
- 待機は 200ms を超えない間隔での再試行で実現する。`-w <seconds>` では期限を過ぎてから再試行しない。
- npm の依存は持たず、Node.js 組み込みモジュールだけを使う。
