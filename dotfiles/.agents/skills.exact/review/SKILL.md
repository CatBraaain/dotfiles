# Review

## コンテキストと用語

- コンテキストは、対象、目的、契約、原則、根拠からなる。入力はどのような文書形式でもよく、これらに対応する名称や区分を持つ必要はない。
- 契約は、対象が満たすと表明・要求された、成否を確認できる約束である。
- 原則は、目的に向けた判断軸であり、契約のように直接の成否を確認できないことがある。
- 根拠は、対象またはコンテキスト内の、判定を裏付ける箇所・事実である。
- 反証テストは、原則の前提を保ったまま、その原則と両立しない結果を示せるかを確かめるテストである。skip は、対象外または評価しない項目とその理由を示す記録である。

## 判断の基準

入力の見出し・ラベル・節構成だけから優先順位を推測せず、与えられたコンテキストに含まれる対象、目的、契約、原則、根拠を判断の基準にする。入力に例外・優先関係が明示されている場合は、適用条件を確認し、その関係に従って契約・原則を評価する。

契約・原則は、対象とともに依頼された入力からだけ抽出する。依頼に契約・原則として指し示せる内容がなく、AGENTS.md・rules・スキル等の既存規則しか候補にないときは、それらを契約・原則の代用にしない。依頼が賛否・意見を求める相談のときは本スキルを適用せず、通常の回答として扱う。

## 差分を指定したコードレビュー

- 比較範囲：両端が指定されていればその範囲を使う。コミット・ブランチ・タグからの変更や PR は共通祖先から、作業中の変更だけなら `HEAD` から比較する。比較先の指定がなければ、PR はその先端、それ以外は worktree の `HEAD` を使う。
- 作業中の変更：依頼が作業中の変更を含む場合は、比較先と `HEAD` が一致する worktree の現在の内容を、ステージの有無にかかわらず基点と比較する。依頼範囲内の未追跡ファイルも含め、無視設定の対象は除く。
- 評価：要求適合は依頼本文・ticket・仕様などの要求元に、コード品質はプロジェクトの規約と `coding` のカタログに照らし、分けて報告する。要求がないと確認できた場合は要求適合を `skip` とする。カタログとプロジェクトの規約が矛盾する場合は規約を優先する。
- 性能退行：性能要件がなくても、頻繁に通る処理や入力・データ件数に応じて負荷が増える処理に差分が影響するなら、変更前後のコストを比較する。影響が大きい可能性があり、コードから判断できなければ同じ条件・代表的な入力で前後を計測する。計測できなければ、その旨と判断に必要な条件を示す。指摘はコード品質に含め、差分の箇所・影響条件・比較根拠を示す。

## サブエージェントに委譲するレビュー

初回のレビューを委譲するときは、レビュー分野ごとに `senior` サブエージェントを1人、新規セッションで起動する。

1. 親エージェントは、依頼の目的・範囲に沿って、コード（`coding`）と文書（`writing`）のような大きな分野に分ける。スキルは分野の粒度の目安とし、参照するスキルの数で分けない。実装の正しさ・保守性・性能など、同じ分野の確認項目は1人にまとめる。性能などを別担当にするのは、それ自体が依頼の独立した評価目的である場合に限る。
2. 親エージェントは、各 `senior` に同じ版の対象と共通の評価前提、担当分野、参照すべき根拠を渡す。各担当は「評価の実行」に従い、他のレビュアーの判定を受け取らずに初回の評価を行う。
3. 親エージェントは、分野ごとの判定と根拠を照合し、重複する指摘をまとめる。判定が食い違う場合は根拠で判断し、未評価の項目は理由とともに `skip` に残す。統合結果は「評価の実行」の形式で報告する。

## 評価の実行

1. コンテキストから対象、目的、契約、原則、根拠を特定する。入力がどのように記述されていても、対応する内容と明示された例外・優先関係を抽出する。
2. 契約ごとに、対象と根拠を照合し、成功・失敗・判定不能のいずれかを決める。
3. 原則ごとに、その前提と両立する反証テストを組み、対象と根拠に適用する。結果を反証あり・反証なし・判定不能として記録し、反証ありまたは判定不能には重要度を付ける。原則への適合を宣言で済ませず、前提と両立する反証を探す。
4. 契約、原則、skip、サマリを、次の表の区分と必須内容で出力する。該当項目がない区分は「なし」とする。

重要度は高・中・低の3段階とする。

| 重要度 | 定義 |
| --- | --- |
| 高 | 放置すると目的または契約の達成を妨げる |
| 中 | 放置しても目的または契約は達成されるが、対処する価値がある |
| 低 | 対処しなくてもよい参考指摘 |

| 区分 | 必須内容 |
| --- | --- |
| 契約 | 契約ごとの判定（成功・失敗・判定不能）、根拠、失敗・判定不能時の対象内の場所・重要度（高・中・低）・目的に適合する修正案 |
| 原則 | 原則ごとの反証テスト、結果（反証あり・反証なし・判定不能）、根拠、反証あり・判定不能時の対象内の場所・重要度（高・中・低）・目的に適合する修正案 |
| skip | 評価しない項目と理由 |
| サマリ | 対象ごとの高・中・低の件数と最高重要度（高・中・低・該当なし）。対象が複数なら対象ごとに契約・原則・skipを分ける。 |

### 評価中の制約

- 対象、コンテキスト、目的のいずれかが評価に必要な範囲で不足するときは、不足情報を質問して停止する。
- 評価中および停止中は、対象を編集せず、契約を再定義せず、修正を承認せず、収束しない。
