# Converge

## 収束条件

- **収束条件**は、ユーザーが明示した観測可能な終了条件である。明示がない場合は、最終の `review` における変更スコープ内の高重要度指摘が 0 件であること。
- **収束対象**は、明示指定された収束では収束条件の判定に使う `review` の評価項目とその修正に必要な変更、許可によって開始した収束では許可時に示した対象と目的である。
- `review` は、入力から対象、目的、契約、原則、根拠を抽出して評価項目を出力する正本である。

## 変更スコープ

- **変更スコープ**は、収束で修正を適用できる範囲である。既定は今回の変更で、今回の変更で新規作成したファイルは全体を、既存ファイルは今回の変更で編集した箇所を変更スコープとする。ユーザーが範囲を明示した場合は、明示された範囲を変更スコープとする。
- 変更スコープ外の指摘と検証失敗は、修正せず、収束条件の判定にも使わない。
- フォーマッター・リンター等の検証ツールが既存ファイルへ行う変更も、変更スコープに合わせる。変更スコープ外の変更は適用せず、すでに適用されていれば元に戻す。
- 変更スコープ外の指摘と適用しなかったツールの変更は、完了報告に列挙し、別セッションでのレビュー収束による対応をユーザーへ推奨する。

## 収束の実行

対象・目的・制約を `review` で評価し、収束をユーザーが明示的に指定した場合、または明示的に許可した場合に限り、収束条件を満たすまで修正・検証・再評価を反復する。

- 評価項目と重要度は `review` の出力に従う。
- 収束条件を満たさない原因だけを、収束対象と変更スコープの範囲内で最小に修正する。

### 実行の許可

- 収束をユーザーが明示的に指定した場合は、許可を求めずに実行手順を開始する。対象、目的、制約、収束条件、変更スコープを文脈から特定し、特定できない情報だけを質問して停止する。
- 明示的な指定がない場合は、`review` の指摘やエージェント自身の判断だけで収束を開始してはならない。収束を開始する前に、対象・目的・制約・収束条件を示してユーザーへ許可を求め、許可されるまで停止する。質問は次の形式にする。

  ```markdown
  1. [対象]を[収束条件]まで収束させてよいですか？ (y/a)
     (y) はい
     (a) 収束しない
  ```

- 明示的な指定がない場合、ユーザーが `(y)` で許可した場合だけ、実行手順を開始する。それ以外の場合は収束を実行しない。

### 実行手順

1. `review` を、対象・目的・制約を特定できる入力へ適用する。この段階では対象を編集しない。
2. 収束条件の判定に必要な検証を実行し、`review` の結果と検証結果のうち変更スコープ内のものから収束条件を判定する。満たせば、収束したと報告して停止する。
3. 収束条件を満たさない原因となる評価項目または検証失敗を、収束対象と変更スコープの範囲内で最小に修正する。
4. `review` を再適用し、手順2から繰り返す。

### 停止と編集境界

- 対象、目的、制約、変更スコープ、またはユーザーが明示した収束条件を一意に特定できない場合は、必要な情報を質問して停止する。
- `review` が必要情報を質問して停止した場合は、その質問を解決するまで修正も収束判定も行わない。
- `review` と再評価では対象を編集しない。
- 明示指定された収束では、収束対象の修正にあらためて許可を求めない。
- 許可によって開始した収束で、収束対象の範囲外の修正が必要な場合は、必要な情報または許可を質問して停止する。
- 安全に実行できない変更が必要な場合は、必要な情報または許可を質問して停止する。
- オーナーが停止を指示した場合は、現在の評価結果と未解決項目を報告して停止する。
- 完了報告には、収束条件、最終の `review` 結果、実行した検証、収束条件を満たす根拠を含める。
