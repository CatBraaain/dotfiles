# Converge

## 収束条件

- **収束条件**は、ユーザーが明示した観測可能な終了条件である。明示がない場合は、最終の `review` における変更スコープ内の高重要度指摘が 0 件であること。呼び出し元の skill が追加の評価や完了条件を定める場合は、それらも満たすこと。
- **収束対象**は、収束条件の判定に使う `review` の評価項目とその修正に必要な変更である。作業計画には対象と目的を含める。
- `review` は、入力から対象、目的、契約、原則、根拠を抽出して評価項目を出力する正本である。

## 変更スコープ

- **変更スコープ**は、収束で修正を適用できる範囲である。既定は今回の変更で、今回の変更で新規作成したファイルは全体を、既存ファイルは今回の変更で編集した箇所を変更スコープとする。ユーザーが範囲を明示した場合は、明示された範囲を変更スコープとする。
- 変更スコープ外の指摘と検証失敗は、修正せず、収束条件の判定にも使わない。
- フォーマッター・リンター等の検証ツールが既存ファイルへ行う変更も、変更スコープに合わせる。変更スコープ外の変更は適用せず、すでに適用されていれば元に戻す。
- 変更スコープ外の指摘と適用しなかったツールの変更は、完了報告に列挙し、別セッションでのレビュー収束による対応をユーザーへ推奨する。

## 収束の実行

対象・目的・制約を `review` で評価し、承認済み作業計画が収束を自律範囲に含めている場合に限り、収束条件を満たすまで修正・検証・再評価を反復する。

- 評価項目と重要度は `review` の出力に従う。呼び出し元の skill が追加評価を定める場合は、その評価項目と重要度も収束判定に含める。
- 収束ループは `review` と修正の1往復を1周とし、3周までとする。3周で収束条件を満たさないときは、残った指摘と検証失敗を tickets に起票し、最終の `review` 結果と残課題を報告して停止する。
- 収束条件を満たさない原因だけを、収束対象と変更スコープの範囲内で最小に修正する。

### 作業計画との連携

- 収束の対象、目的、制約、収束条件、変更スコープ、自律して進める周回数を共有AGENTS.mdの作業計画に含める。承認済み計画が収束を含む場合、収束開始時に追加の許可を求めない。
- `review` の指摘やエージェント自身の判断だけでは、承認済み計画にない収束を開始しない。収束が必要になった場合は停止し、対象・目的・制約・収束条件・変更スコープを含めた計画の更新を提示して承認を得る。
- 対象、目的、制約、変更スコープ、またはユーザーが明示した収束条件を一意に特定できない場合は、必要な情報を質問して停止する。

### 実行手順

1. `review` を、対象・目的・制約を特定できる入力へ適用する。呼び出し元の skill が追加評価を定める場合はそれも適用する。この段階では対象を編集しない。
2. 収束条件の判定に必要な検証を実行する。`review` と検証結果は変更スコープ内のものを判定し、呼び出し元の skill が定める追加評価は、その skill が定める判定範囲で判定する。すべての収束条件を満たせば、収束したと報告して停止する。
3. 収束条件を満たさない原因となる評価項目または検証失敗を、収束対象と変更スコープの範囲内で最小に修正する。
4. `review` と呼び出し元の skill が定める追加評価を再適用し、手順2から繰り返す。

### 停止と編集境界

- 対象、目的、制約、変更スコープ、またはユーザーが明示した収束条件を一意に特定できない場合は、必要な情報を質問して停止する。
- `review` が必要情報を質問して停止した場合は、その質問を解決するまで修正も収束判定も行わない。
- `review` と再評価では対象を編集しない。
- 明示指定された収束では、収束対象の修正にあらためて許可を求めない。
- 計画承認によって開始した収束で、収束対象の範囲外の修正が必要な場合は、必要な情報または計画更新の承認を質問して停止する。
- 安全に実行できない変更が必要な場合は、必要な情報または許可を質問して停止する。
- ユーザーが停止を指示した場合は、現在の評価結果と未解決項目を報告して停止する。
- 完了報告には、収束条件、最終の `review` 結果、実行した検証、収束条件を満たす根拠を含める。
