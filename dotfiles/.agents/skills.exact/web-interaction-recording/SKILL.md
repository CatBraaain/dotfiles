# Web Interaction Recording

## 録画の境界

対象は、ユーザーが録画を求めた Playwright Test、または Vitest から Playwright ライブラリでブラウザーを操作する E2E テスト。動画でレビューする操作と画面上の結果を基に、録画専用の E2E シナリオを作る。関連する操作はレビュー時に流れを追える範囲で1本にまとめ、動画の本数を抑える。各シナリオに結果を検証する自動アサーションを置く。録画の実行を別途指示されなくても、録画ケースを実行して動画を生成する。通常の E2E には録画用の設定変更・実行・動画生成を適用しない。既存のランナーを録画のためだけに移行しない。

録画は操作と画面上の結果を人がレビューするためのもの。ランナーの自動テスト結果と、ユーザーが動画を見て行う go/no-go 判断を区別する。画面上の表示からアサーションの成否を推測せず、実際に実行したランナーの結果を自動テストの合否とする。テストデータの選定はテストケースを設計する側の責務であり、この skill は入力値の検査やマスクを追加しない。

## 録画を組み込む

対象プロジェクトのランナー、既存の E2E helper / fixture、reporter、動画の保存先、主要なウェブ使用フローを調べ、既存の構成に合わせて録画ケースだけに録画を組み込む。Playwright のページ動画を WebM で保存し、`ffmpeg` で無音の H.264 MP4 に変換する。ページ画面を隠さない上部余白に、describe 階層を含むテストタイトルを無地の黒背景の帯で表示する。帯はページの UI と誤認できない見た目にする。既存の装飾・変換処理が要件を満たすなら重複して追加しない。

失敗したテストでも動画の保存を試み、保存・変換の失敗はテスト結果を上書きせず別に報告する。録画 context を自分で管理する場合は、ページと context を閉じて録画を確定させてから WebM の保存・変換を待つ。並列実行や再試行では出力名の衝突を避け、各テストの最後の試行で対象操作を収めたページの MP4 を1本確定する。最終試行を選別できない場合は、制約と残った動画を報告し、各テスト1本と主張しない。

`ffmpeg` の `libx264` と `drawtext` が利用できることを確認する。既存の package manager、Playwright バージョン、プロジェクト・ブラウザ設定で録画ケースを実行する。録画を有効にした設定や helper が後続の通常実行でも録画する場合、依頼が一時的な録画なら組み込みの変更を残さない。報告する MP4 は実際に出力されたパスから確認する。変換エラーはテスト合否とは別に報告し、MP4 が欠けた場合は録画完了としない。

## 操作を読みやすくする

録画開始前に画面サイズを一定にし、必要なテストだけを実行する。操作を人が追える間隔で進めるが、待機時間の追加で録画ケースのアサーションの意味を変えない。移動を見せたいクリックでは、途中のマウス移動イベントを実時間で発生させてからクリックし、カーソルが対象へ移動してクリック位置に波紋が出るようにする。必要なクリックがポップアップや画面遷移を起こすときは、遷移前に動きが見えることを確認する。

次の表は録画の見せ方を既存仕様と未採用の候補に分けた一覧。候補は必須要件としない。

| 起点となる操作・場面 | 画面上の表示・録画への反映 | 境界・注意点 | 状態 |
| --- | --- | --- | --- |
| マウスの移動 | 途中のマウス移動に合わせて疑似カーソルを移動する | 移動を見せたいクリックでは、途中のマウス移動イベントを実時間で発生させる | 既存仕様 |
| 移動を見せたいクリック | カーソルが対象へ移動してからクリックする | ポップアップや画面遷移を起こすクリックでは、遷移前に動きが見えることを確認する | 既存仕様 |
| クリック | クリック位置に波紋を出す | マウス移動とクリック位置が対応するようにする | 既存仕様 |
| 文字入力 | 画面下部中央の固定幅の暗い入力帯に、入力中の文字を連続した文字列として表示する | 入力値の検査・マスクは追加しない。帯は文字列が変わっても動かない | 既存仕様 |
| `Ctrl + A` / `Meta + A` | 入力帯の文字列を操作名に置き換え、続く文字入力を新しい文字列として表示する |  | 既存仕様 |
| `Backspace` | 入力帯を削除後の文字列に更新する。直後の文字入力は削除結果が見えるまで最大160ms遅らせて表示する |  | 既存仕様 |
| keydown なしの文字入力対象の `input` | 入力帯に対象の値を表示する | `locator.fill()` などが該当する | 既存仕様 |
| checkbox など非文字入力対象の `input` | 入力帯に対象の値を表示しない |  | 既存仕様 |
| 入力帯の表示更新後 | 最後の更新から約600ms後に帯全体を300msでフェードさせる | 表示対象の次のキーや値の更新から時間を数え直す | 既存仕様 |
| テストの録画中 | ページ画面を隠さない上部余白に、無地の黒背景の帯で describe 階層を含むタイトルを表示する | 合否表示ではない | 既存仕様 |
| テストの録画終了後 | 各テストの最後の試行で対象操作を収めたページの MP4 を1本確定する | 最終試行を選別できない場合は制約と残った動画を報告し、各テスト1本と主張しない | 既存仕様 |
| 操作フェーズの切り替わり・結果の観測点 | 次に見る結果を示す短いラベルを動画後処理で付ける | `PASS` を断定しない | 候補（高） |
| 通知・値など重要領域が表示されたとき | 観測箇所に、その表示時だけ静的な枠を付ける | 他の変化を隠さない | 候補（中） |
| 長い録画で操作・結果へ再訪するとき | 動画外の章・時刻索引から該当箇所へ戻れるようにする | プレイヤーの章対応を前提にしない | 候補（中） |
| 小さな UI を読む区間 | 必要な区間だけ局所拡大し、全体表示へ戻す | 周辺の変化を切らず原映像を保持する | 候補（低） |
| 一瞬だけ表示された結果を読むとき | レビュー版だけ静止保持して読む時間を確保する | 静止と元の時刻を明記し、実際の持続時間と混同しない | 候補（低） |
| 長いページをスクロールするとき | 移動を短く区切り、到着先で落ち着かせて対象 UI を見せる | 実際の移動・待機・失敗を削らない | 候補（中） |
| 内容を読む間、カーソルが動かないとき | 停止カーソルだけを隠して内容へ視線を向けられるようにする | hover・ドラッグ中は隠さない | 候補（中） |
| 長いページをスクロール中 | 固定の小型マーカーで現在位置・方向を示す | 効果・制作根拠が弱く、内部スクロールや iframe の位置対応が難しい | 候補（要検証） |
| `Tab`・矢印キーでフォーカスを移すとき | 入力帯のキー表示と実際のフォーカス先を対応付ける | DOM 装飾や `activeElement` だけでフォーカス・選択を断定しない | 候補（中） |
| hover でクリックせず内容が現れたとき | 実際の hover と同期した控えめな状態表示を付ける | hover 中はカーソルを隠さない。表示区間の同期は未検証 | 候補（中） |
| ドラッグ・ドロップの押下・保持移動・解放 | 各段階を実操作と同期して視認できるようにする（表示方式は未決） | 軌道や保持時間を作り直さない。正確な区間取得は未検証 | 候補（高） |
| ローディング・通信待ちが発生したとき | 原動画と照合できる時系列で通信中・UI 更新・確認待ちを区別する | 応答を UI 完了やテスト成功と同一視しない | 候補（中） |

画面下部中央の固定幅の暗い帯に、入力中の文字を一つの連続した文字列として表示する。`Ctrl + A` / `Meta + A` は操作名に置き換え、続く文字入力は新しい文字列として表示し、Backspace では削除後の文字列に更新する。表示対象の最後のキー（keydown がない場合は値の更新）による帯の更新から約600ms後に帯全体を300msでフェードさせる。Backspace 直後の文字入力は、削除結果が見えるまで表示を最大160ms遅らせる。帯の位置と幅は文字列が変わっても動かない。`locator.fill()` のように keydown なしで文字入力対象に `input` が起きた場合は、その対象の値を表示する。checkbox など文字入力対象でない要素の `input` は表示しない。文字が順に増える様子を見せたいシナリオでは、操作の意味が変わらないことを確かめて `pressSequentially()` を使う。

装飾は DOM に要素を追加する。スクリーンショット比較や全要素数を調べるアサーションには影響しうるため、その間だけ装飾を隠すなどして期待値とテストの意味を維持し、装飾なしの結果とも照合する。維持できなければ録画の制約として報告し、合否が変わらないとは主張しない。

ポップアップ、複数ページ、iframe 内の操作を主に確認したい場合は、装飾するページと動画の選択を調整してから「各テストの操作が収まる」と報告する。画面外のアサーションやネットワーク結果は映像だけでは判定しない。

## 確認と報告

録画ケースごとに MP4 が1本あるか、上部の無地の黒背景の帯に describe 階層を含むタイトルが読めるか、連続フレームでカーソルの中間位置・拡大する波紋・画面下部中央で動かない帯への連続した文字入力と帯全体のフェードが確認できるか、失敗したテストも録画されたかを確認する。ショートカット、Backspace、keydown なしの文字入力、非文字入力対象の操作を含む場合は、文字列の更新と、非文字入力の値が帯に出ないことも確認する。`ffprobe` で動画の映像コーデックと再生時間を確認し、対象の MP4 をそれぞれ再生して、開始から終了までテストの操作と画面上の結果を追えるか確かめる。ユーザーが動画を見て go/no-go を判断できるよう、各録画ケース・対象の主要なウェブ使用フロー・動画のパス・アサーションを含む自動テスト結果を対応付ける。通常の E2E の実行結果と録画ケースの実行結果、動画に対する人手の go/no-go 判断を区別し、映像だけでは判断できない点も報告する。

動画レビューまで依頼された場合は、失敗テストを先に確認し、指摘には動画パス、経過時間、見えた事実を添える。失敗と判定できない見た目は観測として区別し、動画を見ただけでテストのアサーションが成功したと結論しない。
