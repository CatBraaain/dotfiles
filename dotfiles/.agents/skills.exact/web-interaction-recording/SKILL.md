# Web Interaction Recording

## 録画の境界

対象は、ユーザーが録画を求めた Playwright Test、または Vitest から Playwright ライブラリでブラウザーを操作する E2E テスト。動画でレビューする操作と画面上の結果を基に、録画専用の E2E シナリオを作る。関連する操作はレビュー時に流れを追える範囲で1本にまとめ、動画の本数を抑える。複数ページにまたがる場合は発生順にページ映像をつなぎ、各操作と結果が追える1本にする。つなげられない場合は動画と対象を分け、収まらない操作を明示する。各シナリオに結果を検証する自動アサーションを置く。録画の実行を別途指示されなくても、録画ケースを実行して動画を生成する。通常の E2E には録画用の設定変更・実行・動画生成を適用しない。既存のランナーを録画のためだけに移行しない。

録画処理が映像へ付加する表示の見た目（配置・色・状態）の正本は、この skill の「注釈の見た目」（共通注釈）である。skill のほかの節は、録画の生成と、操作・画面変化といった対象イベントの注釈への対応付けを担う。録画処理が付加する表示の全体は、共通注釈と、ユーザーが承認したプロジェクト固有の表示で構成する。ページ本来の UI は録画対象の映像として扱い、録画処理が付加する表示と区別する。

録画は操作と画面上の結果を人がレビューするためのもの。ランナーの自動テスト結果と、ユーザーが動画を見て行う go/no-go 判断を区別する。画面上の表示からアサーションの成否を推測せず、実際に実行したランナーの結果を自動テストの合否とする。テストデータの選定はテストケースを設計する側の責務であり、この skill は入力値の検査やマスクを追加しない。

## 録画を組み込む

対象プロジェクトのランナー、既存の E2E helper / fixture、reporter、動画の保存先、主要なウェブ使用フローを調べ、既存の構成に合わせて録画ケースだけに録画を組み込む。Playwright のページ動画を WebM で保存し、`ffmpeg` で無音の H.264 MP4 に変換する。ページ画面を隠さない上部余白に、describe 階層を含むテストタイトルを無地の黒背景の帯で表示する。帯はページの UI と誤認できない見た目にする。既存の装飾・変換処理が要件を満たすなら重複して追加しない。

失敗したテストでも動画の保存を試み、保存・変換の失敗はテスト結果を上書きせず別に報告する。録画 context を自分で管理する場合は、ページと context を閉じて録画を確定させてから WebM の保存・変換を待つ。並列実行や再試行では出力名の衝突を避け、各テストの最後の試行で対象操作と結果を収めた MP4 を1本確定する。最終試行を選別できない場合は、制約と残った動画を報告し、各テスト1本と主張しない。

`ffmpeg` の `libx264` と `drawtext` が利用できることを確認する。既存の package manager、Playwright バージョン、プロジェクト・ブラウザ設定で録画ケースを実行する。録画を有効にした設定や helper が後続の通常実行でも録画する場合、依頼が一時的な録画なら組み込みの変更を残さない。報告する MP4 は実際に出力されたパスから確認する。変換エラーはテスト合否とは別に報告し、MP4 が欠けた場合は録画完了としない。

## 操作と変化を見せる

録画開始前に画面サイズを一定にし、必要なテストだけを実行する。録画ケースの各操作と、シナリオで確認する各画面変化について、操作の予告、操作する箇所、操作そのもの、変化した箇所を動画内で対応付ける。操作前に短い「操作 → 期待する画面変化」のステップラベルを表示し、結果が確認できるまで維持する。遷移・リロード・別タブでは新しい document やページにも装飾を設置し直し、ページ映像を切り替える区間でもステップラベルが途切れないようにする。結果が現れたら確認対象を枠で囲み、複数箇所が変化するならそれぞれを示す。対象が消える場合は消える前の位置を示し、消えた後の結果や空になった領域も示す。遷移・リロードでは移動先の画面の確認箇所も示す。枠やラベルを UI、成功判定、実際の表示内容と誤認させず、変化を覆わない位置に置く。動画の尺や待機を調整してラベル、操作、結果を読めるようにするが、実際の操作順やアサーションの意味は変えない。

### 注釈の見た目

録画処理が映像へ付加する表示（録画注釈）のうち、この節が定めるものを共通注釈と呼ぶ。共通注釈は、タイトル帯、ステップラベル、状態行、ページ・frame 識別、対象・結果の枠と見出し、カーソル、波紋、入力帯、キー表示で構成する。ページ本来の UI は録画対象の映像であり、共通注釈の配置・色の判定に含めない。時計・章・時刻索引は共通注釈に含めない。注釈はページ映像の手前に置き、タイトル帯は最前面に置く。比率は特記ない限りページ映像（タイトル帯より下の領域）の幅・高さに対する値で、解像度に依存しない。

文字は装飾なしの sans-serif（ui-sans-serif, system-ui, sans-serif）を基本とし、ページ識別だけは等幅（ui-monospace, monospace）にする。表中の文字サイズの倍率は基準文字サイズ（映像幅の約 1.2%、1280px 幅で約 15px）に対する値で、倍率を記さない要素は等倍とする。パネルは、背景 `#111A20`、角丸 10px、外側へ `0 8px 24px rgba(7,9,11,0.35)` の影を共通で使う。ステップラベルとページ識別は背景の不透明度を 0.55 に下げ、14px の背景ぼかしで覆った後ろの表示が見えるようにする。入力帯とキー表示は背景の不透明度 0.92 に 10px の背景ぼかしを付ける。

#### 要素ごとの配置と見た目

| 要素 | 配置 | 見た目 |
| --- | --- | --- |
| タイトル帯 | 映像最上部。高さは映像の高さの 15% で、ページ映像は帯の下から始まる | 背景 `#07090B` に白文字。describe 階層を含むテストタイトルを太字・1.05 倍・左寄せで表示する |
| ステップラベル | ページ映像の左上（上端から 3%、左端から 4%）。幅はページ映像の 58% まで | パネル。1 行目に「操作 → 期待する画面変化」を太字で置き、2 行目に状態行を置く |
| 状態行 | ステップラベルの 2 行目 | パネルの文字を通常の太さ・不透明度 0.88 で、「操作待ち」「操作中」「確認待ち」「結果表示」の段階を区別する |
| ページ・frame 識別 | ページ映像の右上（上端から 4%、右端から 3%）。ステップラベルと対角 | パネル。等幅・0.88 倍で `Page: <ページ名> / <frame>` の形で表示する |

| 操作・場面 | 現れる共通注釈 |
| --- | --- |
| マウス移動・クリック | 実際の軌道に沿うカーソル、クリック前の対象の枠、クリック位置の波紋。ポップアップや画面遷移の前にも移動と押下が見える |
| 文字入力・値の変更 | 入力先の枠、入力帯の連続した入力文字列、変更後のフィールドや結果領域の枠 |

| スクロール | 移動の過程が追える映像とカーソル、ホイール操作の種別（`ScrollDown` / `ScrollUp`）を示す画面中央のキー表示 |
| hover・ドラッグ | hover 先の枠、ドラッグの押下・保持移動・解放とその結果を実操作の時間軸で示す |

### 実操作と同期

マウス操作は途中の移動イベントを実時間で発生させ、カーソルが対象に着いてからクリックする。`scrollIntoViewIfNeeded()` による瞬間移動だけで画面外のクリック対象を見せたことにしない。スクロールでは、シナリオの挙動を変えずに済む場合は長い移動を小刻みな wheel 操作にし、画面外の対象へは先に滑らかに移動してから操作する。スクロールによる遅延読込などで検証対象の挙動が変わる場合は元の操作を維持し、移動をラベルと画面上の到着位置で補う。装飾は録画中の DOM オーバーレイで操作・変化と同期させる。後処理で加える表現も、元の映像と時刻が一致する場合に限る。局所拡大、静止保持、停止中のカーソルの非表示は、既にある映像と注釈の見せ方を変える範囲で読みやすさの補助として選べる。ただし、実際の移動・待機・失敗を消したり、保持を実際の表示時間と混同させたりしない。新たな表示要素を加える補助（章・時刻索引、拡大像の追加表示など）は、共通注釈に含まず、ユーザーが承認したプロジェクト固有の表示としてのみ使う。

キー表示は画面上の入力文字列と区別し、実際の操作に対応させる。フォーム送信を `Enter` で行う場合は送信前に `Enter` を表示し、クリック送信ならボタンへのカーソル移動と波紋で示す。ブラウザー側の `Ctrl+R` や `Alt+←` が Playwright のキー送出では動作しない場合は、キー表示に「操作案内」と明記してから `page.reload()` / `page.goBack()` を呼ぶ。実キー入力時のキー表示と API による代行を区別し、キーを押したと偽らない。キー入力を伴わない操作もステップラベルと対象・結果の枠で示し、視覚表現のない操作を残さない。

入力帯は画面下部中央の固定幅の暗い帯とし、入力中の文字を一つの連続した文字列として表示する。`Ctrl + A` / `Meta + A` は帯を操作名に置き換え、続く文字入力は新しい文字列として表示し、Backspace では削除後の文字列に更新する。表示対象の最後のキーによる帯の更新後のフェードと、Backspace 直後の表示遅延、帯の位置と幅の固定は「注釈の見た目」に定める。`locator.fill()` のように keydown なしで文字入力対象に `input` が起きた場合は、その対象の値を表示する。checkbox など文字入力対象でない要素の `input` は帯に値を出さず、対象の枠と状態変化で示す。文字が順に増える様子を見せたいシナリオでは、操作の意味が変わらないことを確かめて `pressSequentially()` を使う。

装飾は DOM に要素を追加する。スクリーンショット比較や全要素数を調べるアサーションには影響しうるため、その間だけ装飾を隠すなどして期待値とテストの意味を維持し、装飾なしの結果とも照合する。維持できなければ録画の制約として報告し、合否が変わらないとは主張しない。ポップアップ、複数ページ、iframe 内の操作では、装飾するページと動画の選択を調整する。ページ映像の切り替えでは URL の露出を確認し、フォーカス先の強調は `activeElement` や DOM 装飾だけで正しいと断定せず映像と照合する。画面外のアサーションやネットワーク結果を画面上の成功表示と混同しない。

## 確認と報告

録画ケースの操作と確認する画面変化を列挙し、各々について操作前から結果の確認まで途切れないラベル、対象の強調、操作の視覚表現、結果箇所の強調が最終 MP4 の連続フレームで追えるかを照合する。対応するフレームが欠けるときは録画ケースや装飾を修正して再録画し、なお見せられない操作・変化は対象と制約を報告して、視覚的に網羅できたとは主張しない。上部の無地の黒背景の帯に describe 階層を含むタイトルが読めるか、カーソルの中間位置・拡大する波紋・画面下部中央で動かない帯への連続した文字入力と帯全体のフェードが確認できるか、失敗したテストも録画されたかを確認する。ショートカット、Backspace、keydown なしの文字入力、非文字入力対象の操作を含む場合は、キー表示・文字列の更新と、非文字入力の値が帯に出ないことも確認する。短時間の表示は該当区間を高頻度でフレーム抽出して確認し、粗い間隔の抽出だけで表示がなかったと断定しない。`ffprobe` で動画の映像コーデックと再生時間を確認し、各録画ケースの最終試行の MP4 を1本ずつ再生して開始から終了まで照合する。ユーザーが動画を見て go/no-go を判断できるよう、各録画ケース・対象の主要なウェブ使用フロー・動画のパス・アサーションを含む自動テスト結果を対応付ける。通常の E2E の実行結果と録画ケースの実行結果、動画に対する人手の go/no-go 判断を区別し、映像だけでは判断できない点も報告する。

録画の組み込み・再調整では、実装の DOM オーバーレイと動画の後処理、および各最終 MP4 に現れる録画処理由来の表示を列挙し、共通注釈、既にある映像と注釈の見せ方を変えるだけの補助、ユーザーが承認したプロジェクト固有の表示のいずれかに対応付ける。全表示の対応先を示せたときに適合を報告する。対応先が定まらない表示は余剰であり、実装から取り除いて再録画するか、ユーザーの承認を得てプロジェクト固有の表示として確定してから判定する。

動画レビューまで依頼された場合は、失敗テストを先に確認し、指摘には動画パス、経過時間、見えた事実を添える。失敗と判定できない見た目は観測として区別し、動画を見ただけでテストのアサーションが成功したと結論しない。
