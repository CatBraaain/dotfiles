# skills 同期フック spec

`dotfiles/.agents/skills.exact/.pre-chezmoi.ts` の観測可能な振る舞いの仕様。対象は、Bun ランタイムでこのファイルを実行したときの、入力（`.pre-chezmoi.skills.yaml`、`.pre-chezmoi.skills.machine.yaml`、Git ミラー、環境変数）から出力（カレントディレクトリの skill ツリー、標準出力・標準エラー出力、終了コード）への変換。読者は、この spec だけを読んで要件を承認するオーナーと、実装・テストの担当者。

- このフックは pre-chezmoi.spec.md §2 のローカルフックとして、`dotfiles/.agents/skills.exact` に対応する `dist/` フォルダをカレントディレクトリにして起動される。単独で実行したときも、カレントディレクトリを出力先として同じ振る舞いをする。
- 経路表記: `~` はホームディレクトリ。hook 相対のパスはこのフックを置くディレクトリからの相対。
- ミラーは `~/mirrors/github.com/<owner>/<repo>` にある Git リポジトリの作業コピーである。

## 1. 入力

| 入力 | 値 |
| --- | --- |
| config | hook 相対の `.pre-chezmoi.skills.yaml` |
| machine レイヤー | hook 相対の `.pre-chezmoi.skills.machine.yaml`（git 管理外）。存在しなくてもよい（§2.1） |
| ミラーの配置先 | `~/mirrors/github.com/<owner>/<repo>` |
| 出力先 | カレントディレクトリ |
| 環境変数 `PRE_CHEZMOI_FORCE_PULL` | `1` のとき、TTL に関係なく pull を試みる（§3） |

## 2. config

config は `externalSkills` マッピングを持つ。キーは `<owner>/<repo>`、値はリポジトリ設定のマッピングである。

```yaml
externalSkills:
  code-yeongyu/oh-my-openagent:
    entries:
      - packages/shared-skills/skills/frontend
    run_after:
      - [node, packages/omo-codex/plugin/scripts/materialize-shared-upstreams.mjs, --strict]
  microsoft/playwright-cli:
    entries:
      - skills/playwright-cli
    edit:
      "skills/playwright-cli/SKILL.md.$append": |
        ## ローカル camoufox server への接続
```

リポジトリ設定は次のキーを持つ。

| キー | 値 | 解釈 |
| --- | --- | --- |
| `entries` | パス文字列の配列 | ミラー内で解決してコピーする skill パス（§4）。配列順を保持する |
| `run_after` | argv 配列の配列（任意） | Git の内容が変わったとき、skill コピー前にミラーで実行するコマンド（§3.2） |
| `edit` | パス操作のマッピング（任意） | コピー元の staging tree に適用するテキスト編集（§5.1） |

`entries` の要素はパス文字列だけを受け付ける。entry ごとのオブジェクト、`appendSkillMd`、`omoFrontend` は使用しない。`edit` のキーは `<ミラー内のファイルパス>.$append`、値は追記するテキストである。

config がこの形を満たさないときは §7 の文言で異常終了する。

### 2.1 machine レイヤー

hook 相対の `.pre-chezmoi.skills.machine.yaml`（git 管理外。machine 固有レイヤー。root pre-chezmoi.spec.md §8.1 の machine レイヤーと同名の規約）が存在するとき、machine レイヤーとして読む。合成の結果、フックは `externalSkills` と `localSkills` の 2 つを読み取る。

| キー | 解釈 |
| --- | --- |
| `externalSkills` | §2 と同じ形。共有の `externalSkills` へのパッチとして振る舞う |
| `localSkills` | hook 相対の glob の配列。要素はパス文字列だけを受け付け、実体は hook 相対の `local/` ディレクトリ（git 管理外）の配下に置く |

machine レイヤーの合成は、共有 config を base として、リポジトリルートの pre-chezmoi.spec.md §9（パッチ適用）に従う。操作キーの例:

```yaml
externalSkills:
  my-org/internal-skills:
    entries:
      - skills/foo
  "mattpocock/skills.entries.$append":
    - skills/another
  "mattpocock/skills.entries.$remove":
    - skills/grilling
  "DreambigOu/ELI5.$unset": true
```

- machine レイヤーに `externalSkills` がなくてもよい。そのとき `externalSkills` は共有のまま。`localSkills` がなくてもよい。そのとき localSkills は空配列。
- 合成結果の `externalSkills` に対して、§2 の検証をやり直す。
- `localSkills` の要素はパス文字列だけを受け付ける。エラー文言は§7のとおり。
- 合成に使わないキーが machine レイヤーにあっても、フックは `externalSkills` と `localSkills` だけを読む。

## 3. ミラー同期

externalSkills（§2.1 で machine レイヤーと合成した結果）の各リポジトリを独立に処理する。リポジトリ間の順序は不定で、あるリポジトリの pull の失敗が他のリポジトリのログやコピーに影響しない。同じリポジトリの `entries` は、1 回の同期と必要な `run_after` のあと配列順に処理する。

各リポジトリの同期は、ミラーの状態と前回 pull の記録に応じて次のように動く。

| ミラーの状態 | 前回 pull の記録（§3.1） | 操作 | Git 内容の変更 |
| --- | --- | --- | --- |
| なし | — | `git clone --depth 1 --quiet https://github.com/<owner>/<repo>.git` を実行してミラーを作る | 変更あり |
| あり | なし、または 6 時間以上前 | ミラー内で `git pull --ff-only --quiet` | pull 前後の HEAD が異なるときだけ変更あり |
| あり | 6 時間以内 | Git 操作をしない | 変更なし |

- `PRE_CHEZMOI_FORCE_PULL=1` のときは記録に関係なく pull を試みる。
- 6 時間の境界: 前回 pull からちょうど 6 時間が経過した時点で、pull を試みる行に変わる。
- pull が成功しても HEAD が変わらなければ、`run_after` は実行しない。
- pull が失敗したときは pull 時刻を記録せず、stderr に `warning: git pull failed for <owner>/<repo>: <gitのstderr>` を出力して、既存ミラーを使った処理を続行する。
- clone の失敗は §7 の異常終了であり、既存ミラーを使った継続はしない。

### 3.1 前回 pull の記録

前回 pull の記録は、ミラーの `.git/pre-chezmoi-pull-time` に記録時刻の UNIX 時間（ミリ秒）として書く。clone 成功時と pull 成功時に記録する。ファイルがない、内容が数値でないときは、記録なしとして扱う。

### 3.2 run_after

リポジトリ設定に `run_after` があり、§3 の同期で Git 内容に変更があったとき、skill の解決・コピー前に次の順序で処理する。

1. ミラーの作業ディレクトリを cwd として、`git clean -fdX` を実行する。Git 管理対象外で、かつ ignore されたファイルとディレクトリだけを削除する。Git 管理対象外だが ignore されていないファイルは保持する。
2. `run_after` のコマンドを配列順に実行する。各コマンドは shell を介さず、配列の先頭を実行ファイル、残りを引数として起動する。
3. すべてのコマンドが終了コード `0` なら、§4・§5 の skill 解決・コピーへ進む。

次の場合は `git clean` と `run_after` を実行しない。

- Git 内容に変更がない
- リポジトリ設定に `run_after` がない

`git clean` または `run_after` のいずれかが失敗したときは異常終了し、そのリポジトリの skill コピーを行わない。run_after の標準出力は捨て、標準エラーはエラーメッセージに含める。run_after によって生成されたファイルは、次回の同期でもミラーに残り、Git 内容に変更がなければ再ビルドせずコピーに使う。

## 4. skill の解決

`entries` または `localSkills` のパスを、基準ディレクトリ相対の glob として解釈し、その中のディレクトリへ一致させる。基準ディレクトリは、externalSkills の entry ではミラー、localSkills の entry では hook を置くディレクトリである。

| 条件 | 結果 |
| --- | --- |
| ディレクトリ 1 件に一致 | そのディレクトリをコピー元にする |
| 0 件（ファイルにのみ一致する場合を含む） | §7 で異常終了: `skill path matched nothing: <path>` |
| 2 件以上 | §7 で異常終了: `skill path matched multiple directories: <path>` |

## 5. skill のコピー

コピー元ディレクトリを、解決したディレクトリの最終パス要素を名前とする出力先へコピーする。glob の `path` では、glob 自体の `*` ではなく §4 で一致したディレクトリ名を使う。

| 項目 | 振る舞い |
| --- | --- |
| 再帰 | サブディレクトリを含めてコピーする |
| `.git` | 名前が `.git` のエントリは、どの深さでもコピーしない |
| 既存ファイル | 残す。ミラー側の内容で上書きしない（ローカル修正を優先する） |
| 既存ディレクトリ | その中へマージする |
| chezmoi 属性 prefix | `after_` `before_` `create_` `dot_` `empty_` `encrypted_` `exact_` `executable_` `external_` `literal_` `modify_` `once_` `onchange_` `private_` `readonly_` `remove_` `run_` `symlink_` のいずれかで始まる名前は `literal_<名前>` に変えてコピーする |

コピー元に存在しないファイルを出力先から削除しない。root の `pre-chezmoi.ts` は各実行時に `dist/` を削除してから再構築するため、通常経路では前回実行の stale file が残らない。

localSkills の entry を externalSkills より先に、配列順に処理する。出力先のファイルが同名のときは、既存ファイルを上書きしない規則により、localSkills の内容が優先される。

すべての処理が完了したとき、出力先の `local/` ディレクトリ（localSkills の実体の置き場所の名前）を削除する。エラーで終了するときの削除は保証しない。

### 5.1 edit

`edit` があるリポジトリの entry は、ミラーのコピー元を一時 staging tree へ複製してから編集し、その staging tree を出力先へコピーする。ミラーの実ファイルは変更しない。staging tree は entry ごとに作成し、コピー完了後に削除する。

現在サポートする操作は `$append` だけである。`<ミラー内のファイルパス>.$append` は、対応する entry の staging tree 内のファイルへ次の規則で追記する。

| 対象ファイルの状態 | 結果 |
| --- | --- |
| なし、または空 | 追記テキストで作成する |
| 末尾が改行 | そのまま末尾へ追記する |
| 末尾が改行でない | 改行 1 つを挟んでから追記する |

edit のキーは glob ではなく、ミラー内のファイルへの相対パスとして解釈する。対象ファイルがまだ存在しなくても、親ディレクトリが存在すれば `$append` で作成できる。親ディレクトリが存在しない、編集対象がどの entry にも含まれない、または staging tree の編集に失敗したときは §7 の異常終了とする。edit は Git 内容の変更有無にかかわらず、entry のコピーごとに適用する。

## 6. ログ

成功した処理は stdout に何も出力しない。stderr へは、§3 の pull 失敗 warning のみが出力され得る。git と run_after コマンド自身の進行出力も抑制される。リポジトリ間の順序は不定のため、warning が複数あるときの現れ順は実行ごとに異なり得る。

## 7. 成功と失敗

すべての entry のコピーが完了したとき、終了コード `0` で終了する。

次のいずれかが起きたとき、終了コード `0` 以外で終了する。stderr へ、先頭に `dotfiles/.agents/skills.exact/.pre-chezmoi.ts: ` を付けたエラーメッセージを 1 行出力する。エラーメッセージ内の改行は、実際の改行ではなく二文字の `\\n` に置き換える。

| 条件 | エラーメッセージ（先頭を除く） |
| --- | --- |
| config に `externalSkills` マッピングがない | `.pre-chezmoi.skills.yaml must have an externalSkills mapping: <configのパス>` |
| リポジトリの設定がマッピングでない | `externalSkills.<owner>/<repo> must be a mapping` |
| `entries` が配列でない | `externalSkills.<owner>/<repo>.entries must be an array` |
| `entries` の要素が文字列でない | `externalSkills.<owner>/<repo>.entries[<index>] must be a path string` |
| `run_after` が配列でない | `externalSkills.<owner>/<repo>.run_after must be an array` |
| `run_after` のコマンドが空、または文字列配列でない | `externalSkills.<owner>/<repo>.run_after[<index>] must be a non-empty string array` |
| `edit` がマッピングでない | `externalSkills.<owner>/<repo>.edit must be a mapping` |
| `edit` のキーが `.$append` で終わらない、または値が文字列でない | `externalSkills.<owner>/<repo>.edit[<key>] must be a .$append text edit` |
| edit 対象ファイルの親ディレクトリが解決できない | `edit path matched nothing: <path>` |
| edit 対象が entry に含まれない | `edit path is not included in entries: <path>` |
| staging tree の edit に失敗した | `edit failed for <path>: <I/O error>` |
| clone が失敗した | `git clone failed for https://github.com/<owner>/<repo>.git: <gitのstderr>` |
| pull 前後の HEAD の取得が失敗した | `git revision lookup failed for <owner>/<repo>: <gitのstderr>` |
| `git clean -fdX` が失敗した | `git clean failed for <owner>/<repo>: <gitのstderr>` |
| run_after コマンドが失敗した | `run_after failed for <owner>/<repo>: <コマンドのstderr>` |
| skill の解決が §4 の不一致・複数一致 | §4 の文言 |
| localSkills が配列でない | `localSkills must be an array` |
| localSkills の要素が文字列でない | `localSkills[<index>] must be a path string` |
| machine レイヤーの操作キー適用が root pre-chezmoi.spec.md §9 のエラーに当たる | その §9 のエラーメッセージ |
| machine レイヤーの適用後に `externalSkills` がマッピングでない | `.pre-chezmoi.skills.machine.yaml must keep an externalSkills mapping: <machineレイヤーのパス>` |
| config または machine レイヤーが YAML としてパースできない | YAML パーサーのエラーメッセージ |

エラー発生後も他のリポジトリのコピーが続行するかどうかは保証しない。出力先の rollback は行わないため、出力先は処理途中の状態になり得る。
