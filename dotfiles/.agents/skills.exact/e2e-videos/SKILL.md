# e2e-videos

## 録画の境界

対象は、ユーザーが録画を求めた Playwright Test、または Vitest から Playwright ライブラリでブラウザーを操作する E2E テスト。動画でレビューする操作と画面上の結果を基に、録画専用の E2E シナリオを作る。録画はステップを単位に分割して取得し、1 ステップを1本の動画にする。ステップの単位は `SPEC.md` の「ステップの対応と表示状態」に従う。複数ページにまたがるシナリオでもステップの区切りは変えず、ステップ内のページ切替は1本のステップ動画に収める。各シナリオに結果を検証する自動アサーションを置く。通常の E2E には録画用の設定変更・実行・動画生成を適用しない。既存のランナーを録画のためだけに移行しない。

録画は操作と画面上の結果を人がレビューするためのもの。ランナーの自動テスト結果と、ユーザーが動画を見て行う go/no-go 判断を区別する。画面上の表示からアサーションの成否を推測せず、実際に実行したランナーの結果を自動テストの合否とする。テストデータの選定はテストケースを設計する側の責務であり、この skill は入力値の検査やマスクを追加しない。

## 録画シナリオの正本

録画シナリオ（レビュー対象の操作と確認する画面変化をステップに分解した定義）の正本は、対象プロジェクトの `SPEC.md` の録画シナリオのセクション（例: 「レビュー用動画」）に置く。セクションがなければ、既存の `SPEC.md` の構成に合わせて追加する。正本には、レビュー対象のウェブ使用フロー、ステップ番号ごとの操作と確認する画面変化、録画ケース（テストファイルとテスト名）の所在を書く。

動画のパスは生成物であり正本に含めない。報告では正本のステップ番号と動画のパスを対応付ける。シナリオを変更するときは正本を先に更新し、録画ケースと動画を正本へ適合させる。

## 同梱テンプレートを使う

録画注釈とビューア・生成スクリプトの見た目・振る舞いの正本は、この skill のディレクトリ直下の `SPEC.md` である。録画の共通注釈には `assets/overlay.html`・`assets/overlay.css`・`assets/overlay.mjs` を直接使い、見本や本文から DOM・CSS・アイコンを毎回作り直さない。

Playwright Test と Vitest から Playwright を使う録画ケースは、`assets/load-overlay.mjs` の `loadRecordingOverlay(page, state)` を共通入口とする。テスト側はタイトル・ステップ・task anchor・対象矩形・表示値・観測したサイトテーマ・実イベントを渡す。矩形はすべて null でないことを確認した実測値を、注釈を受けた document の viewport 座標で渡し、frame 内の座標は録画ケース側で変換する。実操作・アサーション・時間の間隔・背景取得とテーマ判定・ページ切替・動画保存と変換は録画ケース側で行う。設置・更新時に返る配置制約を確認し、表示できない内容を省略して録画完了としない。ステップ途中で別 document へ再設置するときは、操作終了時刻を `checkAt` として渡して check の360ms フェードを最初からやり直さない。`painted()` で描画を待つ場合は環境によって完了しないことがあるため（`~/.agents/tickets/dotfiles/20261002-235342.md`）、タイムアウトを付けて待ち、完了しない場合を握りつぶさず報告する。

タイトル帯は2通りで置ける。ページ映像と同じ viewport 内に予約するか、`layer: "page"` でページ注釈だけを描画し、外タイトルを `layer: "title"` の同じ renderer で別途描いて合成するかである。`page.screencast` のフレーム取得と `ffmpeg` 変換の接続は `assets/recording-example.mjs` を接続例として使う。ステップごとの `start()` / `stop()` とフレーム収集の呼び出しは録画ケース側で行う。これは runner 所有の Page と出力先だけを受け取り、操作・アサーション・URL・セレクターを持たない。接続には `page.screencast` を備えた Playwright ビルド（動作確認済み: 1.64.0-alpha-1790635538000）と `ffmpeg` が必要である。screencast のタイムスタンプと `Date.now()` のエポックが一致しないランナーでは、例の `frameClockOffsetMs` で時刻基準を揃える。screencast の取得は可変フレームレートで、約60fps への変換は元の取得間隔と一致しないため、フェード境界の正確な時刻を合否基準にしない（`~/.agents/tickets/dotfiles/20261003-205058.md`）。

見た目の確認には、この skill のディレクトリを基点とする `assets/design.html` を開く。明暗と各表示状態を比較できる日本語ギャラリーを同梱した単一 HTML であり、`file://` でサーバーなしに閲覧できる。ギャラリーは録画・アサーションの合否を表さない。同梱 assets（`overlay.html`・`overlay.css`・`overlay.mjs`）を編集したら、`design.html` の埋め込みも同じ内容に差し替えてから `assets/overlay.test.mjs` の同一性検査を通す。

同梱テンプレートの表示も、`SPEC.md` の見た目・状態・配置・時間の規定および最終のステップ動画と照合する。テンプレートの再利用やギャラリーの閲覧だけで適合済みとは判定せず、満たせない点は制約として報告する。サイト側 JavaScript が注釈の host を除去することがあるほか、top-layer、root の transform や stacking context、非 Chromium エンジン、サイト固有のクロスオリジン frame ポリシーでは組み込み検証が要る。テンプレートは汎用の互換性を主張しない。

## 録画を組み込む

対象プロジェクトのランナー、既存の E2E helper / fixture、reporter、動画の保存先、主要なウェブ使用フローを調べ、既存の構成に合わせて録画ケースだけに録画を組み込む。ページ映像は `page.screencast` をステップの開始で `start()`、終了で `stop()` してステップごとに取得し、`ffmpeg` で無音の H.264 MP4 に変換する。1 回の録画を後から分割せず、ステップの区切りをまたぐ映像を作らない。ページ切替・別タブでは新しい page で `start()` し直し、ステップ内のページ映像をつなぐ。同梱テンプレートを組み込む際は既存の装飾と二重に表示せず、要件を満たす既存の変換処理は再利用する。

失敗したテストでも動画の保存を試み、保存・変換の失敗はテスト結果を上書きせず別に報告する。録画 context を自分で管理する場合は、ページと context を閉じて録画を確定させてから保存・変換を待つ。並列実行や再試行では出力名の衝突を避け、各テストの最後の試行で全ステップの動画を確定する。最終試行を選別できない場合は、制約と残った動画を報告し、全ステップがそろうことと主張しない。

録画を有効にした設定や helper が後続の通常実行でも録画する場合、依頼が一時的な録画なら組み込みの変更を残さない。報告するステップ動画は実際に出力されたパスから確認し、変換エラーはテスト合否とは別に報告する。ステップ動画が欠けた場合は録画完了としない。

## 録画の成果物とビューア

録画したステップ動画の保存先フォルダ名は `recordings` とする。`recordings` フォルダにはステップごとの MP4 と、`recordings/metadata.json`、生成した単一の `index.html` を置く。テスト結果の中間ファイルを `recordings` に混在させない。

`recordings/metadata.json` に録画データを書く。`title` と `steps`（`action`・`expected`・`video` の配列）を持ち、`steps` の配列順が再生順であり、正本（対象プロジェクトの SPEC.md の録画シナリオのセクション）のステップ番号と 1 対 1 に対応させる。`video` は `recordings` フォルダからの相対パスとする。

ビューアは `node assets/build-viewer.mjs <recordings フォルダのパス>` で生成し、`recordings/index.html` のパスを報告に含める。生成スクリプトとビューアの振る舞い・見た目の正本は `SPEC.md` である。

## 確認と報告

録画ケースの操作と確認する画面変化を列挙し、各々について task label から結果の確認まで途切れない注釈、対象の強調、操作の視覚表現、結果箇所の強調が最終ステップ動画の連続フレームで追えるかを照合する。各ステップが `SPEC.md` の「時間の間隔」の指定を満たすか、操作中の最低時間、操作終了時刻から check が 360ms でフェードすること、各確認箇所の最低 1 秒、前の確認枠・ラベルの消失から次の表示までの 0.2 秒を経過時間で確認する。複数結果が1組ずつ表示されること、badge の番号が全状態で維持されることも照合する。task label が anchor の上に固定され、長文が折返しで全文表示されていること、入力帯が下中央・キー表示が中央基準で dock の逆明暗になっていることも確認する。対応するフレームが欠けるときは録画ケースや装飾を修正して再録画し、なお見せられない操作・変化は対象と制約を報告して、視覚的に網羅できたとは主張しない。タイトル帯のタイトルが読めるか、カーソルの中間位置と開始時の加速・終了時の減速、実移動と同期した通過位置の残像と最後の移動から200ms 後の消失・クリック前の停止、拡大する波紋、入力帯への連続した文字入力と dock のフェードが確認できるか、失敗したテストも録画されたかを確認する。ショートカット、Backspace、keydown なしの文字入力、非文字入力対象の操作を含む場合は、キー表示・文字列の更新と、非文字入力の値が帯に出ないことも確認する。dock の背景追従と注釈の保護配置、動きを減らす設定での残像の無表示も照合する。短時間の表示は該当区間を高頻度でフレーム抽出して確認し、粗い間隔の抽出だけで表示がなかったと断定しない。`ffprobe` で各ステップ動画の映像コーデックと再生時間を確認し、ステップごとの MP4 を再生して開始から終了まで照合する。ビューアを `file://` で開き、ステップ一覧・移動・リプレイ・ステップ移動時の前の動画の停止が動くことを確認する。各録画ケース・対象の主要なウェブ使用フロー・ステップごとの動画のパス・アサーションを含む自動テスト結果を対応付けて報告し、正本（対象プロジェクトの SPEC.md の録画シナリオのセクション）のステップ番号と動画のパスを対応付けて、通常の E2E の実行結果と録画ケースの実行結果、動画に対する人手の go/no-go 判断を区別する。映像だけでは判断できない点も報告する。

録画の組み込み・再調整では、実装の DOM オーバーレイと動画の後処理、および各ステップ動画に現れる録画処理由来の表示を列挙し、共通注釈、既にある映像と注釈の見せ方を変えるだけの補助、ユーザーが承認したプロジェクト固有の表示のいずれかに対応付ける。全表示の対応先を示せたときに適合を報告する。対応先が定まらない表示は余剰であり、実装から取り除いて再録画するか、ユーザーの承認を得てプロジェクト固有の表示として確定してから判定する。

動画レビューまで依頼された場合は、失敗テストを先に確認し、指摘には動画パスとステップ番号、経過時間、見えた事実を添える。失敗と判定できない見た目は観測として区別し、動画を見ただけでテストのアサーションが成功したと結論しない。
