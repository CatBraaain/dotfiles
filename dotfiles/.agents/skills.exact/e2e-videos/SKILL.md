# e2e-videos

## 録画の境界

対象は、ユーザーが録画を求めた Playwright Test、または Vitest から Playwright ライブラリでブラウザーを操作する E2E テスト。動画でレビューする操作と画面上の結果を基に、録画専用の E2E シナリオを作る。録画はステップを単位に分割して取得し、1 ステップを1本の動画にする。ステップの単位は「ステップの対応と表示状態」に従う。複数ページにまたがるシナリオでもステップの区切りは変えず、ステップ内のページ切替は1本のステップ動画に収める。各シナリオに結果を検証する自動アサーションを置く。通常の E2E には録画用の設定変更・実行・動画生成を適用しない。既存のランナーを録画のためだけに移行しない。

録画は操作と画面上の結果を人がレビューするためのもの。ランナーの自動テスト結果と、ユーザーが動画を見て行う go/no-go 判断を区別する。画面上の表示からアサーションの成否を推測せず、実際に実行したランナーの結果を自動テストの合否とする。テストデータの選定はテストケースを設計する側の責務であり、この skill は入力値の検査やマスクを追加しない。

## 録画シナリオの正本

録画シナリオ（レビュー対象の操作と確認する画面変化をステップに分解した定義）の正本は、対象プロジェクトの `SPEC.md` の録画シナリオのセクション（例: 「レビュー用動画」）に置く。セクションがなければ、既存の `SPEC.md` の構成に合わせて追加する。正本には、レビュー対象のウェブ使用フロー、ステップ番号ごとの操作と確認する画面変化、録画ケース（テストファイルとテスト名）の所在を書く。

動画のパスは生成物であり正本に含めない。報告では正本のステップ番号と動画のパスを対応付ける。シナリオを変更するときは正本を先に更新し、録画ケースと動画を正本へ適合させる。

## 同梱テンプレートを使う

最初に、この skill のディレクトリを基点とする `assets/README.md` を読み、同梱テンプレートの設置方法・データ・制約を確認する。録画の共通注釈には `assets/overlay.html`・`assets/overlay.css`・`assets/overlay.mjs` を直接使い、見本や本文から DOM・CSS・アイコンを毎回作り直さない。

Playwright Test と Vitest から Playwright を使う録画ケースは、`assets/load-overlay.mjs` の `loadRecordingOverlay(page, state)` を共通入口とする。テスト側はタイトル・ステップ・task anchor・対象矩形・表示値・観測したサイトテーマ・実イベントを渡す。実操作・アサーション・時間の間隔・背景取得とテーマ判定・ページ切替・動画保存と変換は録画ケース側で行う。設置・更新時に返る配置制約を確認し、表示できない内容を省略して録画完了としない。

タイトル帯は2通りで置ける。ページ映像と同じ viewport 内に予約するか、`layer: "page"` でページ注釈だけを描画し、外タイトルを `layer: "title"` の同じ renderer で別途描いて合成するかである。`page.screencast` のフレーム取得と `ffmpeg` 変換の接続は `assets/recording-example.mjs` を接続例として使う。ステップごとの `start()` / `stop()` とフレーム収集の呼び出しは録画ケース側で行う。これは runner 所有の Page と出力先だけを受け取り、操作・アサーション・URL・セレクターを持たない。screencast 対応ビルドと `ffmpeg` が必要であり、要件と既知の取得精度の限界は `assets/README.md` に従う。

見た目の確認には、この skill のディレクトリを基点とする `assets/design.html` を開く。明暗と各表示状態を比較できる日本語ギャラリーを同梱した単一 HTML であり、`file://` でサーバーなしに閲覧できる。手順は `assets/README.md` に従う。ギャラリーは録画・アサーションの合否を表さない。

同梱テンプレートの表示も、以下の見た目・状態・配置・時間の規定および最終のステップ動画と照合する。テンプレートの再利用やギャラリーの閲覧だけで適合済みとは判定せず、満たせない点は制約として報告する。

## 録画を組み込む

対象プロジェクトのランナー、既存の E2E helper / fixture、reporter、動画の保存先、主要なウェブ使用フローを調べ、既存の構成に合わせて録画ケースだけに録画を組み込む。ページ映像は `page.screencast` をステップの開始で `start()`、終了で `stop()` してステップごとに取得し、`ffmpeg` で無音の H.264 MP4 に変換する。1 回の録画を後から分割せず、ステップの区切りをまたぐ映像を作らない。ページ切替・別タブでは新しい page で `start()` し直し、ステップ内のページ映像をつなぐ。同梱テンプレートを組み込む際は既存の装飾と二重に表示せず、要件を満たす既存の変換処理は再利用する。

失敗したテストでも動画の保存を試み、保存・変換の失敗はテスト結果を上書きせず別に報告する。録画 context を自分で管理する場合は、ページと context を閉じて録画を確定させてから保存・変換を待つ。並列実行や再試行では出力名の衝突を避け、各テストの最後の試行で全ステップの動画を確定する。最終試行を選別できない場合は、制約と残った動画を報告し、全ステップがそろうことと主張しない。

録画を有効にした設定や helper が後続の通常実行でも録画する場合、依頼が一時的な録画なら組み込みの変更を残さない。報告するステップ動画は実際に出力されたパスから確認し、変換エラーはテスト合否とは別に報告する。ステップ動画が欠けた場合は録画完了としない。

## 録画の成果物とビューア

録画したステップ動画の保存先フォルダ名は `recordings` とする。`recordings` フォルダにはステップごとの MP4 と、単一の `index.html` を生成する。テスト結果の中間ファイルを `recordings` に混在させない。

ビューアはサーバーなしの `file://` で開けて、相対参照でステップ動画を再生できる単一 HTML にする。ステップ一覧（番号・操作文・確認内容）、前のステップへ・次のステップへの移動、現在ステップのリプレイを持つ。ステップ移動時は前の動画を停止し、ステップはユーザーの操作でだけ開始する。ステップの自動連続再生はしない。ステップ動画は正本（SPEC.md のセクション）のステップ番号と1対1に対応させる。

## 操作と変化を見せる

録画開始前に画面サイズを一定にし、必要なテストだけを実行する。録画ケースの各操作と、シナリオで確認する各画面変化について、操作の予告、操作する箇所、操作そのもの、変化した箇所を動画内で対応付ける。各ステップでは、操作対象の上に固定した task label で現在の操作を予告し、実操作とその入力・キー表示を映し、操作終了を badge の check で示し、結果枠と結果ラベルで確認する。遷移・リロード・別タブでは新しい document やページにも装飾を設置し直し、ページ映像を切り替える区間でも task label が途切れないようにする。

結果が確認できる箇所は「時間の間隔」に従い、結果枠とそのラベルを1箇所ずつ示す。複数箇所を確認する場合はシナリオで確認する順に1箇所ずつ表示し、同時に複数の結果枠・ラベルを表示しない。ページ本来の更新は順次表示のために遅らせない。対象が消える場合は消える前の位置を示し、消えた後の結果や空になった領域も示す。遷移・リロードでは移動先の画面の確認箇所も示す。枠やラベルを UI、成功判定、実際の表示内容と誤認させず、変化を覆わない位置に置く。待機と操作の速度は「時間の間隔」の最低時間に従い、実際の操作順やアサーションの意味は変えない。

### ステップの対応と表示状態

録画専用シナリオでレビューする操作と結果を、発生順にステップ `1` から `N` まで番号付けする。ステップの単位は、動画でレビューする利用者の操作の意図 1 つに、その結果確認 1 組を対応させる。

- 利用者の目的が変わる、操作対象が変わって別の結果確認になる、結果として確認する状態が変わるときは、別のステップにする
- 画面の状態そのものを変える操作（表示モード・設定・表示切替など）は、レビュー対象の 1 つの意図として扱い、他のステップの操作中に埋め込まない。その操作と、変化後の状態の確認で 1 つのステップにする
- 1 つの目的を完成させるための補助的な操作は同じステップに含めてよい。操作対象へのフォーカスのクリックに続けて文字入力する場合がこれに当たる

操作の意味ごとに区切るのであって、都合の良い粒度で結合・分割しない。`N` は操作開始前に確定する。badge の番号と task label は同じステップを指し、操作の予告から結果の確認まで番号を維持する。ページ・frame の切替でも番号をリセットしない。空のシナリオを架空のステップで埋めず、録画対象がないことを報告する。

ステップの進行はビューアが示す。動画内の注釈は現在のステップだけを扱い、他のステップの注釈を表示しない。

| 場面 | 番号badge |
| --- | --- |
| 操作の予告から操作開始まで（操作待ち） | 数字だけ |
| 操作を行っている間（操作中） | 数字だけ（回転する装飾は付けない） |
| 操作終了から最初の結果枠を表示するまで（確認待ち） | 数字と、操作終了時刻から360msでフェードインする check |
| 結果枠とラベルを表示している間（結果表示、箇所の切替間隔も含む） | check を維持 |

操作待ち・操作中・確認待ち・結果表示は文書内の状態名とする。check は、動画で確認する結果の閲覧を開始したことだけを示し、アサーションの合格を示さない。画面上の結果が現れた後でテストが失敗しても、テスト合否を注釈から推測しない。

### 注釈の見た目

録画処理が映像へ付加する表示（録画注釈）のデザイン正本はこの節である。共通注釈は、タイトル帯、task label と番号 badge・check、対象枠・結果枠、結果ラベル、カーソルとその残像、波紋、入力帯、キー表示で構成する。全ステップ一覧、回転する spinner・リング、操作種別ごとの対象見出しは置かない。時計・章・時刻索引・追加の拡大像など、この節にない表示はユーザーの承認を得てプロジェクト固有の表示としてのみ加える。ページ本来の UI は録画対象であり、注釈の配色を適用しない。ページ・frame の識別バッジは共通注釈に含めない。

見た目は、sans-serif の本文と mono の番号・入力文字列、余裕のある内側余白、薄い中立色の外周で階層を作る。緑は check だけに用い、操作の種別で色分けしない。背景のぼかし、装飾グラデーション、文字の影、グローは付けない。

#### 寸法・文字・共通面

`W`・`H` はタイトル帯を除くページ映像の幅・高さ、`s = max(1, W / 1280)` は寸法倍率。以下の px 値を `s` 倍し、最終映像上の寸法とする。1280px 未満でも文字・余白を縮めない。映像・ページ領域の寸法は録画全期間で固定し、注釈を収めるためにサイトを縮小・リサイズ・切り抜きしない。

幅・高さはすべて外寸。外周線は内側に含める。本文の幅を求めるときは、左右の線・padding・badge・gap を外寸から差し引く。`M(text, role)` は下表の書体・サイズ・weight で描いた文字列の実幅。日本語を含む全文の実幅で計算し、半角の文字数だけで幅を決めない。定常表示中の全テキストの不透明度は1。ラベルとカードは、表示時に150msで opacity 0 から1、非表示時に300msで opacity 1 から0へ遷移し、通常は `prefers-reduced-motion: reduce` でも同時間の opacity のみで遷移する。テーマ・配置・入力途中の更新では遷移を再開始しない。省略記号、行数上限による切り落とし、横スクロール、文字サイズの縮小で収めない。空白で折り返し、空白のない URL・期待値・長語は収まる最後の文字境界で折り返す。数値の桁・符号・小数点・通貨記号・単位を削除・置換しない。

| 用途 | 書体 | size / line-height | weight / 字間 |
| --- | --- | --- | --- |
| 基本文字 | sans-serif | 15px / 24px | 400 / 0 |
| テストタイトル | sans-serif | 16px / 24px | 600 / 0 |
| task label 本文 | sans-serif | 17px / 26px | 600 / 0 |
| 結果ラベル本文 | sans-serif | 14px / 20px | 600 / 0 |
| 入力帯の文字列 | mono | 21px / 30px | 400 / 0 |
| キー表示のキー名 | sans-serif | 21px / 30px | 600 / 0 |
| 操作案内 | sans-serif | 14px / 20px | 400 / 0 |

sans-serif の書体は `ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", "Noto Sans CJK JP", sans-serif`、mono は `ui-monospace, SFMono-Regular, Menlo, Consolas, "Liberation Mono", "Noto Sans Mono CJK JP", monospace`。番号の桁は等幅にし、本文中の数値・期待値は本文と同じ書体で保つ。

| `key-sheen` | `rgba(247,248,252,0.18)` | `rgba(23,25,34,0.12)` | キー表示の内側下の面 |

`surface`・`caption-surface`・dock の各面は背景色だけを下に見えている映像色と合成し、定常表示中の要素全体・文字・子要素は透明化しない。各 RGB 成分について `C = α × 色トークンの RGB + (1 - α) × 背景の RGB` で合成する。タイトル帯、チップ面、check の面と ring、文字、eye、dock は不透明。最も明るい背景と最も暗い背景への合成の両方で、`text`・`secondary`・`dock-text` の文字用途は4.5:1以上、チップ数字・`on-active`・`done` はそれぞれの面に対して4.5:1以上のコントラストを保つ。

対象を透かす `frame-fill` には注釈の文字を置かない。枠は `frame-stroke` の線の内側に1px の `frame-inner-guard`、外側に1px の `frame-outer-guard` を添え、合成後も背景の明度によらず少なくとも一方の対比線が3:1以上で見える。波紋は `accent` の線と不透明色の `ripple-inner-guard`・`ripple-outer-guard` でクリック位置を示し、消失中の不透明度は動きの指定に従う。確認するページ文字には枠内の塗りを重ねても判読性を維持し、変化の細部を隠さない。

#### タイトル帯

タイトル帯は `label-height`（基準64px）を基準に、映像の最上部・幅 `W`・上下16px・左右24px の padding、`title-surface` 面。`text` 色で左に describe 階層を含むテストタイトルを置き、進行表示は置かない。外タイトル合成ではこの帯だけを `W × 64`（長いタイトルは事前に確定した最大高さ）で別レイヤーに描き、ページ映像の上に連結する。

タイトル領域幅は `W - 48s - 24s` で、この幅で全文を折り返す。帯の高さは `max(64s, 32s + 内容の高さ)`。折返しを含めた最大の内容高さを操作前に確定し、全期間で固定する。1280×720px の映像で帯が64px ならページ領域は1280×656px。長いタイトルのため帯を高くする場合もページ映像を遮らず、その分の帯領域を確保する。

#### task label・番号 badge・check

task label は現在ステップの操作文を示す1枚の面で、操作対象・確認対象とは独立に測った anchor の上に置く。幅は anchor の幅に追従し、高さは `max(48s, 22s + 26s × 行数)`。本文はステップの操作文（動詞で始まる `action`）を全文で折り返し、長文で高さを増やす。左に番号 badge（`badge` 44px 四方の領域に `chip` 32px の数字面、`active-fill` 面・`on-active` 数字）、badge と本文の間は `task-gap`。面は `surface`、`surface-line` 外周と `shadow`、角丸 `label-radius`、左右の padding 12px。

anchor の既定は操作対象の矩形。操作対象より意味のある広さ（行・入力欄を含むコンテナなど）を anchor にするとき、録画ケースが実 DOM で採寸して `taskAnchor` として渡す。anchor のない操作ではページ領域の安全余白の上端を代替の anchor とし、その幅いっぱいに label を置く。label の下端は anchor の上端から `task-gap` 離し、横位置は anchor の左端に揃えて安全余白内に収まるよう補正する。上に置けないときだけ anchor の下端 + `task-gap` に置き直し、どちらも収まらないときは録画の制約として報告する。自動で別の場所へ動かさない。

label の位置は同一画面内では固定し、対象や注釈の変化で動かさない。スクロール・遷移・frame 切替で基準画面が変わるときだけ、録画ケースが実測 anchor を再び渡して置き直す。別 document への再設置では、check の出現時刻と dock の出現時刻もケース側で新しい時計に変換して渡す。

番号 badge は非回転とし、回転する spinner・リングを付けない。check は badge 領域の右下、`check` 16px 四方の円（`done` 面、外側2px の `surface` ring、中央に11px 四方の SVG パス `m2 6 2.5 2.5L10 3`）。操作終了時刻から360ms で opacity 0 から1へフェードインし（cubic-bezier(0, 0, 0.58, 1) 相当）、以降はステップ動画の終わりまで維持する。動きを減らす設定でも同時間の opacity のみでフェードする。check の出現はアサーションの合格を示さない。

#### 対象・結果の枠と結果ラベル

枠は強調する要素の実際の位置・大きさに追従し、その外側2px に `frame-stroke` 色・`frame-line` 幅の実線を置く。角丸は `min(frame-radius, 枠幅 / 2, 枠高さ / 2)`。線の内側の対比線は `frame-inner-guard`、外側は `frame-outer-guard`、内側の塗りは `frame-fill`。映像の境界を越える線だけ境界で切り、対象の見える部分をずらさない。操作対象の枠は操作待ちから確認待ちまで表示し、結果表示の間は結果枠に置き換える。対象が消える場合は消える前の位置と、消えた後の結果や空の領域を示す。操作種別の見出し・アイコン・短語は枠に付けず、操作の意味は task label と dock が担う。

結果ラベルは、結果枠の左端から8px、枠の上辺より8px 上に下端を置く。`caption-surface` 面、不透明な `on-active` の文字と eye（20px 四方・2px 線の単色 SVG）、角丸 `caption-radius`、上下8px・左右12px の padding。本文は `<対象名> === <期待する状態・値>` だけを表示する。`===` は期待値を示す表示上の区切りであり、JavaScript の比較の実行やアサーションの合格を示さない。番号を付けない。全文を折り返し、長い数値・値を切らない。上に置けない、または task label と重なる場合は結果枠の下端 + 8px に置き直し、どちらも収まらないときは制約として報告する。

複数箇所を確認するステップでは、結果枠とラベルを1組ずつ順番に表示する。前の組を消してから次の組を出すまでの間、結果枠・ラベルは表示しない。切替の間隔は「時間の間隔」に従う。

#### カーソル・波紋・入力帯・キー表示

| 要素 | 寸法・面・文字 | 位置 |
| --- | --- | --- |
| カーソル | 標準ポインター形状の矢印、16×24px。`cursor-fill` 面、`edge-guard` の1.5px 縁。先端が操作座標 | 実際の操作の軌道に沿う |
| カーソルの残像 | カーソルと同じ形状・寸法・色トークンの半透明な複製。通過時の opacity 0.25から200ms で等速に0へ消す | 実マウスの通過座標に、通過時刻と同期して残す。複製はその位置から動かさない |
| 波紋 | 直径12px から48px へ450ms 等速で拡大し、opacity 0.75から0へ。`accent` の2px 円、内側1px の `ripple-inner-guard`、外側1px の `ripple-outer-guard`、面なし | 実際のクリック位置が中心 |
| 入力帯 | 外幅 `input-width` 基準（全文が収まらないときは内容に合わせて広げ、`W - 2edge` を上限とする）、上下12px・左右20px padding、`dock` 系トークン、角丸は高さの半分。高さ `max(input-height, 26s + 30s × 行数)` | 常にページ映像の下中央、下端から `edge` |
| キー表示 | 外幅 `key-width` 基準（長いキー名で広げる）、上下12px・左右20px padding、`dock` 系トークン、角丸 `caption-radius`、内側下に `key-sheen` の4px 面。高さ `max(input-height, 26s + 30s × 行数) + (操作案内 ? 28s : 0)` | ページ映像の中央を基準に候補順（中央、下中央、上中央、左端中央、右端中央） |

入力帯とキー表示は同じ dock のトークンを持ち、サイトと逆の明暗で描く。入力帯はページ下中央に固定し、他へ動かさない。キー表示は画面中央を基準に置き、保護対象・配置済みの注釈に重なる場合だけ候補順の次の位置へ置く。下中央で入力帯と重なるときは位置分離で解消し、片方だけに制限しない。入力帯は `dock-text` の連続した文字列を中央寄せで折り返し、更新で幅と下端位置を動かさず、高さだけ上方へ増やす。空文字列では空の1行を残し、削除結果を見せる。

キー名は `dock-text`、文字入力以外の実際のキー名（`Tab`、矢印、`Enter`、`Backspace`、`Ctrl+R`、`Alt+←`、プラットフォームに応じた `Meta` 系など）とホイール操作の `ScrollDown` / `ScrollUp` を表示する。API で代行した操作だけ `dock-secondary` の「操作案内」を8px 下に添える。動きを減らす設定ではカーソルの残像を表示せず、実操作に同期するカーソルと移動・停止の時間は維持する。入力帯・キー表示のフェードは維持し、波紋は直径24px のまま450ms で消す。

#### 折返し・衝突・収まり

操作対象・確認対象の可視矩形を各方向に `protect-gap` 広げた領域を保護する。枠の薄い塗り・追従するカーソルとその残像・クリックの波紋を除き、注釈の文字・面・外周線をこの領域へ重ねない。ページ本来の要素を移動・隠蔽しない。注釈同士の文字面にも `gap` を取る。重なり順はページ映像、枠と波紋・残像、task label・dock、結果ラベル、カーソル、タイトル帯の順とする。残像は注釈の文字面に重なる部分を描かず、ページの確認内容の判読性を維持する。

配置は次の順で確定する。task label を anchor の上（不成立は下）に置く。結果ラベルを結果枠の上（不成立は task label との重なりと収まりを見て下）に置く。入力帯を下中央に置く。キー表示を候補順に置く。いずれも安全余白 `edge` 内に収まり、保護領域と配置済みの文字面に重ならないことを条件とする。テーマだけの変更では位置・幅・高さを変えない。

折返し後の面全体が `W - 2edge`・`H - 2edge` に収まることを必要条件とする。現在の task label の全文を常に保ち、結果ラベルは表示中の1箇所の全文を保つ。どの候補も成立しない場合は、全件表示と確認箇所の視認を両立できない対象・ステップ数・値・映像寸法を録画の制約として報告する。隠す・省略する・小さくする・勝手に別の注釈を増やすことで適合したことにしない。背景追従や配置の都合でサイトの遷移・状態更新を遅延させたり、実操作と違う時間軸にしたりしない。

### 背景とサイトテーマの追従

サイトの main 背景は、現在映しているページの主要コンテンツ面の背景であり、OS の設定・テーマ名・操作中の要素の色ではない。主要領域はサイトが main ランドマークとして示す領域とする。可視の main ランドマークが複数あれば、映像内の可視面積が最大の領域を使い、同面積なら上端が小さいもの、次に左端が小さいものを選ぶ。main ランドマークがなければページ映像全体を使い、見た目から別の領域を任意に選ばない。iframe 内を操作していてもページ全体を映す間はページの主要領域を使い、frame だけを映す場面ではその映像の主要領域を使う。

選んだ領域の映像内にある部分の最小外接矩形を横5・縦5に等分し、各セルの中心25点で背景色を観測する。対象は文字・ボタン・カード・注釈などの前景を重ねる前の主要面の色。透明な主要面は祖先の背景・画像・グラデーションを奥から合成し、最後はページのキャンバス色へ合成する。ページのキャンバスも透明ならブラウザーの白いキャンバスへ合成する。各背景色は sRGB に揃え、成分を0から1の範囲へ収める。透明度αの各層を奥から `C = α × 手前のRGB + (1 - α) × 奥のRGB` で合成する。背景画像・グラデーションは各点の実色を使う。可視領域の外の点は除外し、有効点が13点未満ならページ映像全体の25点で同じ観測を行う。前景の占有率、注釈自身の色、マウス位置で分類を変えない。

各点の合成後の sRGB 成分を0から1へ正規化する。成分 `c <= 0.04045` は `c / 12.92`、それ以外は `((c + 0.055) / 1.055)^2.4` に変換し、輝度 `Y = 0.2126R + 0.7152G + 0.0722B` を得る。有効点の `Y` の中央値を main 背景の輝度とする。偶数点なら中央2点の平均を使う。

| 観測時点・条件 | サイトの分類と `theme` |
| --- | --- |
| 最初の主要面、または遷移・リロード・別タブ・映像のページ切替後の新しい主要面で `Y <= 0.179` | dark サイト（`theme: "dark"`） |
| 同じ初回条件で `Y > 0.179` | light サイト（`theme: "light"`） |
| 同一ページで light サイトを使い、`Y >= 0.21` が100ms 以上続く | light サイトへ変わったと分類し、`theme: "light"` へ切替 |
| 同一ページで dark サイトを使い、`Y <= 0.15` が100ms 以上続く | dark サイトへ変わったと分類し、`theme: "dark"` へ切替 |
| 同一ページで上の切替条件を満たさない | 現在の分類を維持 |

最初の注釈を出す前に初回分類する。以後、背景の観測間隔は50ms 以下とし、同一ページの切替は100ms 以上離れた2回の観測で同じ条件を満たして確定する。背景が条件を満たし続けた最初の映像時点から250ms 以内に全注釈を切り替える。main 背景のテーマ切替、画像やグラデーションの変化、主要領域の交替を含み、ステップの終わりを待たない。100ms 未満の一時的な明滅では切り替えない。

遷移等で旧主要面が消え、新主要面がまだない区間は旧テーマと task label を維持する。main ランドマークもサイト本来の可視内容もない白紙を、主要面がまだない区間とする。新主要面が映ったら初回閾値で再分類し、その最初の映像時点から100ms 以内に全注釈へ適用する。主要面がない白紙のまま250ms 続く場合はページ全体を主要面として再分類する。主要面の新設・交替は、同一ページなら継続観測の切替条件、ページ切替なら初回条件を使う。

切替は同じ映像フレームでタイトル帯・task label・badge・check・枠・結果ラベル・カーソル・残像・波紋・入力帯・キー表示の全トークンへ適用する。dock は常にサイトと逆の明暗へ揃う。新旧テーマを混ぜず、クロスフェードしない。表示中の入力や波紋・残像も追従し、番号・操作文・状態・値・位置・操作の時間や残像の通過時刻をリセットしない。追従できない区間は制約として報告し、ステップ中固定のテーマで代用しない。

### dock と check の表示時間

入力帯とキー表示は、最初の出現時刻 `firstAt` と最終更新時刻 `at` から、出現200ms・保持1200ms・消失250msの時間式で表示する。保持の起算は `max(firstAt + 200, at)` であり、連続する文字入力で出現フェードを毎文字再開始せず、保持だけを最終更新まで延ばす。消失の開始時刻から250ms後に値を除き、次の値で出現からやり直す。Backspace 直後の文字入力では、削除結果が見えるまで最大160ms 表示を遅らせる。キー表示は操作の間維持し、最後の更新から同じ時間式で消す。操作と同期する内容は「実操作と同期」に従う。動きを減らす設定では、同じ時間式で opacity のみを遷移させる。

### 操作・場面ごとの共通注釈

| 操作・場面 | 現れる共通注釈 |
| --- | --- |
| マウス移動・クリック | 実際の軌道に沿うカーソルと通過位置の残像、操作待ちの間の対象枠、クリック位置の波紋。ポップアップや画面遷移の前にも移動と押下が見える |
| 文字入力・値の変更 | 入力先の枠、task label、入力帯の連続した入力文字列、変更後のフィールドや結果領域の結果枠とラベル |
| キー操作・ショートカット | 対象の枠、実際のキー名のキー表示、移動後のフォーカス先や変化した領域の結果枠とラベル |
| スクロール | 移動の過程が追える映像とカーソル、ホイール操作の種別（`ScrollDown` / `ScrollUp`）を示す画面中央のキー表示 |
| hover・ドラッグ | hover 先の枠、ドラッグの押下・保持移動・解放とその結果を実操作の時間軸で示す |
| クリックを伴わない状態変化 | 変化した領域（ローディング、通知、値・一覧の更新など）の結果枠とラベル、task label の番号と check |
| popup・別タブ・iframe | 開く操作の共通注釈と、移動先のページ・frame に再設置した注釈 |

### 時間の間隔

ステップ動画の長さは注釈の最低表示時間だけで決める。視聴者はビューアで自分のタイミングでステップを見るため、視聴時間を録画内の固定待機で担保しない。時間は注釈の動きではなく動画の経過時間で測る。

- 操作待ち: 対象の可視化・操作可能性など操作前の準備を終え、task label・操作対象の注釈がすべて実際に映った時点から操作を始めてよい。準備や描画待ちの自然な待機は短縮・省略しない
- 操作中: カーソル移動は 1 回を最低 400ms かけ、クリックの前にカーソルを対象の上へ最低 250ms 止めてからクリックする。文字入力は 1 文字ごとに 120ms 以上空ける。`fill()` など keydown なしで瞬時に完了する代行操作は、入力帯の文字列と対象の枠を最低 600ms 表示してから結果の確認へ移る
- 操作終了: 操作終了の時刻が badge の check のフェード開始時刻になる。結果枠とラベルは、確認対象の出現と描画の安定を待って表示する。待機中にページ本来の状態更新を遅らせない
- 結果表示: 各確認箇所の枠・ラベル・確認する内容が実際に映った時点から最低 1 秒維持する。前の確認枠とラベルを消してから次の確認枠とラベルを出すまで 0.2 秒空ける。最後の確認箇所の表示時間を終えたら録画を確定させる

遷移・リロード・別タブを挟むステップでは、移動先の描画が落ち着いてから結果の確認へ移り、各確認箇所の表示時間を改めて満たす。視聴者が読む時間はビューアのリプレイと一時停止で担保されるため、これ以上の待機を録画に埋め込まない。

### 実操作と同期

カーソル移動は `ease-in-out`（`cubic-bezier(0.42, 0, 0.58, 1)`）で開始時に加速し、終了時に減速する。実マウス座標とカーソル先端を同じ進捗・時刻に揃え、途中の移動イベントを実時間で発生させる。残像は同じ座標・時刻の移動履歴を示し、別の軌道や遅れて動く実カーソルで代用しない。カーソルが対象に着いた後の停止と残像の消失は「時間の間隔」に従ってからクリックする。`scrollIntoViewIfNeeded()` による瞬間移動だけで画面外のクリック対象を見せたことにしない。スクロールでは、シナリオの挙動を変えずに済む場合は長い移動を小刻みな wheel 操作にし、画面外の対象へは先に滑らかに移動してから操作する。スクロールによる遅延読込などで検証対象の挙動が変わる場合は元の操作を維持し、移動を task label と画面上の到着位置で補う。装飾は録画中の DOM オーバーレイで操作・変化と同期させる。後処理で加える表現も、元の映像と時刻が一致する場合に限る。局所拡大、静止保持、停止中のカーソルの非表示は、既にある映像と注釈の見せ方を変える範囲で読みやすさの補助として選べる。ただし、実際の移動・待機・失敗を消したり、保持を実際の表示時間と混同させたりしない。

キー表示は画面上の入力文字列と区別し、実際の操作に対応させる。フォーム送信を `Enter` で行う場合は送信前に `Enter` を表示し、クリック送信ならボタンへのカーソル移動と波紋で示す。ブラウザー側の `Ctrl+R` や `Alt+←` が Playwright のキー送出では動作しない場合は、キー表示に「操作案内」を明記してから `page.reload()` / `page.goBack()` を呼ぶ。実キー入力時のキー表示と API による代行を区別し、キーを押したと偽らない。キー入力を伴わない操作も task label と対象・結果の枠で示し、視覚表現のない操作を残さない。

入力中の文字は一つの連続した文字列として表示する。`Ctrl + A` / `Meta + A` は帯を操作名に置き換え、続く文字入力は新しい文字列として表示し、Backspace では削除後の文字列に更新する。`locator.fill()` のように keydown なしで文字入力対象に `input` が起きた場合は、その対象の値を表示する。checkbox など文字入力対象でない要素の `input` は帯に値を出さず、対象の枠と状態変化で示す。文字が順に増える様子で入力を示すため、録画ケースの文字入力は操作の意味が変わらない限り `pressSequentially()` で 1 文字ずつ行い、`fill()` などの一括設定で映す箇所を作らない。長い値などで 1 文字ずつが現実的でない場合だけ一括設定を使い、その箇所と理由を報告する。

装飾は DOM に要素を追加する。スクリーンショット比較や全要素数を調べるアサーションには影響しうるため、その間だけ装飾を隠すなどして期待値とテストの意味を維持し、装飾なしの結果とも照合する。維持できなければ録画の制約として報告し、合否が変わらないとは主張しない。ポップアップ、複数ページ、iframe 内の操作では、装飾するページと動画の選択を調整する。ページ映像の切り替えでは URL の露出を確認し、フォーカス先の強調は `activeElement` や DOM 装飾だけで正しいと断定せず映像と照合する。画面外のアサーションやネットワーク結果を画面上の成功表示と混同しない。

## 確認と報告

録画ケースの操作と確認する画面変化を列挙し、各々について task label から結果の確認まで途切れない注釈、対象の強調、操作の視覚表現、結果箇所の強調が最終ステップ動画の連続フレームで追えるかを照合する。各ステップが「時間の間隔」の指定を満たすか、操作中の最低時間、操作終了時刻から check が 360ms でフェードすること、各確認箇所の最低 1 秒、前の確認枠・ラベルの消失から次の表示までの 0.2 秒を経過時間で確認する。複数結果が1組ずつ表示されること、badge の番号が全状態で維持されることも照合する。task label が anchor の上に固定され、長文が折返しで全文表示されていること、入力帯が下中央・キー表示が中央基準で dock の逆明暗になっていることも確認する。対応するフレームが欠けるときは録画ケースや装飾を修正して再録画し、なお見せられない操作・変化は対象と制約を報告して、視覚的に網羅できたとは主張しない。タイトル帯のタイトルが読めるか、カーソルの中間位置と開始時の加速・終了時の減速、実移動と同期した通過位置の残像と最後の移動から200ms 後の消失・クリック前の停止、拡大する波紋、入力帯への連続した文字入力と dock のフェードが確認できるか、失敗したテストも録画されたかを確認する。ショートカット、Backspace、keydown なしの文字入力、非文字入力対象の操作を含む場合は、キー表示・文字列の更新と、非文字入力の値が帯に出ないことも確認する。dock の背景追従と注釈の保護配置、動きを減らす設定での残像の無表示も照合する。短時間の表示は該当区間を高頻度でフレーム抽出して確認し、粗い間隔の抽出だけで表示がなかったと断定しない。`ffprobe` で各ステップ動画の映像コーデックと再生時間を確認し、ステップごとの MP4 を再生して開始から終了まで照合する。ビューアを `file://` で開き、ステップ一覧・移動・リプレイ・ステップ移動時の前の動画の停止が動くことを確認する。各録画ケース・対象の主要なウェブ使用フロー・ステップごとの動画のパス・アサーションを含む自動テスト結果を対応付けて報告し、正本（SPEC.md のセクション）のステップ番号と動画のパスを対応付けて、通常の E2E の実行結果と録画ケースの実行結果、動画に対する人手の go/no-go 判断を区別する。映像だけでは判断できない点も報告する。

録画の組み込み・再調整では、実装の DOM オーバーレイと動画の後処理、および各ステップ動画に現れる録画処理由来の表示を列挙し、共通注釈、既にある映像と注釈の見せ方を変えるだけの補助、ユーザーが承認したプロジェクト固有の表示のいずれかに対応付ける。全表示の対応先を示せたときに適合を報告する。対応先が定まらない表示は余剰であり、実装から取り除いて再録画するか、ユーザーの承認を得てプロジェクト固有の表示として確定してから判定する。

動画レビューまで依頼された場合は、失敗テストを先に確認し、指摘には動画パスとステップ番号、経過時間、見えた事実を添える。失敗と判定できない見た目は観測として区別し、動画を見ただけでテストのアサーションが成功したと結論しない。
