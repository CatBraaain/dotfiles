# playwright-e2e

E2Eテストで、保守に必要な振る舞いをカバーする。同じテスト実行で撮影した画像を
`e2e-gallery.html` にまとめ、ユーザーが画面上の結果を一括で確認できるようにする。

## SPEC との対応

テスト・撮影・目視確認の内容は、対象プロジェクトの SPEC に従う。
SPEC を作成・修正するときは specs を使う。

テストとギャラリーから、対応する SPEC の節・項目を参照できるようにする。
ギャラリー用に別のシナリオ定義を管理せず、同じテストの操作と確認内容を使う。

## テストの書き方

- 操作と確認の単位を `test.step()` にする。step名は操作文で、1 step を意図1つと
  確認1組に対応させる
- 主要な locator に `.describe("名前")` を付ける
- アサーションは通常の `expect()` で書く

## 撮影とギャラリー生成

- 撮影は通常の E2Eテストの `test.step()` に含める。
  撮影専用の別テストへ同じ操作を重複して実装しない
- 画像はテストケース・step・実行環境を識別できる形で保存する。
  並列実行やリトライでも互いの画像を上書きしない配置にする
- 実際のテスト結果と保存画像から `e2e-gallery.html` を生成する。
  既存の撮影・生成処理があれば、それを使う
- ギャラリーでは、SPEC の確認内容と、対応するテスト結果・スクリーンショットを
  一覧表示する。画像は原寸でも確認できるようにする
- 一覧は今回の実行結果を使い、失敗・未実行・画像なしを区別する。
  過去の画像を今回の撮影結果として表示しない

スクリーンショットは目視確認の材料であり、保存できただけで見た目が正しいとは判定しない。
自動テストの合否はランナーの実行結果、見た目の判断はユーザーの確認結果として分ける。

## ギャラリーの閲覧

ギャラリー閲覧用の npm script は `review` とし、`e2e-gallery.html` と画像を
静的サーバーで配信する。既存の静的サーバーを優先して使い、画像への参照は
配信先から解決できる相対パスにする。

`review` はギャラリーの閲覧入口とし、Playwright の `show-report` とは分ける。
エージェントはサーバーのブラウザー自動オープンを抑止し、ギャラリーの URL をユーザーに伝える。

## HTML report の閲覧

既存の HTML report を `show-report` でサーブする場合、エージェントは
`CLAUDECODE=1` を前置きして自動オープンを抑止し、出力の URL をユーザーに伝える
(例: `CLAUDECODE=1 playwright show-report --port 0`)。

`--port 0` により、9323 が使用中なら空きポートを使う。既存設定で report の出力先を
変更している場合は、`show-report` の引数にそのフォルダを渡す。Ctrl+C でサーバーを
終了する。

前置きは Claude Code 限定ではなく、Playwright が coding agent 環境の検出に使う変数
(`CLAUDECODE` / `COPILOT_CLI`) の設定である。既存の script経由で実行する場合も、
前置きはエージェントの呼び出し時に付け、scripts には組み込まない。ユーザーの
手動実行ではブラウザーが開く方がよいためである。
