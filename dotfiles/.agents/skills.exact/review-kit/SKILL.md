# review-kit

録画専用ケースとステップ動画・ビューアを生成し、ユーザーがレビューするための材料を用意する。生成物の品質検証と自動アサーションの確認はこの skill の責務であり、材料を見て行う go/no-go 判断はユーザーの責務である。

## 録画の境界

対象は、ユーザーが録画を求めた Playwright Test、または Vitest から Playwright ライブラリでブラウザーを操作する E2E テスト。動画でレビューする操作と画面上の結果を基に、録画専用の E2E シナリオを作る。通常の E2E には録画用の設定変更・実行・動画生成を適用しない。既存のランナーを録画のためだけに移行しない。

レビューする操作と結果を発生順に `1` から `N` まで番号付けし、操作開始前に `N` を確定する。1 ステップは利用者の操作の意図 1 つと結果確認 1 組であり、1本の動画にする。

- 目的が変わる、操作対象が変わって別の結果確認になる、確認する状態が変わる場合は別ステップにする
- 表示モード・設定・表示切替など画面の状態を変える操作は独立した意図として扱い、他の操作中に埋め込まない
- 目的を完成させる補助操作（入力前のフォーカスクリックなど）は同じステップに含めてよい

操作の意味に従って区切り、都合のよい粒度で結合・分割しない。複数ページ・frame にまたがっても区切りや番号を変えず、ステップ内のページ切替は1本の動画に収める。動画内は現在ステップだけを示し、進行はビューアが示す。空のシナリオは架空のステップで埋めず、録画対象がないと報告する。各シナリオに結果を検証する自動アサーションを置く。

録画は操作と画面上の結果を人がレビューするためのもの。ランナーの自動テスト結果と、ユーザーが動画を見て行う go/no-go 判断を区別する。画面上の表示からアサーションの成否を推測せず、実際に実行したランナーの結果を自動テストの合否とする。テストデータの選定はテストケースを設計する側の責務であり、この skill は入力値の検査やマスクを追加しない。

## 録画シナリオの正本

録画シナリオ（レビュー対象の操作と確認する画面変化をステップに分解した定義）の正本は、対象プロジェクトの `SPEC.md` の録画シナリオのセクション（例: 「レビュー用動画」）に置く。セクションがなければ、既存の `SPEC.md` の構成に合わせて追加する。正本には、レビュー対象のウェブ使用フロー、ステップ番号ごとの操作と確認する画面変化、録画ケース（テストファイルとテスト名）の所在を書く。

動画のパスは生成物であり正本に含めない。報告では正本のステップ番号と動画のパスを対応付ける。シナリオを変更するときは正本を先に更新し、録画ケースと動画を正本へ適合させる。

## 実行入口

対象プロジェクトの `package.json` に、録画ケースの実行とビューア生成をまとめた npm script を用意する。新規の入口名は `review-kit` とし、既存の入口があれば名前を保ち、不足する処理を追加するか既存コマンドを組み合わせて両方を実行できるようにする。対象プロジェクトのパッケージマネージャーでこの入口を実行し（新規入口の例: `bun run review-kit`）、初回生成と再生成で同じ入口を使う。

実際の実行コマンドを、対象プロジェクトの `SPEC.md` の録画シナリオのセクションに記録する。実行後はランナーのアサーション結果と生成物の品質を「確認と報告」に従って検証し、録画・動画保存・ビューア生成の成否を区別して報告する。

## 同梱テンプレートを使う

録画の入力・手順・利用側の責務はこの文書で扱う。同梱 assets のパスは、この skill のディレクトリを基点とする。録画の共通注釈には `assets/overlay.html`・`assets/overlay.css`・`assets/overlay.mjs` を直接使い、見本や本文から DOM・CSS・アイコンを毎回作り直さない。

Playwright Test と Vitest から Playwright を使う録画ケースは、`assets/load-overlay.mjs` の `loadRecordingOverlay(page, state)` を共通入口とする。テスト側はタイトル・ステップ・task anchor・対象矩形・表示値・観測したサイトテーマ・実イベントを渡す。矩形はすべて null でないことを確認した実測値を、注釈を受けた document の viewport 座標で渡し、frame 内の座標は録画ケース側で変換する。実操作・アサーション・時間の間隔・背景取得とテーマ判定・ページ切替・動画生成と保存は録画ケース側で行う。設置・更新時に返る配置制約を確認し、表示できない内容を省略して録画完了としない。ステップ途中で別 document へ再設置するときは、操作終了時刻を `checkAt` として渡して check の360ms フェードを最初からやり直さない。`painted()` で描画を待つ場合は環境によって完了しないことがあるため（`~/.agents/tickets/dotfiles/20261002-235342.md`）、タイムアウトを付けて待ち、完了しない場合を握りつぶさず報告する。

`await loadRecordingOverlay(page, state)` に渡す状態は次の形状とする。`update(patch)` は渡したトップレベル項目を更新し、不要になった `target`・`result`・`input`・`key` は `null` で消す。

| 入力 | 内容 |
| --- | --- |
| `title`・`steps` | タイトル文字列と、各要素に文字列の `name`・`action`・`expected` を持つ非空配列。`action` は動詞で始まる操作文 |
| `current`・`phase` | 1 始まりのステップ番号と、`waiting`（操作待ち）・`acting`（操作中）・`checking`（操作終了後の確認待ち）・`result`（結果表示）。badge は前2状態で数字だけ、後2状態で check を維持する。check は結果閲覧の開始を示し、合格ではない |
| `theme`・`layer` | 観測したサイトの `light` / `dark`。`layer` は既定の `both`、ページ注釈だけの `page`、タイトル帯だけの `title` |
| `pageArea`・`titleArea` | 事前に予約したページ映像領域・タイトル帯領域の矩形 |
| `target`・`taskAnchor` | 任意の `target: { kind, rect }`。`kind` は `click`・`input`・`key`・`scroll`・`hover`・`drag`・`open`。独立に測った anchor は `taskAnchor` の矩形で渡す |
| `result` | 表示中の1箇所を `{ rect, name, expected }` で渡す。ラベルは `<対象名> === <期待する状態・値>` となり、`===` は期待値の区切りであって比較の実行・合格ではない |
| `pointer`・`input`・`key` | 実イベントを `pointer: { x, y, at, move?, pressed?, released?, click? }`、`input: { text, at, firstAt?, hold? }`、`key: { name, at, firstAt?, hold?, api? }` で渡す。キー名が1文字のキー（アルファベットなど）は中央のキー表示でなく、`input` と同じ入力帯の文字列として表示する。`api: true` は API 代行の「操作案内」。`hold: true` は表示の保持に使い、保持終了後に解除する |
| `checkAt`・`reducedMotion` | 操作終了の時刻。任意の `reducedMotion` は動きを減らす表示の指定（未指定はブラウザー設定に従う） |

矩形は `{ x, y, width, height }` の有限値で、幅・高さは正とする。イベントの `at`・`firstAt`・`checkAt` は注釈 document の `performance.now()` の時計を使う。別 document への再設置では check と dock の出現・更新時刻を新しい時計へ変換して渡し、フェードや連続入力を再開始しない。

`pointer.move` は `{ from: { x, y }, durationMs: 400 }` とし、終点を `x/y`、移動の起算を `at` で渡す。同じmoveとatを保つpressed更新は移動を再開始しない。`inspect().pointer` はCSSの実測先端座標・document時刻・`moving`を返し、実マウス追従に使う。手動実装もこの経路を使い、down直後に同じmoveとatへ `pressed:true` を加え、up直後に `{x,y,at,released:true}` を送る。pressed解除だけでは解放波紋は始まらない。旧 `pointer: {x,y,at}` は直接配置、`click:true` は解放波紋として引き続き受理するが、実mouse.upの後に渡す。旧入力だけで接近・押下表示が自動生成されるわけではない。新規ケースはmove・pressed・releasedまたはdriverを使う。`pointer:null` がcancelとなる。

ドラッグは同一 document 内で source→target の直線を400ms ease-in-outで移動する。source到着後400ms静止してdown、固定円を保持してtargetへ移動し、到着後押下したまま400ms保持してupする。upの実操作終了時刻からcheckを開始する。driver.drag({ source, target, result/results, anchor? }) は必要な2つのlocatorを受け、既存anchor・結果契約へ接続する。任意経路・HTML DnD・autoscroll・別documentの自動支援は含めない。例外時は押下入力を解放し、原エラーを保持する。

返り値の `installed`、`await update(patch)`、`await inspect()` の layout には `constraints`・`placements`・`requiredTitleHeight` がある。配置制約と必要なタイトル高さを実映像に照合する。`painted()` は描画と進行中の表示アニメーションを待つ。`await setVisible(false/true)` は注釈の非表示・再表示、`await dispose()` は除去に使う。再設置前の document や除去後の handle で更新を続けず、未設置・除去済み・入力不正の例外は停止・制約として報告する。

単一 document 内のクリック・文字入力・キー操作・hover・ドラッグ・スクロールのステップ実行と注釈更新は、`assets/step-driver.mjs` の録画ドライバへ任せられる。録画ケースは録画セットのタイトルとステップの操作文・動画パスを 1 箇所の宣言 `{ title, steps: [{ action, video? }] }` に置き、`await createStepDriver(page, overlay, plan, options)` へ渡す。タイトルと操作文は非空文字列とする。`options.step` は 1 始まり（省略時は1）で、1インスタンスは1ステップの操作1回だけを実行する。ステップごとに作成する。

ドライバは task anchor の実測採寸 → 注釈の予告 → 実操作と実値の転送 → check → 結果枠とラベル → 待機の順で実行する。各操作の入力は次のとおり。

| 呼び出し | 入力 |
| --- | --- |
| `click(operation)`・`hover(operation)` | 操作対象の `locator` |
| `drag(operation)` | 同一document内の `source` と `target` locator |
| `type(operation)`・`fill(operation)` | `locator` と文字列 `text`。`type` は1文字ずつ入力し、任意の `key` を最後に送る。`fill` は一括設定 |
| `press(operation)` | `key`、任意の `locator` |
| `scroll(operation)` | `deltaY`、任意の `locator` |
| 全操作 | 確認箇所の `result: { locator, name, expected }`、またはその配列の `results`。`name` は非空文字列、`expected` は文字列。操作対象より意味のある広さの行などを anchor にするときは `anchor` の locator |

`options.theme` に観測した明暗、`options.layer`・`pageArea`・`titleArea` に実際の領域を渡す。ドライバの既定は `layer: "page"`、`titleHeight: 64`、ページ領域は viewport の上からその高さを除いた矩形である。外タイトル合成でページ全体を映す場合は、0 起点の全 viewport を `pageArea` に明示し、予約と実映像を一致させる。`options.timing` の入力キーと既定値は、予告 `announceMs: 1800`・接近 `moveMs: 400`・到着後の停止 `holdMs: 400`・文字間隔 `typeIntervalMs: 120`・一括設定後 `fillHoldMs: 600`・各結果 `resultViewMs: 3000`・結果切替 `resultSwitchMs: 200`（単位はすべて ms）。`moveMs` と `holdMs` は400ms固定とする。他の時間を調整する場合も「録画を組み込む」の最低時間を満たす。

ドライバは採寸できない対象（frame 内の要素など）や document をまたぐ操作を吸収しない。ナビゲーション・リロード・別タブ・iframe 内の操作・dialog・API 代行が必要なキー操作は録画ケースが直接行い、overlay の入力と時間・同期の扱いに従う。採寸不可や再使用の例外を握りつぶさない。アサーションはドライバへ含まれないため、録画ケースは各ステップの結果を自動テストで検証する。`recordingMetadata(plan)` または `driver.metadata()` は `{ title, steps: [{ number, action, video }] }` を返し、宣言順に採番する。動画パスを省略すると `step-N.mp4` という既定名を返すが、動画を生成する処理ではない。生成・保存する実ファイルのパスを宣言し、録画データを二重管理しない。

タイトル帯は2通りで置ける。ページ映像と同じ viewport 内に予約するか、`layer: "page"` でページ注釈だけを描画し、外タイトルを `layer: "title"` の同じ renderer で別途描いて合成するかである。`page.screencast` のフレーム取得と `ffmpeg` による動画生成・外タイトル合成には `assets/recording-example.mjs` を接続例として使える。`recordWithExternalTitle(page, scenario)` は外タイトル合成つきの 1 ステップ動画を書き出し、`scenario.run(handle)` の中で録画ドライバの 1 ステップを実行するのが接続の形である。ステップごとの `start()` / `stop()` とフレーム収集の呼び出しは録画ケース側で行う。これは runner 所有の Page と出力先だけを受け取り、操作・アサーション・URL・セレクターを持たない。この接続例には `page.screencast` を備えた Playwright ビルド（動作確認済み: 1.64.0-alpha-1790635538000）と `ffmpeg` が必要である。screencast のタイムスタンプと `Date.now()` のエポックが一致しないランナーでは、例の `frameClockOffsetMs` で時刻基準を揃える。screencast の取得は可変フレームレートで、約60fps への変換は元の取得間隔と一致しないため、フェード境界の正確な時刻を合否基準にしない（`~/.agents/tickets/dotfiles/20261003-205058.md`）。

タイトル全文の折返しに必要な帯領域を操作前に確定し、全期間で固定する。ページ映像の寸法も固定し、注釈を収めるためにサイトを縮小・リサイズ・切り抜きしない。外タイトル時の `pageArea` は0起点の全 viewport、`titleArea` は別レイヤーの予約領域とする。接続例の `scenario` には `title`、overlay 形状の `steps`（`name/action/expected`）、`current`、観測した `theme`、`outputDir`、`run(handle)` を渡し、必要なら `titleHeight`・`frameClockOffsetMs` を指定する。`run` の handle は `update`・`inspect`・`painted`・`setVisible`・`dispose` を持つ。接続例は内部で開始・停止を行うため、使う場合はステップごとに呼び出す。出力先の中間フレーム等と完成動画を区別し、完成動画を `review-kit/<flow>` へ保存する。`run` が失敗すると接続例は動画書き出し前に例外を返すため、失敗動画の保存はケース側で別に扱う。

見た目の確認には、この skill のディレクトリを基点とする `assets/design.html` を開く。明暗と各表示状態を比較できる日本語ギャラリーを同梱した単一 HTML であり、`file://` でサーバーなしに閲覧できる。ギャラリーは録画・アサーションの合否を表さない。

同梱テンプレートの表示を、以下の利用条件と最終のステップ動画に照合する。task label は実測 anchor の上に固定し、上に収まらない場合だけ下へ置く。同一画面内では動かさず、スクロール・遷移・frame 切替時だけ実測 anchor を渡し直す。結果枠とラベルは1組ずつ表示し、対象が消える場合は消える前の位置と消えた後の結果・空領域も示す。結果ラベルは枠の上、収まらないか task label と重なる場合は下へ置く。入力帯は下中央、キー表示は `Tab` などの特殊キーだけを中央を基準に下中央・上中央・左端中央・右端中央の順で配置し、両者が重なる場合は位置分離する。アルファベットなど1文字のキーは中央のキー表示に出さず、入力帯の文字列として示す。task label と dock はサイトと逆の明暗になる。

タイトル・操作文・結果の長い値は折返しで全文を保ち、省略・行数制限・横スクロール・文字の縮小で収めない。数値の桁・符号・小数点・通貨記号・単位も保つ。`s = max(1, ページ映像幅 / 1280)` として、安全余白24s px、操作・確認対象の保護余白8s px、注釈同士の文字面の間隔16s px を保つ。枠の塗り・出現するカーソル・波紋以外の注釈を保護領域に重ねず、ページ本来の要素や変化を隠さない。どの配置も成立しない場合は、対象・ステップ数・値・映像寸法を制約として報告し、省略や追加注釈で適合したことにしない。背景追従や配置のためにサイトの遷移・更新や実操作の時間軸を変えない。

テンプレートの再利用やギャラリーの閲覧だけで適合済みとは判定せず、満たせない点は制約として報告する。サイト側 JavaScript が注釈の host を除去することがあるほか、top-layer、root の transform や stacking context、非 Chromium エンジン、サイト固有のクロスオリジン frame ポリシーでは組み込み検証が要る。テンプレートは汎用の互換性を主張しない。

## 録画を組み込む

対象プロジェクトのランナー、既存の E2E helper / fixture、reporter、動画の保存先、主要なウェブ使用フローを調べ、既存の構成に合わせて録画ケースだけに録画を組み込む。ページ映像は `page.screencast` をステップの開始で `start()`、終了で `stop()` してステップごとに取得し、取得したフレームから必要な注釈合成を含む無音のステップ動画を生成する。1 回の録画を後から分割せず、ステップの区切りをまたぐ映像を作らない。ページ切替・別タブでは新しい page で `start()` し直し、ステップ内のページ映像をつなぐ。同梱テンプレートを組み込む際は既存の装飾と二重に表示せず、要件を満たす既存の動画生成・合成処理は再利用する。

録画開始前に画面サイズを固定する。ドライバに任せない操作も、task label の予告 → 実操作と実値の転送 → 操作終了時刻を `checkAt` とする `phase: "checking"` → 安定した確認箇所の `phase: "result"` の順で行う。遷移・リロード・別タブでは新 document に注釈を再設置し、映像を切り替える間も task label と番号を途切れさせない。

失敗したテストでも動画の保存を試み、動画生成・保存の失敗はテスト結果を上書きせず別に報告する。録画 context を自分で管理する場合は、ページと context を閉じて録画を確定させてから動画生成・保存を待つ。並列実行や再試行では出力名の衝突を避け、各テストの最後の試行で全ステップの動画を確定する。最終試行を選別できない場合は、制約と残った動画を報告し、全ステップがそろうことと主張しない。

録画を有効にした設定や helper が後続の通常実行でも録画する場合、依頼が一時的な録画なら組み込みの変更を残さない。報告するステップ動画は実際に出力されたパスから確認し、動画生成・保存のエラーはテスト合否とは別に報告する。ステップ動画が欠けた場合は録画完了としない。

### 背景観測

背景取得と以下の分類は録画ケース側で行い、観測した `theme` を overlay に渡す。renderer やドライバがサイトの背景を取得・判定するわけではない。

サイトの main 背景は、現在映しているページの主要コンテンツ面の背景であり、OS の設定・テーマ名・操作中の要素の色ではない。主要領域はサイトが main ランドマークとして示す領域とする。可視の main ランドマークが複数あれば、映像内の可視面積が最大の領域を使い、同面積なら上端が小さいもの、次に左端が小さいものを選ぶ。main ランドマークがなければページ映像全体を使い、見た目から別の領域を任意に選ばない。iframe 内を操作していてもページ全体を映す間はページの主要領域を使い、frame だけを映す場面ではその映像の主要領域を使う。

選んだ領域の映像内にある部分の最小外接矩形を横5・縦5に等分し、各セルの中心25点で背景色を観測する。対象は文字・ボタン・カード・注釈などの前景を重ねる前の主要面の色。透明な主要面は祖先の背景・画像・グラデーションを奥から合成し、最後はページのキャンバス色へ合成する。ページのキャンバスも透明ならブラウザーの白いキャンバスへ合成する。各背景色は sRGB に揃え、成分を0から1の範囲へ収める。透明度αの各層を奥から `C = α × 手前のRGB + (1 - α) × 奥のRGB` で合成する。背景画像・グラデーションは各点の実色を使う。可視領域の外の点は除外し、有効点が13点未満ならページ映像全体の25点で同じ観測を行う。前景の占有率、注釈自身の色、マウス位置で分類を変えない。

各点の合成後の sRGB 成分を0から1へ正規化する。成分 `c <= 0.04045` は `c / 12.92`、それ以外は `((c + 0.055) / 1.055)^2.4` に変換し、輝度 `Y = 0.2126R + 0.7152G + 0.0722B` を得る。有効点の `Y` の中央値を main 背景の輝度とする。偶数点なら中央2点の平均を使う。

| 観測時点・条件 | サイトの分類と `theme` |
| --- | --- |
| 最初の主要面、または遷移・リロード・別タブ・映像のページ切替後の新しい主要面で `Y <= 0.179` | dark サイト（`theme: "dark"`） |
| 同じ初回条件で `Y > 0.179` | light サイト（`theme: "light"`） |
| 同一ページで light サイトを使い、`Y >= 0.21` が100ms 以上続く | light サイトへ変わったと分類し、`theme: "light"` へ切替 |
| 同一ページで dark サイトを使い、`Y <= 0.15` が100ms 以上続く | dark サイトへ変わったと分類し、`theme: "dark"` へ切替 |
| 同一ページで上の切替条件を満たさない | 現在の分類を維持 |

最初の注釈を出す前に初回分類する。以後、背景の観測間隔は50ms 以下とし、同一ページの切替は100ms 以上離れた2回の観測で同じ条件を満たして確定する。背景が条件を満たし続けた最初の映像時点から250ms 以内に全注釈を切り替える。main 背景のテーマ切替、画像やグラデーションの変化、主要領域の交替を含み、ステップの終わりを待たない。100ms 未満の一時的な明滅では切り替えない。

遷移等で旧主要面が消え、新主要面がまだない区間は旧テーマと task label を維持する。main ランドマークもサイト本来の可視内容もない白紙を、主要面がまだない区間とする。新主要面が映ったら初回閾値で再分類し、その最初の映像時点から100ms 以内に全注釈へ適用する。主要面がない白紙のまま250ms 続く場合はページ全体を主要面として再分類する。主要面の新設・交替は、同一ページなら継続観測の切替条件、ページ切替なら初回条件を使う。

切替は同じ映像フレームでタイトル帯・task label・badge・check・枠・結果ラベル・カーソル・波紋・入力帯・キー表示の全トークンへ適用する。dock は常にサイトと逆の明暗へ揃う。新旧テーマを混ぜず、クロスフェードしない。表示中の入力や波紋も追従し、番号・操作文・状態・値・位置・操作の時間をリセットしない。追従できない区間は制約として報告し、ステップ中固定のテーマで代用しない。

### 時間と実操作の同期

ステップ動画の長さは注釈の最低表示時間だけで決める。視聴者はビューアで自分のタイミングでステップを見るため、視聴時間を録画内の固定待機で担保しない。時間は注釈の動きではなく動画の経過時間で測る。

- 操作待ち: 対象の可視化・操作可能性など操作前の準備を終え、task label・操作対象の注釈がすべて実際に映った時点から操作を始めてよい。準備や描画待ちの自然な待機は短縮・省略しない
- 操作中: カーソルは左上余白から400ms で対象へ接近し、到着してから操作する前に最低 400ms 止める。文字入力は 1 文字ごとに 120ms 以上空ける。`fill()` など keydown なしで瞬時に完了する代行操作は、入力帯の文字列と対象の枠を最低 600ms 表示してから結果の確認へ移る
- 操作終了: 操作終了でカーソルを消す。操作終了の時刻が badge の check のフェード開始時刻になる。結果枠とラベルは、確認対象の出現と描画の安定を待って表示する。待機中にページ本来の状態更新を遅らせない
- 結果表示: 各確認箇所の枠・ラベル・確認する内容が実際に映った時点から最低 1 秒維持する。前の確認枠とラベルを消してから次の確認枠とラベルを出すまで 0.2 秒空ける。最後の確認箇所の表示時間を終えたら録画を確定させる

遷移・リロード・別タブを挟むステップでは、移動先の描画が落ち着いてから結果の確認へ移り、各確認箇所の表示時間を改めて満たす。視聴者が読む時間はビューアのリプレイと一時停止で担保されるため、これ以上の待機を録画に埋め込まない。

check は操作終了時刻から360ms でフェードインし、ステップの終わりまで維持する。表示アニメーション自体は同梱 renderer に任せ、ケースは次の実値と時計を渡す。

入力帯とキー表示は、最初の出現時刻 `firstAt` と最終更新時刻 `at` から、出現200ms・保持1200ms・消失250msの時間式で表示する。保持の起算は `max(firstAt + 200, at)` であり、連続する文字入力で出現フェードを毎文字再開始せず、保持だけを最終更新まで延ばす。消失の開始時刻から250ms後に値を除き、次の値で出現からやり直す。Backspace 直後の文字入力では、削除結果が見えるまで最大160ms 表示を遅らせる。キー表示は操作の間維持し、最後の更新から同じ時間式で消す。操作と同期する内容は、以下の実値の転送方法に従う。動きを減らす設定では、同じ時間式で opacity のみを遷移させる。

カーソルの接近は全ステップでページ映像の左上余白（pageArea.x + 24s, pageArea.y + 24s）から対象中央へ、CSS transform の400ms ease-in-out（0.42,0,0.58,1）で行う。実マウスも表示の実測先端へ中間 move を送り、同じ経路・時間軸を追従する。毎フレームの overlay.update で位置を描かない。到着後400ms静止し、hover によるサイト更新は移動途中・到着時から許す。表示と離散入力の送出遅延・位置誤差はブラウザーで計測し、完全一致とは主張しない。`scrollIntoViewIfNeeded()` による瞬間移動だけで画面外のクリック対象を見せたことにしない。スクロールでは、シナリオの挙動を変えずに済む場合は長い移動を小刻みな wheel 操作にし、その間に待ちを挟まず、画面外の対象へは先に滑らかに移動してから操作する。スクロールによる遅延読込などで検証対象の挙動が変わる場合は元の操作を維持し、移動を task label と画面上の到着位置で補う。装飾は録画中の DOM オーバーレイで操作・変化と同期させる。後処理で加える表現も、元の映像と時刻が一致する場合に限る。局所拡大、静止保持は、既にある映像と注釈の見せ方を変える範囲で読みやすさの補助として選べる。ただし、実際の移動・待機・失敗を消したり、保持を実際の表示時間と混同させたりしない。

手動スクロールも、移動の過程が追える映像とホイール操作の始点へ出現するカーソルに加え、ホイール操作の方向を `key.name: "ScrollDown"` / `"ScrollUp"` と document の実操作時刻 `key.at` で渡し、画面中央基準のキー表示で示す。ドラッグは押下・保持移動・解放とその結果を実操作の時間軸で示す。

キー表示は画面上の入力文字列と区別し、実際の操作に対応させる。中央のキー表示は特殊キー（`Tab`・`Enter`・`Backspace`・矢印・`ScrollDown` / `ScrollUp`・修飾キーとの組合せなど、1文字でないキー）だけに使い、アルファベットなど1文字のキーは入力帯の文字列として示す。フォーム送信を `Enter` で行う場合は送信前に `Enter` を表示し、クリック送信ならボタンへのカーソル移動と波紋で示す。ブラウザー側の `Ctrl+R` や `Alt+←` が Playwright のキー送出では動作しない場合は、キー表示に「操作案内」を明記してから `page.reload()` / `page.goBack()` を呼ぶ。実キー入力時のキー表示と API による代行を区別し、キーを押したと偽らない。キー入力を伴わない操作も task label と対象・結果の枠で示し、視覚表現のない操作を残さない。

入力中の文字は一つの連続した文字列として表示する。`Ctrl + A` / `Meta + A` は帯を操作名に置き換え、続く文字入力は新しい文字列として表示し、Backspace では削除後の文字列に更新する。`locator.fill()` のように keydown なしで文字入力対象に `input` が起きた場合は、その対象の値を表示する。checkbox など文字入力対象でない要素の `input` は帯に値を出さず、対象の枠と状態変化で示す。文字が順に増える様子で入力を示すため、録画ケースの文字入力は操作の意味が変わらない限り `pressSequentially()` で 1 文字ずつ行い、`fill()` などの一括設定で映す箇所を作らない。長い値などで 1 文字ずつが現実的でない場合だけ一括設定を使い、その箇所と理由を報告する。

装飾は DOM に要素を追加する。スクリーンショット比較や全要素数を調べるアサーションには影響しうるため、その間だけ装飾を隠すなどして期待値とテストの意味を維持し、装飾なしの結果とも照合する。維持できなければ録画の制約として報告し、合否が変わらないとは主張しない。ポップアップ、複数ページ、iframe 内の操作では、装飾するページと動画の選択を調整する。ページ映像の切り替えでは URL の露出を確認し、フォーカス先の強調は `activeElement` や DOM 装飾だけで正しいと断定せず映像と照合する。画面外のアサーションやネットワーク結果を画面上の成功表示と混同しない。

## 録画の成果物とビューア

録画したステップ動画の保存先は、`review-kit` フォルダの下の、正本（対象プロジェクトの SPEC.md の録画シナリオのセクション）が定めるウェブ使用フローごとのフォルダ `review-kit/<flow>/` とする。`<flow>` は正本が定めるフロー識別子であり、録画するフローが1つでも `review-kit/<flow>/` に置く。各 `<flow>` フォルダは1フローの録画セットであり、その直下には、ビューアで再生できるステップごとの動画と `metadata.json` を置く。ビューアの単一の `index.html` は `review-kit` フォルダの直下に置く。テスト結果の中間ファイルを録画セットのフォルダに混在させない。

`metadata.json` に録画データを書く。非空文字列の `title` と非空配列の `steps` を持つ。各要素の `action` は非空の操作文、`video` は実在する動画を指す非空文字列とし、`steps` の配列順が再生順であり、その `<flow>` の正本ステップ番号と 1 対 1 に対応させる。`video` は録画セットのフォルダからの相対パスとし、絶対パスや `..` で始まるパスを使わない。

実行入口から同梱の `assets/build-viewer.mjs` を呼んでビューアを生成し、`review-kit/index.html` のパスを報告に含める。生成スクリプトは対象プロジェクトを基点に `node <skill ディレクトリ>/assets/build-viewer.mjs review-kit` で実行する。スクリプトは `review-kit` フォルダ直下の各 `<flow>` フォルダをフォルダ名の昇順でフローとして収集し、フローごとのステップ番号（フロー内で 1 から）を埋め込み、動画を `index.html` からの相対パス `<flow>/…` で参照する。JSON・入力値・動画パスが不正な場合は、ファイル名（ステップの不正では番号も）を含むエラーで停止し、HTML を書き出さない。

ビューアは `file://` で開ける。フローの一覧ボタンでフローを切り替え、切り替え先のフローで最後に表示していたステップを表示して再生する。各フローで番号と操作文の一覧、Previous / Next と ← / → でフロー内を移動し、Replay と R で現在動画を最初から再生する。移動時は前の動画を止めて移動先を再生し、初期表示と動画終了時は自動で再生・次へ進行しない。表示は英語で、OS の明暗に従い、動きを減らす設定では遷移アニメーションを無効にする。データ不正・動画を読めない場合の通知も確認する。

## 確認と報告

録画ケースの操作と確認する画面変化を列挙し、各々について task label から結果の確認まで途切れない注釈、対象の強調、操作の視覚表現、結果箇所の強調が最終ステップ動画の連続フレームで追えるかを照合する。各ステップが 「録画を組み込む」の「時間と実操作の同期」の指定を満たすか、操作中の最低時間、操作終了時刻から check が 360ms でフェードすること、各確認箇所の最低 1 秒、前の確認枠・ラベルの消失から次の表示までの 0.2 秒を経過時間で確認する。複数結果が1組ずつ表示されること、badge の番号が全状態で維持されることも照合する。task label が anchor の上に固定され、長文が折返しで全文表示されていること、入力帯が下中央・キー表示が中央基準で dock の逆明暗になっていることも確認する。対応するフレームが欠けるときは録画ケースや装飾を修正して再録画し、なお見せられない操作・変化は対象と制約を報告して、視覚的に網羅できたとは主張しない。タイトル帯のタイトルが読めるか、カーソルが左上余白から400ms ease-in-outで接近すること・操作までの停止・操作終了後の消失、拡大する波紋、入力帯への連続した文字入力と dock のフェードが確認できるか、失敗したテストも録画されたかを確認する。ショートカット、Backspace、keydown なしの文字入力、非文字入力対象の操作を含む場合は、キー表示・文字列の更新と、非文字入力の値が帯に出ないこと、1文字のキーが中央のキー表示でなく帯の文字列として現れることも確認する。dock の背景追従と注釈の保護配置、動きを減らす設定でも空間移動を保ち、pop・fadeがないことも照合する。短時間の表示は該当区間を高頻度でフレーム抽出して確認し、粗い間隔の抽出だけで表示がなかったと断定しない。`ffprobe` で各ステップ動画の映像コーデックと再生時間を確認し、生成した `index.html` のビューアを `file://` で開いて各ステップ動画を実際に再生し、開始から終了まで照合する。フロー切替が前のフローの表示位置を記憶して復帰すること、ステップ一覧・移動・リプレイ・ステップ移動時の前の動画の停止が動くことを確認する。各録画ケース・対象の主要なウェブ使用フロー・ステップごとの動画のパス・アサーションを含む自動テスト結果を対応付けて報告し、正本（対象プロジェクトの SPEC.md の録画シナリオのセクション）のステップ番号と録画セット配下の動画のパスを対応付けて、通常の E2E の実行結果と録画ケースの実行結果、動画に対する人手の go/no-go 判断を区別する。映像だけでは判断できない点も報告する。

録画の組み込み・再調整では、実装の DOM オーバーレイと動画の後処理、および各ステップ動画に現れる録画処理由来の表示を列挙し、共通注釈、既にある映像と注釈の見せ方を変えるだけの補助、ユーザーが承認したプロジェクト固有の表示のいずれかに対応付ける。全表示の対応先を示せたときに適合を報告する。対応先が定まらない表示は余剰であり、実装から取り除いて再録画するか、ユーザーの承認を得てプロジェクト固有の表示として確定してから判定する。

生成物の品質検証で指摘を報告するときは、動画パスとステップ番号、経過時間、見えた事実を添える。失敗と判定できない見た目は観測として区別し、動画を見ただけでテストのアサーションが成功したと結論しない。
