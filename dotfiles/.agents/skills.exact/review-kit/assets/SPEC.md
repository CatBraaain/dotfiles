# review-kit の正本

このファイルは、review-kit skill の同梱 assets を保守するための正本であり、録画注釈とビューア・生成スクリプトについて、ユーザーが観測できる見た目・振る舞いを定義する。通常の録画に必要な入力・手順・利用側の責務は `SKILL.md` にあり、本書の読取を前提としない。対象プロジェクトの `SPEC.md` に置く録画シナリオとは別の正本である。

同梱 assets（`overlay.html`・`overlay.css`・`overlay.mjs`）を編集したら、`design.html` の埋め込みも同じ内容に差し替えてから `overlay.test.mjs` の同一性検査を通す。

## 注釈の設置と Trusted Types

注釈の設置は、録画する document への DOM オーバーレイ追加と `adoptedStyleSheets` のスタイル適用で行う。Trusted Types を強制するサイト（例: YouTube）でも設置でき、注釈の見た目・表示タイミングは強制のないサイトと変わらない。markup の代入は、強制のない document では文字列をそのまま行う。強制がある document では、渡した値をそのまま返す `createHTML` を持つ名前付き policy（`recording-annotation-overlay`）だけを通し、default policy は登録しない。policy は同一 document で 1 度だけ生成し、同一 document での設置し直しでも再生成しない。別 document への再設置では、その document で生成する。強制がある document で policy の生成が許されないときは、設置の失敗として制約を報告する。

## 操作と変化を見せる

録画開始前に画面サイズを一定にし、必要なテストだけを実行する。録画ケースの各操作と、シナリオで確認する各画面変化について、操作の予告、操作する箇所、操作そのもの、変化した箇所を動画内で対応付ける。各ステップでは、操作対象の上に固定した task label で現在の操作を予告し、実操作とその入力・キー表示を映し、操作終了を badge の check で示し、結果枠と結果ラベルで確認する。遷移・リロード・別タブでは新しい document やページにも装飾を設置し直し、ページ映像を切り替える区間でも task label が途切れないようにする。

結果が確認できる箇所は「時間の間隔」に従い、結果枠とそのラベルを1箇所ずつ示す。複数箇所を確認する場合はシナリオで確認する順に1箇所ずつ表示し、同時に複数の結果枠・ラベルを表示しない。ページ本来の更新は順次表示のために遅らせない。対象が消える場合は消える前の位置を示し、消えた後の結果や空になった領域も示す。遷移・リロードでは移動先の画面の確認箇所も示す。枠やラベルを UI、成功判定、実際の表示内容と誤認させず、変化を覆わない位置に置く。待機と操作の速度は「時間の間隔」の最低時間に従い、実際の操作順やアサーションの意味は変えない。

### ステップの対応と表示状態

録画専用シナリオでレビューする操作と結果を、発生順にステップ `1` から `N` まで番号付けする。ステップの単位は、動画でレビューする利用者の操作の意図 1 つに、その結果確認 1 組を対応させる。

- 利用者の目的が変わる、操作対象が変わって別の結果確認になる、結果として確認する状態が変わるときは、別のステップにする
- 画面の状態そのものを変える操作（表示モード・設定・表示切替など）は、レビュー対象の 1 つの意図として扱い、他のステップの操作中に埋め込まない。その操作と、変化後の状態の確認で 1 つのステップにする
- 1 つの目的を完成させるための補助的な操作は同じステップに含めてよい。操作対象へのフォーカスのクリックに続けて文字入力する場合がこれに当たる

操作の意味ごとに区切るのであって、都合の良い粒度で結合・分割しない。`N` は操作開始前に確定する。badge の番号と task label は同じステップを指し、操作の予告から結果の確認まで番号を維持する。ページ・frame の切替でも番号をリセットしない。空のシナリオを架空のステップで埋めず、録画対象がないことを報告する。

ステップの進行はビューアが示す。動画内の注釈は現在のステップだけを扱い、他のステップの注釈を表示しない。

| 場面 | 番号badge |
| --- | --- |
| 操作の予告から操作開始まで（操作待ち） | 数字だけ |
| 操作を行っている間（操作中） | 数字だけ（回転する装飾は付けない） |
| 操作終了から最初の結果枠を表示するまで（確認待ち） | 数字と、操作終了時刻から360msでフェードインする check |
| 結果枠とラベルを表示している間（結果表示、箇所の切替間隔も含む） | check を維持 |

操作待ち・操作中・確認待ち・結果表示は文書内の状態名とする。check は、動画で確認する結果の閲覧を開始したことだけを示し、アサーションの合格を示さない。画面上の結果が現れた後でテストが失敗しても、テスト合否を注釈から推測しない。

### 注釈の見た目

録画処理が映像へ付加する表示（録画注釈）のデザイン正本はこの節である。共通注釈は、タイトル帯、task label と番号 badge・check、対象枠・結果枠、結果ラベル、カーソル、波紋、入力帯、キー表示で構成する。全ステップ一覧、回転する spinner・リング、操作種別ごとの対象見出しは置かない。時計・章・時刻索引・追加の拡大像など、この節にない表示はユーザーの承認を得てプロジェクト固有の表示としてのみ加える。ページ本来の UI は録画対象であり、注釈の配色を適用しない。ページ・frame の識別バッジは共通注釈に含めない。

見た目は、sans-serif の本文と mono の番号・入力文字列、余裕のある内側余白、薄い中立色の外周で階層を作る。緑は check だけに用い、操作の種別で色分けしない。背景のぼかし、装飾グラデーション、文字の影、グローは付けない。

#### 寸法・文字・共通面

`W`・`H` はタイトル帯を除くページ映像の幅・高さ、`s = max(1, W / 1280)` は寸法倍率。以下の px 値を `s` 倍し、最終映像上の寸法とする。1280px 未満でも文字・余白を縮めない。映像・ページ領域の寸法は録画全期間で固定し、注釈を収めるためにサイトを縮小・リサイズ・切り抜きしない。

幅・高さはすべて外寸。外周線は内側に含める。本文の幅を求めるときは、左右の線・padding・badge・gap を外寸から差し引く。`M(text, role)` は下表の書体・サイズ・weight で描いた文字列の実幅。日本語を含む全文の実幅で計算し、半角の文字数だけで幅を決めない。定常表示中の全テキストの不透明度は1。ラベルとカードは、表示時に150msで opacity 0 から1、非表示時に300msで opacity 1 から0へ遷移し、通常は `prefers-reduced-motion: reduce` でも同時間の opacity のみで遷移する。テーマ・配置・入力途中の更新では遷移を再開始しない。省略記号、行数上限による切り落とし、横スクロール、文字サイズの縮小で収めない。空白で折り返し、空白のない URL・期待値・長語は収まる最後の文字境界で折り返す。数値の桁・符号・小数点・通貨記号・単位を削除・置換しない。

| 用途 | 書体 | size / line-height | weight / 字間 |
| --- | --- | --- | --- |
| 基本文字 | sans-serif | 15px / 24px | 400 / 0 |
| テストタイトル | sans-serif | 16px / 24px | 600 / 0 |
| task label 本文 | sans-serif | 17px / 26px | 600 / 0 |
| 結果ラベル本文 | sans-serif | 14px / 20px | 600 / 0 |
| 入力帯の文字列 | mono | 21px / 30px | 400 / 0 |
| キー表示のキー名 | sans-serif | 21px / 30px | 600 / 0 |

sans-serif の書体は `ui-sans-serif, system-ui, -apple-system, BlinkMacSystemFont, "Segoe UI", "Noto Sans CJK JP", sans-serif`、mono は `ui-monospace, SFMono-Regular, Menlo, Consolas, "Liberation Mono", "Noto Sans Mono CJK JP", monospace`。番号の桁は等幅にし、本文中の数値・期待値は本文と同じ書体で保つ。

対象を透かす `frame-fill` には注釈の文字を置かない。枠は `frame-stroke` の線の内側に1px の `frame-inner-guard`、外側に1px の `frame-outer-guard` を添え、合成後も背景の明度によらず少なくとも一方の対比線が3:1以上で見える。波紋は `accent` の線と不透明色の `ripple-inner-guard`・`ripple-outer-guard` でクリック位置を示し、消失中の不透明度は動きの指定に従う。確認するページ文字には枠内の塗りを重ねても判読性を維持し、変化の細部を隠さない。

#### タイトル帯

タイトル帯は `label-height`（基準64px）を基準に、映像の最上部・幅 `W`・上下16px・左右24px の padding、`title-surface` 面。`text` 色で左に describe 階層を含むテストタイトルを置き、進行表示は置かない。外タイトル合成ではこの帯だけを `W × 64`（長いタイトルは事前に確定した最大高さ）で別レイヤーに描き、ページ映像の上に連結する。外タイトル合成でページ側を `layer: "page"` として描画するときは帯は描かず、`titleArea` は高さの予約領域としてのみ扱い、帯の配置制約は報告しない。

タイトル領域幅は `W - 48s - 24s` で、この幅で全文を折り返す。帯の高さは `max(64s, 32s + 内容の高さ)`。折返しを含めた最大の内容高さを操作前に確定し、全期間で固定する。1280×720px の映像で帯が64px ならページ領域は1280×656px。長いタイトルのため帯を高くする場合もページ映像を遮らず、その分の帯領域を確保する。

#### task label・番号 badge・check

task label は現在ステップの操作文を示す1枚の面で、操作対象・確認対象とは独立に測った anchor の上に置く。幅は anchor の幅に追従し、高さは `max(48s, 22s + 26s × 行数)`。本文はステップの操作文（動詞で始まる `action`）を全文で折り返し、長文で高さを増やす。左に番号 badge（`badge` 44px 四方の領域に `chip` 32px の数字面、`active-fill` 面・`on-active` 数字）、badge と本文の間は `task-gap`。面はサイトと逆の明暗の半透明 `surface`、`dock-line` 外周と `dock-shadow`、角丸 `label-radius`、左右の padding 12px。本文は `dock-text`。

anchor の既定は操作対象の矩形であり、結果表示の間は結果矩形を anchor に用いる。操作対象より意味のある広さ（行・入力欄を含むコンテナなど）を anchor にするとき、録画ケースが実 DOM で採寸して `taskAnchor` として渡す。anchor のない操作ではページ領域の安全余白の上端を代替の anchor とし、その幅いっぱいに label を置く。label の下端は anchor の上端から `task-gap` 離し、横位置は anchor の左端に揃えて安全余白内に収まるよう補正する。上に置けないときだけ anchor の下端 + `task-gap` に置き直し、どちらも収まらないときは録画の制約として報告する。自動で別の場所へ動かさない。

label の位置は同一画面内では固定し、対象や注釈の変化で動かさない。スクロール・遷移・frame 切替で基準画面が変わるときだけ、録画ケースが実測 anchor を再び渡して置き直す。別 document への再設置では、check の出現時刻と dock の出現時刻も、新しい document の `performance.now()` の時計に変換してケース側から渡す。

番号 badge は非回転とし、回転する spinner・リングを付けない。check は badge 領域の右下、`check` 16px 四方の円（`done` 面、外側2px の `surface` ring、中央に11px 四方の SVG パス `m2 6 2.5 2.5L10 3`）。操作終了時刻から360ms で opacity 0 から1へフェードインし（cubic-bezier(0, 0, 0.58, 1) 相当）、以降はステップ動画の終わりまで維持する。動きを減らす設定でも同時間の opacity のみでフェードする。check の出現はアサーションの合格を示さない。

#### 対象・結果の枠と結果ラベル

枠は強調する要素の実際の位置・大きさに追従し、その外側2px に `frame-stroke` 色・`frame-line` 幅の実線を置く。角丸は `min(frame-radius, 枠幅 / 2, 枠高さ / 2)`。線の内側の対比線は `frame-inner-guard`、外側は `frame-outer-guard`、内側の塗りは `frame-fill`。映像の境界を越える線だけ境界で切り、対象の見える部分をずらさない。操作対象の枠は操作待ちから確認待ちまで表示し、結果表示の間は結果枠に置き換える。対象が消える場合は消える前の位置と、消えた後の結果や空の領域を示す。操作種別の見出し・アイコン・短語は枠に付けず、操作の意味は task label と dock が担う。

結果ラベルは、結果枠の左端から8px、枠の上辺より8px 上に下端を置く。`caption-surface` 面、不透明な `on-active` の文字と eye（20px 四方・2px 線の単色 SVG）、角丸 `caption-radius`、上下8px・左右12px の padding。本文は `<対象名> === <期待する状態・値>` だけを表示する。`===` は期待値を示す表示上の区切りであり、JavaScript の比較の実行やアサーションの合格を示さない。番号を付けない。全文を折り返し、長い数値・値を切らない。上に置けない、または task label と重なる場合は結果枠の下端 + 8px に置き直し、どちらも収まらないときは制約として報告する。

複数箇所を確認するステップでは、結果枠とラベルを1組ずつ順番に表示する。前の組を消してから次の組を出すまでの間、結果枠・ラベルは表示しない。切替の間隔は「時間の間隔」に従う。

#### カーソル・波紋・入力帯・キー表示

| --- | --- | --- |
| カーソル | 標準ポインター形状の矢印、16×24px。`cursor-fill` 面、`edge-guard` の1.5px 縁。先端が操作座標 | 左上余白から操作対象中央へ400ms ease-in-outで接近 |
| 波紋 | 押下中は直径24px 固定、解放時に24px から48px へ450ms 等速で拡大し、opacity 0.75から0へ。`accent` の2px 円、内側1px の `ripple-inner-guard`、外側1px の `ripple-outer-guard`、面なし | 押下中は先端に追従し、解放後は実際の up 位置が中心 |
| 入力帯 | 外幅 `input-width` 基準（全文が収まらないときは内容に合わせて広げ、`W - 2edge` を上限とする）、上下12px・左右20px padding、`dock` 系トークン、角丸は高さの半分。高さ `max(input-height, 26s + 30s × 行数)` | 常にページ映像の下中央、下端から `edge` |
| キー表示 | 外幅 `key-width` 基準（長いキー名で広げる）、上下12px・左右20px padding、`dock` 系トークン、角丸 `caption-radius`、内側下に `key-sheen` の4px 面。高さ `max(input-height, 26s + 30s × 行数) + (操作案内 ? 28s : 0)` | ページ映像の中央を基準に候補順（中央、下中央、上中央、左端中央、右端中央） |

カーソルの先端はSVGの（1,1）を倍率sで補正して操作座標に一致させる。出現時にpop・fadeは付けず、空間移動は「実操作と同期」に従う。down で直径24sの固定円を先端へ表示し、up でカーソルと固定円を消し、その円から直径48sへ450ms linear、opacity 0.75から0の解放波紋を開始する。down に追加の固定待機・別波紋・色変更・二重円を付けない。解放波紋は固定地点で寿命まで残る。テーマ・pressed の更新で移動を再開始しない。pointer:null・cancel・dispose は移動を止めて固定円を除き、既存の解放波紋の寿命を保つ。

入力帯とキー表示は同じ dock のトークンを持ち、サイトと逆の明暗で描く。入力帯はページ下中央に固定し、他へ動かさない。キー表示は画面中央を基準に置き、保護対象・配置済みの注釈に重なる場合だけ候補順の次の位置へ置く。下中央で入力帯と重なるときは位置分離で解消し、片方だけに制限しない。入力帯は `dock-text` の連続した文字列を中央寄せで折り返し、更新で幅と下端位置を動かさず、高さだけ上方へ増やす。空文字列では空の1行を残し、削除結果を見せる。

キー名は `dock-text`、文字入力以外の実際のキー名（`Tab`、矢印、`Enter`、`Backspace`、`Ctrl+R`、`Alt+←`、プラットフォームに応じた `Meta` 系など）とホイール操作の `ScrollDown` / `ScrollUp` を表示する。API で代行した操作だけ `dock-secondary` の「操作案内」を8px 下に添える。動きを減らす設定でも必要なカーソルの空間移動は通常のease-in-outを保ち、pop・fadeを付けない。入力帯・キー表示のフェードは維持し、波紋は直径24px のまま450ms で消す。

#### 折返し・衝突・収まり

操作対象・確認対象の可視矩形を各方向に `protect-gap` 広げた領域を保護する。枠の薄い塗り・操作対象上のカーソル・クリックの波紋を除き、注釈の文字・面・外周線をこの領域へ重ねない。ページ本来の要素を移動・隠蔽しない。注釈同士の文字面にも `gap` を取る。重なり順はページ映像、枠と波紋、task label・dock、結果ラベル、カーソル、タイトル帯の順とする。

配置は次の順で確定する。task label を anchor の上（不成立は下）に置く。結果ラベルを結果枠の上（不成立は task label との重なりと収まりを見て下）に置く。入力帯を下中央に置く。キー表示を候補順に置く。いずれも安全余白 `edge` 内に収まり、保護領域と配置済みの文字面に重ならないことを条件とする。テーマだけの変更では位置・幅・高さを変えない。

折返し後の面全体が `W - 2edge`・`H - 2edge` に収まることを必要条件とする。現在の task label の全文を常に保ち、結果ラベルは表示中の1箇所の全文を保つ。どの候補も成立しない場合は、全件表示と確認箇所の視認を両立できない対象・ステップ数・値・映像寸法を録画の制約として報告する。隠す・省略する・小さくする・勝手に別の注釈を増やすことで適合したことにしない。背景追従や配置の都合でサイトの遷移・状態更新を遅延させたり、実操作と違う時間軸にしたりしない。

### 背景とサイトテーマの追従

サイトの main 背景は、現在映しているページの主要コンテンツ面の背景であり、OS の設定・テーマ名・操作中の要素の色ではない。主要領域はサイトが main ランドマークとして示す領域とする。可視の main ランドマークが複数あれば、映像内の可視面積が最大の領域を使い、同面積なら上端が小さいもの、次に左端が小さいものを選ぶ。main ランドマークがなければページ映像全体を使い、見た目から別の領域を任意に選ばない。iframe 内を操作していてもページ全体を映す間はページの主要領域を使い、frame だけを映す場面ではその映像の主要領域を使う。

選んだ領域の映像内にある部分の最小外接矩形を横5・縦5に等分し、各セルの中心25点で背景色を観測する。対象は文字・ボタン・カード・注釈などの前景を重ねる前の主要面の色。透明な主要面は祖先の背景・画像・グラデーションを奥から合成し、最後はページのキャンバス色へ合成する。ページのキャンバスも透明ならブラウザーの白いキャンバスへ合成する。各背景色は sRGB に揃え、成分を0から1の範囲へ収める。透明度αの各層を奥から `C = α × 手前のRGB + (1 - α) × 奥のRGB` で合成する。背景画像・グラデーションは各点の実色を使う。可視領域の外の点は除外し、有効点が13点未満ならページ映像全体の25点で同じ観測を行う。前景の占有率、注釈自身の色、マウス位置で分類を変えない。

各点の合成後の sRGB 成分を0から1へ正規化する。成分 `c <= 0.04045` は `c / 12.92`、それ以外は `((c + 0.055) / 1.055)^2.4` に変換し、輝度 `Y = 0.2126R + 0.7152G + 0.0722B` を得る。有効点の `Y` の中央値を main 背景の輝度とする。偶数点なら中央2点の平均を使う。

| 観測時点・条件 | サイトの分類と `theme` |
| --- | --- |
| 最初の主要面、または遷移・リロード・別タブ・映像のページ切替後の新しい主要面で `Y <= 0.179` | dark サイト（`theme: "dark"`） |
| 同じ初回条件で `Y > 0.179` | light サイト（`theme: "light"`） |
| 同一ページで light サイトを使い、`Y >= 0.21` が100ms 以上続く | light サイトへ変わったと分類し、`theme: "light"` へ切替 |
| 同一ページで dark サイトを使い、`Y <= 0.15` が100ms 以上続く | dark サイトへ変わったと分類し、`theme: "dark"` へ切替 |
| 同一ページで上の切替条件を満たさない | 現在の分類を維持 |

最初の注釈を出す前に初回分類する。以後、背景の観測間隔は50ms 以下とし、同一ページの切替は100ms 以上離れた2回の観測で同じ条件を満たして確定する。背景が条件を満たし続けた最初の映像時点から250ms 以内に全注釈を切り替える。main 背景のテーマ切替、画像やグラデーションの変化、主要領域の交替を含み、ステップの終わりを待たない。100ms 未満の一時的な明滅では切り替えない。

遷移等で旧主要面が消え、新主要面がまだない区間は旧テーマと task label を維持する。main ランドマークもサイト本来の可視内容もない白紙を、主要面がまだない区間とする。新主要面が映ったら初回閾値で再分類し、その最初の映像時点から100ms 以内に全注釈へ適用する。主要面がない白紙のまま250ms 続く場合はページ全体を主要面として再分類する。主要面の新設・交替は、同一ページなら継続観測の切替条件、ページ切替なら初回条件を使う。

切替は同じ映像フレームでタイトル帯・task label・badge・check・枠・結果ラベル・カーソル・波紋・入力帯・キー表示の全トークンへ適用する。dock は常にサイトと逆の明暗へ揃う。新旧テーマを混ぜず、クロスフェードしない。表示中の入力や波紋も追従し、番号・操作文・状態・値・位置・操作の時間をリセットしない。追従できない区間は制約として報告し、ステップ中固定のテーマで代用しない。

### dock と check の表示時間

入力帯とキー表示は、最初の出現時刻 `firstAt` と最終更新時刻 `at` から、出現200ms・保持1200ms・消失250msの時間式で表示する。保持の起算は `max(firstAt + 200, at)` であり、連続する文字入力で出現フェードを毎文字再開始せず、保持だけを最終更新まで延ばす。消失の開始時刻から250ms後に値を除き、次の値で出現からやり直す。Backspace 直後の文字入力では、削除結果が見えるまで最大160ms 表示を遅らせる。キー表示は操作の間維持し、最後の更新から同じ時間式で消す。操作と同期する内容は「実操作と同期」に従う。動きを減らす設定では、同じ時間式で opacity のみを遷移させる。

### 操作・場面ごとの共通注釈

| 操作・場面 | 現れる共通注釈 |
| --- | --- |
| マウス移動・クリック | 対象の位置へ出現するカーソル、操作待ちの間の対象枠、クリック位置の波紋。ポップアップや画面遷移の前にも出現と押下が見える |
| 文字入力・値の変更 | 入力先の枠、task label、入力帯の連続した入力文字列、変更後のフィールドや結果領域の結果枠とラベル |
| キー操作・ショートカット | 対象の枠、実際のキー名のキー表示、移動後のフォーカス先や変化した領域の結果枠とラベル |
| スクロール | 移動の過程が追える映像と、ホイール操作の始点へ出現するカーソル、ホイール操作の種別（`ScrollDown` / `ScrollUp`）を示す画面中央のキー表示 |
| hover・ドラッグ | hover 先の枠、ドラッグの押下・保持移動・解放とその結果を実操作の時間軸で示す |
| クリックを伴わない状態変化 | 変化した領域（ローディング、通知、値・一覧の更新など）の結果枠とラベル、task label の番号と check |
| popup・別タブ・iframe | 開く操作の共通注釈と、移動先のページ・frame に再設置した注釈 |

### 時間の間隔

ステップ動画の長さは注釈の最低表示時間だけで決める。視聴者はビューアで自分のタイミングでステップを見るため、視聴時間を録画内の固定待機で担保しない。時間は注釈の動きではなく動画の経過時間で測る。

- 操作待ち: 対象の可視化・操作可能性など操作前の準備を終え、task label・操作対象の注釈がすべて実際に映った時点から操作を始めてよい。準備や描画待ちの自然な待機は短縮・省略しない
- 操作中: カーソルは左上余白から400ms で対象へ接近し、到着してから操作する前に最低 400ms 止める。文字入力は 1 文字ごとに 120ms 以上空ける。`fill()` など keydown なしで瞬時に完了する代行操作は、入力帯の文字列と対象の枠を最低 600ms 表示してから結果の確認へ移る
- 操作終了: 操作終了でカーソルを消す。操作終了の時刻が badge の check のフェード開始時刻になる。結果枠とラベルは、確認対象の出現と描画の安定を待って表示する。待機中にページ本来の状態更新を遅らせない
- 結果表示: 各確認箇所の枠・ラベル・確認する内容が実際に映った時点から最低 1 秒維持する。前の確認枠とラベルを消してから次の確認枠とラベルを出すまで 0.2 秒空ける。最後の確認箇所の表示時間を終えたら録画を確定させる

遷移・リロード・別タブを挟むステップでは、移動先の描画が落ち着いてから結果の確認へ移り、各確認箇所の表示時間を改めて満たす。視聴者が読む時間はビューアのリプレイと一時停止で担保されるため、これ以上の待機を録画に埋め込まない。

### 実操作と同期

ドラッグは同一 document 内で source→target の直線を400ms ease-in-outで移動する。source到着後400ms静止してdown、固定円を保持してtargetへ移動し、到着後押下したまま400ms保持してupする。upの実操作終了時刻からcheckを開始する。driver.drag({ source, target, result/results, anchor? }) は必要な2つのlocatorを受け、既存anchor・結果契約へ接続する。任意経路・HTML DnD・autoscroll・別documentの自動支援は含めない。例外時は押下入力を解放し、原エラーを保持する。

カーソルの接近は全ステップでページ映像の左上余白（pageArea.x + 24s, pageArea.y + 24s）から対象中央へ、CSS transform の400ms ease-in-out（0.42,0,0.58,1）で行う。実マウスも表示の実測先端へ中間 move を送り、同じ経路・時間軸を追従する。毎フレームの overlay.update で位置を描かない。到着後400ms静止し、hover によるサイト更新は移動途中・到着時から許す。表示と離散入力の送出遅延・位置誤差はブラウザーで計測し、完全一致とは主張しない。`scrollIntoViewIfNeeded()` による瞬間移動だけで画面外のクリック対象を見せたことにしない。スクロールでは、シナリオの挙動を変えずに済む場合は長い移動を小刻みな wheel 操作にし、画面外の対象へは先に滑らかに移動してから操作する。スクロールによる遅延読込などで検証対象の挙動が変わる場合は元の操作を維持し、移動を task label と画面上の到着位置で補う。装飾は録画中の DOM オーバーレイで操作・変化と同期させる。後処理で加える表現も、元の映像と時刻が一致する場合に限る。局所拡大、静止保持は、既にある映像と注釈の見せ方を変える範囲で読みやすさの補助として選べる。ただし、実際の移動・待機・失敗を消したり、保持を実際の表示時間と混同させたりしない。

キー表示は画面上の入力文字列と区別し、実際の操作に対応させる。フォーム送信を `Enter` で行う場合は送信前に `Enter` を表示し、クリック送信ならボタンの位置へ出現するカーソルと波紋で示す。ブラウザー側の `Ctrl+R` や `Alt+←` が Playwright のキー送出では動作しない場合は、キー表示に「操作案内」を明記してから `page.reload()` / `page.goBack()` を呼ぶ。実キー入力時のキー表示と API による代行を区別し、キーを押したと偽らない。キー入力を伴わない操作も task label と対象・結果の枠で示し、視覚表現のない操作を残さない。

入力中の文字は一つの連続した文字列として表示する。`Ctrl + A` / `Meta + A` は帯を操作名に置き換え、続く文字入力は新しい文字列として表示し、Backspace では削除後の文字列に更新する。`locator.fill()` のように keydown なしで文字入力対象に `input` が起きた場合は、その対象の値を表示する。checkbox など文字入力対象でない要素の `input` は帯に値を出さず、対象の枠と状態変化で示す。文字が順に増える様子で入力を示すため、録画ケースの文字入力は操作の意味が変わらない限り `pressSequentially()` で 1 文字ずつ行い、`fill()` などの一括設定で映す箇所を作らない。長い値などで 1 文字ずつが現実的でない場合だけ一括設定を使い、その箇所と理由を報告する。

装飾は DOM に要素を追加する。スクリーンショット比較や全要素数を調べるアサーションには影響しうるため、その間だけ装飾を隠すなどして期待値とテストの意味を維持し、装飾なしの結果とも照合する。維持できなければ録画の制約として報告し、合否が変わらないとは主張しない。ポップアップ、複数ページ、iframe 内の操作では、装飾するページと動画の選択を調整する。ページ映像の切り替えでは URL の露出を確認し、フォーカス先の強調は `activeElement` や DOM 装飾だけで正しいと断定せず映像と照合する。画面外のアサーションやネットワーク結果を画面上の成功表示と混同しない。

## 録画ドライバ

録画ケースは、ステップの実行と注釈の更新を同梱の録画ドライバ（`step-driver.mjs`）へ任せられる。ドライバは、単一 document 内のクリック・文字入力・キー操作・hover・ドラッグ・スクロールの実操作を吸収し、ステップごとに「task anchor の実測採寸 → 注釈の予告 → 実操作の実値転送 → check の開始 → 結果枠の表示 → 視聴時間の待機」の順で実行する。ページ遷移・リロード・別タブ・iframe 内の操作・dialog・Playwright のキー送出で代行が必要なキー操作は録画ケース側の責務であり、ドライバへ含めない。録画ケースが直接行う操作も、この spec の注釈・時間・同期の規定に従う。

ドライバは録画セットのタイトルとステップの操作文・動画パスを 1 箇所の宣言（`{ title, steps }`）から読む。その宣言から、「ビューアと生成スクリプト」節の入力と同じ形状の `metadata.json` データ（`{ title, steps: [{ number, action, video }] }`、`number` は宣言順に 1 から採番）を生成できる。

ドライバが消化するステップは 1 つとする。実操作では、カーソルの出現位置、クリック位置、入力文字列の累積、キー名を、操作 document の `performance.now()` の時刻とともに注釈へ転送する。文字入力は 1 文字ずつの入力と一括設定の両方を吸収し、一括設定では入力帯と対象枠の表示を一括設定後の表示時間だけ維持する。確認対象は録画ケースが対象の locator と期待値で渡し、ドライバはその出現を待って実測矩形の結果枠と結果ラベルを表示する。複数の確認箇所は 1 組ずつ表示し、組の間は切替間隔だけ空ける。ドライバは操作と注釈だけを行い、アサーションの合否を判断せず、check を合格の意味に使わない。

採寸できない対象（frame 内の要素など）、操作の途中で document が変わる場合は、ドライバはその操作を行わず例外で停止する。anchor は操作対象の矩形が既定であり、操作対象より意味のある広さの行・入力欄を含むコンテナを anchor にするときは、録画ケースが anchor の locator をドライバへ渡す。スクロールでは採寸できる対象があればその枠を示し、ホイール操作を小刻みに分割して `ScrollDown` / `ScrollUp` のキー表示を中央基準で示す。

ドライバの待機時間は次の値であり、いずれも「時間の間隔」の最低時間を満たす。

| 区間 | 値 | 「時間の間隔」の最低 |
| --- | --- | --- |
| 予告（注釈を設置してから操作するまで） | 1800 ms | — |
| カーソルの接近・保持移動 | 400 ms | 400 ms |
| 到着後の操作までの停止 | 400 ms | 400 ms |
| 1 文字ごとの入力間隔 | 120 ms | 120 ms |
| 一括設定後の入力帯と対象枠の表示 | 600 ms | 600 ms |
| 結果の視聴（各確認箇所） | 3000 ms | 1000 ms |
| 結果枠・ラベルの切替間隔 | 200 ms | 200 ms |

## ビューアと生成スクリプト

`review-kit` フォルダ直下の各 `<flow>` フォルダの録画データから、フロー切替つきステップビューアの単一 HTML（`review-kit/index.html`）を生成する。ビューアはサーバーなしの `file://` で開ける。生成には同梱テンプレート `viewer.html` を使い、ビューアの見た目・振る舞いの正本はこの節である。

### 入力: <flow>/metadata.json

`review-kit` フォルダ直下の各サブディレクトリをフローとみなし、そのフォルダ名をフロー識別子とする。フローの並びはフォルダ名の昇順である。`<flow>/metadata.json` は `title` と `steps` を持つ JSON オブジェクトである。

- `title`: 非空の文字列。フローのタイトル
- `steps`: 非空の配列。配列順が再生順であり、その `<flow>` の正本（プロジェクト SPEC.md のセクション）のステップ番号と 1 対 1 に対応する
- 各要素は `action`（非空の文字列。操作文）・`video`（`<flow>` フォルダからの相対パス。実在する動画ファイルを指す）を持つオブジェクトである

### 生成: index.html

`node build-viewer.mjs <review-kit フォルダのパス>` を実行すると、`<review-kit フォルダ>/index.html` を書き出す。

- 埋め込む録画データは `{ flows: [{ id, title, steps: [{ number, action, video }] }] }` の形状である。`id` はフロー識別子、`number` はフロー内で配列順に 1 から採番する
- ステップ動画は `index.html` からの相対パス（`<flow>/<metadata.json の video>`）で参照する
- 入力が不正な場合は、ファイル名とステップ番号を含むエラーで停止し、`index.html` を書き出さない

| 不正な入力 | 結果 |
| --- | --- |
| フローとなる `<flow>` フォルダが1つもない | フォルダ名を含むエラーで停止する |
| `<flow>/metadata.json` が存在しない | ファイル名を含むエラーで停止する |
| `<flow>/metadata.json` が JSON として読めない、またはオブジェクトでない | ファイル名を含むエラーで停止する |
| `title` が非空の文字列でない | ファイル名を含むエラーで停止する |
| `steps` が非空の配列でない | ファイル名を含むエラーで停止する |
| ステップの `action` が非空の文字列でない | ファイル名とステップ番号を含むエラーで停止する |
| `video` が相対パスでない（絶対パス、`..` 開始、非空文字列でない） | ファイル名とステップ番号を含むエラーで停止する |
| `video` が指すファイルが存在しない | ファイル名とステップ番号を含むエラーで停止する |

### ビューアの振る舞い

生成された `index.html` を `file://` で開いたときの振る舞い。

- フローの一覧をボタンで表示し、クリックでフローを切り替えられる
- フローを切り替えると、そのフローで最後に表示していたステップを表示して再生する。そのセッションで未表示のフローでは最初のステップを表示する
- ステップ一覧に現在のフローの各ステップの番号（フロー内 1..N）と操作文を表示する
- 一覧クリック、Previous / Next ボタン、← / → キーでフロー内のステップを移動できる
- Replay ボタンと R キーで、現在ステップの動画を最初から再生する
- ステップ移動時は前の動画を停止し、移動先のステップ動画を自動で再生する
- 初期表示では動画を自動再生しない
- 動画が終わっても次のステップを自動で再生しない
- 表示テキストは英語である
- 録画データが読めないときは、ビューアの代わりに通知を表示する

### ビューアの見た目

- 配色と書体は録画注釈の色トークンと書体を継承する。明るい表示では背景に `title-surface`、主文字に `text`、補助文字に `secondary`、区切り線に `line` を使う。カード面（一覧項目・操作など）は明るい表示では白、`prefers-color-scheme: dark` では `#171A21` とし、全体の配色も注釈の dark 値（背景 `title-surface` の `#111318`、強調 `accent` の `#B7AFFF` など）へ切り替わる。ビューアの明暗は OS の設定に従い、録画したサイトのテーマには連動しない
- 書体は録画注釈と同じ sans-serif と mono のスタックで、ステップ番号・ステップ数は mono とする
- レイアウトは、上部に現在のフローのタイトルとステップ数、その下にフロー切替ボタン列、左にステップ一覧（番号チップ・操作文）、主領域に現在ステップの動画ステージと操作文の詳細、前のステップ / リプレイ / 次のステップの操作を置く。動画ステージは16:9 の黒背景に動画を内接させ、幅が狭いときはステップ一覧を主領域の上へ縦に積む
- フロー切替ボタンは操作ボタンと同じカード面と枠を用い、現在のフローを `active-fill` の枠で示す
- 現在ステップの一覧項目は `active-fill` の枠と番号チップ（`on-active` の数字）で示し、主操作（リプレイ）の面は明るい表示では `active-fill`、dark では `accent` を使う。動画がない・読めないステップではステージに通知を重ねる
- 主領域の下部に、このビューアを録画のレビュー専用とする注記（英語）を置く。自動テストの結果はランナーの結果から読み、動画内の注釈から推測しない
- 動きを減らす設定では遷移アニメーションを無効化する
