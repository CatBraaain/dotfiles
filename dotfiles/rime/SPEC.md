# Kagiroi 日本語入力

Windows の Weasel と Linux の fcitx5-rime で共通に使う Rime ユーザー設定の仕様である。Kagiroi のスキーマ・辞書・Lua プラグインが利用可能な環境を前提とし、利用者と実装・検証担当者が「今の状態でキーを押した結果」を読むために定める。設定ファイルは dotfiles で管理する。

- 日本語入力と半角英数入力は IME ON。半角英数入力も未確定文字列を編集する。IME OFF は半角文字をアプリへ直接入力し、未確定文字列を作らない。
- 読みはローマ字入力から得たかな等の文字列、文節は変換対象となる連続した読みの区間。`|` は文節境界、対象文節は今操作している文節を表す。
- OFF 予約は、未確定文字列を削除し終えるまで IME OFF への移行を保留する状態。解除・保持の条件は「半角切替と OFF 予約」に従う。

## 共通前提

操作表は Rime に到達するキーイベントを対象とする。Linux frontend が物理無変換を処理する境界は[配置](#配置)に従う。表示は、アプリ内の未確定文字列（preedit）の表示に対応し、アプリ内表示が有効な環境で読む。

- キー列は左から順に押す。`ka` は `k → a` の2打鍵、`Shift+A` は修飾付きの1打鍵。文字追加・削除の例はキャレット末尾を前提とする。`␠` は半角空白1個、`　` は全角空白1個。
- 例に示す候補順・第一候補はその例の前提であり、辞書・学習に対して常に同じ順位を要求するものではない。

## 状態

表の「未入力」「変換前」「変換済み」「一覧表示中」は日本語入力の状態である。

| 状態 | 定義 |
| --- | --- |
| 日本語入力：未入力 | 未確定文字列がない状態。 |
| 日本語入力：変換前 | 候補への変換前の未確定文字列がある状態。アプリ内には入力中の読みを表示する。文字入力は「ローマ字表」「n の過不足補完」「共通の文字対応」に従う。 |
| 日本語入力：変換済み | 未確定文字列を候補へ変換した状態。候補一覧は表示せず、アプリ内には全文節の現在の表示文字列を順に連結したものを表示する。候補操作は対象文節だけに作用する。 |
| 日本語入力：候補一覧表示中 | 変換モードで対象文節の候補一覧が開いている状態。アプリ内には全文節の現在の表示を順に連結し、対象文節の選択変更に追従する。非展開は最大10件/ページ、展開は最大30件/ページ。「候補一覧の見た目」にラベル等を定める。 |
| 半角英数入力 | IME ON のまま半角文字を未確定文字列へ追加・編集する状態。OFF 予約の有無と、切替前から保持した一覧の有無を区別する。切替で保持する内容は「半角切替と OFF 予約」に従う。 |
| IME OFF | 未確定文字列を作らない状態。 |

## IME OFF の操作

- 非修飾の `Zenkaku_Hankaku` press: 日本語入力の未入力へ。
- `Zenkaku_Hankaku` release / 修飾付き（例: `Control+Zenkaku_Hankaku`）: モードを切り替えない。
- 左 Shift 単独の押下・解放: [モード・予約・未確定文字列・一覧の開閉/展開/選択をすべて保持する](#左-shift-単独)。
- その他（`Muhenkan` を含む）: 半角文字をアプリへ直接入力するか、通常の frontend 動作に従う。

## 操作の細則

### 変換の開始

変換前の `Space` は、[n の過不足補完](#n-の過不足補完)後の全読みを[自動分割](#文節と境界変更)し、全文節の第一候補を連結表示する。対象は先頭文節とし、一覧は閉じたまま変換済みへ移る。

変換前の `Henkan` は、読み全体を1文節としてカタカナ第一候補を表示する。

### Space で一覧を開く

- 通常の変換済み: 対象文節の次候補を選んで一覧を開く。最後の次は第一候補とし、唯一候補なら選択を変えず一覧を開く。
- 直前が `Henkan`: その1文節の通常第一候補へ戻り、一覧を閉じた変換済みを維持する。さらに次の `Space` で一覧を開く。

### 確定と次入力

- `Enter` は、現在表示している未確定文字列全体を表示どおりに一括確定する。変換中は全文節の表示を順に連結し、辞書候補がない文節の読みも含める。入力中に済んだ n のペア消費・不足補完は含むが、確定時に末尾 n 補完・過剰補正はしない。テンキーの Enter（Windows の拡張 `VK_RETURN` / Linux の `KP_Enter`）も同じ。

「確定して次入力」は、表示中の全体を一括確定し、押したキーで次の入力を開始する。非修飾のアルファベットはローマ字入力、数字・記号・句読点・テンキーの文字キー（Enter を除く）は[共通の文字対応](#共通の文字対応)に従う。

確定は予約を解除する。一覧表示中の確定は一覧を閉じて展開も解除し、次の入力も閉じた一覧から始める。`Enter` 後は半角英数入力からも日本語入力の未入力へ移る。

### 文字追加

文字を加える操作は、末尾へ追加し、予約を解除して一覧を閉じ、展開も解除する。日本語入力の字形は[共通の文字対応](#共通の文字対応)、ローマ字入力は[ローマ字表](#ローマ字表)・[n の過不足補完](#n-の過不足補完)に従う。半角英数入力では半角文字を加え、`Space` は半角空白 `␠` を加える。未入力の `Space` は全角空白 `　` の即確定入力であり、未確定文字列を作らない。

- Shift+アルファベット: 半角大文字を加える。日本語入力からは表示を保持して半角英数入力へ移り、変換前の未完成ローマ字も保持する。未入力からは予約なしで開始する。

### 削除後の状態

`Backspace` は末尾1文字を削る。変換済み・一覧表示中では、全文節の表示を連結した文字列から削り、一覧を閉じて展開を解除する。変換前・半角英数入力の `Esc` は全消去する。

- 文字が残る場合: 日本語入力は変換前、半角英数入力はそのまま。予約の有無を保持する。
- 空になる場合: 変換前・半角英数入力では、予約ありなら IME OFF、予約なしなら日本語入力の未入力。変換済み・一覧表示中からの削除なら日本語入力の未入力。

全消去後のモードは、入り方の履歴ではなく予約の有無で決まる。

### Esc で変換を戻す

- 変換済み: 全文節を連結した読みに戻して変換前へ移る。かなはひらがなにし、混在する英数字・記号は保持する。展開は解除する。
- 一覧表示中: 文節ごとの選択候補と対象文節を保持して一覧を閉じ、変換済みへ移る。

### 一覧の展開と折りたたみ

`Tab` は選択位置を保持して最大30件/ページへ展開し、展開後は無操作。`Shift+Tab` は展開中の選択位置を保持して最大10件/ページへ折りたたみ、非展開なら無操作。

### キャレット移動

変換前の `Left` / `Right` は、文字列と予約を保持してキャレットを左 / 右へ移す。

### ショートカット

次のキーは、IME ON の全5状態で Rime の編集・モード切替・emoji切替に割り当てず、キーイベントを消費せずアプリへ渡す。

- 編集: `Control+p` / `Control+n` / `Control+b` / `Control+f` / `Control+a` / `Control+e` / `Control+d` / `Control+k` / `Control+h` / `Control+g` / `Control+bracketleft`
- モード切替: `Control+Shift+1`〜`Control+Shift+5` と、対応する記号キー `Control+Shift+exclam` / `Control+Shift+at` / `Control+Shift+numbersign` / `Control+Shift+dollar` / `Control+Shift+percent`
- emoji切替: `Control+q`

### 左 Shift 単独

単独の押下・解放は、モード・予約・未確定文字列・一覧の開閉/展開/選択をすべて保持する。

## 候補選択の循環

候補選択は対象文節だけに作用し、確定しない。キーごとの循環範囲は次のとおり。

- `Space`: 展開の有無によらず、ページをまたいで全候補の次候補を選ぶ。最後の次は第一候補。
- `Up` / `Down`: 前 / 次候補を選ぶ。非展開では表示中の最大10件で循環し、展開ではページをまたいで全候補を循環する。半角英数入力で保持した一覧から選ぶ場合も同じ選択規則に従う。
- `PageUp` / `PageDown`: 前 / 次ページの先頭候補を選ぶ。先頭ページの前は最終ページ、最終ページの次は先頭ページへ循環する。1ページだけでもその先頭候補を選ぶ。

## 操作例

### 文字の追加・削除と変換解除

- 未入力で `k` は `k`、`ka` は `か` の変換前となる。`Shift+A` は `A` の半角英数入力となる。
- 変換前の `か１k` / `か1k` に `i` を入力すると `か１き` / `か1き` となる。
- 通常候補順 `蚊 / か` の読み `か` は、変換前で `Space` を押すと `蚊`、`Henkan` を押すと `カ` になる。
- 変換済みの `今日` に `k` / `1` / `KP_1` を入力すると、`今日` を確定して `k` / `１` / `1` を表示し、変換前へ移る。
- 変換済みの `今日` に `Shift+A` は `今日A` の半角英数入力になる。
- 変換済みの `今日` に `/` / `.` は、`今日` を確定して `・` / `。` の変換前になる。
- `Backspace` は変換済み・一覧表示中の `今日` を `今` にする。一覧表示中の `京` は空になる。
- 変換済みの `今日|Ab1・` は `Esc` で `きょうAb1・` の変換前になる。

### 一覧を開く・閉じる・文字を追加する

例えば通常候補順 `蚊 / か` の読み `か` に `Space → Space` を押すと、`蚊` への変換後に `か` を選んだ一覧が開く。唯一候補なら、その候補の一覧が開く。`Henkan → Space` では `カ` から `蚊` に戻り、一覧はまだ開かない。

一覧表示中の `,`・`.`・`-`・`=` もページ送りではなく[確定して次入力](#確定と次入力)となる。選択候補 `京` の1文節に `-` / `,` / `KP_Decimal` / `KP_Separator` を入力する例では、`京` を確定して `ー` / `、` / `.` / `,` の変換前になる。一覧は閉じ、展開も解除する。

読み `きょう`、候補順 `今日 / 京 / 凶` で `京` を選んでいる例では、`Esc` で `京` のまま変換済み、次の `Esc` で `きょう` の変換前、さらに `Esc` で全消去して未入力となる。

### 半角英数入力・予約・IME OFF

例えば `Ab1` から日本語入力へ戻って `ki` を入力すると `Ab1き`、テンキーの `KP_1 → KP_Decimal → KP_Separator` を半角入力で `A` に加えると `A1.,` となる。

予約ありの `か` から日本語入力へ戻ると変換前予約となる。そこで `Tab` は予約を保ち、続く `Backspace` による全消去で IME OFF になる。一方、`Space` は予約を解除して通常の変換を行うため、その後 `Esc → Esc` で全消去すると日本語入力の未入力になる。

IME OFF で非修飾の `Zenkaku_Hankaku` press の後、続く `ka` は `か` の変換前となる。IME OFF の `a` はアプリへ直接入力する。

## 共通の文字対応

日本語入力で加える文字を定める。追加位置と状態遷移は[キーと状態の操作表](#キーと状態の操作表)に従う。テンキー名は Windows / Linux の順で併記し、`KP_*` は Windows の Rime 内部でも使う共通キー名である。テンキー記号は日本語入力・半角英数入力のどちらでも半角で加える。`ascii_punct`（半角句読点モード）はセッション開始時に毎回無効になる。

| キー | 動作 |
| --- | --- |
| 数字キー | 全角 `０`〜`９` を加える |
| テンキーの数字（`VK_NUMPAD0`〜`VK_NUMPAD9` / `KP_0`〜`KP_9`） | 半角 `0`〜`9` を加える |
| テンキーの小数点（`VK_DECIMAL` / `KP_Decimal`） | `.` を加える |
| テンキーのカンマ（`VK_SEPARATOR` / `KP_Separator`） | `,` を加える |
| `KP_Add` / `KP_Subtract` / `KP_Multiply` / `KP_Divide` / `KP_Equal` | `+` / `-` / `*` / `/` / `=` を加える |
| `,` / `.` | `、` / `。` を加える |
| `-` | `ー` を加える |
| `/` / `\` / `~` | `・` / `￥` / `〜` を加える |
| 縦線キー | `·` を加える |
| `[` / `]` / `{` / `}` | `「` / `」` / `『` / `』` を加える |
| `'` / `"` | 引用符のペア `‘’` / `“”` を加える |
| 上記以外の ASCII 記号 | 対応する全角字形を加える |

## n の過不足補完

入力中と変換時にはペア消費・不足補完を行い、過剰補正は変換時だけ行う。以下の表と例は、未入力から各入力を終えたときの表示と、変換前の `Space` で変換へ渡す読みを示す。実際の候補表示は[変換の開始](#変換の開始)に従う。読み `かん`・`かんあ`・`かんな` が1文節で読み自体を第一候補に持つ例では、変換後もその読みを表示する。

| 入力 | 入力中の表示 | Space 時の読み |
| --- | --- | --- |
| `kana` | `かな` | `かな` |
| `kanna` | `かんあ` | `かんあ` |
| `kannna` | `かんな` | `かんな` |
| `kannnna` | `かんんあ` | `かんな` |
| `kanji` | `かんじ` | `かんじ` |
| `kannji` | `かんじ` | `かんじ` |
| `kannnji` | `かんんじ` | `かんじ` |
| `kannnnji` | `かんんじ` | `かんじ` |

- ペア消費: 2個目の `n` の打鍵で `nn` を「ん」にする。消費した `n` は、後続の母音や `y` に補わない。例えば `nnyo` は、入力中の表示も `Space` 時の読みも `んよ` となる。
- 不足補完: 入力中は直後に子音が来た `n`、変換時は末尾の `n` を「ん」にする。例えば `kan` は入力中に `かn`、`Space` 時の読みは `かん` となる。`y` が続く場合は「ん」にせず、`nya` は入力中の表示も `Space` 時の読みも `にゃ` となる（`んや` にはしない）。
- 過剰補正: 日本語の語に「んん」という連続は存在しないため、変換時に連続する「ん」を1つに畳む。余った「ん」は、直後の `a`・`i`・`u`・`e`・`o`・`y` と次の音節を作る頭の `n` として結合する。例えば `kannnnen` は入力中に `かんんえn`、`Space` 時の読みは `かんねん` となる。

## 半角切替と OFF 予約

### 切替キー

`Muhenkan` / `Zenkaku_Hankaku` は、日本語入力の未入力なら IME OFF、未確定文字列があれば OFF 予約を作って半角英数入力へ移る。切替時は変換表示・未完成ローマ字・候補一覧の開閉・展開・選択を保持する。

半角英数入力では、`Muhenkan` は未確定文字列があれば保持して OFF 予約を作り、予約中も保持する。未確定文字列がなければ IME OFF へ移る。`Zenkaku_Hankaku` は未確定文字列と予約を保持して、日本語入力の変換前へ戻る。

日本語入力へ戻ると、保持した表示・未完成ローマ字・半角入力中の追加文字を再解釈せず変換前の編集対象とし、続くローマ字だけをかなへ変換する。

### OFF 予約の解除と保持

OFF 予約は文字追加・確定・変換・候補選択で解除し、削除・キャレット移動・左 Shift 単独・実際に何も起こさないキーでは保持する。文字追加時の一覧処理は[文字追加](#文字追加)、全消去後のモードは[削除後の状態](#削除後の状態)に従う。

### 保持した一覧からの選択

半角英数入力で保持した一覧からの候補選択は `Up` / `Down` に限る。一覧を保持しているときは[前 / 次候補を選び](#候補選択の循環)、予約を解除して日本語入力の一覧表示中へ戻る。一覧の展開状態は保持する。一覧なしの `Up` / `Down` は未規定である。他のキーは[キーと状態の操作表](#キーと状態の操作表)の半角英数入力の列に従う。

### 切替と予約の例

例えば `かn` から `Muhenkan → Enter` で確定する表示は `かn`。`Shift+A → Zenkaku_Hankaku → ki` なら `かnAき` となる。未完成の `k` から `Muhenkan → a → Zenkaku_Hankaku → ki` なら `kaき`、変換表示 `今日` から `Muhenkan → b → Zenkaku_Hankaku → ki` なら `今日bき` となる。

展開した一覧で `京` を選んだまま `Muhenkan` を押す例では、半角英数入力に予約と一覧を保持する。続く `Down` は `凶` を選んで日本語入力の一覧へ戻り、展開も保持する。非展開の同じ候補順で `Up` なら `今日` を選び、非展開を保持する。`Space` を押す場合は候補選択でなく半角空白追加となり、`京␠` の半角英数入力へ移って予約・一覧・展開を解除する。

## 文節と境界変更

全読みを辞書と連接評価で自動分割し、辞書候補も[基本字形候補](#変換候補と学習)もない文節は読みを唯一の候補とする。読み `きょうはかれー` は `きょうは|かれー` に分割する。各第一候補が `今日は / カレー` なら表示は `今日はカレー`、`Esc` で読みに戻すと `きょうはかれー` となる。他の読みの境界は辞書・連接評価・学習に応じて決まり、境界伸縮で調整できる。

### 文節移動

変換済み・一覧表示中の `Left` / `Right` は、前 / 次の文節へ対象を移す。全文節を未確定のまま保ち、各文節の選択候補を保持する。候補操作は対象文節だけに作用し、一覧を開くと対象文節の候補だけを表示する。ページは送らない。

- 変換済み: 一覧を閉じたまま対象を移す。
- 一覧表示中で対象が変わる場合: 一覧を閉じ、展開を解除して変換済みへ移る。
- 先頭での `Left` / 末尾での `Right`: 対象を動かさず、一覧の開閉・展開・選択と状態を保持する。

例えば文節1の候補順が `今日は / 京は`、文節2が `カレー / かれー` の各第一候補で文節1の一覧が開いている場合、`Right → Down` の `Right` で対象は文節2へ移り、一覧を閉じた変換済みになる。続く `Down` は未規定である。`Right → Space` なら文節2の次候補 `かれー` を選んで一覧を開き、表示は `今日はかれー` になる。文節1はそのまま、一番左・右の文節を越えて移動しない。展開した一覧で末尾の `Right` を押しても、一覧と展開・選択はそのまま保つ。

### 境界変更

`Shift+Left` / `Shift+Right` は、対象文節の末尾境界を縮める / 伸ばす。

境界を動かす単位は読みの Unicode コードポイント1個。小書きかな・長音符・英字・数字・記号も各1文字として数える。

- 縮める場合: 対象の読みが2文字以上なら末尾1文字を次文節の先頭へ移す。最後の文節なら、その文字を切り出して新しい次文節を作る。読みが1文字なら境界を保つ。
- 伸ばす場合: 次文節の先頭1文字を対象の末尾へ取り込み、空になった次文節は除く。最後の文節なら境界を保つ。
- 境界が動いた場合: 読みが変わった両側を第一候補へ再変換する。対象文節は同じ文節を保ち、読みが変わらない文節の境界・選択候補を保持する。変換済みでは一覧の開閉・展開を保持する。一覧表示中では一覧を閉じ、展開を解除して変換済みへ移る。
- 境界が動かない場合: 文節の境界・選択候補、一覧の開閉・展開・選択と状態を保持する。

例として、読み `あい|う|え`、選択 `愛|宇|絵` の文節1を縮めると `あ|いう|え`、伸ばすと `あいう|え` になる。新しい読み `あ`・`いう`・`あいう` に辞書候補がなければ表示は `あいう絵` で、文節3の `絵` は保持する。展開した一覧で縮めた場合は一覧を閉じ、展開を解除して変換済みへ移る。再び `Space` を押すと、対象の唯一候補 `あ` を選んだ非展開の一覧が開く。

最後の1文節 `あい` を縮めると `あ|い`、`きゃ` を縮めると `き|ゃ` になる。各新しい読みに辞書候補がなければ各読みを表示する。

読み1文字の `う|え` を縮めても `宇|絵` は変わらず、最後の文節 `あい` を伸ばしても選択 `愛` は変わらない。境界が動かないこの2例では、展開した一覧と選択もそのまま保つ。

## 候補一覧の見た目

一覧は既定で閉じ、入力開始・確定後の次入力では閉じる。新たな一覧は非展開の最大10件から始まり、上限未満なら存在する候補だけを表示する。確定後の次の読み入力、`Backspace` または `Esc` で読みに戻ったときは展開を解除し、次の一覧も最大10件から始める。

ラベルは各ページの先頭から `1`〜`30` の連番にし、ページごとに `1` へ戻す。filter 後の最終表示順で各ページの先頭候補に `Page 1`、`Page 2`、… を補足表示し、既存の補足情報も残す。候補ウィンドウ上部の読みは、アプリ内 preedit とは別の表示である。

例えば読み `こう` の候補順が `公 / 工 / 口 / 江 / 幸 / 向 / 后 / 好 / 考 / 行 / 孝 / 抗 / 攻 / 更 / 効 / 肯 / 侯 / 厚 / 洪 / 皇 / 紅 / 郊 / 香 / 校 / 航 / 貢 / 高 / 康 / 控 / 黄 / 港` の31件で、`公` の既存補足が `共通` の場合、展開すると Page 1 は `公`〜`黄` の30件、Page 2 は `港` の1件になる。各ページのラベルは `1`〜`30` と `1`、先頭の補足は `Page 1` と `共通`、`Page 2` となる。

この例で非展開の先頭10件なら、`Up` は `公` から `行`、`Down` は `行` から `公` に循環する。展開中なら `公` の前は `港`、`行` の次は `孝`、`黄` の次は `港`、`港` の次は `公`。ページ移動は選択中の `工` を保つのでなく移動先の先頭を選び、Page 1 から前・次どちらへ送っても `港`、Page 2 から Page 1 へ送ると `公` になる。

## 変換候補と学習

Rime の選択スキーマは Kagiroi とする。ローマ字入力は Kagiroi 標準のローマ字 processor（Lua の kana speller と script_translator）の仕組みに従い、「ローマ字表」の対応と n の過不足補完を使う。

変換候補には入力中の読みと一致する語と、読みから変換できる辞書語を含める。例えば `かんじ` には `かんじ`・`漢字`・`感じ` のいずれか、`かな` には `かな` を含める。数字・記号・句読点・半角アルファベットも変換対象とし、英数字には辞書候補の有無によらず、元の表記、全角・半角、大文字・小文字の基本字形候補を含める。1文節になる条件で辞書候補のない `q` にも、`q`・`ｑ`・`Q` を候補として示す。かなと英数字が混在する文字列の区切りや変換対象は、既存の変換処理に従う。

絵文字候補機能は既定でオフとする。

選択して確定した候補はユーザー辞書に記録し、同じ読みでは選択した回数に応じて上位に表示する。

## ローマ字表

ローマ字からかなへの対応の正本は `dotfiles/rime/roma.data.yaml` の宣言である。`dotfiles/rime/roma.build.ts` が build 時に宣言から `kagiroi_dotfiles_romaji.dict.yaml` を生成し、辞書そのものをリポジトリに置かない。宣言は MS-IME 用の宣言（`undotfiles/ime/roma-table.yaml`）から独立しており、両者の一致は保証しない。Kagiroi 標準の `kagiroi_romaji` 辞書は `import_tables` で取り込まず、`speller/algebra` の派生綴り（`ti` → `chi` など）も無効にする。宣言と Kagiroi 標準の綴り衝突は宣言側のかなで置き換わる（`wi` は `うぃ`、`tha` は `ちゃ`、`va` は `ヴぁ`、`lka` は `ヵ` など）。

入力中は宣言に一致する綴りをかなへ変換する。入力中の未変換英字列全体が宣言に一致しないときも、末尾に一致する綴りがあれば最長のものをかなへ変換し、その前の英字を原文のまま残す。末尾にも一致する綴りがなければ英字列をそのまま表示する。たとえば `ka` は `か`、`fdsa` は `fdさ`、宣言にない `shi` は `sひ`、宣言にある `sha` は `しゃ` と表示される。

入力インフラとして、宣言は重複子音（`kk`・`tt` 等）に対応する促音の音節（`kkanji` は `っかんじ`）と、長音の `-` → `ー` も持つ。撥音の音節（`nk`・`nt`・`nwa`・`nwi`・`nwe`・`nwo` 等）は保持しない。子音前の「ん」は n 補完が置くため、`nka` は `んか`、`nwo` は `んを` と表示される。`q` はかなに変換せず `q` のまま表示する。

## MS-IME との比較

比較のために MS-IME の標準設定を示す。

| キー | 動作 |
| --- | --- |
| `Space` | MS-IME は一覧未表示のとき、確定せず一覧を表示して第一候補を選ぶ |
| `Tab` | MS-IME は一覧を展開してすべてのページを表示し、展開後は次候補へ移す |
| `Henkan` | MS-IME は通常の候補変換を行う |
| `F6`〜`F10` | MS-IME は文字種変換を行う |

## 配置

同じ Rime 設定を次のユーザーデータディレクトリへ配置する。

- Windows / Weasel: `%APPDATA%/Rime`
- Linux / fcitx5-rime: `~/.local/share/fcitx5/rime`

dotfiles は共通の `default.custom.yaml`、`kagiroi.custom.yaml`、`kagiroi_romaji.custom.yaml`、ローマ字表の宣言 `roma.data.yaml` と辞書生成スクリプト `roma.build.ts`、n の過不足補完と共通キー・候補操作の Lua、Weasel 固有の `weasel.custom.yaml`、Linux 固有の fcitx5 設定 `fcitx5/config` と `fcitx5/conf/rime.conf` を管理する。`fcitx5/conf/rime.conf` は、Linux の fcitx5-rime のアプリ内未確定表示を制御する設定として `~/.config/fcitx5/conf/rime.conf` へ配置する。Linux の fcitx5 では、`fcitx5/config` が `Muhenkan` を入力メソッドの無効化に割り当てる。fcitx5 が入力メソッドを無効化している間はキーが Rime に渡らず、fcitx5 の標準トリガーで戻る。Weasel の表示設定は Linux の fcitx5-rime の表示に影響しない。Kagiroi の標準ローマ字 processor とスキーマ構成を保ち、Rime が生成するデータベース、ユーザー辞書、学習データは既存内容を保持する。

Windows の Weasel では入力状態の通知とトレイアイコンを表示しない。

## 開発と検証

変更はこの SPEC、対応する自動テスト、実装の順に同期する。ローマ字表の変更は `roma.data.yaml` の宣言に対して行い、辞書は `roma.build.ts` が build 時に生成する。完了判定は `just test-rime` の成功とし、Windows の Weasel と Linux の fcitx5-rime での実機確認を要しない。
