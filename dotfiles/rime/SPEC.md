# Kagiroi 日本語入力

対象は、Windows の Weasel と Linux の fcitx5-rime から共通の Kagiroi 日本語変換を使う Rime ユーザー設定である。設定ファイルは dotfiles で管理し、Windows と Linux の各 Rime ユーザーデータディレクトリへ配置する。Kagiroi のスキーマ、辞書、Lua プラグインが利用可能な環境を前提とする。

## 変換

Rime の選択スキーマは Kagiroi とする。ローマ字からかなへの変換は Kagiroi 標準のローマ字 processor（Lua の kana speller と script_translator）の仕組みに従い、対応表は「ローマ字表」節のとおりとする。連続する `n` の入力には次節の過不足補完を挟む。編集中の読みは、漢字変換が確定する前のローマ字入力の結果として表示されるかなである。変換候補には、編集中の読みと一致する語と、読みから変換できる辞書語が含まれる。

| 編集中の読み | 変換候補に含まれる文字列 |
| --- | --- |
| `かんじ` | `かんじ`、`漢字`、`感じ` のいずれか |
| `かな` | `かな` |

## n の過不足補完

連続する `n` を含む入力は、次のように補正する。不足の補完は入力中と変換時に行い、過剰の補正は変換時にのみ行う。

- 不足:「ん」になるべき `n` が1個のとき、`n` を「ん」として扱う。入力中は `n` の直後に子音が来たとき(`kanji` は `かんじ` と表示される)、変換時は末尾の `n` に対して(`kan` は `かん` で変換される)。ただし、単独の `n` の直後が `w` のときは、「ん」にせず宣言の `nw` 合成の頭の子音として保持する(`nwa` は `ぬぁ` と表示される。「ん」+「わ」は `nnwa` と入力する)。
- 過剰: 編集中の読みに「ん」が連続しているとき(日本語の語に「んん」という連続は存在しない)。変換時に連続する「ん」を1つに畳む。余った「ん」は、直後に母音(`a` `i` `u` `e` `o` `y`)が続くとき、次の音節の頭の `n` としてその母音と結合する。

| 入力 | 入力中の表示 | Space で変換するときの読み |
| --- | --- | --- |
| `kan` | `かn` | `かん` |
| `kanji` | `かんじ` | `かんじ` |
| `kanda`、`kannda` | `かんだ` | `かんだ` |
| `kana`、`nya` | `かな`、`にゃ` | `かな`、`にゃ` |
| `kanna`、`kannna` | `かんな` | `かんな` |
| `kannnna` | `かんんあ` | `かんな` |
| `konnnitiha` | `こんにちは` | `こんにちは` |
| `kannnji` | `かんんじ` | `かんじ` |
| `kannnen` | `かんねn` | `かんねん` |
| `kannnnen` | `かんんえn` | `かんねん` |
| `nwa`、`nnwa` | `ぬぁ`、`んわ` | `ぬぁ`、`んわ` |

## Windows / Linux 共通の操作と候補表示

Windows の Weasel と Linux の fcitx5-rime で Kagiroi を使用するとき、`Zenkaku_Hankaku` は Rime の日本語入力と英字入力を切り替える。Windows の Weasel では、入力状態の通知とトレイアイコンを表示しない。候補一覧の表示中、マウスホイールでページを前後に送る。

日本語入力中は、入力開始から候補一覧を表示しない。次の入力では再び `Space` を押すまで候補一覧を表示しない。編集中の文字列があるときのキー操作は次のとおりである。MS-IME の挙動は標準設定を基準とし、数字キーだけは表中のオプションをオフにした場合と比較する。Rime 列の「同じ」は、対応する MS-IME 列の挙動を指す。

| キー | MS-IME の挙動 | Rime での設定 |
| --- | --- | --- |
| `Space` | 候補一覧を表示していないとき、入力を確定せず候補一覧を表示し、第一候補を選択する。表示しているとき、入力を確定せず選択を次の候補へ移す。最後の候補の次は第一候補に戻る | 同じ |
| `Tab` | 候補一覧を表示しているとき、候補一覧ウィンドウを展開してすべてのページを表示する。展開後の `Tab` は選択を次の候補へ移す | ウィンドウの展開はしない。選択を次の候補へ移す。`Shift+Tab` は前の候補へ移す |
| `Enter` | 選択中の候補を確定する | 同じ |
| `Backspace` | ひらがなの読みを入力中で候補一覧が非表示のときは、前字を削除する。候補一覧を表示中または `Henkan` 後は、確定せずひらがなの読みへ戻して候補一覧を非表示にする | 同じ |
| `Esc` | ひらがなの読みを入力中（候補一覧が非表示）のときは、編集中の文字列をすべて削除する。それ以外のときは、確定せず、編集中の文字列をひらがなの読みへ戻し、候補一覧を非表示にする | 同じ |
| `Henkan` | 通常の候補変換をする | 確定せず第一候補をカタカナにして候補一覧を非表示にする |
| 英字キー | 選択中の候補で確定し、押したキーを次の全角入力の読みにする | 同じ |
| 数字キー | 選択中の候補で確定し、押したキーを次の全角入力の読みにする（「メインキーボードの数字キーで候補を選択する」をオフにした場合） | 同じ |
| その他の通常入力キー | この表では比較しない | 選択中の候補で確定し、押したキーを次の全角入力の読みにする |
| F6〜F10 | 文字種変換をする | 対応しない |

候補一覧の1ページの候補数は 30 とする。MS-IME の `Tab` によるウィンドウ展開に合わせ、ほとんどの変換で全候補が1ページに収まる大きさである。候補一覧のページを前後に送る操作は `-` と `=` とマウスホイールで行い、`,` と `.` はページ操作に使わない。共有設定 `default.yaml` の `key_binder` が含める `,` と `.` のページ操作は、`default.custom.yaml` がバインディング全体を `,` と `.` を除いた共有プリセットの構成へ置き換えることで除外する。

## ローマ字表

ローマ字からかなへの対応の正本は `dotfiles/rime/roma.data.yaml` の宣言である。`dotfiles/rime/roma.build.ts` が build 時に宣言から `kagiroi_dotfiles_romaji.dict.yaml` を生成し、辞書そのものをリポジトリに置かない。宣言は MS-IME 用の宣言（`undotfiles/ime/roma-table.yaml`）から独立しており、両者の一致は保証しない。Kagiroi 標準の `kagiroi_romaji` 辞書は `import_tables` で取り込まず、`speller/algebra` の派生綴り（`ti` → `chi` など）も無効にする。したがって宣言にない綴りは、Kagiroi 標準で有効だった `shi` `chi` `tsu` `kyi` `wha` `tsa` `dhe` `fya` `ltsu` なども含めて、かなに変換されない。宣言と Kagiroi 標準の綴り衝突は宣言側のかなで置き換わる（`wi` は `うぃ`、`tha` は `ちゃ`、`va` は `ヴぁ`、`lka` は `ヵ` など）。

宣言は入力インフラとして、次の対応も持つ。

| 綴り | かな | 目的 |
| --- | --- | --- |
| 子音の重複（`kk` `tt` など） | 重複子音に対応する促音（`kkanji` は `っかんじ` と表示される） | 促音入力の音節 |
| `-` | `ー` | 長音の入力 |

撥音の音節（`nk` `nt` など）は保持しない。`n` に子音が続く入力の「ん」は n の過不足補完が置くため、`nka` は `んか` と表示される。`q` は `q` のままかなに変換されない。

## 句読点

日本語入力モードでは、`,` と `.` を押すとそれぞれ `、` と `。` を確定する。候補一覧を表示せず、編集中の文字列の有無にかかわらず押した時点で確定する。変換候補の選択中に押したときは、選択中の候補で確定した上で、句読点を入力する。`full_shape` が有効なときは、Kagiroi 標準の対応（`,` → `、`、`.` → `。`）を維持する。`ascii_punct`（半角句読点モード）はセッションの開始時に毎回無効になる。

## 配置

同じ Rime 設定を次のユーザーデータディレクトリへ配置する。

- Windows / Weasel: `%APPDATA%/Rime`
- Linux / fcitx5-rime: `~/.local/share/fcitx5/rime`

dotfiles は共通の `default.custom.yaml`、`kagiroi.custom.yaml`、`kagiroi_romaji.custom.yaml`、ローマ字表の宣言 `roma.data.yaml` と辞書生成スクリプト `roma.build.ts`、n の過不足補完と共通キー・候補操作の Lua、Weasel 固有の `weasel.custom.yaml` を管理する。Weasel の表示設定は Linux の fcitx5-rime の表示に影響しない。Kagiroi の標準ローマ字 processor とスキーマ構成を保ち、Rime が生成するデータベース、ユーザー辞書、学習データは既存内容を保持する。

## 開発と検証

変更はこの SPEC、対応する自動テスト、実装の順に同期する。ローマ字表の変更は `roma.data.yaml` の宣言に対して行い、辞書は `roma.build.ts` が build 時に生成する。完了判定は `just test-rime` の成功とし、Windows の Weasel と Linux の fcitx5-rime での実機確認を要しない。
