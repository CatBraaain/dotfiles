# 操作体験の探索

このリポジトリで扱うツールを調査するエージェントに向けた手順である。利用者が目的を達成するまでの操作と応答を観測し、仕様にまだ書かれていない問題候補を発見する。

## 作業境界

責務は探索・再現・切り分け・報告までとする。別の明示指示がなければ、発見した問題を修正しない。

spec/CSDD は、既知の観測可能な期待を正本に定め、その期待への適合を確認する。この探索は、正本に未記載の問題を発見する上流の作業である。既存の正本は期待の根拠として参照し、発見した期待を無断で正本へ追加しない。

## 探索の組み立て

1. 対象、利用者の目的、開始状態、実行環境を特定する。依頼の範囲で主要な操作経路を選び、何を達成できればよいかを置く。成果を左右する不明点は、探索前に確認する。
2. 静的解析で、操作の入口から状態更新・外部処理・表示までのつながりを追う。文書やテストにある期待と、実装から推測した期待を分ける。
3. 状態や処理のつながりから、「どの条件で、どの操作をすると、何が目的達成を妨げるか」という反証可能な仮説を立てる。仮説ごとに観測する区間と、否定できる結果を決める。
4. 実際の主要操作経路を開始から完了までたどり、仮説の箇所だけでなく前後の状態遷移も観測する。探索中に新しい手掛かりを得たら、仮説と次の操作を更新する。

症状の一覧を順に消化するのではなく、利用者の目的と観測結果に基づいて次の探索箇所を選ぶ。

## 入力から表示までの時系列観測

操作前から観測を開始し、入力、処理中の状態変化、表示の更新、操作後の安定状態を同じ時間軸で記録する。操作の送信時刻と処理・描画の完了を区別し、入力が受理されたかも確認する。

単発のスクリーンショットは、その瞬間の証拠として使う。途中の短い変化を捉えるには、利用可能な環境に応じて、時刻付きの画面録画・フレーム列・端末出力の連続取得を選ぶ。イベントや状態のログが利用できる場合は、表示の記録と時刻を対応付ける。ログだけで実際に見えた表示を断定しない。

観測方法、取得間隔またはフレームレート、観測区間を残す。間隔が粗い記録で変化が見えなくても、不発生の証拠にしない。連続観測ができない場合は、その制約と未確認の区間を報告する。

## 再現と切り分け

1. 違和感を観測したら、開始状態、操作順、入力、実行環境、観測時刻を保存する。期待する結果とその根拠を、実際に観測した事実から分けて書く。
2. 同じ開始状態から同じ操作を繰り返し、再現回数と試行回数を記録する。再現しない試行も残し、成立条件を絞る。
3. 条件を一度に1つずつ変え、問題が現れる場合と現れない場合を比較する。再現を保つ最小の操作列へ絞り、入力から表示までのどの区間で差が生まれるかを調べる。
4. 観測手段による遅延や実行環境の差も切り分ける。実装上の原因を推測した場合は、再現できた事実とは分けて記載する。

期待の根拠が既存の正本にない場合は、利用者の目的と、観測した挙動がその達成をどう妨げるかを示す。意図された挙動か判断できなければ、その点を未確定とする。未確認の違和感や実装の疑いだけで問題と断定しない。

## 報告

再現手順、期待と実際、時系列上の証拠、利用者への影響を示せるものだけを問題候補として報告する。各候補に次を含める。

- 対象・実行環境・開始状態と、順に実行できる再現手順。
- 期待する結果と根拠、実際に観測した結果。
- 操作と状態・表示の変化を対応付けた時系列。記録の該当時刻・フレーム・行へたどれる参照。
- 再現回数／試行回数、成立条件、比較した条件とその結果。
- 目的達成への影響と、意図された挙動かどうかの確定状況。

証拠のファイルと関連する実装箇所には、後から確認できるパスまたはリンクを付ける。

最後に、探索した経路、未観測の経路・区間、観測上の制約、判断待ちの事項を示す。候補の条件を満たさない手掛かりは未確認として分ける。候補がない場合も、確認した範囲で見つからなかったと報告し、未観測範囲まで問題なしと一般化しない。
